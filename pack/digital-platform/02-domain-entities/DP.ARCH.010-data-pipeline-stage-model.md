# DP.ARCH.010 — Стадийная модель конвейера персональных данных (С1-С9)

## 1. Определение

Единица учёта — **конвейер**: цепочка С1→С9 для пары (тип данных, дом записи С5) с одним владельцем. Отдельный найденный механизм — станция конвейера, не отдельный конвейер (иначе один и тот же поток данных считается несколько раз). Конвейеры сцепляются каскадом: выход одного (С9) может быть источником другого (С1) — производный конвейер обязан ссылаться на дом-источник и наследовать его свежесть.

## 2. Девять стадий

| # | Стадия | Вход | Действие | Выход |
|---|--------|------|----------|-------|
| С1 | Источник | данные носителя (внешний) или С9 конвейера-источника (каскад) | декларировать источник, сторону, потребность в данных, наследование свежести | декларация источника |
| С2 | Захват | сырьё источника; декларация С1 | съём/сбор | сырой материал |
| С3 | Нормализация и согласие | сырой материал; согласие пилота (внешнее) | нормализовать; сверить согласие — при недоступности проверки поток останавливается, а не продолжается (fail-closed) | данные, допущенные к записи |
| С4 | Проверка | данные С3; класс проверки из декларации С1; незавершённое с прошлого прохода | автоматически / смысловой контроль / решение живого пилота | проверенные данные; незавершённое переносится на следующий проход |
| С5 | Запись в дом | данные С4 | запись ровно одним автором, с датой рождения записи | факт в доме с датой рождения |
| С6 | Индекс/Реестр | факт в доме (С5) | автоматический пересчёт индекса; прописка конвейера в реестре | индекс/запись реестра |
| С7 | Актуализация | дом; пороги свежести; событие отзыва согласия (внешнее) | истечение срока/замена устаревшего; сторож пропажи данных с проверкой на искусственно внесённом разрыве; удаление по отзыву согласия | актуализированный дом; запись в журнале удалений; сигнал о разрыве — пилоту |
| С8 | Сохранность | дом; журнал удалений | резервная копия по расписанию; восстановление с повторным применением журнала удалений поверх восстановленных данных | резервная копия; восстановленный дом (обратный переход к С5) |
| С9 | Потребление | дом через интерфейс владельца; метка свежести | выдача с меткой возраста данных | выдача потребителю; для каскада — источник следующего конвейера |

**Правило полноты:** конвейер называет все 9 стадий; отсутствующая стадия — явная запись в декларации (например, «сохранность: нет — данные полностью восстановимы пересчётом»), не молчание. Дом с невоспроизводимым сырьём без возможности выгрузки — блокер регистрации конвейера, а не декларируемая дыра.

**Обратный переход и удаление данных.** Восстановление из резервной копии (С8→С5) может воскресить данные, удалённые по отзыву согласия ПОСЛЕ момента снятия копии. Решение (ArchGate 14.07): вести журнал удалений — постоянную, переживающую восстановление запись каждого отзыва/удаления, реплеиваемую поверх восстановленных данных перед их вводом в строй.

## 3. Карантин-класс «вне оси» (данные не своего владельца)

Ось типов 2.1-2.4 и эта модель покрывают только данные, на которые согласие даёт сам пилот IWE. Четыре класса материала структурно вне оси, согласие на них должен давать не пилот:

- **Данные третьих лиц** — чужие персональные данные, попавшие в материалы пилота (собеседники в расшифровках, банки персон для тестирования и т.п.).
- **Намерения и планы** пилота (в терминах этого Pack — учёт ≠ планирование, у них свой конвейер, не эта модель).
- **Секреты и учётные данные** — свои стадии (срок действия, ротация), эта модель в принципе применима, но не покрывает его целиком.
- **Платёжные/финансовые данные** — не инвентаризированы этой моделью.

**Решение:** ось 2.1-2.4 не расширяется под эти классы. Данные вне оси размечаются меткой карантина и никогда не подаются в конвейеры или в генерацию контента. Эталонная реализация разметки — Разметчик (DP.ROLE.085).

## 4. Разграничение с DP.KR.002

DP.KR.002 задаёт **ось** — куда класть материал (дом + режим). Эта модель задаёт **стадии конвейера** поверх уже выбранного дома — что происходит с данными после того, как место выбрано (проверка, свежесть, сохранность, потребление). Ось не переопределяется этой моделью.
