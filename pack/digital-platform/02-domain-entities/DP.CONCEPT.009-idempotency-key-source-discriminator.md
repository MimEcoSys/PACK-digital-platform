# DP.CONCEPT.009: идемпотентность-ключ с дискриминатором источника

## Дыра
Ключ `external_id` из одного лишь PK строки легаси-таблицы. Несколько легаси-таблиц — независимые последовательности ID, значения совпадают: событие «квалификация #3» воспринято шлюзом как повтор «занятия #3» → тихий 200 idempotent, курсор растёт, данных нет.

## Правило
Идемпотентный ключ из PK внешней системы ОБЯЗАН включать источник/тип события, если PK не глобально уникален кросс-таблично (а PK легаси-таблиц почти никогда не уникален).

## Симптом диагностики
Конвейер сообщает успех (200, курсор растёт), целевая таблица не растёт → сразу подозревать namespace collision в ключе идемпотентности, не искать баг в бизнес-логике. Сверка `external_id` двух разных event_type напрямую.

## Шире
Тесты и код-ревью проверяют, что код делает написанное; они не проверяют, что написанное совпадает с реальным состоянием разделяемого ресурса. Для конвейеров, пишущих в shared-хранилище через сторонний идемпотентный ключ, живая проверка целевой таблицы после первого реального прогона обязательна, не опциональна.
