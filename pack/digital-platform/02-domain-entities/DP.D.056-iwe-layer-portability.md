# DP.D.056 — IWE Слои как критерий портируемости

## Различение

Три слоя IWE имеют разную степень платформенной привязки:

| Слой | Содержимое | При смене AI-платформы |
|------|-----------|----------------------|
| **L1** (CLAUDE.md §1-7, hooks, skills) | Claude Code + macOS специфика | Нужно переписать |
| **L2** (staging) | Частично специфичен | Нужно пересмотреть |
| **L3** (extensions/, params.yaml, §9) | Платформенно-нейтральный | Переносится без изменений |

## Универсальные элементы (платформа не важна)

- ОРЗ-фрактал (Открытие → Работа → Закрытие)
- Pack/DS/Base архитектура знания
- Memory/Capture логика
- WP Gate ритуал согласования

## Тест

> «Встретил инструкцию → посмотри, в каком слое она живёт. L3 менять не нужно. L1 — нужно при смене платформы.» Оговорка для навыков L1 — уточнение 24.11.2026 ниже.

## Применение

- При миграции IWE между AI-ассистентами: точно знать, что переписывать
- При оценке vendor lock-in: смотреть долю L1/L3
- При Extension Gate: новое в L3 = низкий migration cost

## Уточнение 24.11.2026 (РП-592 Ф7) — замысел, пробой не подтверждён

Навыки слоя L1, вероятно, не придётся переписывать целиком: замысел РП-592 Ф7 — навыки класса «общий» **переводить**. Программа сборки собирает общую версию для других агентов, а шаги, которые держатся на особых возможностях Claude, получают в исходном навыке требования и запасные пути словами (DP.D.389, DP.ROLE.129). Защитные проверки (хуки) и навыки, держащиеся на возможностях без замены, остаются в графе «нужно переписать». До проб РП-592 Ф7 основным правилом остаётся таблица и тест выше; доля навыков, которые удастся перевести, — предмет описи в Ф7.
