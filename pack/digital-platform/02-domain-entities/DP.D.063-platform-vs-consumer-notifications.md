# DP.D.063: Платформа-инициированные ≠ Потребитель-инициированные уведомления

## Различение

**Платформа-инициированные (DP.SC.116):** уведомления отправляются платформой автоматически по системным событиям (напоминание Day Open, алерт об аномалии, приближение дедлайна). Инициатор — система.

**Потребитель-инициированные (DP.SC.134):** уведомления отправляются по явному запросу потребителя (пользователь через /remind, агент через MCP-tool, воркер через internal API). Инициатор — пользователь или агент.

## Общий транспорт

Оба типа используют один транспортный слой — Notification Dispatcher — как исполнителя доставки. Различие в инициаторе, не в транспорте.

## Архитектурное значение

| Свойство | Платформа-инициированные | Потребитель-инициированные |
|----------|--------------------------|---------------------------|
| Инициатор | Система (event-trigger) | Пользователь / агент (API-вызов) |
| Режим | Фоновый (background) | Осознанный запрос |
| Видимость ошибки | Мониторинг платформы | Немедленно пользователю |
| SC | DP.SC.116 | DP.SC.134 |

## Следствие: наследование UI-контролов и политики повтора (2026-10-07)

Кнопки обратной связи и политика повтора при сбое доставки, спроектированные для платформа-инициированных подсказок (необязательный фоновый совет), нельзя по умолчанию наследовать потребитель-инициированной доставке — она явный, именованный запрос пилота, а не предположение агента.

Конкретный случай: у роли Секретарь (`DP.ROLE.098`) кнопки «Полезно / Позже / Не предлагать» под фоновыми подсказками корректно выключают именно этот вид подсказки навсегда при тапе «Не предлагать». Новая команда `/remind` (потребитель-инициированная, WP-389 Ф8a) по умолчанию унаследовала тот же набор кнопок — случайный тап «Не предлагать» выключил бы напоминания навсегда без команды отмены. Аналогично, при неподтверждённом сбое транспорта (таймаут, не точный отказ) платформа-инициированная подсказка помечается «unknown» и теряется разово — для потребитель-инициированной доставки это недопустимо: запись о доставке удаляется, и следующий тик забирает задачу на повтор.

**Тест следствия:** «Элемент UI (кнопка отказа, политика ретрая) спроектирован для платформа-инициированного необязательного совета или для потребитель-инициированной доставки по имени?» Тип доставки должен отдельно определять набор кнопок И политику повтора — не разделяться одним кодовым путём на все виды уведомлений сразу.

## Тест

> «Кто инициирует отправку?» Система → SC.116. Пользователь или агент → SC.134.
