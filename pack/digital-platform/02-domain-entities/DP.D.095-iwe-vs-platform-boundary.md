# DP.D.095 — IWE ≠ Платформа: правило «кто управляет экземпляром»

> Критерий классификации компонента: **кто управляет экземпляром**. Управляет пользователь → IWE. Управляет платформа → Платформа. Устраняет пограничные случаи без третьей категории.

## Различение

| Аспект | IWE | Платформа |
|--------|-----|-----------|
| **Кто управляет экземпляром** | Пользователь | Aisystant |
| **Хранение** | Git пользователя (Pack-клоны, DS-репо) | Облако Aisystant (Neon DB, CF Workers) |
| **Конфигурация** | Пользователь меняет params.yaml, CLAUDE.md | Платформа обновляет через API/деплой |
| **Примеры** | Pack-клон, DS-my-strategy, FMT-exocortex-template | ЦД (Нeon), Activity Hub, MCP Gateway |

## Антипаттерн

Классификация по **месту хранения данных**: Pack-клон хранится у пользователя в git, но создан из шаблона Aisystant → на первый взгляд «Платформа». Правило «кто управляет экземпляром» снимает неоднозначность: пользователь делает git commit, изменяет содержимое → IWE.

## Тест

«Кто делает изменения в этом компоненте?»
- Пользователь (edit/commit/deploy) → IWE
- Платформа (API call/migration/Aisystant release) → Платформа
- Неясно → уточнить ownership.

## Пограничные случаи

| Компонент | Классификация | Обоснование |
|-----------|---------------|-------------|
| Pack-клон | IWE | Пользователь управляет, Aisystant только создал шаблон |
| FMT-exocortex-template | IWE (авторский) / Платформа (для пользователей) | Зависит от того, кто управляет конкретной копией |
| ЦД в Neon | Платформа | Платформа вычисляет и хранит |
| Telegram-бот | Платформа | Деплой и конфигурацию делает Aisystant |

## Оговорка v2 — управление локальной копией ≠ владение каноном

> **Инверсия модели (WP-415 §1a, 2026-06-14).** Критерий «кто управляет экземпляром» не должен путать **управление локальной копией** с **владением каноном**.

Пользователь управляет клоном Pack (личный Git) → по основному критерию это IWE. Но **канон Pack** (source-of-truth) принадлежит платформе → обновления идут с платформы вниз, не наоборот.

**Тест на канон:** «Если платформа изменит этот Pack — мой экземпляр обновится через `update.sh`?» Да → содержимое канона платформенное, локальный клон лишь его копия. Управление копией остаётся за пользователем (IWE), владение источником — за платформой.

## Доставка ≠ владение (уточнение 2026-09-05)

Оговорка v2 разбирает канон Pack (кто владеет источником). Отдельно от неё — вопрос о судьбе конкретного развёрнутого компонента (скилл, скрипт, правило, шаблон): после развёртывания он становится частью IWE, даже если создан платформой.

| Как компонент попадает к пользователю | Что после этого |
|---|---|
| **Развёртывается** (копируется в IWE): скиллы, скрипты, правила, шаблоны, CLAUDE.md | Часть IWE — пользователь управляет экземпляром, может изменить, может не принять следующее обновление. Платформа остаётся источником обновлений, не владельцем |
| **Обращение** (остаётся у платформы, не копируется): цифровой двойник, база знаний, MCP как протокол, биллинг | Не входит в IWE — IWE обращается к этим сервисам, не хранит их у себя |

**Тест:** «Компонент скопирован в git пользователя, или IWE каждый раз обращается к нему заново?» Скопирован → доставка ≠ владение (IWE). Обращение каждый раз → сервис платформы.
