# DP.D.233: Тихое исключение при деплое (silent-exclude) ≠ Уведомление об устаревании (notify-deprecate)

В системах распространения шаблона два механизма с похожим внешним эффектом «файл не доезжает / считается устаревшим», но разной семантикой:
- **Silent-exclude:** файл игнорируется при деплое, потребитель не уведомлён (тихо).
- **Notify-deprecate:** потребителю явно сигнализируется удалить файл вручную — сигнал повторяется при каждой проверке (`--check`), пока файл не удалён.

**Тест:** «Скрыть файл при деплое или предупредить потребителя, что его нужно удалить?» Скрыть молча → silent-exclude. Явно предупредить с повтором до устранения → notify-deprecate.

**Связано с:** DP.FM.075 (deprecated_files как TODO-tracker — конкретная реализация половины пары «notify-deprecate»).

**Источник:** capture session-close 2026-06-30 (`update-manifest.json`: поля `deprecated_files` vs `excluded_paths`); решение о Pack-маршруте (абстрактно, без привязки к именам полей) — пилот, 2026-07-11.

## §3. Третья ось (добавлено 2026-10-23): канал получения — первичный клон ≠ последующее обновление

Пара «silent-exclude ≠ notify-deprecate» выше описывает эффект файла ТОЛЬКО в канале инкрементальных обновлений (`update.sh`/аналог). Полный `git clone` (или эквивалент первичного получения) копирует всё содержимое репозитория целиком, независимо от классификации файла (`files` / `excluded_paths` / `deprecated_files`) — классификация влияет ТОЛЬКО на последующие прогоны обновления, не на первичное получение.

Отсюда три, не два, различных исхода для файла в системе доставки:
1. **Обновляется** — участвует в обоих каналах (clone и update).
2. **Заморожен** (`excluded_paths` / silent-exclude) — есть у получателя (из clone или истории), но больше не обновляется.
3. **Удаляется** (`deprecated_files` / notify-deprecate) — помечен на ручное удаление, сигнал повторяется до устранения.

**Тест на два канала:** «Это про то, что получает НОВЫЙ потребитель при первом клоне, или про то, что происходит с УЖЕ ПОЛУЧИВШИМ потребителем при следующем обновлении?» Путаница этих двух каналов — типовая ошибка при проектировании изменения классификации файла: ожидание, что перенос в `excluded_paths` уберёт файл из новых клонов, неверно — уберёт только из будущих обновлений, новый клон получит файл в любом случае.
