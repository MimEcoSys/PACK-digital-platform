# DP.D.243: Контур IWE ≠ Физическое место ≠ Доверие/Контроль (Substrate Criterion)

| Контур IWE (Substrate Criterion) | Внешняя точка |
|----------------------------------|--------------|
| Место, где физически хранится (версионируется) дерево IWE — `~/.claude/`, `~/IWE/**`, PACK-* | Всё остальное: Railway, Neon, WakaTime, SaaS, публичные API, GitHub.com |
| Критерий: «здесь версионируется дерево IWE?» → Да → контур | Критерий: «нет» → внешняя точка, независимо от уровня контроля или доверия |
| Входящий поток всегда разрешён | Исходящий поток — только с явным согласием пользователя |

**Почему важно**: Два отклонённых критерия: (1) «физическое место» — GitHub физически не на машине пользователя, но приватный git-хостинг всё равно в контуре (хранит дерево IWE); (2) «доверие/контроль» — Railway управляется пользователем, но не хранит дерево IWE → внешняя точка. Только критерий субстрата не сломался ни на одном контрпримере.

**Тест**: «Здесь хранится (версионируется) дерево самого IWE?» Да → контур. Нет → внешняя точка.

**Примеры**:
- Локальная машина (`~/IWE/`) → контур ✅
- Приватный self-hosted Gitea → контур ✅
- Railway (деплой бота) → внешняя точка ❌
- Neon (база данных) → внешняя точка ❌
- GitHub.com (публичное зеркало) → внешняя точка ❌

**Не путать с [DP.IWE.009](DP.IWE.009-pilot-authority-boundary.md) (граница полномочий пилота)**: контур отвечает на вопрос «хранится ли здесь дерево IWE» и решает, можно ли отправлять данные наружу; граница полномочий отвечает на вопрос «распоряжается ли здесь пилот сам» и решает, от кого зависит работа среды. Отвергнутый выше критерий «доверие/контроль» относится к вопросу о хранении, а не к границе полномочий.
