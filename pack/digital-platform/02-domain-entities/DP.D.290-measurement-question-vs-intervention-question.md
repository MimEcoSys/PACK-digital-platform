# DP.D.290 Измерительный вопрос ≠ Интервенционный вопрос

| Аспект | Измерительный вопрос | Интервенционный вопрос |
|--------|----------------------|-------------------------|
| **Цель** | Получить точное значение текущего состояния (питает gate/оценку) | Изменить состояние собеседника через сам факт вопроса |
| **Пример роли** | Диагност (R28, `DP.ROLE.042`) — cp-профиль → gate Аттестатора | Стратег (R1) в `discovery-session` — распаковка неудовлетворённостей |
| **Пресуппозиция в формулировке** | Запрещена — искажает измеряемую величину | Допустима и нормативна (SFBT: чудо-вопрос, вопрос об исключениях) |
| **Механизм риска** | Пресуппозированная деталь подтверждается собеседником систематически чаще, чем та же деталь в прямом вопросе (см. эксперименты Лофтус) — смещает самоотчёт, который затем используется как факт | Тот же механизм здесь и есть желаемый эффект — встроенное предположение о наличии решения/прогресса запускает рефлексию |
| **Условие безопасности** | Нет — риск не самокорректируется, если решение (gate) принимается один раз на основе ответа | Есть — собеседник может отвергнуть пресуппозицию без социальных издержек (напр. «если ошибки нет — это не проблема», см. discovery-session Шаг 2) |

## Правило

Вопрос, ответ на который сохраняется как значение и участвует в дальнейшем автоматическом решении (gate, ступень, метрика), формулируется без пресуппозиции величины или факта — только явные симметричные варианты, включая нулевой. Вопрос, назначение которого — сама рефлексия собеседника (коучинг, стратегирование, терапевтическая интервенция), может и должен использовать пресуппозицию как рабочий приём, при условии, что собеседник может её открыто отвергнуть без цены за отказ.

## Тест

«Ответ на этот вопрос когда-нибудь автоматически определит решение системы (ступень, доступ, рекомендацию) без дополнительной человеческой проверки?» Да → измерительный, пресуппозиция запрещена. Нет, это разовая рефлексия для самого собеседника → интервенционный, пресуппозиция допустима.

## Пример

`/diagnose` (`DP.ROLE.042`, cp.agt): формулировка «Какая доля задач... инициирована вами лично» пресуппозирует ненулевую величину (спор о величине вместо факта) — исправлено на «Насколько часто...» (FMT-exocortex-template `24a8bcb`, iwe-local-config `71062d4`). `discovery-session` (DP.METHOD.053): «Что за последнюю неделю вызывало беспокойство...» — та же конструкция, но здесь уместна, потому что в методе явно прописан отказ без цены (Шаг 2: «если ошибки нет — не тащить в таблицу НЭП»).

## Применимо к

Формулировкам вопросов в диагностических диалогах (`DP.ROLE.042`, будущие RCS — `PD.FORM.108` и аналоги), опросникам с автоматическим gate, коучинговым/стратегирующим сценариям (`DP.ROLE.012`), любому self-report инструменту, результат которого используется без последующей верификации человеком.
