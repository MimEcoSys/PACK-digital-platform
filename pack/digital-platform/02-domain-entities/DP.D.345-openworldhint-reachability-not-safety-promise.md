# DP.D.345 — openWorldHint: досягаемость для планировщика, не обещание безопасности

## Различение

| | openWorldHint как заявлено (неверно) | openWorldHint как спроектировано (верно) |
|---|---|---|
| **Что описывает** | Общее «на всякий случай», default true из осторожности | Выходит ли инструмент за пределы заранее известного, фиксированного набора данных |
| **Для SHA-зафиксированного снимка корпуса** | true (перестраховка) | false — корпус не расширяется и не обращается в открытый мир по запросу |
| **Закрепление значения** | Нет — значение может дрейфовать от реальной архитектуры | Приёмочный скрипт требует именно это значение (мутационный тест на порчу) |
| **Отношение к риску анонимного доступа** | «false значит безопасно» | Риск злоупотребления анонимным доступом НЕ снят отсутствием прямого запрета в правилах площадки — отдельный, независимо управляемый контракт (лимит/429/журнал/контакт) |

## Механизм

Аннотации инструментов MCP (`readOnlyHint`, `destructiveHint`, `openWorldHint`) — обязательные булевы декларации, которые планировщик модели использует для решений о вызове инструмента. `openWorldHint` отвечает на вопрос «может ли этот инструмент достать данные за пределами известного заранее набора», а не «насколько это безопасно вообще». Для корпуса, зафиксированного по SHA (предустановленный снимок, не расширяющийся сам), правильное значение — `false`, независимо от того, кажется ли `true` более консервативным выбором на вид.

Отдельно от аннотации: если правила площадки, у которой регистрируется сервер, не содержат прямого запрета безвходного (анонимного) доступа, это НЕ эквивалентно безопасности такого доступа. Численные меры (лимит запросов на IP с burst, поведение при превышении — 429, журнал попыток без PII, контакт для abuse-отчётов) должны быть подняты из «вопрос политики на будущее» в «обязательный измеримый контракт заявки» — с конкретными числами за владельцами сервера, не выдуманными экстрактором.

## Конкретное применение (WP-581)

Решение `openWorldHint=false` принято для сервера, регистрирующего предустановленный, зафиксированный по SHA корпус паттернов FPF/DPF (WP-581, площадка «marketplace»): корпус не расширяется и не обращается в открытый мир по запросу, поэтому значение `false` корректно описывает именно эту архитектуру, а не выбрано «на всякий случай». Приёмочный скрипт/CI-тест этой регистрации проверяет мутацией, что манифест сервера объявляет ровно `openWorldHint: false`, и фейлит сборку, если значение по привычке вернут в `true`.

## Тест различения

«Эта аннотация описывает архитектурное свойство инструмента (что он может достать) или служит заменой проверки реальной безопасности эндпоинта?» Первое — корректное использование аннотации; подмена второго первым — нарушение этого различения.

Отдельно: «Правила площадки явно запрещают анонимный доступ?» Нет → это НЕ довод «значит разрешено и безопасно» — открытый риск, требующий отдельного контракта.

## Границы

Применимо к любой регистрации MCP-сервера (или аналогичного каталога инструментов) у внешней площадки, где аннотации инструментов булевы и обязательны. Не определяет сами числа лимитов — решение владельца сервера на основе его инфраструктуры.
