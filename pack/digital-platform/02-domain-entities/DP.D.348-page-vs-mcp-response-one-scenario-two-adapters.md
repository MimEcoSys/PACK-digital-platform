# DP.D.348 — «Страница» и «MCP-ответ» — два адаптера одного сценария, не два сценария

## Различение

| | Два независимых сценария | Один сценарий, два channel-адаптера |
|---|---|---|
| **Источник различий в выдаче** | Расходящаяся логика двух отдельных реализаций | Явное именованное условие общего сценария (`канал=страница` / `канал=mcp`) |
| **Риск при тихом расхождении** | Поведение каналов дрейфует независимо, несогласованно | — |
| **Что меняется при добавлении различия** | Правка одной из двух копий логики | Правка условия в едином сценарии, видимая для обоих адаптеров |

## Механизм

При проектировании общего списка направлений онбординга (хаб ссылок) для страницы сайта (WP-442) и ответа MCP-инструмента (WP-590) была отклонена альтернатива — вести две независимые реализации списка с собственной логикой на каждой поверхности. Принято: один версионированный сценарий с шагом выбора из N размеченных выходов и явными per-канал адаптерами; любая разница в поведении канала (обязательность пункта, формулировка, видимое подмножество) — именованное условие сценария, не отдельная ветка кода.

## Тест различения

«Если один канал покажет что-то отличное от другого — это потому, что так явно размечено в сценарии (`канал=X`), или потому, что их логика просто разошлась со временем?» Второе → воспроизведён антипаттерн двух сценариев вместо одного.

## Границы

Смежно, не дубль: `DP.M.069` (Multi-scenario Service Clause) — там одно обещание (SC) допускает N delivery-сценариев с разными SLA/триггерами; здесь — наоборот, один сценарий должен сохранять единство поведения через N channel-адаптеров, различия которых явно поименованы, а не стихийны. `DP.D.064` — дискриминатор «то же обещание vs другое обещание» работает на уровне РП/promise; это различение — на уровне реализации одного уже согласованного сценария.
