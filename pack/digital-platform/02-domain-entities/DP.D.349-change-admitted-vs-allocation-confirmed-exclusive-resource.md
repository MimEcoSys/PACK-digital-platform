# DP.D.349 — Допуск изменения ≠ разрешение действовать на эксклюзивном ресурсе

## Различение

| | change_admitted (допуск) | allocation_confirmed (разрешение действовать) |
|---|---|---|
| **Что проверяет** | Полномочия инициатора + применимость перехода в принципе | Исключительное право действовать на конкретном ресурсе прямо сейчас |
| **Сколько агентов может пройти одновременно** | Несколько — проверка не знает о других претендентах | Один — стадия существует именно для устранения этой гонки |
| **Когда обязательна отдельная стадия** | Всегда | Только когда запрос заявляет `claims_exclusive_resource=true` |
| **Риск при слиянии стадий** | Два агента, независимо прошедшие допуск для одного эксклюзивного ресурса, оба решают, что имеют право действовать, — до публикации | — |

## Механизм

В трёхстадийной модели состояний элемента плана (приём/допуск/публикация) допуск (admission) проверяет полномочия и формальную применимость перехода. Если прохождение допуска само по себе трактуется как «можно действовать», для обычных (неэксклюзивных) изменений это безопасно, но для эксклюзивных ресурсов — нет: два независимых агента могут пройти admission независимо и параллельно для одного и того же ресурса, и оба получат (противоречащее) ощущение права действовать до момента публикации, когда конфликт впервые становится видимым. Исправление — третье явное событие `allocation_confirmed`, обязательное только при `claims_exclusive_resource=true`; обычные изменения остаются на двухстадийной дорожке.

## Тест различения

«Эта проверка подтверждает, что действие ВООБЩЕ допустимо, или что ИМЕННО Я прямо сейчас вправе выполнить его единолично на этом ресурсе?» Если схема отвечает только на первый вопрос, но ресурс эксклюзивный — гонка не закрыта.

## Границы

Различение применимо там, где есть независимые проверяющие (несколько агентов, проходящих admission параллельно) и общий ресурс с эксклюзивным владением. Для неэксклюзивных изменений дополнительная стадия не нужна — риска гонки на запись нет.
