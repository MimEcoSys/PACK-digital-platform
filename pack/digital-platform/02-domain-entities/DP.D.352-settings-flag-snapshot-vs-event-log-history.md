# DP.D.352 — Флаг настройки (снимок) ≠ журнал событий (история)

## Различение

| | Флаг настройки (снимок) | Журнал событий (история) |
|---|---|---|
| Что отвечает | «Что сейчас включено/выключено» | «Как часто и когда это менялось» |
| Данные | Текущее значение поля | Последовательность событий с таймстемпами |
| Достаточно для | Разового pass/fail по виду сигнала на конец периода | Подсчёта частоты/динамики изменений за период |
| Недостаточно для | Подсчёта, сколько раз менялось | — |

## Механизм

Для планового пилота проактивных правил понадобилась разбивка статуса по видам сигнала к концу периода. Пир-сессия сознательно решила не заводить журнал событий нажатий «отложить»/«не предлагать» для этого инкремента, а брать только текущее значение флага (`snoozed_kinds`/`disabled_kinds`) — этого достаточно для «прошёл/не прошёл» к концу пилота, но недостаточно, чтобы сказать, сколько раз вид сигнала отвергался за период.

## Тест различения

«Вопрос, на который должен ответить замер — про текущее состояние на момент проверки, или про то, как часто/когда оно менялось?» Снимок отвечает только на первый; если нужен второй — снимка недостаточно, нужен журнал событий.

## Границы

Прежде чем добавлять измерение к фиче-флагу/настройке, разделять вопрос «что сейчас включено/выключено» от вопроса «как часто это менялось». Если scope инкремента — только снимок, это осознанное сужение, которое стоит явно зафиксировать (как решение пир-сессии), а не недосмотр, обнаруживаемый постфактум.
