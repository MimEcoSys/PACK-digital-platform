# DP.D.354 — Существование MCP-тула ≠ подтверждённая готовность интеграции

## Различение

| | Существование тула | Готовность интеграции |
|---|---|---|
| **Что подтверждает** | Такая возможность в принципе реализована где-то в системе | Тул подходит именно для этого места использования |
| **Что проверяется** | Регистрация/видимость тула (`tools/list`, каталог MCP) | Контракт: принимаемый идентификатор, формат/состав ответа — совместимы с вызывающей стороной |
| **Ошибка при смешении** | «Тул есть → можно подключать» | Пропущен шаг проверки входа/выхода под конкретный кейс |

## Механизм

MCP-тул может быть полностью рабочим для одного вызывающего контекста и
несовместимым для другого — например, принимать один тип идентификатора
(внутренний user_id), когда у нового потребителя (табло наставника) на входе
другой идентификатор (участник из списка). Факт существования тула отвечает
только на вопрос «реализована ли такая возможность», не на вопрос «подходит
ли её текущий контракт сюда». Эти два вопроса проверяются раздельно: первый —
по каталогу/документации тула, второй — по его фактической сигнатуре
(параметры, формат ответа) и по тому, что есть на стороне конкретного
вызывающего места.

## Тест различения

«Я подтвердил, что тул СУЩЕСТВУЕТ, или что его КОНТРАКТ (входной идентификатор,
формат ответа) совместим именно с этим местом использования?» Первое — не
основание для вывода «интеграция готова».

## Прецедент

Peer-сессия WP-578 (панель мониторинга наставника, кандидат-колонка
«чек-лист»): Kimi оценил чек-лист как технически готовый к подключению,
сославшись на существование MCP-тула `checklist_get_checklist_status`. Живая
проверка кода (Codex) возразила: нужно подтвердить, что тул принимает
идентификатор участника из табло и возвращает нужный по форме статус — это не
следует автоматически из факта существования тула.

## Границы

Применимо к любому решению «подключить существующий тул/API к новому
потребителю» — не только MCP. Не предписывает, как проверять контракт
(достаточно прочитать сигнатуру/документацию или сделать тестовый вызов) —
только то, что этот шаг обязателен и не взаимозаменяем с подтверждением
существования.
