# DP.D.357 — «Функция определена» ≠ «маршрут записи функционален»

## Различение

| | declare -f (функция определена) | LEDGER_ROUTE_READY (маршрут функционален) |
|---|---|---|
| **Что подтверждает** | Shell-библиотека загрузилась, имя функции видно в текущем окружении | Конкретный маршрут записи (ledger-append) реально доступен и работает прямо сейчас |
| **Природа признака** | Побочный эффект загрузки библиотеки | Явный флаг состояния, выставляемый по факту проверки готовности |
| **Риск при смешении** | Гейт считает «можно писать событие», хотя запись реально недоступна — событие теряется без следа в stderr | — |

## Механизм

Холодное ревью однократного блокирующего гейта (`ritual-shown-detector.sh`) нашло: готовность маршрута записи в журнал (`ledger-append.sh`) проверялась через `declare -f ledger_route_append` — предикат, истинный, если shell-библиотека с этим именем функции была подгружена, независимо от того, способен ли сам маршрут записи выполнить что-либо (например, при недоступности целевого процесса/файла). При недоступном `ledger-append.sh` событие `ritual_gate_enforced` терялось без следа в stderr. Фикс: явный флаг `LEDGER_ROUTE_READY`, выставляемый по факту проверки готовности маршрута, плюс явное сообщение о пропуске в stderr.

## Тест различения

«Эта проверка подтверждает, что ИМЯ функции/команды определено в текущем окружении, или что САМ маршрут/подсистема, которую эта функция реализует, прямо сейчас способна выполнить своё действие?» Первое — косвенный признак через побочный эффект загрузки; там, где различимо, явный флаг состояния надёжнее.

## Границы

Применимо к любой проверке вида «функция/команда определена» (`declare -f`, `hasattr`, `command -v`) как предвестнику готовности подсистемы — не ограничено bash или ledger-записью. Не относится к случаям, где определение функции и есть всё, что требуется (чистые утилитарные функции без внешних зависимостей для выполнения).
