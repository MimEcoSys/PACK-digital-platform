# DP.D.359 — Join-ключ сессии: поле с содержимым ≠ поле-метка

## Различение

| | `slug:` (поле-метка) | `file:` (поле с содержимым) |
|---|---|---|
| **Что это** | Человекочитаемая метка, присваиваемая harness | Путь к реальной папке/файлу сессии |
| **Надёжность как join-ключ** | Может быть общим placeholder'ом (`placeholder`, `placeholder2`…) для НЕСКОЛЬКИХ разных папок пир-сессий, открытых в одном чате | Указывает на единственную конкретную папку — не переиспользуется между сессиями |
| **Риск при смешении** | Join по slug склеивает записи разных сессий, которым harness присвоил одинаковую заглушку | — |

## Механизм

Сканер незавершённых журналов пир-сессий сначала спроектировали на `slug` как join-ключ между записями о сессии. Холодный ревьюер (Fable) отклонил этот дизайн: slug внутри session-guard semaphore может быть harness-заглушкой, общей для нескольких разных папок пир-сессий, открытых в одном чате — join по такому полю склеивает несвязанные сессии. Переписали на строку `file:` внутри semaphore как единственный надёжный указатель на реальную папку.

## Тест различения

«Это поле — стабильный человекочитаемый ярлык, который harness может присвоить одинаково нескольким разным сессиям, или путь/идентификатор, уникально указывающий на одну конкретную папку?» Первое не годится как join-ключ без отдельной проверки уникальности; второе — безопасный join-ключ.

## Границы

Применимо к любой записи о сессии/процессе, где одновременно присутствуют человекочитаемая метка (slug/name/label) и путь к реальному артефакту (file/path): метка предпочтительна для отображения человеку, путь — для машинного join. Не описывает сам механизм присвоения placeholder'ов harness'ом (вне scope этой карточки).
