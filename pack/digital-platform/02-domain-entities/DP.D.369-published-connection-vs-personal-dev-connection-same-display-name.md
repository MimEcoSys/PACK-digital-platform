# DP.D.369 — Опубликованное подключение ≠ личное dev-подключение с тем же отображаемым именем

## Различение

| Механизм | Что подтверждает | Чего сам по себе не подтверждает |
|---|---|---|
| UI каталога установленных приложений | Факт наличия записи с данным именем | Какая из одноимённых записей — официально опубликованная |
| Издатель/иконка в списке | Отображаемый лейбл издателя | Версию и содержимое реально опубликованного пакета (личная dev-копия может иметь стандартную иконку, неотличимую на вид) |
| Метаданные опубликованного ZIP/пакета (иконка, версия внутри пакета) | Какая именно запись соответствует официальному выпуску | — |

После публикации интеграции/плагина в едином каталоге установленных приложений у пользователя могут одновременно существовать две карточки с одинаковым отображаемым именем, указывающие на один и тот же backend-эндпоинт: официальная опубликованная (издатель, фирменный значок, версия пакета) и личная копия для разработки (другой издатель-лейбл, но часто стандартная, а не «отсутствующая» иконка — визуально почти неотличима). Различить, какая из двух — настоящая опубликованная, по самому списку подключений нельзя; нужна проверка метаданных (иконка, версия) внутри реально опубликованного пакета.

## Проверенное наблюдение

После публикации Aisystant Open в каталоге OpenAI у пользователя в ChatGPT одновременно существовали две карточки «Aisystant Open» на один и тот же эндпоинт `open.aisystant.com/mcp`: официальная (издатель Aisystant, Corp., фирменный значок, версия `0.1.3`, подтверждена по содержимому официального ZIP) и личная dev-копия (издатель Liya Rooney, стандартная иконка, версия `1.0.0`). Различение выполнено сверкой метаданных опубликованного пакета, не по списку каталога.

## Применение

При публикации интеграции/плагина под тем же отображаемым именем, что уже использует личная dev-версия, в общем каталоге установленных приложений — после публикации явно сверить метаданные (иконку, версию) внутри реально опубликованного пакета, прежде чем подключать «похожую на официальную» запись; затем отключить и удалить личную dev-копию из каталога.
