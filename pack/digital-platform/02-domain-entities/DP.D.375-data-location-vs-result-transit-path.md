# DP.D.375: Где лежат и обрабатываются данные ≠ через кого проходят результаты

**Описание:**
Суверенитет данных определяется не только местом хранения и обработки (DP.D.175), но и **путём, по которому идут результаты** этой обработки до потребителя.

- **Место данных:** индекс и поиск работают у владельца (свой сервер, своя машина).
- **Транзитный путь:** найденные фрагменты попадают в ИИ-клиент либо напрямую, либо через посредника (облачный шлюз платформы).

Если поиск у владельца, а результаты идут через шлюз платформы, содержимое всё равно оказывается у третьей стороны. Суверенитет потерян, хотя «данные лежат у себя».

**Следствие для проектирования:**
Для сценариев «данные у владельца» точку подключения выбирают так, чтобы содержимое не проходило транзитом через сервис третьей стороны. Личный поиск подключается к ИИ-клиенту владельца напрямую, а не как upstream-инструмент облачного шлюза.

**Тест:** «Через чьи серверы проходят результаты (фрагменты, ответы) по пути к ИИ-клиенту?» Если среди них есть сервис не владельца, суверенитет нарушен независимо от места хранения.

**Пределы:** Различение не запрещает шлюзу видеть метаданные подключения (факт вызова, идентичность). Оно касается содержимого результатов. Сам ИИ-клиент (LLM-вендор) — отдельная граница доверия, которую выбирает владелец; это различение её не решает.

**Источник:** разбор обращения участника со своим git-сервером в РФ, который просил индексировать его git по адресу и токену (РП-610 Ф7, РП-483 Ф12).
**Смежно:** DP.D.175 (зона суверенитета = машина владельца), DP.IWE.005 (Local MCP Gateway — upstream proxy).
