# DP.D.377: Текст сообщения ≠ Строка-контракт формата

При переводе шаблона на другой язык человекочитаемый текст делится на три категории. У каждой своя политика.

| Категория | Кто читает | Что будет при переводе | Политика |
|-----------|-----------|----------------------|----------|
| **Сообщение** пользователю | человек | ничего не ломается | переводится через каталог сообщений по языку |
| **Строка-контракт формата** (заголовок раздела плана, колонка таблицы, метка статуса) | код и тесты ищут её точным совпадением | парсеры молча перестают находить раздел, тесты падают или, хуже, проходят пусто | выносится в каталог языковых данных как ключ формата; меняется только синхронно с парсерами и тестами |
| **Текст для контекста агента** (выводы хуков, подсказки) | модель | меняется поведение агента | отдельная политика, решается отдельно |

**Тест:** «Есть ли в коде или тестах поиск этой строки точным текстом (`grep`, `in header`, регулярное выражение)?» Да → это контракт формата, не перевод.

**Предусловие перевода:** до массового перевода составить инвентарь строк-контрактов. Без инвентаря перевод «всех строк в кавычках» затрагивает контракты, и его приходится откатывать.

**Прецедент:** WP-610 Ф9. Шаг перевода шаблона (~7500 строк сообщений в yaml/json/heredoc) отложен до инвентаря. Предыдущий перевод 310+71 строк в кавычках отменён. Примеры контрактов: заголовки DayPlan «Горлышко недели», «Итоги вчера», «Мир», колонки таблиц РП.
