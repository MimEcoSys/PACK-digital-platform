# DP.D.379: owner ≠ delivery_authority

## Различение
- **owner** — кто по смыслу хозяин контента (user/platform/agent).
- **delivery_authority** — какой репозиторий имеет право перезаписывать канонический экземпляр на другом хосте.

## Почему важно
Смешение осей даёт ложную классификацию: файлы с `owner: agent` (локальные уроки про баги харнесса конкретного хоста) семантически «принадлежат агенту», но НЕ должны автоматически разливаться на хост с другим харнессом.

## Тест
«Кто по смыслу автор документа?» ≠ «Какой репозиторий имеет право его перезаписывать на другом хосте?». Если ответы могут разойтись хотя бы для одного реального файла — нужны два отдельных поля, не одно выведенное из другого.

## Как применять
При проектировании любой автодоставки/синхронизации между хостами (root↔сервер, root↔шаблон, rsync/git-pull манифест) — НЕ выводить критерии доставки из метаданных владения (owner/status/type), даже если на текущих данных вывод выглядит корректным. Явное поле (`delivery: managed` + `delivery_authority: <источник>`), fail-closed по умолчанию.
