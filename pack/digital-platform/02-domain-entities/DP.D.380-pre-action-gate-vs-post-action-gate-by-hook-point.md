# DP.D.380 — Гейт до действия ≠ гейт после действия

## Различение

| | Гейт до действия | Гейт после действия (хук после записи) |
|---|---|---|
| Действие к моменту вердикта | ещё не произошло | уже произошло |
| Может запретить | да | нет |
| Кто читает вывод | вызывающий/агент | зависит от встройки; в случае-источнике — никто |
| Честный режим | строгий допустим | наблюдение + журнал, переживающий сессию; либо совет агенту, если вывод возвращается в его ход (DP.M.436) |

## Тест

Перед выбором режима гейта: произошло ли действие к моменту вердикта и кто читает его вывод? Если действие уже произошло и вывод не читают, «строгий» режим создаёт ложное чувство защиты: отказ теряется молча.

## Случай-источник

Заявку файла в семафоре сессии делала автоматическая проверка, срабатывающая уже после записи файла (РП-561 Ф33). Строгий отказ такой проверки никто не видел: файл изменён, заявки нет, агент о конфликте не узнал. Выбран режим наблюдения с журналом, который переживает сессию.

## Отличие от соседей

- DP.M.525 — порядок включения нового гейта (сначала предупреждение, потом блокировка). Здесь — какой режим вообще осмыслен в данной точке встройки: после действия блокировка недоступна никогда.
- DP.SC.204 — обещание гейта объявления намерения (блокирует до действия). Случай-источник — встройка этого гейта в заявку файла, которая срабатывает после записи; в DP.SC.204 этот режим не описан.
- DP.M.436 — хук после правки, чей отчёт возвращается в тот же ход агента: запретить он тоже не может, но его вывод читают, поэтому осмыслен режим немедленного совета.
