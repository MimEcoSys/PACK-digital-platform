# DP.D.384 — Поле записи: строгий отбор ≠ смысловой поиск ≠ отдача ИИ человека

## Различение

Сервер каталога отдаёт записи ИИ человека: карточки методов, документы, позиции каталога. О каждом поле записи задают три вопроса, и ответы на них независимы.

| Назначение | Кто использует поле | Что с ним происходит | Смешение |
|---|---|---|---|
| Строгий отбор | программа сервера | запись исключается из выдачи или остаётся: да или нет | фильтр по полю, значение которого сервер проверить не может |
| Смысловой поиск | индекс (модель эмбеддингов) | поле участвует в ранжировании записей по близости к запросу | в индекс попадают заметки, лицензия, авторство, происхождение, история изменений |
| Отдача | ИИ человека | по тексту поля ИИ ведёт человека | ИИ получает служебные поля и тратит на них внимание и токены |

Есть и поля только для программы сборки: их не индексируют и не отдают.

Одно поле может иметь одно, два или три назначения. Смешение начинается, когда одно назначение выводят из другого: «показываем ИИ — значит, и фильтруем», «индексируем — значит, и отдаём».

## Пример (Библиотека методов, решения пилота 10.11)

- **Строгий отбор:** статус (в рабочий каталог — только утверждённые), доступ, язык.
- **Отдаётся ИИ, но не фильтр:** требование к модели. Сервер не знает модель клиента, поэтому требование читает ИИ человека и решает сам.
- **Только для поиска:** примеры ситуаций словами человека. По совету исполнителя MCP по ним ищется лучше всего; в ответе «карточка» их нет.
- **Не отдаются (служебные поля сборки):** выдержки, редакция, версия карточки, фасеты, доступ, уровень доверия, утверждение. При этом доступ (отдельное поле `access`) и язык (поле `facets.language`) служат строгими фильтрами — доступ служит только фильтром и не отдаётся ИИ.
- **Проверяется при приёме, а не при выдаче:** лицензия.

## Тест

Для каждого поля ответить отдельно:
1. Может ли сервер сам проверить значение поля и по нему исключить запись? Нет → это не фильтр, даже если поле важно для выбора.
2. Помогает ли поле найти запись по смыслу запроса? Нет → в индекс не включать.
3. Нужно ли поле ИИ человека, чтобы вести человека? Нет → не отдавать.

Ответ на один вопрос выведен из ответа на другой → назначения смешаны.

## Почему важно

Фильтр по требованию к модели нечем вычислить: сервер не знает модель клиента. Служебные поля в ответе тратят внимание и токены ИИ (решение пилота 10.11).

## Границы

- Один источник: Библиотека методов (РП-581 Ф29, РП-608). Конкретный список полей — решение DS («Как используется карточка метода»); в пак переносится различение, а не список. Перечень полей для индекса в том документе помечен как предложение, поля определяет пилот.
- Захват относил к строгим фильтрам лицензию и требование к модели. В утверждённом документе решено иначе (см. пример); карточка следует ему.
