# DP.D.385 — Копия индекса на читателя ≠ копия на источник

## Различение

| | Копия на читателя | Копия на источник |
|---|---|---|
| Единица хранения | пара «читатель — источник» | источник |
| Личный источник (один владелец) | одна копия | та же одна копия |
| Общий источник, N читателей | N копий закрытых текстов | одна копия |
| Откуда следует право читать | из принадлежности копии пользователю (привязка «пользователь — источник») | из отдельной записи «источник + основания доступа», одной для всех путей чтения |
| Отзыв доступа одного читателя | удаляется только его копия, остальные остаются | снимается его основание; тексты остаются недоступными ему |
| Полное удаление источника | чистка у каждого читателя | одна операция по запросу распорядителя |

С одним владельцем выбор незаметен: обе схемы дают одну копию. Различие проявляется, когда у источника появляется второй читатель.

## Тест

1. Сколько копий текстов закрытого источника существует при N читателях?
2. Что происходит с остальными копиями, когда доступ снят у одного читателя?
3. Где записано, кто имеет доступ к источнику: в принадлежности копий или в отдельной записи, одной для всех путей чтения (поиск, документ, перечни, метаданные, статистика, граф понятий, служебные выгрузки)?

Ответ «N копий, остальные остаются, право следует из принадлежности копии» — схема «на читателя». Проверять нужно на источнике с двумя читателями: на личном источнике расхождения не видно.

## Почему важно

- Копии закрытого источника у каждого читателя — отдельные места утечки: ушедший участник не убирает текст из системы, а полное удаление требует чистки у всех.
- Единая запись «источник + основания» проверяется одной функцией на всех путях чтения; право, выведенное из принадлежности копий, придётся проверять на каждом пути чтения отдельно (вывод из проекта РП-604, где путей около восьми, а не прямое утверждение его документа).
- Отзыв и неоплата не требуют удаления текстов: полное удаление — отдельный запрос распорядителя с проверкой полномочий и других действующих оснований.

## Пример (РП-604 Ф3, решение пилота 10.11)

Индекс сервиса знаний хранился на пользователя: командный источник каждый участник индексировал в свою копию, а сверка доступа при исключении участника удаляла копию ушедшего. Принята схема «источник + основания доступа»: единая запись для всех путей, личный источник регистрируется в ней без переноса индекса, командный источник индексируется один раз, участнику выдаётся основание. Сверка при отзыве участника меняется с удаления текстов на деактивацию основания.

## Границы

- Один источник — проект РП-604. В DS это принятый проект (решения пилота 10.11, вариант B) и план поставки; сведений о реализации в прочитанных документах нет. Карточка описывает различение и выбранную схему, а не работающую систему.
- Различение не сравнивает варианты по стоимости: варианты хранения и оценки трудозатрат — в DS (`WP-604`, Ф3).
- Из различения не следует, что тексты не удаляют: удаление остаётся отдельной операцией распорядителя.
