# DP.D.386: Исходный код ≠ Промпт

Исходный код и промпт относятся к одному роду: оба описывают, как действовать. Различаются они тем, кто по ним работает. По исходному коду работает программа: компьютер собирает её из исходного кода и исполняет. По промпту работает ИИ-агент: модель толкует текст.

| | Исходный код | Промпт |
|---|---|---|
| Кто по нему работает | запущенная программа; компьютер исполняет её буквально, шаг за шагом | ИИ-агент; модель толкует текст |
| Повторяемость | на том же входе и в той же среде программа ведёт себя одинаково | поведение агента каждый раз немного разное |
| Как проверяют | тестами программы | прогонами на испытательном стенде, по нескольку раз на сценарий, с записью модели |
| Язык | язык программирования | естественный язык |
| Кто пишет | разработчик | автор инструкции для ИИ |
| Как называют | исходный код (не «первичный»); файлы с ним — документ | системный промпт, инструкция сервера для ИИ, описание операции, карточка метода |

**Главное правило: род текста определяет тот, кто по нему работает, а не место хранения и не автор.**

**Случай-источник (22.11.2026).** Общая инструкция сервера Open MCP и описания его двух операций лежат внутри исходного кода сервера, и вписал их разработчик. Сервер по этим текстам не работает: он передаёт их ИИ-ассистенту при подключении. Поэтому они относятся к промпту ассистента, а не к исходному коду сервера. Промпт ассистента собирается из четырёх текстов: инструкций вендора, общей инструкции сервера, описаний операций и прочитанной карточки метода. Текст сервера говорил только «ищи и читай» и ничего не говорил о ведении по методу. В пробном прогоне ассистент нашёл и прочитал карточку «Конфликтное облако», а затем сам заполнил облако вместо того, чтобы вести человека по шагам.

**Почему важно.** Если путать:
- правила поведения ИИ пишет разработчик заодно с кодом, и как ИИ им следует, никто не проверяет;
- текст для ИИ проверяют тестами программы: тест подтвердит, что сервер отдал текст, но не то, что модель ему следует;
- недостаток программы пытаются исправить промптом, а недостаток промпта — кодом.

**Как применять.** Текст для ИИ внутри исходного кода пишет и ведёт автор инструкции для ИИ отдельным документом с номером версии. Разработчик вставляет его без правок. Как ИИ следует тексту, проверяет испытательный стенд, а не тесты программы.

**Тест.** «Кто читает этот текст в момент работы: компьютер или модель?» Если компьютер, текст относится к исходному коду. Если модель, текст относится к промпту, где бы он ни лежал.

**Связь с DP.D.048 «Скрипт ≠ Агент».** То различение говорит о системах-исполнителях: кто выбирает следующий шаг. Это различение говорит об описаниях, по которым они работают. Скрипт работает по исходному коду. Агент работает по промпту и вызывает программы-инструменты.
