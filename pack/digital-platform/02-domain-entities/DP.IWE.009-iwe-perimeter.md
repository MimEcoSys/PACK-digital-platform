# Контур IWE (DP.IWE.009)

## 1. Определение

**Контур IWE** — граница, внутри которой пилот имеет полный контроль над данными и процессами интеллектуальной среды. Внутри контура пилот распоряжается сам; снаружи — зависит от условий и решений других сторон (провайдеров, платформ, контрагентов).

**Ключевое:** Контур — не физическое место и не один сервис, а **граница распоряжения**. Тот же файл может быть внутри контура (Git-репозиторий пилота) и снаружи (копия в чужом облаке без экспорта) одновременно.

## 2. Три слоя контура

| Слой | Что внутри | Тест разрыва |
|---|---|---|
| **Физический** | Устройства, носители, локальные копии | Если устройство сломается — есть ли работающая замена? |
| **Логический** | Репозитории, базы данных, файловые хранилища под управлением пилота | Если провайдер заблокирует доступ — есть ли независимая копия? |
| **Процессный** | Автоматизации, агенты, скрипты с известными правилами работы | Если внешний API сломается — продолжит ли среда работать? |

**Тест на разрыв контура:** «Если связь с провайдером X отключится завтра — продолжит ли среда работать?» Если нет — этот участок снаружи контура.

## 3. Реализация контура

Контур задаётся не одним решением, а **системой выборов**:

- **Хранение:** Git как первичное хранилище (Pack-документы, заметки, код), облако как реплика — не наоборот.
- **Доступ:** локальные ключи и SSH вместо «вход через Google».
- **Интеграции:** MCP / открытые протоколы вместо vendor-API.
- **Резервирование:** Резервная копия (DP.M.123) с независимым ритмом и хранилищем.

## 4. Различения

| **Privacy / Конфиденциальность** | Контур — про распоряжение данными. Конфиденциальность — про доступ к ним. Можно иметь полный контур и публичные данные одновременно. |

## 5. Расширение и сужение контура

Контур не статичен: пилот целенаправленно расширяет и сужает его по областям:

- **Расширение:** перенос Notion → Obsidian+Git; экспорт документов с Google Drive в локальное хранилище; переход на FileVault для ноутбука.
- **Сужение:** делегирование почты внешнему сервису; принятие зависимости от LLM-провайдера для конкретной задачи.

Не любая зависимость снаружи контура — плохо. Плохо — **неосознанная зависимость**, когда пилот не знает, что находится снаружи и какова цена восстановления.
