# Архитектура IWE (DP.IWE.013)

> **Архитектура по уровням.** Экосистема — [ECO.ARCH.001](https://github.com/MimEcoSys/PACK-ecosystem/blob/main/pack/ecosystem/02-domain-entities/ECO.ARCH.001-ecosystem-architecture.md) · платформа — [DP.ARCH.001](DP.ARCH.001-platform-architecture.md) · IWE — **DP.IWE.013 (этот документ)**.

> **Статус — черновик.** Описание уточняет главное описание IWE (DP.IWE.001). Там IWE описана через пять видов (системы, описания, роли, методы, рабочие продукты), и пять видов читаются как состав. Здесь — устройство IWE как системы. Расхождения с другими описаниями пака собраны в §11.

## 1. Граница и назначение

IWE — система. Пользователь — отдельная система вне IWE: он работает с IWE, но в её состав не входит. Совместная работа пользователя и IWE описывается как другая, более широкая система «человек + IWE» (имя — открытый вопрос, §12).

**Назначение IWE как целого** (функция наружу): пользователь с помощью IWE думает, планирует, создаёт и развивается при поддержке ИИ-агентов, методологии и накопленных знаний (DP.IWE.001 §1). Всё остальное в этом документе — устройство, которое это назначение обеспечивает.

Различение «модули IWE» и «системы окружения» (§6) заменяет употреблявшееся прежде слово «контур».

## 2. Четыре описания одной системы

| Описание | На какой вопрос отвечает |
|---|---|
| Функциональные подсистемы (§4) | на какие функциональные части делится IWE: каждая подсистема названа и выполняет свою функцию в составе целого |
| Модули (§5) | из каких конкретных конструктивных элементов IWE собрана |
| Размещение (§7) | где работает каждый модуль и чей это ресурс |
| Соответствия (§8) | какими модулями реализована каждая функциональная подсистема (многие ко многим) |

**Функциональная подсистема** — часть IWE, выделенная и названная по тому, что она делает для целого. **Модуль** — конкретный конструктивный элемент, названный по своей конструкции (какая программа, служба или хранилище), который можно установить и заменить. Это два разных разбиения одной системы. Одна функциональная подсистема может держаться на нескольких модулях, один модуль — работать на несколько функциональных подсистем.

От набора FPF E.17.2 описание отличается так: процедурная точка зрения (ОРЗ, конвейеры) остаётся в описаниях методов и здесь не строится; распределение ролей по модулям — после ревизии реестра ролей; размещение добавлено как отдельная точка зрения.

**Модуль** — конкретный конструктивный элемент системы, который можно заменить. Это не учебный модуль: запрет пака на дидактические слова («шаг», «урок», «модуль») относится к учебному смыслу.

**Программа** (скрипт и хук — тоже программы) — система, когда её файл запущен на железе. Незапущенный файл программы — документ.

## 3. Модуль IWE и система окружения

- **Модуль IWE** — в экземпляре IWE есть артефакт его установки или настройки, и замена возможна внутри границы IWE.
- **Система окружения** — система вне IWE, с которой IWE взаимодействует; часто её экземпляр общий для многих, и IWE обращается к ней по интерфейсу.

Рантайм агента — модуль IWE, который поставляет вендор: так ядро входит в дистрибутив, хотя пишет его не автор дистрибутива. Рантайм установлен и настроен в экземпляре IWE и заменяется другим рантаймом. Модель, к которой обращается рантайм, — система окружения.

## 4. Функциональные подсистемы

| Функциональная подсистема | Что делает в составе IWE | Где есть |
|---|---|---|
| Подсистема исполнения работы | выполняет задачи пользователя действиями агента и производит рабочие продукты | ядро |
| Подсистема предъявления инструкций и памяти | подаёт агенту инструкции и память по событиям сессии (прежнее имя — экзокортекс) | ядро |
| Подсистема маршрутизации знаний | определяет место хранения для каждой единицы знания и артефакта | ядро |
| Подсистема защиты секретов и личных данных | не пропускает секреты и личные данные в команды, вывод, коммиты и публикацию | ядро |
| Подсистема контроля реестров | обнаруживает расхождения между реестрами и их копиями | ядро |
| Подсистема фоновых работ | запускает работы по времени и событиям и сигналит пользователю | ядро |
| Подсистема проверки установки | проверяет состояние установки и выдаёт заключение | ядро |
| Подсистема учёта работы | ведёт сессии, карточки рабочих продуктов, реестр и журнал дня | ядро |
| Подсистема координации агентов | разграничивает правки параллельных агентов, изолирует их и выстраивает очередь публикации | ядро |
| Подсистема обновления среды | доставляет обновления шаблона в установку пользователя | ядро |
| Подсистема доступа к знаниям платформы | получает для агента документы паков и личных знаний | ядро |
| Подсистема контроля ясности ответа | проверяет ответы агента пользователю на понятность | по выбору |
| Подсистема сбора личных данных | собирает данные о событиях (здоровье, сон) из сервисов пользователя | по выбору |
| Подсистема представления состояния работы | показывает пользователю состояние рабочих продуктов в редакторе | по выбору |
| Подсистема учёта времени | отмечает время работы пользователя в рантайме и в редакторе | по выбору |

«Ядро» — подсистема есть в любой установке по шаблону; «по выбору» — подключается пользователем.

Инструкции, память, протоколы и паки — описания; описания скиллов хранят файлы SKILL.md (документы). Подсистемами и модулями они не являются: это то, с чем работают подсистемы.

## 5. Модули

Модуль — то, что запускается или работает: конкретная программа, служба, хранилище. Имя модуля называет конструкцию. Файлы и каталоги, которые модуль читает или пишет, — документы; они названы в отдельном столбце. Пометки: (ш) — есть в шаблоне IWE; (а) — только в установке автора.

| Модуль | Чем хранится или настраивается | Интерфейсы | Чем заменяется при том же интерфейсе | Где есть |
|---|---|---|---|---|
| CLI-рантайм агента: Claude Code CLI (ш); варианты — Codex CLI, Kimi CLI, Hermes | файлы настройки рантайма | события для хуков, инструменты, клиент MCP, обращение к модели | другим рантаймом с теми же событиями и клиентом MCP | ядро |
| Программы-хуки рантайма `.claude/hooks/*.sh` (ш) | файлы хуков, их регистрация в настройках рантайма | события рантайма (старт сессии, ввод, вызов инструмента, остановка) | хуками другого рантайма; при смене рантайма их переписывают (DP.D.056) | ядро |
| Программы-скрипты IWE на bash и Python `scripts/` (ш) | файлы скриптов | командная строка, файлы, git | любыми программами с тем же входом и выходом | ядро |
| Системный планировщик ОС: таймеры systemd на Linux, launchd на macOS (ш) | описания заданий и таймеров | запуск скриптов по времени | другим планировщиком ОС или облачным | ядро |
| Файловая система ОС с git (ш) | рабочие копии репозиториев; каталоги состояния среды выполнения (журналы, отметки сессий, квитанции) | файлы, git | другой файловой системой или хранилищем с git | ядро |
| Программа изолированной публикации `isolate-push.sh` (ш) с очередью `ds-publish.sh` (а) | файлы очереди и квитанций | отправка коммитов через изолированную копию и очередь | другой программой публикации или прямой отправкой при одном агенте | ядро |
| Программа учёта сессий `session-guard.sh` (ш) | файлы отметок открытых сессий | командная строка, вызовы из хуков | другой программой разграничения правок | ядро |
| Служба `local-gateway` на Node.js (а; DP.IWE.005) | файлы настройки | MCP | прямым подключением рантайма к шлюзу платформы | по выбору |
| Python-программы синхронизации с сервисами пользователя, по расписанию (а) | файлы программ, учётные данные сервисов | интерфейсы сервисов, файлы | другими программами синхронизации | по выбору |
| Расширение VS Code `iwe-wp-panel` с фоновой программой (а) | файлы расширения | редактор, карточки и реестр | другим расширением или представлением тех же карточек | по выбору |
| Расширение учёта времени для редактора (например, WakaTime для VS Code) | файл настройки | редактор, сервис учёта времени | другим расширением учёта времени | по выбору |

**Хуки и скрипты — классы модулей.** Каждая программа-хук и каждый скрипт — отдельный модуль; здесь они сгруппированы, потому что заменяются по одному правилу. Перечень скриптов — каталог скриптов шаблона (`docs/scripts-catalog.md`), перечень хуков — их регистрация в настройках рантайма. Поэтому в §8 эти две строки стоят у многих подсистем: работают разные программы класса.

Имя модуля может совпадать по смыслу с именем роли (учёт сессий, публикация): имя модуля называет программу, роль — вклад в работу.

## 6. Системы окружения

Системы окружения — внешние системы: они вне IWE, но IWE с ними взаимодействует. Их указывают по двум причинам: без них часть подсистем не работает, и они задают интерфейсы, к которым подключаются модули IWE. Граница IWE проходит между её модулями и этими системами.

**Тест:** уберите систему окружения — что перестанет работать в IWE? Если ничего, её незачем указывать.

| Система окружения | Как IWE с ней взаимодействует | Что перестанет работать без неё |
|---|---|---|
| Пользователь | работает с IWE через рантайм агента, редактор и сообщения | всё: у IWE нет задач |
| Модель вендора | CLI-рантайм обращается к ней за каждым шагом работы | подсистема исполнения работы и все, что работают через агента |
| Шлюз знаний платформы | рантайм или служба `local-gateway` обращается по MCP | подсистема доступа к знаниям платформы |
| Хостинг репозиториев (например, GitHub) | git; репозитории — ресурс пользователя | публикация и обмен между машинами; учёт работы остаётся локальным |
| Сервис учёта времени (например, WakaTime) | хук и расширение редактора передают отметки | подсистема учёта времени |
| Сервисы личных данных пользователя (например, данные сна и здоровья) | программы синхронизации получают данные | подсистема сбора личных данных |

## 7. Размещение

| Место | Что там |
|---|---|
| Машины пользователя (свои или арендованные) | все модули IWE |
| У вендора | модели (системы окружения) |
| Облако платформы | шлюз знаний платформы (система окружения) |
| Облако пользователя | ресурсы пользователя в системах окружения: удалённые репозитории, учётные записи сервисов |

## 8. Соответствия: функциональные подсистемы → модули

Агент — запущенный CLI-рантайм, который обращается к модели и работает по инструкциям.

| Функциональная подсистема | Модули |
|---|---|
| Исполнения работы | CLI-рантайм агента |
| Предъявления инструкций и памяти | CLI-рантайм, программы-хуки, файловая система с git |
| Маршрутизации знаний | CLI-рантайм (агент работает по правилам маршрутизации), программы-хуки (проверка при записи нового файла) |
| Защиты секретов и личных данных | программы-хуки (блок и маскирование), программы-скрипты (сканеры, проверка перед коммитом), программа изолированной публикации |
| Контроля реестров | программы-скрипты (проверки расхождений), системный планировщик |
| Фоновых работ | системный планировщик, программы-скрипты, файловая система с git |
| Проверки установки | CLI-рантайм (агент по описанию скилла аудитора), программы-скрипты (аудит) |
| Учёта работы | программы-скрипты, файловая система с git, программа изолированной публикации, программа учёта сессий |
| Координации агентов | файловая система с git, программа изолированной публикации, программа учёта сессий |
| Обновления среды | программы-скрипты, системный планировщик |
| Доступа к знаниям платформы | CLI-рантайм, служба `local-gateway` |
| Контроля ясности ответа | программы-хуки |
| Сбора личных данных | Python-программы синхронизации, системный планировщик |
| Представления состояния работы | расширение VS Code `iwe-wp-panel` |
| Учёта времени | программы-хуки (время в рантайме), расширение учёта времени для редактора (время в редакторе) |

Подсистема защиты секретов держится на трёх модулях; программы-скрипты работают на шесть подсистем.

## 9. Как добавить или расширить функциональную подсистему

1. Проверить по §4, не относится ли новая возможность к существующей подсистеме. Если относится — расширить её, новую не заводить.
2. Выбрать, на каких модулях её реализовать, по моменту, когда подсистема должна сработать: на событии агента — программа-хук; по вызову или перед коммитом — скрипт; по времени — системный планировщик со скриптом; при отправке в систему окружения — программа изолированной публикации. Новый модуль нужен, только если ни один не даёт нужного момента или интерфейса.
3. Добавить строку в §8, а при новом модуле — в §5 и §7.

Пример: проверка секретов перед публикацией расширяет подсистему защиты секретов и личных данных; момент — отправка в хостинг репозиториев, значит модуль — программа изолированной публикации; новый модуль не нужен.

## 10. Что перестаёт работать при отключении модуля

| Отключённый модуль | Какие функциональные подсистемы перестают работать |
|---|---|
| CLI-рантайм агента | исполнения работы, предъявления инструкций и памяти, маршрутизации знаний, проверки установки, доступа к знаниям платформы; фоновые работы по расписанию продолжаются |
| Программы-хуки | предъявления инструкций и памяти по событиям, защиты секретов на событиях, маршрутизации при записи, контроля ясности ответа, учёта времени в рантайме |
| Программы-скрипты | защиты секретов перед коммитом, контроля реестров, фоновых работ, проверки установки, учёта работы, обновления среды |
| Системный планировщик | фоновых работ, регулярного контроля реестров, обновления среды по расписанию, сбора личных данных; работа в сессиях идёт |
| Файловая система с git | все подсистемы: модулям негде читать и писать документы |
| Программа изолированной публикации | публикации коммитов, координации агентов, защиты секретов при публикации |
| Программа учёта сессий | учёта работы и координации агентов: параллельные агенты перестают разграничивать правки |
| Служба `local-gateway` | доступа к знаниям платформы через локального посредника; прямое подключение рантайма остаётся |
| Python-программы синхронизации | сбора личных данных |
| Расширение VS Code `iwe-wp-panel` | представления состояния работы |
| Расширение учёта времени для редактора | учёта времени в редакторе |

Если пропали сами документы инструкций и памяти (модули на месте), подсистема исполнения работы остаётся, но агент работает с базовым контекстом: протоколы, скиллы и роли не применяются. Последствия отключения систем окружения — в §6.

| DP.IWE.009 «Контур IWE» | граница полного контроля пользователя | то же различение — «модули IWE / системы окружения» (§3); само описание этим документом не отменяется |

Нумерация сценариев пака по контурам (L4-Personal и др.) этим документом не меняется.

## 12. Открытые вопросы

- Имя совместной системы «человек + IWE». Кандидат — уже названный в паке экосистемы «железный человек»; «рабочая сессия» по реестру родов ближе к работе этой системы за интервал.
- Род слов «хранилище», «репозиторий», «сервис» остаётся «неоднозначно» — при употреблении называть объект; слова «подсистема» в реестре родов нет.
- Назначение ролей (DP.ROLE.001) модулям.
- DP.IWE.005 «Локальный шлюз» помечен черновиком, хотя модуль уже работает.

## 13. Термины

| Термин | Здесь означает | Где определён |
|---|---|---|
| Функциональная подсистема | часть IWE, выделенная и названная по тому, что она делает для целого | этот документ, §2 |
| Модуль | конкретный конструктивный элемент IWE, названный по конструкции, который можно заменить | этот документ, §2; реестр понятий и родов |
| Агент | запущенный рантайм, обращающийся к модели | реестр понятий и родов |
| Рантайм агента | программа, которая ведёт диалог с моделью и вызывает инструменты | DP.IWE.001 §1, DP.IWE.011 |
| Хук | программа, которую рантайм запускает по событию | реестр понятий и родов |
| Скилл | способность агента; её описание хранит файл SKILL.md | реестр понятий и родов |
| MCP | открытый протокол подключения инструментов и знаний к агенту (Model Context Protocol) | внешний стандарт; применение — DP.IWE.003 |
| Пак | описание предметной области | реестр понятий и родов |
| Экземпляр IWE, установка | одна развёрнутая IWE пользователя | DP.IWE.002 |
| Программа изолированной публикации, служба `local-gateway`, шлюз знаний платформы | три разные системы: отправка коммитов; локальный посредник MCP; общий сервис знаний платформы (система окружения) | §5, §6 |
