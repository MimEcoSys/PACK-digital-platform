# Архитектура IWE (DP.IWE.013)

> **Статус — черновик.** Описание уточняет главное описание IWE (DP.IWE.001). Там IWE описана через пять видов (системы, описания, роли, методы, рабочие продукты), и пять видов читаются как состав. Здесь — устройство IWE как системы. Расхождения с другими описаниями пака собраны в §11.

## 1. Граница

IWE — система. Пользователь — отдельная система вне IWE: он работает с IWE, но в её состав не входит. Совместная работа пользователя и IWE описывается как другая, более широкая система «человек + IWE» (имя — открытый вопрос, §12).

Различение «модули IWE» и «внешние системы, к которым IWE обращается» (§3) заменяет употреблявшееся прежде слово «контур».

## 2. Четыре описания одной системы

| Описание | На какой вопрос отвечает |
|---|---|
| Функции (§4) | что IWE делает; граница функции — по входам и выходам |
| Модули (§5) | из каких заменяемых конструктивных частей IWE устроена |
| Размещение (§7) | где работает каждый модуль и чей это ресурс |
| Соответствия (§8) | какой модуль реализует какую функцию (многие ко многим) |

Это четыре описания одной системы, а не четыре вида её частей. От набора FPF E.17.2 он отличается так: процедурная точка зрения (ОРЗ, конвейеры) остаётся в описаниях методов и здесь не строится; распределение ролей по модулям — после ревизии реестра ролей; размещение добавлено как отдельная точка зрения.

**Подсистема** в этом описании — функциональная подсистема (функция из §4) или модульная (модуль из §5); где слово стоит без уточнения, имеется в виду модуль.

**Модуль** — конструктивная часть системы, которую можно заменить. Это не учебный модуль: запрет пака на дидактические слова («шаг», «урок», «модуль») относится к учебному смыслу.

**Программа** (скрипт и хук — тоже программы) — система, когда её файл запущен на железе. Незапущенный файл программы — документ.

## 3. Модуль IWE и внешняя система

- **Модуль IWE** — в экземпляре IWE есть артефакт его установки или настройки, и замена возможна внутри границы IWE.
- **Внешняя система** — её экземпляр общий для многих; IWE обращается к ней по интерфейсу.

Рантайм агента — модуль IWE, который поставляет вендор: так ядро входит в дистрибутив, хотя пишет его не автор дистрибутива. Рантайм установлен и настроен в экземпляре IWE и заменяется другим рантаймом (Claude Code, Codex, Kimi, Hermes и др., DP.IWE.001 §1). Модель, к которой обращается рантайм, — внешняя система вендора.

## 4. Функции

| Функция | Вход → выход | Где есть |
|---|---|---|
| Исполнение работы агентом | задача + инструкции + память → действия и рабочие продукты | ядро |
| Предъявление инструкций и памяти агенту | документы инструкций и памяти + событие сессии → контекст агента | ядро |
| Маршрутизация знаний | единица знания или артефакт → место хранения | ядро |
| Защита секретов и личных данных | команда, файл, вывод, коммит → блок, маскирование или пропуск | ядро |
| Контроль согласованности реестров | реестры и их копии → сигнал расхождения или блок | ядро |
| Фоновое выполнение и наблюдение | время или событие → запуск работ, сигналы пользователю | ядро |
| Проверка установки | состояние установки → заключение | ядро |
| Учёт работы | сессии, рабочие продукты, коммиты → карточки, реестр, журнал дня | ядро |
| Координация нескольких агентов | параллельные сессии → разграничение правок, изоляция, очередь публикации | ядро |
| Доставка обновлений среды | шаблон → установка пользователя | ядро |
| Доступ к знаниям платформы | запрос агента → документ пака или личных знаний | ядро |
| Контроль ясности ответа пользователю | текст ответа → предупреждение или блок | по выбору |
| Сбор личных данных о событиях | данные внешних сервисов → записи и сводки | по выбору |
| Представление состояния работы | карточки и реестр → панель в редакторе | по выбору |
| Учёт времени работы | активность в редакторе и рантайме → отметки во внешнем сервисе | по выбору |

«Ядро» — функция есть в любой установке по шаблону; «по выбору» — подключается пользователем.

«Предъявление инструкций и памяти агенту» — функция, которую прежде называли экзокортексом. Инструкции, память, протоколы и паки — описания; описания скиллов хранят файлы SKILL.md (документы). Предъявляют их агенту рантайм и хуки (§8).

## 5. Модули

Модуль — то, что запускается: запущенная программа или служба. Файлы и каталоги, которые модуль читает или пишет, — документы; они названы в отдельном столбце.

| Модуль (что запускается) | Чем хранится или настраивается | Интерфейсы | Чем заменяется, если сохранён интерфейс | Где есть |
|---|---|---|---|---|
| Рантайм агента | файлы настройки рантайма | события для хуков, инструменты, клиент MCP, обращение к модели | другим рантаймом с теми же событиями и клиентом MCP | ядро |
| Хуки рантайма — программы, которые рантайм запускает по событию | файлы хуков, их регистрация в настройках рантайма | события рантайма (старт сессии, ввод, вызов инструмента, остановка) | хуками другого рантайма; при смене рантайма их переписывают (DP.D.056) | ядро |
| Скрипты IWE — программы, запускаемые по вызову | файлы скриптов | командная строка, файлы, git | любыми программами с тем же входом и выходом | ядро |
| Планировщик фоновых работ — служба ОС с расписанием | описания заданий и таймеров | вызов скриптов по времени | другим планировщиком ОС или облачным | ядро |
| Файловое хранилище машины — файловая система ОС и git | рабочие копии репозиториев; каталоги состояния среды выполнения (журналы, отметки сессий, квитанции) | файлы, git | другой файловой системой или хранилищем с git | ядро |
| Шлюз публикации — программа | файлы очереди и квитанций | отправка коммитов в хостинг репозиториев через очередь, изолированные копии | другой программой публикации или прямой отправкой при одном агенте | ядро |
| Охранник сессий — программа | файлы отметок открытых сессий | командная строка, вызовы из хуков | другой программой разграничения правок | ядро |
| Локальный шлюз (DP.IWE.005) — служба | файлы настройки | MCP | прямым подключением рантайма к шлюзу платформы | ядро |
| Программы сбора личных данных | файлы программ, учётные данные сервисов | интерфейсы внешних сервисов, файлы | другими программами сбора | по выбору |
| Панель рабочих продуктов — расширение редактора и фоновая программа | файлы расширения | редактор, карточки и реестр | другим представлением тех же карточек | по выбору |

Имя модуля может совпадать с именем роли («Охранник сессий», «Планировщик»): имя модуля называет программу, роль — вклад в работу.

## 6. Внешние системы

| Система | Как IWE обращается |
|---|---|
| Модель вендора | из рантайма агента |
| Шлюз знаний платформы | из рантайма или локального шлюза по MCP |
| Хостинг репозиториев (например, GitHub) | git; репозитории — ресурс пользователя |
| Сервис учёта времени (например, WakaTime) | из хука |
| Внешние сервисы личных данных (например, данные сна и здоровья) | из программ сбора личных данных |

## 7. Размещение

| Место | Что там |
|---|---|
| Машины пользователя (свои или арендованные) | все модули IWE |
| У вендора | модели (внешние системы) |
| Облако платформы | шлюз знаний платформы (внешняя система) |
| Облако пользователя | ресурсы пользователя во внешних системах: удалённые репозитории, учётные записи сервисов |

## 8. Соответствия функция → модули

Агент — запущенный рантайм, который обращается к модели и работает по инструкциям. В таблице он стоит как модуль «рантайм агента».

| Функция | Модули IWE | Внешние системы |
|---|---|---|
| Исполнение работы агентом | рантайм агента | модель вендора |
| Предъявление инструкций и памяти | рантайм, хуки, файловое хранилище | — |
| Маршрутизация знаний | рантайм (агент работает по правилам маршрутизации), хуки (проверка при записи нового файла) | — |
| Защита секретов и личных данных | хуки (блок и маскирование), скрипты (сканеры, проверка перед коммитом), шлюз публикации | — |
| Контроль согласованности реестров | скрипты (проверки расхождений), планировщик | — |
| Фоновое выполнение и наблюдение | планировщик, скрипты, файловое хранилище | — |
| Проверка установки | рантайм (агент по описанию скилла аудитора), скрипты (аудит) | — |
| Учёт работы | скрипты, файловое хранилище, шлюз публикации, охранник сессий | хостинг репозиториев |
| Координация нескольких агентов | файловое хранилище, шлюз публикации, охранник сессий | — |
| Доставка обновлений среды | скрипты, планировщик | хостинг репозиториев |
| Доступ к знаниям платформы | рантайм, локальный шлюз | шлюз знаний платформы |
| Контроль ясности ответа | хуки | — |
| Сбор личных данных о событиях | программы сбора, планировщик | внешние сервисы личных данных |
| Представление состояния работы | панель рабочих продуктов | — |
| Учёт времени работы | хуки | сервис учёта времени |

Одна функция держится на нескольких модулях (защита секретов — на трёх), один модуль работает на несколько функций (скрипты — на шесть).

## 9. Как добавить функцию

1. Назвать функцию по входу и выходу и проверить по §4, нет ли её уже.
2. Выбрать модуль по моменту, когда функция должна сработать: на событии агента — хук; по вызову или перед коммитом — скрипт; по времени — планировщик со скриптом; при отправке во внешнюю систему — шлюз публикации. Новый модуль нужен, только если ни один не даёт нужного момента или интерфейса.
3. Добавить строки в §4 и §8, а при новом модуле — в §5 и §7.

Пример: проверка секретов перед публикацией — функция «Защита секретов и личных данных»; момент — отправка во внешнюю систему, значит модуль — шлюз публикации; новый модуль не нужен.

## 10. Что перестаёт работать при отключении

| Что отключено | Последствие |
|---|---|
| Документы инструкций и памяти пропали | рантайм работает, но агент получает базовый контекст без правил и памяти: протоколы, скиллы и роли не применяются |
| Хуки отключены, документы на месте | агент может прочитать документы сам, но они не предъявляются по событиям; проверки при записи, защита секретов на событиях и контроль ясности ответа не работают |
| Планировщик остановлен | фоновое выполнение, регулярный контроль реестров и сбор личных данных прекращаются; работа в сессиях идёт |
| Шлюз знаний платформы недоступен | доступа к знаниям платформы нет; локальная работа идёт |

## 11. Расхождения с другими описаниями пака

| Описание | Как там | Как здесь |
|---|---|---|
| DP.IWE.001 | IWE — среда, «в которой человек думает»; пять видов, включая роли и рабочие продукты | пользователь вне IWE; роли и рабочие продукты — не части IWE; виды заменены четырьмя описаниями (§2) |
| DP.IWE.009 «Контур IWE» | граница полного контроля пользователя | то же различение — «модули IWE / внешние системы» (§3); само описание этим документом не отменяется |
| DP.IWE.010 «Машина IWE» | совокупность ресурсов: устройства, хранилища, репозитории, резервные копии, в том числе удалённые | машины пользователя (§7, первая строка) и ресурсы пользователя во внешних системах (четвёртая строка); Машина шире первой строки |
| DP.D.095 | граница IWE и платформы — по тому, кто управляет экземпляром; скиллы, скрипты, правила после развёртывания относятся к IWE | вопрос другой: здесь граница системы IWE по модулям; описания не называются частями IWE, их хранят документы в файловом хранилище |
| DP.IWE.003 | IWE — «репозиторий + шлюз + протоколы» | репозиторий хранит документы, протоколы — описания; модули — §5 |

Нумерация сценариев пака по контурам (L4-Personal и др.) этим документом не меняется.

## 12. Открытые вопросы

- Имя совместной системы «человек + IWE». Кандидат — уже названный в паке экосистемы «железный человек»; «рабочая сессия» по реестру родов ближе к работе этой системы за интервал.
- Род слов «хранилище», «репозиторий», «сервис» остаётся «неоднозначно» — при употреблении называть объект.
- Назначение ролей (DP.ROLE.001) модулям.
- DP.IWE.005 «Локальный шлюз» помечен черновиком, хотя модуль уже работает.

## 13. Термины

| Термин | Здесь означает | Где определён |
|---|---|---|
| Агент | запущенный рантайм, обращающийся к модели | реестр понятий и родов |
| Рантайм агента | программа, которая ведёт диалог с моделью и вызывает инструменты | DP.IWE.001 §1, DP.IWE.011 |
| Хук | программа, которую рантайм запускает по событию | реестр понятий и родов |
| Скилл | способность агента; её описание хранит файл SKILL.md | реестр понятий и родов |
| MCP | открытый протокол подключения инструментов и знаний к агенту (Model Context Protocol) | внешний стандарт; применение — DP.IWE.003 |
| Пак | описание предметной области | реестр понятий и родов |
| Экземпляр IWE, установка | одна развёрнутая IWE пользователя | DP.IWE.002 |
| Шлюз публикации, локальный шлюз, шлюз знаний платформы | три разные программы: отправка коммитов; локальный посредник MCP; общий сервис знаний платформы | §5, §6 |
