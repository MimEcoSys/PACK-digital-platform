# Проводник — DP.ROLE.013

> ⚠️ **НЕ доменная роль. Это технический исполнитель (механика открытия доступа).**
> Проводник не ведёт человека и не общается с ним — он лишь переключает видимость кнопок/команд/скиллов по сигналу «условия открытия достигнуты». Разговорную функцию входа (T0/T1 Q&A) поглотил Онбордер (DP.ROLE.067, WP-406 Ф7); устаревшее conversational-обещание — DP.SC.169.
> **Не путать с Онбордером:** Онбордер = содержательная ось (понимание сообщества, выбор траектории), работает до «Стажёра». Проводник = техническая ось (доступ по тирам), работает всю жизнь пользователя при каждом переходе T1→T4. Тест «Скрипт ≠ Агент» (DP.D.048): убери ИИ — Проводник не сломается (детерминированный апдейт по сигналу), значит это механика, а не агентская роль.
>
> **Kind:** FSM State Updater Role — реактивный апдейтер доступного функционала. Получает событие, обновляет состояние, нотифицирует потребителей через channel-mentions (DP.SC.118) или direct FSM push.
> **Owner Role:** IWE Platform — исполнитель: бот (aiogram FSM), VS Code (skill manifest), web-ридер (feature flags).

## 1. Миссия

Сделать так, чтобы пилот видел **только тот функционал, который ему доступен прямо сейчас**, и получал его автоматически при достижении условий — без ручного включения оператором.

Аналогия: проводник в театре, который открывает двери в следующий зал, когда зритель осмотрел текущий. Не решает, готов ли зритель (это Контролёр) — только открывает дверь.

## 2. Контекст

Пилот проходит путь Т1→Т4 (WP-342, WP-343). На каждом переходе открывается новый функционал:
- T1→T2: `/connect`, браузер-интерфейс
- T2→T3: персональное руководство (`/personal-guide-start`, web-ридер)
- T3→T4: полное окружение (VS Code, все скиллы, ритуалы)

Без Проводника бот показывает все команды сразу (или жёстко фильтрует по tier) — оба варианта плохи:
- «Все сразу» → перегрузка, пилот теряется
- «Жёсткий отказ» → фрустрация, непонимание почему недоступно

Проводник решает это через **постепенное открытие** (progressive disclosure) с **мягким предупреждением** (soft-warning): «Вот где вы → вот что нужно → первый шаг».

## 3. Обязанности

| # | Обязанность | Артефакт-следствие |
|---|-------------|---------------------|
| 3.1 | Получить сигнал от Контролёра об открытии функционала | Подписка на `domain_event` типа `onboarding_msg_sent` или direct call от DP.ROLE.046 |
| 3.2 | Обновить FSM состояние пилота (`learning.onboarding_state.level` и флаги `first_use_*`) | Пилот переходит на следующий tier |
| 3.3 | Апдейтить доступные команды бота (inline-кнопки, slash-команды) | Бот показывает `/connect` после msg_5, `/personal-guide-start` после msg_7 |
| 3.4 | Апдейтить доступные скиллы VS Code | Пилот видит новые скиллы в `.claude/skills/` после перехода |
| 3.5 | При запросе недоступной команды — мягкое предупреждение (soft-warning) | «Команда `/personal-guide-start` откроется после подписки и 7 дней активности. Сейчас — шаг 1: /slot» |
| 3.6 | Логировать все FSM-апдейты в `domain_event` | Аудит доступности, метрики «время открытия функционала» |

## 4. Что НЕ делает Проводник

- **Не принимает решение о готовности** — это Контролёр (DP.ROLE.046)
- **Не оценивает ступень** — это Аттестатор (DP.ROLE.041) и Диагност (DP.ROLE.042)
- **Не отправляет нуджи** — это Notification Dispatcher (DP.ROLE.044)
- **Не рендерит контент** — это Портной (DP.ROLE.030)
- **Не учит** — это Портной и Навигатор (MIM.R.007)

## 5. Интерфейсы (каналы апдейта)

| Канал | Как апдейтится | Пример |
|-------|---------------|--------|
| Бот (TG) | Inline-кнопки + tier-guard на handlers | `_personal_guide_button()` появляется при `level ≥ 3` |
| VS Code | Skill manifest refresh | Новые скиллы появляются в `.claude/skills/` при `level ≥ 4` |
| Web-ридер | Feature flags по `pilot_uuid` | Раздел «Рефлексии» открывается при `first_use_guide_render = true` |
| Browser (claude.ai) | MCP tool availability | `personal_write` доступен только при `level ≥ 3` |

## 6. Сигналы-триггеры (от Контролёра)

| Сигнал | Условие открытия | Что открывает |
|--------|-----------------|---------------|
| `open_connect` | msg_5 sent (`slot_count ≥ 2` or `activity_days ≥ 3`) | Кнопка `/connect`, браузер-интерфейс |
| `open_guide` | msg_7 sent (`has_subscription` and `activity_days ≥ 7`) | `/personal-guide-start`, web-ридер URL |
| `open_full_env` | msg_9 sent (`first_use_guide_render` and `activity_days ≥ 14`) | VS Code setup, все скиллы, ритуалы |
| `soft_warn` | Команда выше тира | Мягкое предупреждение с указанием шага |

## 7. Режим отказа

- Контролёр не отправил сигнал → функционал не открывается (safe-fail)
- Бот недоступен → FSM-апдейт записан в БД, бот подхватит при следующем взаимодействии
- Пилот запросил команду выше тира → soft-warning (не отказ), метрика записана

## 8. Метрики наблюдаемости

| Метрика | Источник | Цель |
|---------|----------|------|
| `conductor.fsm_updates_total` | `domain_event` | Кол-во апдейтов в сутки |
| `conductor.soft_warn_total` | `domain_event` (тип `tier_mismatch_soft_warn`) | Частота запросов выше тира |
| `conductor.time_to_open{feature}` | `onboarding_state` timestamps | Время от сигнала до фактического открытия |
