# Мейнтейнер скиллов — DP.ROLE.056

> **Kind:** Governance Role — управляет платформенным артефактом (каталог + стандарт), не исполняет работу.
> **Owner Role:** IWE Platform Developer (автор дистрибутива).

---

## 1. Миссия

Обеспечить, что скилл-система IWE как дистрибутив остаётся:
- **обнаружимой** — каталог актуален, каждый скилл имеет стандартный frontmatter
- **безопасной** — обновление L1-скиллов не ломает L3-кастомизации пользователей
- **эволюционирующей** — скиллы создаются по стандарту, устаревшие помечаются, граф зависимостей строится

**Граница:** Мейнтейнер НЕ:
- пишет содержимое скиллов (это Автор скилла DP.ROLE.057)
- принимает архитектурные решения о том, зачем нужен новый скилл (это ArchGate / Стратег)
- вызывает скиллы в работе (это исполнительные роли)

---

## 2. Обязанности

| Обязанность | Инструмент | Частота |
|------------|-----------|---------|
| Актуализировать `skills-catalog.yaml` | `generate-skills-catalog.sh` | При каждом promote |
| Принять решение о promote L3→L1 | Критерии: SKILL.md v2 + smoke-test + DP.SC | По запросу Автора |
| Поддерживать обратную совместимость | Версионирование + `depends_on` граф | При обновлении L1-скилла |
| Управлять состояниями скилла | `status: deprecated` + `sunset:` | При устаревании |
| Рецензировать новые скиллы | Чеклист IntegrationGate для скиллов | Перед promote |

---

## 3. Права

- Устанавливать `status: deprecated` для L1-скиллов
- Блокировать promote если критерии не выполнены
- Определять политику merge L1↔L3 при `iwe-update`

---

## 4. Критерии готовности скилла к promote (L3→L1)

Все четыре одновременно:
1. `validate-skill.sh` возвращает exit 0 (SKILL.md v2, все обязательные поля)
2. Smoke-test выполнен (скилл вызван хотя бы один раз, работает как ожидается)
3. DP.SC существует (ссылка на DP.SC.NNN в SKILL.md или использование DP.SC.153)
4. `depends_on` декларирует все фактические зависимости
