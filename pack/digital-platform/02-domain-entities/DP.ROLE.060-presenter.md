# DP.ROLE.060 — R60 Презентатор

> **Kind:** Personal Editorial Role (личная роль публичного выступления).
> **Owner Role:** Автор контента (Tseren) — он же исполнитель роли на L3-Personal.
> **Исполнители:** Tseren (вручную) или Claude/Kimi (как субагенты при подготовке слайдов и review).

## 1. Миссия

Обеспечить единый, узнаваемый стиль публичных выступлений IWE/MIM: от структуры слайдов до подачи. Снизить когнитивную нагрузку подготовки за счёт формализованного каркаса, стилевых правил и воспроизводимого процесса.

**Граница:** Презентатор — не автор контента (идеи приходят от Автора), не публикатор (пост-обработка и выкладка — в R21 Публикатор постов клуба, embedded-роль DP.ROLE.001). Презентатор переводит идеи в форму публичного выступления.

## 2. Вход → Выход

- **Вход:** тема, событие, аудитория, слот (время), brief от Автора (опционально — суперзадача), **контент-бриф** (WP-480 — сегмент/тон из карты ЦА + продуктивный/непродуктивный мем из SA.CAT.001, если тема прошла через `topic-log.yaml`).
- **Выход:**
  - Marp MD + PDF — слайды по стилевому гайду
  - Запись репетиции (notes / video)
  - Проведённое выступление
  - Пост-отчёт (что сработало, что нет)
  - Pre-deck / post-deck пакет (PDF + 3 тезиса + 1 цитата) → Публикатор постов клуба

## 3. Обязанности

| Обязанность | Метод | Триггер |
|-------------|-------|---------|
| Прочитать контент-бриф (сегмент/тон + мем) | WP-480 контракт, если тема имеет `topic-log.yaml` запись | До подготовки слайдов |
| Подготовить слайды (Marp MD) | Шаблон §A + правила §B–E | Заявка на доклад принята |
| Провести репетицию | Параметризованный прогон §D.3 | За 3–7 дней до выступления |
| Провести выступление | По согласованному сценарию | Дата события |
| Пост-обработка | Запись → выкладка → краткий отчёт | В течение 3 дней после |
| Подготовить pre-deck / post-deck | PDF + 3 тезиса + 1 цитата §D.4 | Согласно сценарию события |
| Обновить стилевой гайд | Если найден новый паттерн — зафиксировать в WP-249 | После каждого выступления |
| Убрать ИИ-сленг | Vale + метод обратного перевода §C.8 | Перед review слайдов |

## 4. Полномочия

- **Читает** `DS-Tseren-Brand/content/posts/D-NNN-*.md`, `DS-Knowledge-Index-Tseren/docs/` и `WP-249` (read-only).
- **Пишет** в `talks/YYYY-MM-event-slug/` (Marp MD, PDF, notes).
- **Запрашивает review** у Автора (Tseren) или Редактора (DP.ROLE.033).
- **Не меняет** суть идеи без согласования с Автором.
- **Не публикует** посты в соцсети (это R21 Публикатор постов клуба, embedded-роль DP.ROLE.001).
- **Фиксирует** найденный ИИ-сленг в расширяемый реестр штампов.

## 5. Границы роли

| Делает | НЕ делает |
|--------|-----------|
| Структурирует идею в слайды | Не генерирует идею с нуля (Автор) |
| Следует стилевому гайду | Не публикует пост-выступление (Публикатор постов клуба) |
| Проводит репетицию и выступление | Не редактирует контентные черновики |
| Фиксирует обратную связь | Не архивирует записи без согласования |
| Готовит pre-deck / post-deck сырьё | Не форматирует посты (Публикатор постов клуба) |
| Убирает ИИ-сленг из текста | Не заменяет Автора при создании смысла |

## 6. Стилевой гайд презентации (v2)

> Полная версия: `WP-249` + `feedback_writing.md` правило 12.  
> Этот раздел — нормативный артефакт роли. Любое выступление IWE/MIM следует ему, если не оговорено иное.

### A. Композиция (структурный каркас A1–A7)

**A1. Титульный слайд.**
- **Название** (h1) — крупно, ≤6 слов, формулирует ценность или приглашение
- **Подзаголовок** (h2, ~1.5em) — расшифровка названия в одну строку
- **Автор** (`.author`, ~1.15em) — «Имя Фамилия, должность»
- **Событие** (`.event`) — абсолютно позиционированный нижний колонтитул («Конференция X · Месяц Год»)
- Антипаттерн: событие в шапке (перетягивает внимание с темы)

**A2. Слайд «Наш продукт» (обязательный, 2-й или 3-й).**
- Три колонки либо две зоны: **ценность сверху** (что растим) + **инструменты снизу** (чем растим)
- Явное различение продукта (ценность) и средств (среда, методология, платформа, сообщество)
- Финальная плашка: formula-строка («Продукт — X. Инструмент — Y.»)

**A3. Слайд-диагностика (почему это важно сейчас).**
- Цивилизационная рамка: аналогия из прошлого (ПК 1985 → ИИ 2025)
- Персональный уровень: что меняется у конкретного человека
- Противопоставление: «старый способ vs новый способ»

**A4. Слайд-доказательство (статистика работы в IWE).**
- Реальные цифры: коммиты, знаки, часы, мультипликатор WakaTime, систем, ролей
- Схема/навалка — визуализация объёма
- Подпись: источник (git log across N repos, WakaTime, SOTA registry)

**A5. Основная часть — N опор/компонент с примерами.**
- Каждый пункт: название + одно предложение + пример из практики
- Примеры конкретные, не абстрактные («WP-XXX, вот артефакт, вот результат»)
- Антипаттерн: перечисление без примеров

**A6. Слайд «Риск печатной машинки» (обязательный в talks про IWE).**
- Антитеза продукту: «Если IWE используется как печатная машинка с ИИ, потенциал не раскроется»
- Три внутренние опоры: системное мировоззрение, культура работы, системное мышление
- Честность: внешние инструменты без внутренней работы не дают результата

**A7. Финал — связка с parallel talks или следующим шагом.**
- Формула повторяется («Продукт — X. Среда — Y.»)
- Цивилизационная рамка замыкает арку (из A3)
- Ссылка на другой talk / статью / приглашение в сообщество

**A8. Слайд-мем из контент-брифа (WP-480, опционально).**
- Если у темы есть `brief` с `productive_meme`: мысль P-NNN (карточка SA.CAT.001) раскладывается в ход презентации — метод мышления показывается в действии на слайде-диагностике A3 или как одна из опор A5. Код мема и каталог со сцены не называются — аудитория видит метод, не артефакт.
- Если задан `unproductive_meme`: ловушка M-NNN — материал для антитезы A6: риск формулируется через неё (как «печатная машинка», но под конкретный сегмент), аудитория распознаёт мем у себя, а не получает нравоучение.
- Нет `brief` — композиция A1–A7 без специальной калибровки.

### B. Верстка и типографика (Marp + CSS)

**B1. Стек:** Marp-based (Markdown + CSS в `<style>` блок). Экспорт PDF. Единственный инструмент для слайд-deck.
**B2. Темные/светлые секции:** переключение через CSS `section { background: ... }`. На тёмных фонах — `!important` для цвета текста.
**B3. Классы слайдов:** `dense` (плотный текст), `large` (крупный акцент), `quote` (цитата/манифест).
**B4. Цвета:** через CSS `section {}`, НЕ через frontmatter. Frontmatter ломает при экспорте.
**B5. Колонтитул с событием:** абсолютное позиционирование (`position: absolute; bottom: ...`), чтобы не занимать контентную область.
**B6. Два размера автора/события:** автор — крупный (1.15em), событие — скромный (колонтитул).

**B7. Типографические правила (новое):**
- **Правило третей:** контентная область делится на 9 частей. Ключевой тезис (h1/h2) — на пересечении верхних линий. Убирает центрирование по умолчанию.
- **Иерархия через размер, не через цвет:** h1 > h2 > body > caption. Цвет — для смыслового кодирования (продукт vs инструмент), не для иерархии.
- **White space:** не более 60% площади слайда под текст/схемы. 40% — поля и просветы. Антипаттерн: `dense` класс, который забивает слайд до краёв.

**B8. Схемы:** Excalidraw (VS Code extension) для черновых схем на этапе формулы. Экспорт SVG → встраивание в Marp. Napkin — не использовать (внешний SaaS, нет версионирования).

**B9. Проверка PDF:** `tomoki1207.pdf` (VS Code extension) для preview готового PDF без выхода из IDE. Проверка page breaks и шрифтов перед pre-deck.

### C. Язык и тональность

**C1. Формула вместо описания.** «Продукт — X. Среда — Y.» работает лучше, чем «Наш продукт состоит из X, Y, Z».
**C2. Цивилизационная рамка.** Любой тезис проверяем: «что меняется для одного человека?». Не ограничиваться рынком/компанией.
**C3. Тезисный зачин слайда.** Первая строка — ключевая мысль, без раскачки (как в правиле 8 feedback_writing).
**C4. Противопоставления работают лучше списков.** «X — это одно. Y — другое.» лучше, чем «X и Y — это…»
**C5. Личный опыт как доказательство.** Статистика «сделано в моей IWE за N месяцев» сильнее абстрактных обещаний.
**C6. Доменный словарь без кавычек:** экзоскелет, агентность, мастерство, среда, созидатель. Каждое слово имеет строгое определение в Pack.
**C7. Риск-трезвость.** Честно назвать антипаттерн (печатная машинка) — сильнее, чем скрывать.

**C8. Правило C9 (анти-ИИ-сленг):**
- Любое абстрактное существительное в презентации должно иметь конкретный пример из практики в скобках или на следующем слайде. Пример: не «экосистема из 7 инструментов», а «7 инструментов, связанных одним потоком данных».
- Если пример не находится — слово заменяется.

**C9. Уборка ИИ-сленга — три слоя:**
1. **Vale** (локально, pre-commit hook) с кастомным словарём антипаттернов. Ручной grep-чеклист как fallback для спонтанных сессий.
2. **Метод обратного перевода:** ИИ-текст → пересказ простыми словами (как объяснение коллеге за обедом) → проверка на потерю смысла. Если смысл искажается — в оригинале был сленг.
   - Ownership: self-check для текста пилота; peer-check (Claude/Kimi) для ИИ-сгенерированного текста.
3. **Расширяемый реестр штампов:** markdown-файл в pack со списком запрещённых слов + предлагаемыми заменами. Peer дополняет реестр при каждом review.

**Типичные штампы (неполный список):** погружение, трансформация, экосистема, синергия, инновационный, парадигма, комплексный подход, масштабируемое решение, холистичный, глубокая интеграция, платформа (в значении среды), модуль (вместо часть), оптимизация (вместо ускорение), практика (в значении «то, что мы делаем»).

### D. Процесс создания презентации

**D1. Сначала формула — потом слайды.** До верстки — одна строка «Продукт — X. Среда — Y.». Если не формулируется — стоп, презентация не готова к созданию.
- Подпункт: **empathy map аудитории** (интегрирована в D1): перед формулой ответить на три вопроса — что они делают сейчас, что их бесит, что они скажут другу через неделю.
- Подпункт: **контент-бриф** (WP-480, опционально): если у темы есть блок `brief` в `topic-log.yaml` — сегмент `audience` задаёт тон словаря до выбора примеров empathy map: A2 (ИТ-профессионал) → технический словарь допустим; C (тёплая база) → больше личного контекста, меньше жаргона. Нет `brief` — калибровка по общей empathy map.

**D2. Две презентации — одна формула.** Если есть parallel talks, общая формула обязательна. Проверка связки.

**D3. Итерации через диалог.** Пользователь правит по одному слайду: «слайд 5 не влезает», «слайд 10 среднюю колонку». Дешевле, чем переделывать массив.

**D4. Капитальный ремонт рамки допустим.** Если в середине работы обнаружено смешение уровней (продукт vs инструмент) — откатиться и переформулировать обе презентации, не дожидаясь окончания.

**D5. Титульный слайд — последним.** Когда контент зафиксирован, легче подобрать финальное название.

**D6. Репетиция (параметризована длительностью):**
- **≤ 10 мин:** 1 прогон с таймером.
- **11–20 мин:** 2 прогона (таймер + живой слушатель).
- **> 20 мин:** 3 прогона (таймер + камера + живой слушатель).

**D7. Pre-deck (сценарий-зависим):**
- **Конференция / внешнее выступление:** PDF за 24ч до события (pre-read).
- **Клуб / внутренний sync:** deck on demand, pre-read опционален.

**D8. Post-deck:**
- Презентатор передаёт в канал **сырой пакет**: PDF + 3 тезиса + 1 цитата.
- Форматирование в пост — роль Публикатор постов клуба (WP-155). Презентатор не верстает пост.

**D9. Чеклист обратной связи (объективные критерии):**
1. Понятна ли формула «Продукт — X. Среда — Y.» после первого прочтения?
2. Видна ли структура (A1–A7) без подсказок?
3. Есть ли слайд, который вызывает желание переспросить?
4. Достаточно ли контрастен слайд A6 (антитеза «печатной машинки»)?
5. Каждое абстрактное существительное имеет конкретный пример из практики (C9) — да/нет?

### E. Антипаттерны

- Продукт = инструмент (смешение ценностного и инструментального уровней)
- Титульный слайд: событие крупнее автора (перетягивает внимание)
- Перечисление компонент без примеров из практики
- Шесть опор IWE без финального слайда «и этого недостаточно без внутренней работы»
- Завышенные заявления без доказательств («продуктивность 2x», «100% воспроизводимость»)
- Визуальные метафоры, которые ломаются при проверке («Ubuntu для ИИ» — Ubuntu бесплатный)
- ИИ-сленг без примера из практики (C9)
- Слайд, забитый текстом до краёв (white space < 40%)
- Центрирование по умолчанию (нарушение правила третей)

## 7. Сценарии использования роли (≥4)

### Сц-1: Конференция (20–45 мин)
- **Триггер:** Приглашение на конференцию (МИМ, внешняя)
- **Структура:** Полный каркас A1–A7 + Q&A
- **Pre-deck:** PDF за 24ч (обязательно)
- **Репетиция:** 3 прогона (>20 мин)
- **Post-deck:** PDF + 3 тезиса + 1 цитата → Публикатор постов клуба

### Сц-2: Клуб IWE (15–30 мин)
- **Триггер:** Регулярный клубный день
- **Структура:** Сокращённый: A1 + A2 + A3 + A5 (2–3 опоры) + A6 + A7
- **Pre-deck:** on demand (опционально)
- **Репетиция:** 2 прогона (11–20 мин)
- **Post-deck:** 3 тезиса текстом в канал

### Сц-3: Инвесторы (5–10 мин)
- **Триггер:** Питч или демо
- **Структура:** A1 + A2 (продукт + метрики) + A4 (доказательство) + A7 (CTA)
- **Pre-deck:** PDF за 24ч (если запланировано) или deck on demand (спонтанно)
- **Репетиция:** 1 прогон (≤10 мин)
- **Post-deck:** 1 тезис + ссылка на deck

### Сц-4: Внутренний sync / команда (10–15 мин)
- **Триггер:** Внутреннее совещание, статус-апдейт
- **Структура:** A1 + A3 (диагностика текущей ситуации) + A5 (1–2 опоры) + A7 (следующий шаг)
- **Pre-deck:** on demand
- **Репетиция:** 1 прогон (≤10 мин) или 0 (если импровизация по слайдам)
- **Post-deck:** краткий отчёт в канал (2–3 предложения)
