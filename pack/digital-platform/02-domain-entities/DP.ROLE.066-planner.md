# DP.ROLE.066 — Плановик (Planner)

> # see DP.ROLE.012 (Стратег, split-источник), DP.SC.051 (совместный недельный ритуал)
>
> **Kind:** LLM-stateless по in-memory контексту, file-stateful по плановым артефактам
> (`current/WeekPlan`, `current/DayPlan`).
> **Owner Role:** R5 Архитектор IWE.
> **Статус:** draft — наполнен из планировочного контента DP.ROLE.012 (РП378 Ф1).
> Серверная реализация-носитель `agent-runner/planner.txt` — РП378 Ф2.

---

## 1. Миссия

Упаковывать приоритеты месяца (от Стратега R1) в рабочие продукты недели с бюджетами и
распределять их по дням, удерживая WIP-лимит.

**Граница миссии (что Плановик НЕ делает):**
- НЕ ведёт discovery неудовлетворённостей и не ставит приоритеты месяца — это Стратег (R1), WHAT/WHY.
- НЕ делает квартальное/программное планирование — это Навигатор (MIM.R.007).
- НЕ диагностирует ступень мастерства — это Диагност (DP.ROLE.042).

**Граница со Стратегом (R1) — по типу решения, не по артефакту:**

| | Стратег (R1) | Плановик (DP.ROLE.066) |
|---|---|---|
| Что решает | WHAT / WHY | HOW MUCH / WHEN |
| Объекты | НЭП, состояние, цели, приоритеты месяца, системные уровни | бюджеты, WIP, дни недели |
| Корректировка | стратегическая (дропнуть приоритет) | тактическая (переставить РП между днями) |
| Цикл | месяц + рефлексия по запросу | неделя + ежедневно |

## 2. Ключевые понятия (перенесено из DP.ROLE.012 при распаковке)

### 2.1. Рабочий продукт (Work Product)

**Определение:** Артефакт с чёткими критериями готовности, который пользователь намерен создать.

| Атрибут | Описание |
|---------|----------|
| `name` | Название РП |
| `area` | Область знаний (digital-platform, personal, ecosystem) |
| `repo` | Целевой репозиторий |
| `budget` | Бюджет времени (часы) |
| `status` | pending / in-progress / done / blocked |
| `criteria` | Критерии готовности (чеклист) |

### 2.2. Классификация РП по временной природе

| Тип | Определение | Признаки | Триггер выполнения |
|-----|------------|----------|-------------------|
| **Фиксированный (fixed)** | Привязан к дате/событию | Конкретный дедлайн, назначен на день | По расписанию дня |
| **Плавающий (floating)** | По мере возможности | Дедлайн = конец недели, пометка `~floating~` | Свободное время / запрос доп. работы |

**Правила floating:** дедлайн `—` в таблице; ставится на последний день недели; не
включается в план дня (упоминается как доступный); перенос без штрафа к completion rate.

### 2.3. Правило полноты приоритетов дня

**Все РП недели (кроме done) ДОЛЖНЫ быть распределены по дням.** Если РП не назначен —
Плановик ОБЯЗАН спросить: «На какой день поставить РП #N?». **Тест полноты:** число
уникальных РП в расписании по дням = число не-done РП в таблице.

### 2.4. Временные горизонты

| Горизонт | Единица | Источник |
|----------|---------|----------|
| День | РП с бюджетом ≤4h | Из недельного плана |
| Неделя | РП с бюджетом | Из контекста приоритетов (от Стратега) |

## 3. Объект передачи Стратег → Плановик

«Контекст приоритетов» — приоритеты месяца + состояние пилота + системные уровни НЭП
(не голый `monthly-priorities.md`). Плановик имеет право интерпретировать при упаковке.

**Joint weekly ritual (DP.SC.051):** Плановик — ведущий по умолчанию; Стратег
подключается только если приоритеты устарели или состояние пилота изменилось; иначе
Плановик ведёт неделю один.

## 4. Входы

| Источник | Данные |
|----------|--------|
| Контекст приоритетов (от Стратега) | Приоритеты месяца + состояние + системные уровни |
| `WP-REGISTRY.md` + `inbox/WP-*.md` | Активные РП (через `scripts/active-wp-sweep.sh`) |
| Git log (все репо) | Коммиты за период (для week-review) |
| Календарь / факт времени | Загрузка дня (тактическая корректировка) |

## 5. Выходы

| Артефакт | Путь | Описание |
|----------|------|----------|
| План недели | `current/WeekPlan W{N}.md` | РП на неделю + бюджеты + WIP |
| План дня | `current/DayPlan YYYY-MM-DD.md` | РП на день + апдейт вчера |
| Итоги недели | `current/WeekReport W{N}.md` | Факты недели + пост для клуба |

### 5.1. События

| Событие | Когда |
|---------|-------|
| `PLAN.WeekCreated` | После сборки плана недели |
| `PLAN.DayCreated` | После создания плана дня |
| `REVIEW.WeekCompleted` | После недельного ревью |

## 9. Реализация-носитель

**Модель «два фиксатора» (не rename, 2026-06-05):** серверный фиксатор `run_strategist`
сейчас пишет и стратегические файлы (Strategy.md, Dissatisfactions), и плановые (Plan, Day) —
переименование в planner занизило бы его. Решение:
- **`run_strategist`** (сохраняется, не ломается) — фиксатор Стратега: стратегические файлы.
- **`run_planner`** (новый, добавляется) — фиксатор Плановика: `current/WeekPlan`, `current/DayPlan`.

Носитель Плановика = `DS-MCP/agent-runner/src/prompts/planner.txt` (новый промпт) +
MCP-инструмент `run_planner`. Реализация — **в спин-офф РП «серверный discovery-канал»**
(DS-MCP — отдельный деплой-контур + правка production access-control `DEFAULT_AGENT_SCOPES`,
требует своего смоука против прода). Добавление `run_planner` **не ломает** живой
`run_strategist` (claude.ai MCP) — deprecation alias не нужен.
