# Ретранслятор канона (DP.ROLE.081)

> **Kind:** Infrastructure Role (автоматическая, не редакторская — в отличие от R21 Публикатора постов клуба)
> **Owner Role:** Автор источника (per-обещание: `TserenTserenov` для DP.SC.188, авторы `aisystant` для DP.SC.189)

## 1. Миссия

Переносить каждое изменение канона в целевую организацию — без выбора, что публиковать, когда и в каком порядке. Реагирует на каждое сохранение немедленно и одинаково, не курирует поток. Домен роли — доставка проекций канона; конкретный режим доставки (перевод или зеркалирование) задаёт активное обещание (DP.SC.188 / DP.SC.189), не сама роль.

**Мета-критерий успеха роли:** проекция доставлена в целевую организацию в соответствии с активным DP.SC.
**Мета-режим отказа роли:** нарушение контракта активного DP.SC — конкретика (деградация качества перевода vs дивергенция истории при зеркалировании) специфична для режима и описана в соответствующем DP.SC, не в паспорте роли.

## 2. Обязанности

**Режим «перевод» (DP.SC.188):**

| Обязанность | Метод | Триггер |
|------------|-------|---------|
| Перевести изменённые `README.md`/`docs/**` на английский | Дельта-перевод (`translate.py`) | Push в `main` с изменением документации |
| Проверить обязательные термины глоссария перед публикацией | Формальная + содержательная проверка (Tier-1 блокирует, Tier-2/3 предупреждает) | После перевода, перед публикацией |
| Опубликовать переведённый результат как основную ветку `iwesys/iwe-template` | Форс-пуш гейтованной ветки `en-draft` | Успешный перевод + проверка пройдена |
| Явно сигнализировать при недоступности целевого репозитория | Проверка существования репозитория перед публикацией | Целевой репозиторий не создан/недоступен |

**Режим «зеркалирование» (DP.SC.189):**

| Обязанность | Метод | Триггер |
|------------|-------|---------|
| Опубликовать содержимое как есть (без перевода) в парный репозиторий МИМ | Git mirror push | Push в `main` одного из 11 репозиториев `aisystant` |
| Отразить переименования/удаления файлов, не копить «сирот» | Побитовое зеркалирование, не дельта-мердж | После каждого push в источник |
| Требовать подтверждения пилота при первом подключении к непустому МИМ-репозиторию | Bootstrap-approval gate | Первое подключение конвейера к репозиторию |
| Явно сигнализировать при недоступности целевого репозитория | Проверка существования репозитория перед публикацией | Целевой репозиторий не создан/недоступен |

**Режим «манифест» (DP.SC.062, добавлен 20.07.2026):**

| Обязанность | Метод | Триггер |
|------------|-------|---------|
| Перевести (если нужно) и опубликовать ТОЛЬКО явно перечисленные файлы манифеста | Курируемый список путей, не дельта по всему `docs/**` | Push в источник, затрагивающий путь ∈ манифест |
| Не публиковать ничего вне манифеста, даже если оно изменилось | Explicit-allow-list, не directory glob | Каждый прогон |
| Проверить целевой репозиторий против ожидаемого (assert) перед push | Захардкоженный `target_repo` в файле + сверка | Перед публикацией |
| Явно сигнализировать при недоступности целевого репозитория | Проверка существования репозитория перед публикацией | Целевой репозиторий не создан/недоступен |

## 3. Полномочия

- Публикует автоматически, без запроса подтверждения у автора — это часть обещания, не превышение полномочий. **Исключение (DP.SC.189):** первое подключение конвейера к непустому МИМ-репозиторию требует явного подтверждения пилота (Bootstrap-approval gate) — не тихого форс-пуша; для DP.SC.188 такого исключения нет (`iwesys/iwe-template` создаётся пустым).
- Не решает, ЧТО и КОГДА публиковать — публикует всё изменившееся сразу, каждый раз.

## 4. Границы роли

**Режим «перевод» (DP.SC.188):**

| Делает | НЕ делает |
|--------|-----------|
| Переводит изменившуюся документацию | Не переводит и не публикует код/скрипты/конфигурацию |
| Публикует немедленно при каждом push | Не строит расписание, не решает приоритет публикаций (в отличие от R21 Публикатора постов клуба) |
| Сигнализирует явно при сбое/неготовности приёмника | Не адаптирует контент под аудиторию/канал (в отличие от R21 Публикатора постов клуба) |
| Гейтует по глоссарию (Tier-1) | Не редактирует содержание, не принимает решений об оригинале |

**Режим «зеркалирование» (DP.SC.189):**

| Делает | НЕ делает |
|--------|-----------|
| Публикует содержимое как есть, без перевода | Не переводит, не адаптирует контент — побитовая копия |
| Публикует немедленно при каждом push | Не строит расписание, не решает приоритет публикаций (в отличие от R21 Публикатора постов клуба) |
| Сигнализирует явно при сбое/неготовности приёмника | Не адаптирует контент под аудиторию/канал (в отличие от R21 Публикатора постов клуба) |
| Требует подтверждения пилота при первом подключении к непустому приёмнику | Не гейтует по глоссарию — глоссарий относится только к переводу |

## 5. Отличие от R21 Публикатора постов клуба (важно — не путать)

**Публикатор постов клуба (DP.ROLE.001 §R21)** — куратор: сканирует очередь готового контента, решает расписание, публикует по команде или по каденции, адаптирует текст под каждый канал (соцсети, клуб), отслеживает комментарии.

**Ретранслятор канона** — механический перенос: не выбирает, что публиковать (публикует всё изменившееся), не строит расписание (публикует немедленно при каждом push), не адаптирует под аудиторию — переводит по глоссарию в режиме DP.SC.188, копирует побитово без перевода в режиме DP.SC.189. Тест на различение: «эта роль решает, ЧТО и КОГДА показать аудитории, или просто копирует изменение целиком и сразу?» Решает → Публикатор. Копирует (с переводом или без) → Ретранслятор.

## 6. Исполнители

| Исполнитель | Когда | Режим |
|-------------|-------|-------|
| GitHub Actions workflow (`translate-sync.yml`, `TserenTserenov/FMT-exocortex-template`) | Каждый push с изменением документации | Автомат, без участия человека (DP.SC.188) |
| GitHub App `canon-sync` (owner = пилот) | Публикация в другую организацию (`iwesys`) | Автомат, токен per-installation (DP.SC.188) |
| GitHub App `canon-sync` (owner = пилот, установлен также в `aisystant` и МИМ) | Зеркалирование одного из 11 репозиториев в МИМ | Автомат, токен per-installation (DP.SC.189) |

## 7. Артефакты роли

**Режим «перевод» (DP.SC.188):**

| Вход | Выход |
|------|-------|
| Push в `main` с изменением `README.md`/`docs/**` | Ветка `en-draft` (переведённый черновик) в исходном репозитории |
| Гейтованный `en-draft` (0 непереведённых терминов высшей важности) | Основная ветка `iwesys/iwe-template` |
| Недоступный/несуществующий целевой репозиторий | Явное предупреждение в логе прогона (не тихий сбой) |

**Режим «зеркалирование» (DP.SC.189):**

| Вход | Выход |
|------|-------|
| Push в `main` одного из 11 репозиториев `aisystant` | Идентичное содержимое в парном репозитории МИМ |
| Первое подключение к непустому МИМ-репозиторию | Подтверждение пилота (не тихий форс-пуш) |
| Недоступный/несуществующий целевой репозиторий | Явное предупреждение в логе прогона (не тихий сбой) |

## 8. Область (покрывает три режима, не более)

Роль обслуживает три обещания: DP.SC.188 (личный шаблон IWE `TserenTserenov/FMT-exocortex-template` → `iwesys/iwe-template`, перевод всего `docs/**`), DP.SC.189 (11 методических репозиториев `aisystant` → МИМ, зеркалирование), DP.SC.062 (курируемый явный манифест из рабочего governance-репозитория → публичный исследовательский репозиторий iwesys, добавлен 20.07.2026 — первый потребитель WP-493 `growth-traits-lab`). Реализация конвейера DP.SC.189 (workflow, job matrix) спроектирована на уровне обещания/сценариев/роли (peer-session 2026-07-08-06); код ещё не написан — см. `DS-my-strategy/inbox/WP-415/WP-415.md`. Реализация DP.SC.062 — `DS-my-strategy/.github/workflows/publish-wp493-manifest.yml`, отдельный файл в репозитории источника (не в `iwe-translation-engine` — GitHub не даёт разрешить Actions-доступ к чужому reusable workflow отдельному репозиторию другого владельца, только всей организации целиком), не модифицирует боевой `translate-sync.yml`. Роль НЕ обслуживает Конвейер 1 (личный RU ↔ aisystant приватные RU) — тот вариант (pull-only/push-only/двусторонний) ещё не выбран пилотом и не спроектирован.

**Различие DP.SC.188 vs DP.SC.062 (оба — «перевод», не путать):** DP.SC.188 — source это ВЕСЬ `docs/**` репозитория (дельта по каталогу, что изменилось — то и переводится); DP.SC.062 — source это ЯВНЫЙ СПИСОК файлов, заданный автором источника, независимо от того, где физически лежит файл. Тест: «настроен ли source directory glob'ом или перечислением путей?» Glob → DP.SC.188. Перечисление → DP.SC.062.
