# Публикатор материалов практикума (DP.ROLE.100)

<!-- see DP.SC.068, WP-584 -->

> **Kind:** Функциональная роль (FPF A.2) — определение потока/встречи по согласованному правилу именования/контекста и загрузка файла не требуют суждения о содержании, только сопоставление с правилом. Один сценарий (неоднозначность определения потока/встречи) эскалирует к агентской роли: там требуется суждение, которое правило не покрывает.
> **Owner Role:** R6 Кодировщик (техническое сопровождение и настройка правил сопоставления); основной потребитель — R01 Пилот в роли наставника потока.

## 1. Миссия

Снять с наставника ручной труд «файл занятия → нужная папка на Google Диске → обновить список материалов → дать ссылку», когда материалов много и потоков несколько параллельно. Роль не решает, ЧТО является хорошим материалом — она решает, КУДА он попадает и КАК на него сослаться, детерминированно и без потери файлов.

Роль явно не берёт на себя то, что требует суждения о содержании: не проверяет качество материала, не решает вопросы доступа участников (это решение пилота, зафиксированное в РП-584 отдельно), не заменяет наставника в выборе, что публиковать.

## 2. Обязанности

1. Обнаруживать новый файл в отслеживаемых источниках (согласованная папка на Маке, согласованный Телеграм-чат) без пропуска — каждый файл получает исход: опубликован или явный вопрос.
2. Определять поток и встречу, к которым относится файл, по согласованному с пилотом правилу (имя файла, структура папки-источника или контекст сообщения).
3. Загружать файл в соответствующую папку потока/встречи на Google Диске, обновлять версию при повторной загрузке того же материала (не создавать дубликат нового объекта без необходимости).
4. Вести индекс-каталог: логический ID материала → программа/поток/встреча → текущая ссылка → версия → статус (опубликован/архив).
5. При невозможности однозначно определить поток/встречу — остановиться и передать решение с предложенными вариантами агенту или пилоту, не публиковать наугад.
6. Сообщать наставнику короткое подтверждение публикации с готовой ссылкой (успешный путь) или явный вопрос (путь эскалации).

## 3. Полномочия

- Читать отслеживаемые источники (папка на Маке, Телеграм-чат) — только те, что явно согласованы с пилотом, не произвольные каталоги.
- Писать в Google Диск пилота (создавать папки потоков/встреч, загружать/обновлять версии файлов) — в рамках согласованной структуры, не за её пределами.
- Писать в индекс-каталог — единственный писатель логического ID → ссылка (owner integrity: одна запись, один писатель).
- Не имеет полномочий менять права доступа участников, удалять материалы без явного действия наставника, или выбирать, какие файлы достойны публикации.

## 4. Связи с другими ролями

- **R01 Пилот (наставник потока)** — основной потребитель: кладёт файл, получает подтверждение или вопрос.
- **Агент IWE (Claude/сессия)** — принимает эскалацию при неоднозначности потока/встречи; пилот подтвердил (сессия 22.09, РП-584), что такое вмешательство ожидаемо, не считается сбоем.
- **Рабочее место наставника (РП-578)** — потребитель устойчивых ссылок из индекса; не хранит материалы сам, только ссылается.
- **Участник потока** — конечный получатель ссылки на материал (через наставника или РП-578), не взаимодействует с ролью напрямую.

## 5. Входы и выходы как артефакты

| Направление | Артефакт |
|---|---|
| Вход | Файл материала в отслеживаемом источнике (папка на Маке / Телеграм-чат) |
| Вход | Согласованное с пилотом правило определения потока/встречи |
| Выход | Опубликованный файл в папке потока/встречи на Google Диске |
| Выход | Запись в индексе-каталоге (логический ID → поток/встреча/ссылка/версия/статус) |
| Выход | Подтверждение наставнику с готовой ссылкой ИЛИ явный вопрос при неоднозначности |
