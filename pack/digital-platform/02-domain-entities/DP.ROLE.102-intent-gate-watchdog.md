# DP.ROLE.102 — Сторож намерения (intent-gate watchdog)

## Kind / Owner

- **Kind:** специализированный исполнитель (PreToolUse-хук, фиксированный flow — не агент: убери хук, проверка просто не вызывается, ничего не «решает»).
- **Owner Role:** DP.ROLE.001 (IWE Creator) — владелец надсистемы IWE, тот же прецедент, что DP.ROLE.091 (Сторож данных) и DP.ROLE.064 (Сторож новых задач).

## Обязанности

- На каждый перехваченный вызов инструмента любым агентом — прочитать журнал намерений, найти свежую (не старше числового порога) запись вызывающего агента.
- Нет свежей записи → отказать вызову с понятной причиной («сначала объяви намерение — РП или явно "вне РП"»), не тихо пропустить.
- Отказ самой проверки (журнал не читается, повреждён, недоступен) → заблокировать только ЭТОТ вызов (Protective Procedure Fallback, CLAUDE.md), не весь агент и не всю платформу; громкий лог причины.
- Не интерпретировать запись намерения как отчёт о выполненной работе — это объявление, не факт (то же различение намерение/факт, что в DP.SC.201).
- Не подключать и не переиспользовать admission-механику часов плана (`plan_allocation.py`, DR-03) — тот журнал и это намерение-объявление — разные механизмы по решению пилота (РП-561 Ф33, 13.10).

## Полномочия

- Read-only к журналу намерений. Не мутирует журнал — запись туда делает сам вызывающий агент отдельной лёгкой командой, до вызова инструмента.
- Write только в собственный лог отказов (кто/когда заблокирован, причина).

## Входы / Выходы (артефакты)

- **Вход:** событие PreToolUse (агент, инструмент, параметры вызова — без содержимого); журнал намерений (запись агента: РП или «вне РП», метка времени).
- **Выход:** exit 0 (разрешить) / exit 2 (заблокировать, с причиной в stderr); запись в лог отказов.

## Граница с соседними ролями

- **DP.ROLE.064 (Сторож новых задач) / DP.ROLE.091 (Сторож данных)** — тот же Kind (механический скрипт-исполнитель, владелец DP.ROLE.001), другой домен (объявление намерения перед действием, не github issues и не содержимое данных).
- **DP.SC.201 (orz-pipeline) / DR-03 admission-семантика часов плана** — смежный, но НЕ родительский механизм. Этот гейт читает ЛЁГКУЮ запись («я работаю над X»), не допуск к спорному ресурсу (поколение, держатель, fencing token) — развод закреплён решением пилота 13.10, не инженерной догадкой.
- **`wp-gate-check.sh` (существующий PreToolUse-хук)** — тот же архитектурный класс (перехватчик Write/Edit по условию), но узкий охват (только правка `WP-REGISTRY.md`/context-файлов РП). Этот гейт — расширение охвата на ЛЮБОЙ вызов инструмента ЛЮБОГО агента, не замена существующего хука.
