# Вестник (DP.ROLE.122)

> **Уровень владельца:** часть платформы (DP.ROLE.001 §3.6). Вестник - новая функциональная подсистема платформы (решение пилота 18.11.2026); в «Архитектуре платформы и IWE» (DP.ARCH.001) её пока нет, правка DP.ARCH.001 идёт отдельно через РП-611. Роль ≠ система: роль задаёт функцию, подсистема её выполняет. **«Вестник» и «Центр уведомлений» - разные предметы:** Вестник - функциональная подсистема; «Центр уведомлений» - имя будущей программы (модуля), которая выполняет большинство частей Вестника.

## Обязанности

Носитель роли обеспечивает уведомления для всех пользователей платформы. Для каждого человека он ведёт каталог правил уведомлений: платформенных (владелец - платформа; некритическое человек может выключить) и своих (владелец - человек). Принимает выпуски от отправителей (выпуск - одно конкретное сообщение, сделанное по правилу в конкретный момент), решает, отправить ли выпуск толчком (сообщение приходит само, без запроса), доставляет его в канал и хранит последний выпуск каждого правила для показа по запросу.

**Граница.** Вся инициативная доставка человеку идёт через Вестника. Ответ бота в диалоге на реплику человека уведомлением не считается и идёт мимо Вестника. Окна (Telegram, браузерный кабинет, VS Code, приложения ИИ-вендоров) только показывают каталог, переключатели, ленту и виджеты и передают действия человека Вестнику; Вестник - единственный источник истины об уведомлениях. Вестник не решает, сколько своих сообщений получит человек (решение пилота 18.11.2026, DP.SC.177).

## Функциональные части Вестника

Функциональная часть (синоним: функциональный объект; решение пилота 18.11.2026) названа по вкладу; колонка «Что делает» - её функции. Какой модуль выполняет часть - раздел «Модули» ниже.

| Функциональная часть | Что делает | Роль пака |
|---|---|---|
| Хранитель правил | хранит все правила человека, платформенные и свои: чьё, включено ли, срочность и точность; принимает изменения и проверяет право (критическое выключить нельзя, чужое менять нельзя) | нет отдельной карточки |
| Хранитель настроек | хранит тихие часы, выбор окон и каналов, отписки, согласия | нет отдельной карточки |
| Планировщик выпусков | запускает выпуск по своему правилу человека в нужное время по его часовому поясу с учётом перехода времени | DP.ROLE.124 |
| Приёмщик | принимает выпуск: проверяет отправителя, берёт получателя из учётной записи, отсекает повтор, сохраняет выпуск, возвращает отправителю исход | DP.ROLE.123 |
| Оформитель выпуска | пишет текст выпуска по шаблону вида на языке человека, с источником и временем данных | нет отдельной карточки |
| Распорядитель доставки | решает: отправить сейчас, после тихих часов, только в ленту или отсечь (отсекать можно только платформенные необязательные) - и в какой канал | DP.ROLE.075 |
| Диспетчер очереди | держит очередь поручений, повторяет при сбое, соблюдает скорость канала, не отправляет устаревшее, ведёт очередь отказов | DP.ROLE.125 |
| Почтальон | по поручению доставляет выпуск в канал (Telegram, почта, толчок на телефон или в браузер, событие в ChatGPT) и возвращает исход | DP.ROLE.044 |
| Будильщик | заранее ставит будильник на телефон человека для точного уведомления, переставляет и снимает его при изменении правила | нет отдельной карточки |
| Хранитель ленты | хранит историю выпусков и последний выпуск каждого правила для показа по запросу | нет отдельной карточки |
| Учётчик доставки | записывает, что ушло, куда, с каким исходом, и реакции человека | DP.ROLE.126 |
| Составитель табло | считает сводку доставки для человека и для создателей: сколько и чего ушло, что не доставлено и почему | нет отдельной карточки |
| Хранитель отправителей | хранит отправителей: ключ, владельца, разрешённые виды и получателей; выдаёт и отзывает ключ; Приёмщик сверяется с ним (решение пилота 19.11.2026) | нет отдельной карточки |
| Объяснитель выпуска | по номеру выпуска отдаёт своему получателю: что это, откуда, почему пришло, какие действия доступны; им пользуются ответ на уведомление и «почему я это получил» (решение пилота 19.11.2026) | нет отдельной карточки |

**Почтальон один на все каналы:** во всех каналах он вносит один вклад - доставить готовый выпуск и вернуть исход; каналы различаются способом и средством, это варианты исполнителя. **Будильщик - отдельная часть:** он не доставляет выпуск, а заранее ставит срабатывание на телефоне, которое случится и без сети.

## Соседи Вестника

| Функциональная часть | Что делает |
|---|---|
| Владелец правила | создаёт свои правила, включает и выключает некритические, запрашивает полный список |
| Получатель | получает уведомления, смотрит ленту и виджеты, реагирует |
| Отправитель | передаёт Вестнику выпуск: вид, получатель, данные; любой проверенный отправитель с ключом - подсистема платформы, IWE человека, его агент, задача вендора ИИ, источник партнёра (решение пилота 19.11.2026) |
| Агент человека | вендорский (Claude, Grok, ChatGPT по подписке человека), платформенный или собственный агент; как Отправитель шлёт выпуски с ИИ-содержанием (новости, поиск, пересказ) за счёт подписки человека; отвечает на реплику человека под выпуском, беря контекст у Объяснителя выпуска (решение пилота 19.11.2026) |
| Составитель сводок | по своему правилу человека собирает внешние данные и передаёт выпуск; для Вестника он такой же отправитель, как марафон |
| Поставщик прогнозов | отдаёт погоду, качество воздуха, морской прогноз |
| Окно уведомлений | показывает полный список правил, ленту, виджеты; принимает команды и нажатия от людей и ИИ-агентов и передаёт Вестнику |
| Привратник | устанавливает, кто человек; связывает Telegram-чат с учётной записью (подсистема есть в DP.ARCH.001 §4.1) |
| Собеседник в мессенджере | ведёт диалог с человеком; ответы в диалоге идут не через Вестника (есть в DP.ARCH.001 §4.1) |
| Диспетчер инструментов | передаёт вызовы ИИ-агентов серверу уведомлений (есть в DP.ARCH.001 §4.1) |
| Сторож исправности | замечает задержку доставки, рост очереди, отказы (есть в DP.ARCH.001 §4.1) |
| Учётчик событий | принимает события доставки в общий учёт платформы (есть в DP.ARCH.001 §4.1) |

Окно - не почтальон: в claude.ai, ChatGPT и VS Code прислать сами мы не можем (кроме событий в ChatGPT), человек открывает окно и смотрит.

## Модули

Модули выполняют функциональные части подсистемы, не роль (DP.ARCH.001 §4.1, §11.1). Состояние на 19.11.2026. Пересмотр 19.11.2026 (решение пилота): Планировщик выпусков и Диспетчер очереди выполняет только наша программа; Knock - только для будущей ленты кабинета и почты и отложен до появления кабинета.

| Модуль | Какие функциональные части выполняет | Сейчас / целевое |
|---|---|---|
| программа «Центр уведомлений» (notification-center, новая) и её база | Хранитель правил, Хранитель настроек, Хранитель отправителей, Приёмщик, Оформитель выпуска, Объяснитель выпуска, Распорядитель доставки, Планировщик выпусков, Диспетчер очереди (своя очередь к Telegram с приоритетами), Хранитель ленты, Учётчик доставки, Составитель табло | сейчас Приёмщика и Распорядителя доставки выполняет служба уведомлений внутри Telegram-бота (`NotificationService`), Планировщика и Диспетчера очереди - тот же бот |
| внешняя облачная программа Knock | Почтальон и Хранитель ленты для кабинета и почты | отложено до появления кабинета (решение пилота 19.11.2026); переходник к Knock готов |
| Telegram-бот (aist_bot) | Почтальон для Telegram, Окно уведомлений в Telegram, Собеседник в мессенджере; реплику под выпуском передаёт агенту вместе с номером выпуска (тонкое окно, РП-262) | есть |
| задачи вендоров ИИ по расписанию (Claude, Grok, ChatGPT) | Отправитель (как вариант исполнителя Агента человека) за счёт подписки человека | проверяется в РП-568 Ф24 |
| собственный агент человека (класс «собственный» по РП-262) | Отправитель и Агент человека; у владельца IWE - на его сервере | есть у владельца IWE |
| служба рассылки почты (Apprise как запущенная программа) | Почтальон для почты | целевое |
| MCP-сервер уведомлений (новый, за шлюзом MCP) | Окно уведомлений для ИИ-агентов; Почтальон для событий в ChatGPT (эксперимент); вход для агентов и отправителей: «отправить выпуск», «показать выпуск», «действие с выпуском» | целевое |
| кабинет в браузере (программа не выбрана), расширение VS Code (табло, РП-417) | Окно уведомлений | целевое |
| мобильное приложение | Будильщик, Почтальон для толчков на телефон | РП-568 Ф22 |
| программа сводок (новая, имя не выбрано) | Составитель сводок | целевое |

Без исполнителя на 18.11.2026: показ табло для создателей; Будильщик до Ф22; сигнал Сторожу исправности о росте очереди; связывание Telegram-чата с учётной записью.
