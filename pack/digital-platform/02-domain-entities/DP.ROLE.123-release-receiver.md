# Приёмщик (DP.ROLE.123)

> **Уровень владельца:** часть платформы (DP.ROLE.001 §3.6); функциональная часть подсистемы «Вестник» (DP.ROLE.122). Выделен 18.11.2026 из прежней роли «Доставщик» (DP.ROLE.075), которая объединяла Приёмщика и Распорядителя доставки. Не путать с ролью человека «Приёмщик» из каталога R (R26 «Приёмщик» (VR.R.004)): там человек принимает результат работы, здесь часть Вестника принимает выпуск уведомления.

## Обязанности

Носитель роли принимает выпуск (одно конкретное сообщение, сделанное по правилу в конкретный момент) от любого отправителя: программ платформенных подсистем и Составителя сводок.

| Обязанность | Как выполняется |
|---|---|
| Проверить отправителя | у каждого отправителя свой ключ (условие безопасности 11.11.2026) |
| Проверить схему выпуска | вид, данные, срок годности, ключ повтора |
| Взять получателя | только из учётной записи человека, не из тела запроса (условие 11.11.2026) |
| Отсечь повтор | повтор одного срабатывания по ключу повтора не создаёт второго выпуска |
| Сохранить выпуск | без права изменения |
| Вернуть исход отправителю | номер выпуска или отказ с причиной |

**Граница.** Приёмщик не решает, отправлять ли выпуск толчком, когда и в какой канал - это Распорядитель доставки (DP.ROLE.075). Не пишет текст - это Оформитель выпуска. Не доставляет - это Почтальон (DP.ROLE.044).

## Метод

Этап Б4 «Приём» конвейера «Жизнь выпуска» (схемы и конвейеры РП-568 Ф23): сразу проверить ключ отправителя, схему, получателя из учётной записи, повтор; сохранить; вернуть отправителю номер или отказ. В журнал: «принят» или «отклонён».

## Рабочие продукты

Принятый выпуск; ответ отправителю (номер выпуска или отказ с причиной).

## Модули

Сейчас - служба уведомлений внутри Telegram-бота (`NotificationService`, вход `send()`); целевое - программа «Центр уведомлений» (DP.ROLE.122, раздел «Модули»).

## Прежние имена

- **Прежние имена:** часть роли «Доставщик» (DP.ROLE.075, до 18.11.2026).
