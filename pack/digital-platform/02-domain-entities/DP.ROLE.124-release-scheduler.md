# Планировщик выпусков (DP.ROLE.124)

> **Уровень владельца:** часть платформы (DP.ROLE.001 §3.6); функциональная часть подсистемы «Вестник» (DP.ROLE.122). Выделен 18.11.2026 из прежней роли «Notification Dispatcher» (DP.ROLE.044), которая объединяла Планировщика выпусков, Диспетчера очереди, Почтальона (только Telegram) и часть Учётчика доставки.

## Обязанности

| Обязанность | Этап конвейера (РП-568 Ф23) |
|---|---|
| Вычислить следующий запуск правила с расписанием по часовому поясу человека с учётом перехода времени | А4 «Планирование» |
| Пересчитать запуски при изменении правила, паузе, снятии паузы, смене часового пояса | А5, А6 |
| Запустить срабатывание: взять задание с блокировкой, ключ повтора «правило + плановое время» | Б1 «Срабатывание» |
| Точное правило передать на постановку будильника (конвейер «Точные уведомления на телефоне») | А4 |

Запросы человека на напоминание («/remind», инструмент MCP напоминания) - частный случай своего правила (DP.SC.116); их время запуска тоже ведёт Планировщик выпусков. Разбор времени у `/remind` сейчас: регулярные выражения для явных форматов (`ЧЧ:ММ`, `ДД мес ЧЧ:ММ`), «через X» - расчёт от текущего момента, разбор моделью - по желанию для сложных случаев.

**Граница.** Планировщик не собирает данные и не пишет текст (Составитель сводок, Оформитель выпуска), не решает, слать ли толчком (Распорядитель доставки, DP.ROLE.075), не держит очередь доставки (Диспетчер очереди, DP.ROLE.125).

## Рабочие продукты

Время следующего запуска каждого правила; задание на выпуск.

## Модули

Сейчас - Telegram-бот (очередь `reminders` и планировщик по расписанию). Целевое - ядро доставки (свой экземпляр Novu или Knock) или программа «Центр уведомлений», если ядро своё; выбор - РП-568 Ф17.

## Прежние имена

- **Прежние имена:** часть роли «Notification Dispatcher» (DP.ROLE.044, до 18.11.2026; обязанность «доставить в нужное время»).
