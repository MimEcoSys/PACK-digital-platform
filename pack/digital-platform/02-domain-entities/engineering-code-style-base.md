# База инженерного стиля кода (L0)

**Для кого:** все агенты, пишущие код в репозиториях IWE (Claude, Kimi, Hermes).
**Зеркало:** «база разговорного стиля» (DP.SC.050), но ось — код, а не текст для человека.

## Организующий принцип — негативное определение

База **не описывает «хороший код»**. База — это перечень конкретных запахов (антипаттернов) с парой «было → стало». **Вкус — это отсутствие запахов.** Правило, которое нельзя свести к «было/стало», слишком размыто для L0 и уходит в авторский слой L1.

**Зачем база существует (корневая причина).** Агент оптимизирует под «готово сейчас» — у него нет «будущего себя», который будет это поддерживать. Профессионал пишет для следующего читателя (часто себя через 3 месяца). База — встроенный в момент генерации «голос будущего читателя».

## Детектор контекста — «есть ли у кода будущий читатель?»

| Контекст | Признаки | Строгость |
|----------|----------|-----------|
| Боевой / общий код | мёржится в main, живёт в shared-модуле, ожидается тест | строго — все P-правила |
| Одноразовый скрипт / прототип | `/tmp`, разовый анализ, не переживёт задачу | мягко — над-инженерить одноразовое тоже запах |

Тест: «вернётся ли кто-нибудь к этому коду?» Нет → не плоди абстракции. Да → P1-P9 обязательны.

## Граница со смежными слоями

- **Жёсткие запреты** (`git add -A`, секреты в логах, `--no-verify`) → правила агента (PACK-agent-rules, AR.*). Блокирующее, безопасность. **Не дублировать здесь.**
- **Разметка markdown / документы** → `.claude/rules/formatting.md`.
- **База стиля = слой ремесла и вкуса.** Не-блокирующая рекомендация. Тест границы: «ломает систему/безопасность?» → AR. «Делает код хуже на глаз профессионала?» → сюда.

## Правила (одностроки — развёрнутые «было/стало» в разделе «Развёрнуто» ниже)

- **P0 — перед коммитом запусти форматтер и линтер репо** (`ruff`/`prettier`/`shellcheck`/`eslint` по конфигу). Нет конфига → спроси пилота, не выдумывай стиль. Механический слой закрывает инструмент, база — craft-слой.
- **P1 — тест без проверки наблюдаемого результата запрещён.** «Прогнали, не упало» ≠ «работает»; нужен assert конкретного эффекта. `assert True` / `expect(true).toBe(true)` / единственный `toBeDefined` — запах.
- **P2 — третье повторение → извлечь функцию; не `locals()[str]`.** Реальные объекты в списке/словаре, не адресация переменной по строковому имени.
- **P3 — мёртвую ветку / недостижимый enum-вариант удалить**, не «оставлять для совместимости» (вернётся из истории при нужде).
- **P4 — `except: pass` без логирования запрещён.** Голое `except` без типа и действия — всегда запах; логируй или пробрасывай.
- **P5 — длинную функцию со смешанными обязанностями разбить; булевы флаги-режимы → отдельные функции.** Сигналы: >~120 строк, >~6 параметров, флаги `skip/force/in`. **Контр-критерий (Ousterhout):** длина сама по себе не запах — не дроби глубокий модуль (богатый за узким интерфейсом); дроби по смене уровня абстракции, не ради длины.
- **P6 — обработчик/сервис без структурированного лога на входе и при критичном падении — запах.** Минимум: запись на входе + при отказе с контекстом (id/phase, `[handler]`-prefix). Не путать с P4 (P4 — проглоченное исключение, P6 — отсутствие сигнала).
- **P7 — ASCII-баннер между блоками ВНУТРИ функции = скрытая декомпозиция.** Секция под баннером → отдельная функция. Граница: один баннер в начале функции или модульный маркер `# --- helpers ---` — не запах. P7 = симптом, P5 = суть; не дублировать.
- **P8 — борьба с языком вместо идиомы.** Ручной цикл там, где есть comprehension/встроенная функция; `range(len(x))` вместо `for item in x`. Контр-критерий: вложенный comprehension 3+ уровня — сам запах. Граница с P2: единичный цикл = P8, скопирован трижды = P2. Идиомы по языкам — в таблице ниже.
- **P9 — ручной парсинг стандартного формата вместо библиотеки.** CSV/JSON/YAML/ISO-дата/URL руками (split/срезы) → библиотека (`csv`, `json`, `date.fromisoformat`). Только для стандартного/внешнего формата; одноразовый внутренний — `split` ок; `range(len)` без формата = P8.
- **P12 — абзац-комментарий, оправдывающий костыль, сам сигналит, что костыль неверен.** Длинное объяснение «почему это исключение необходимо и трогать нельзя» (история инцидента, «не трогать без ревью с …») — признак незакрытой первопричины, не документация. Фикс первопричины убирает нужду в абзаце; если правда неустранимо сейчас — однострочная WHY-ссылка на тикет, не абзац-оправдание.
- **P13 — «защитную» настройку, которую код доказуемо не читает, не добавлять.** Общие соображения о рисках среды («на всякий случай», «а вдруг понадобится») — гипотеза, а не основание для конфигурации; проверяется чтением кода потребителя, не хеджируется добавлением настройки. Мёртвая конфигурация опаснее отсутствующей: создаёт ложное чувство защищённости и маскирует реальную непокрытую зависимость. Тот же принцип, что P3, но для конфига, а не для кода.

## Развёрнуто — «было/стало» по каждому правилу

> Полные примеры (вне впрыска — для ревью и обучения, не в каждый промпт).

**P1 — тест = наблюдаемый результат.**
```python
# было:
await dp.feed_update(bot, update); assert True
# стало:
await dp.feed_update(bot, update); assert len(bot.sent) > 0   # проверяем реакцию, не отсутствие исключения
```

**P2 — DRY / не `locals()[str]`.**
```python
# было:
for conn_attr in ("rewards_conn", "reference_conn"):
    await locals()[conn_attr].close()
# стало:
conns = {name: await ensure_conn(c, dsn) for name, (c, dsn) in pool_spec.items()}
```

**P3 — удалить мёртвую ветку.**
```ts
// было: вариант, в который нет перехода
type CircuitState = "closed" | "open" | "half-open" | "probing"; // half-open не ставится
// стало: убрать "half-open" из типа и обработчиков
```

**P4 — `except: pass` без лога.**
```python
# было:
try: await conn.close()
except Exception: pass
# стало:
try: await conn.close()
except Exception: log.warning("conn.close failed", exc_info=True)
```

**P5 — декомпозиция + контр-критерий.**
```python
# было: смешанные обязанности + флаги-режимы
async def process_event(event_id, pools, rules, cursor, skip_dlq, force_apply, in_replay): ...
# стало: read_event → check_dlq → group_by_domain → apply → advance_cursor; флаги → отдельные вызовы
```
Контр-критерий Ousterhout: глубокий модуль (богатый функционал за узким интерфейсом) не дроби ради длины; дроби по смене уровня абстракции.

**P6 — наблюдаемость.**
```python
# было:
async def handle(request): return process(await load(request))
# стало:
async def handle(request):
    log.info("[handle] start id=%s", request.id)
    try: return process(await load(request))
    except Exception: log.exception("[handle] failed id=%s", request.id); raise
```

**P7 — ASCII-баннер внутри функции.**
```python
# было:
def process(x):
    # ========== VALIDATION ==========
    ...
    # ========== TRANSFORM ==========
    ...
# стало: validate(x) и transform(x) — отдельные функции, вызовы в process
```

**P8 — идиома вместо борьбы с языком.**
```python
# было:
result = []
for x in items:
    if x.active: result.append(x.name)
# стало:
result = [x.name for x in items if x.active]
```

**P9 — библиотека вместо ручного парсинга.**
```python
# было:
parts = line.split(",")        # CSV руками — ломается на запятых в кавычках
y, m = s[0:4], s[5:7]          # дата срезами
# стало:
row = next(csv.reader([line])); d = datetime.date.fromisoformat(s)
```

**P10 — функция-поиска / функция-попытка возвращает значение, а не флаг наличия.**
```python
# было: bool — caller вынужден вычислять повторно или терять результат
def _try_auto_link(user_id, db) -> bool:
    account = db.find_account(user_id)
    return account is not None  # account.id теряется

if _try_auto_link(uid, db):
    db.link(uid, ???)  # откуда account_id?

# стало: str | None — вычисленный результат передаётся дальше
def _try_auto_link(user_id, db) -> str | None:
    account = db.find_account(user_id)
    return account.id if account else None

if account_id := _try_auto_link(uid, db):
    db.link(uid, account_id)
```
Применяется к: lookup-функции, поиску соответствия, попыткам соединения.

**P11 — lookup из N источников возвращает типизированный результат с провенанс-полем, не голую строку.**
```python
# было: голая строка — откуда она пришла?
def get_meme(slot, catalog) -> str:
    return catalog.get(slot, DEFAULT_TEXT)   # source неизвестен

# стало: типизированный результат с провенансом
@dataclass
class MemeResult:
    text: str
    source: str  # "catalog" | "fallback" | "empty"
    slot: str

def get_meme(slot, catalog) -> MemeResult:
    if slot in catalog:
        return MemeResult(text=catalog[slot], source="catalog", slot=slot)
    if DEFAULT_TEXT:
        logger.warning("meme_fallback", slot=slot)   # P6: explicit warning
        return MemeResult(text=DEFAULT_TEXT, source="fallback", slot=slot)
    return MemeResult(text="", source="empty", slot=slot)
```
Поле `source` одновременно: (1) диагностика для разработчика; (2) сигнал наблюдаемости (`source="fallback"` → WARNING = повод расширить каталог). Тест: «мой lookup из N источников возвращает голую строку — понимаю ли, откуда она пришла?» Нет → верни типизированный результат с полем source.

**P12 — абзац-оправдание = сигнал первопричины, не документация.**
```python
# было: абзац оправдывает костыль вместо фикса первопричины
# Воркэраунд: приходится закрывать соединение вручную здесь, потому что
# драйвер X не освобождает файловый дескриптор при таймауте на версии 2.3,
# баг завёлся после апрельского апгрейда, не трогать без ревью с DBA-командой,
# смотри инцидент INC-4821 и плейбук docs/db-timeout.md
conn.close()

# стало: первопричина зафиксирована в тикете, комментарий — одна строка WHY
conn.close()  # WHY: драйвер X не освобождает fd на таймауте (INC-4821, driver v2.3)
```
Тест: «нужен абзац, чтобы оправдать этот код перед следующим читателем?» Да → первопричина не устранена, костыль неверен — чинить первопричину или завести тикет и оставить однострочный WHY-якорь, не абзац-оправдание.

**P13 — «страховка про запас» в конфиге, которую код не читает.**
```yaml
# было: "защитная" глобальная git-identity и fetch-depth: 0 добавлены в CI workflow
# "на всякий случай" — без проверки, читает ли их хоть один из тестов
- uses: actions/checkout@v4
  with:
    fetch-depth: 0
env:
  GIT_AUTHOR_NAME: ci-bot
  GIT_AUTHOR_EMAIL: ci@example.com

# стало: чтение кода всех тестов показало — каждый сам создаёт временный
# репозиторий и явно задаёт identity (один даже обнуляет
# GIT_CONFIG_GLOBAL=/dev/null) — глобальная настройка была бы мёртвой
# и маскировала бы реальную зависимость; не добавлена
```
Тест: «я проверил чтением кода потребителя, что эта защитная настройка вообще на что-то влияет?» Нет → не добавляй; гипотезу о риске проверяй чтением, а не хеджем.

## Связь с теорией

> Каждое P-правило — не вкусовщина, а сжатие установленной инженерной практики. Якоря для тех, кто хочет первоисточник.

| Правило | Ближайший теоретический якорь |
|---------|-------------------------------|
| **P1** тест = наблюдаемый результат | GOOS (Freeman & Pryce, London-school TDD): поведение через наблюдаемые эффекты, не отсутствие исключения |
| **P2** DRY на 3-м повторении | Pragmatic Programmer «Once and Only Once»; Fowler, Refactoring «Extract Function» |
| **P3** удалять мёртвый код | YAGNI (XP, Beck); Fowler «Remove Dead Code» |
| **P4** `except: pass` без лога | PEP 8 + SRE observability; эмпирически самый частый класс AI-косяков (~8.6%) |
| **P5** декомпозиция + контр-критерий | Martin, Clean Code (SRP) + Ousterhout, APoSD «глубокий модуль ≠ мелкий» — две силы в балансе |
| **P6** наблюдаемость | Google SRE Workbook (структурные логи как сигнал); стиль Андрея (Ф2.1) |
| **P7** баннер = скрытая декомпозиция | Martin, Clean Code «функция как заголовок»; Kerievsky «Compose Method» |
| **P8** идиоматичность | Effective Python/Go/Rust (язык-специфика); «писать с зерном языка, не против» |
| **P9** библиотека вместо ручного парсинга | «не парси известный формат руками» (классика безопасности: CSV/дата/URL edge-cases); stdlib-first |
| **P12** абзац-оправдание = сигнал первопричины | эмпирика: разбор переписывания Bun на Rust (bun.com/blog/bun-in-rust via Fable, 09.07.2026, РП-448) — «если нужен абзац, оправдывающий workaround, код неверен»; Fowler, Refactoring «Comment as Deodorant» |
| **P13** не хеджировать непрочитанной конфигурацией | YAGNI (XP, Beck) — тот же принцип, что P3, применённый к конфигурации вместо кода; эмпирическая проверка кода потребителя вместо общих соображений о риске |

**Почему P5 нуждается в двух якорях.** Мартин толкает к дроблению (SRP), Ousterhout — к укрупнению (глубокий модуль). Это не противоречие: дроби по **смене уровня абстракции**, укрупняй внутри **одного** уровня.

## Энфорсмент (трёхслойный)

1. **Инжекция (первичный, v1):** одностроки P0-P9 между маркерами `CODE-STYLE-INJECT-START/END` впрыскиваются в контекст агента. Якорь — `inject-code-style-anchor.sh` (UserPromptSubmit).
