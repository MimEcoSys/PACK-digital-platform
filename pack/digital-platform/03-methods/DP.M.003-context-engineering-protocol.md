# Context Engineering Protocol

## 1. Определение

Метод проектирования и управления контекстом ИИ-агента через четыре стратегии (Write/Select/Compress/Isolate), операционализированный в 3-слойной архитектуре инструкций экзокортекса.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Write (полнота артефакта) ↔ Compress (минимальность) | §3.1 требует создавать нужные артефакты (CLAUDE.md, memory/*.md, Pack entity), но §3.3 требует сжимать до минимума — каждый новый файл, оправданный полнотой Write, немедленно становится кандидатом на сокращение при следующем проходе Compress, и критерий «когда остановиться» метод не формализует |
| Select (точность выборки) ↔ издержки распознавания | «memory/*.md по теме, когда тема всплывает» (§3.2) экономит контекст только если агент верно распознаёт, что тема всплыла — ошибка в любую сторону (не загрузил нужное / перестраховался и загрузил лишнее) методом не детектируется, только по факту сбоя задачи |
| Isolate (строгая граница агентов) ↔ Cross-repo координация | §3.4 требует «агенты не видят контекст друг друга без явных контрактов», но не определяет, что считать «явным контрактом» — граница между изоляцией ради качества и изоляцией, скрывающей нужную координацию, проводится на усмотрение исполнителя |

## 2. IPO-паттерн

| Элемент | Описание |
|---------|----------|
| **Входы** | Задача агента + доступные знания (Pack, memory, context files) |
| **Обработка** | Write → Select → Compress → Isolate |
| **Выходы** | Оптимизированный контекст агента (CLAUDE.md + memory/ + загруженные entities) |

## 3. Четыре стратегии

### 3.1. Write (создание артефактов)

Создавать правильные артефакты для контекста агента:

| Артефакт | Когда создавать | Размер |
|----------|----------------|--------|
| CLAUDE.md (root) | Кросс-репозиторные правила | ≤200 строк (MEMORY.md) |
| repo CLAUDE.md | Специфика одного репо | Без лимита |
| memory/*.md | Справочные знания | ≤100 строк/файл, ≤10 файлов |
| Pack entity | Доменное знание | ≤10K символов |
| WP context file | Контекст рабочего продукта | Свободный |

### 3.2. Select (выбор релевантного)

Для каждой задачи — минимальный достаточный контекст:

| Уровень | Что загружать | Когда |
|---------|---------------|-------|
| Always | CLAUDE.md + MEMORY.md | Каждая сессия |
| On-demand | memory/*.md по теме | Когда тема всплывает |
| Точечно | Pack entity по ID | Когда нужны детали |
| Context file | WP-N-slug.md | При работе над конкретным РП |

### 3.3. Compress (сжатие до минимума)

- summary в frontmatter ≤150 символов
- memory/ файлы ≤100 строк
- MEMORY.md — только блокирующее + навигация
- Правило: если информация не нужна в каждой сессии → она не в MEMORY.md

### 3.4. Isolate (изоляция контекстов)

- Каждый Pack = отдельный bounded context
- Каждый repo CLAUDE.md = изолированные инструкции
- Агенты не видят контекст друг друга (кроме явных контрактов)
- Platform-space ≠ User-space (DP.D.011)

## 4. Чеклист при проектировании агента

- [ ] Write: все необходимые артефакты созданы?
- [ ] Select: определён протокол загрузки (что always, что on-demand)?
- [ ] Compress: нет ли лишнего в always-in-context?
- [ ] Isolate: контекст агента не пересекается с другими без контрактов?

## Bias-Annotation

_Куда систематически съезжает внимание практикующего. Статус карточки — `draft`: пометка `tentative` по прецеденту SA.METHOD.001 (WP-448 Ф12)._

| Bias | Direction of distortion |
|------|--------------------------|
| _(tentative)_ Write воспринимается как разовое действие | Внимание съезжает на факт создания артефакта (CLAUDE.md написан, memory/-файл создан), а не на последующие Select/Compress/Isolate — метод формулирует 4 стратегии как цикл, но практика часто останавливается на первой |
| _(tentative)_ Compress оценивается по объёму, не по актуальности | Смещение к механическому подсчёту строк (≤100 строк/файл, §3.3) — файл может быть коротким, но устаревшим; метод не проверяет, что сжатое содержимое всё ещё релевантно задаче |

При помощи человеку с повторившимся затруднением ИИ отбирает только доступные ему записи и показывает основание подсказки: исходную запись, дату, контекст прежнего решения и границы применимости. Сходство формулировок недостаточно: требуется проверить, что совпадает в работе, что изменилось и каких сведений нет. При отсутствии записи ответ явно сообщает об этом, а не реконструирует несуществующую память.

Подсказка предлагает подходящий метод или уточняющий вопрос; человек подтверждает применимость либо отказывается. Ранее принятое решение не становится разрешением нового действия. Для предложения ролей и методов нужны ссылки на наблюдаемые действия и продукты, а не только уверенный вывод модели.

**Проверочные случаи для реализации:** (1) повтор при прежних условиях; (2) похожая формулировка, но новый риск; (3) запись отсутствует; (4) данных недостаточно для выбора метода. Во всех случаях проверяются основание, актуальность и возможность отказа. **Пересмотр:** ложное узнавание, скрытая неопределённость или рекомендация без доступного источника. Реализацию и автоматическую проверку этих случаев здесь не заявляем.
