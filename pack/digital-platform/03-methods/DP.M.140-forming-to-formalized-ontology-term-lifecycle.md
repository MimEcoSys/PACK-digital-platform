# Два состояния онтологических терминов: forming → formalized

## Суть

Термины входят в онтологию Pack в два этапа:
1. **forming** — термин нужен для guide/документа, определение черновое, Pack-сущность ещё не создана
2. **formalized** — термин верифицирован, Pack-сущность создана, source = ID Pack-файла

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Скорость guide-разработки ↔ целостность Pack-онтологии (OwnerIntegrity) | Статус `forming` разрешает временную неполноту — черновое определение без Pack ID, — не ломая трассируемость; но инвариант ограничивает поблажку: ни один forming-термин не должен жить дольше одной итерации формализации |
| Гибкость черновика ↔ строгость верифицированной сущности | Двухфазность позволяет термину существовать до создания Pack-файла, но цена — два разных frontmatter-шаблона и обязательный перевод `forming → formalized` с заменой source на ID Pack-файла: дисциплина перехода вместо свободы «термин как-нибудь есть» |

## Frontmatter для forming-термина

```yaml
- id: ontology_term
  status: forming
  source: "docs 1-2 §7"   # ссылка на источник черновика
  # нет Pack ID
```

## Frontmatter для formalized-термина

```yaml
- id: ontology_term
  status: formalized
  source: "PD.FORM.089 §4"  # ссылка на Pack-файл
  pack_id: PD.FORM.089
```

## Инвариант

`status: forming` разрешает временную неполноту без нарушения OwnerIntegrity: guide-разработка идёт впереди Pack-формализации. Ни один forming-термин не должен оставаться в этом статусе дольше одной итерации формализации.

## Детектор долгов

`grep "forming" ontology.md` → список терминов, ожидающих Pack-формализации.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Добавление термина затмевает его перевод в formalized | Внимание сосредотачивается на том, чтобы guide заработал — термин появился в `ontology.md`, определение на месте, — а детектор долгов (`grep "forming" ontology.md`) не запускается: инвариант «не дольше одной итерации формализации» тихо нарушается, долг копится |
| Статус forming привыкает как норма | Спустя итерации внимание перестаёт считывать forming-термины в `ontology.md` как долг вообще: их становится много, они читаются как обычное состояние реестра — сигнал к формализации глохнет ровно от накопления, которое он должен был предотвратить |

## Антипаттерн

Добавить термин в ontology.md без поля `status` → невозможно отследить, что нужна формализация; forming-долги становятся невидимыми.
