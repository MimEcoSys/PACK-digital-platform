# DP.M.172 — Knowledge-file archive: Variant B (git mv)

## Проблема

При накоплении N knowledge-файлов (feedback_*.md, lessons_*.md) в активной директории:
- **Вариант A (удаление):** теряется исследовательская ценность и git-история.
- **Вариант B (перенос в архив):** прежнее содержимое сохраняется. Файлы перестают попадать в автоматическую загрузку только при размещении вне её фактической области; имя `archive/` само по себе этого не обеспечивает.

## Forces

_Какие конкурирующие давления удерживает метод._

| Force | Tension |
|-------|---------|
| Чистота hot-directory (файлы не попадают в context scan агента) ↔ сохранение исследовательской ценности и git-истории | Перенос даёт разгрузку только после исключения архива из автоматической загрузки; сохранность содержимого и истории проверяют отдельно. Цена: архив растёт и требует дисциплины структуры (feedback/, lessons/) |
| Простота «просто оставить файл лежать» ↔ систематическая доступность знаний | Файл в memory/ не требует никаких решений, но принцип разделения требует двух целевых хранилищ: систематически используемое агентом → SQLite (primary, queryable, decaying), ретроспективное человеку → archive/ — каждое дороже инерции, дешевле накопления |

## Решение: Variant B

До переноса установить область автоматической загрузки: начальные каталоги, рекурсию, маски, исключения и ссылки. Ниже исторический пример; он разгружает контекст только если `memory/archive/` не обходится действующим загрузчиком. При рекурсивном обходе `memory/` выбрать архив за пределами этой области.

```bash
git mv memory/feedback_*.md memory/archive/feedback/
git mv memory/lessons_*.md memory/archive/lessons/
git commit -m "archive: move N knowledge files to reduce context pollution"
```

**Принцип разделения:**
- **Агент использует систематически** → SQLite (primary, queryable, decaying)
- **Человеку нужно для ретроспективы** → архив с сохранённым содержимым и проверенным доступом; исключение из автоматической загрузки устанавливают отдельно.

## Когда применять

| Сигнал | Действие |
|--------|---------|
| N > 30 файлов в одной директории | Предложить архивацию на Week Close |
| Файл не открывался > 30 дней | Кандидат на архивацию |
| Файл дублирован в SQLite | Приоритетный кандидат |

## Тест

«Нужен ли файл агенту в текущей сессии?»
- Нет → архивировать с сохранением содержимого и доступа; затем проверить, что действующий загрузчик больше не включает файл.
- Да, систематически → SQLite по контракту исходного внедрения.

Для цели разгрузки сравнить фактически загружаемый перечень до и после. Если архив всё ещё включается по рекурсии, ссылке или импорту, цель переноса не достигнута. Проверка сохранности файла не заменяет эту проверку.

Связанное уточнение по случаю `DP.FM.748`: дифф iwe-local-config `16d5545e589f6b798d35bfe7ebbb7605f2f73957` показывает перенос архива из автоматически загружаемого дерева в соседний справочный каталог. Оговорка о загрузчике уточняет прежние обещания метода; изменение требует решения пилота.

## Связи

- AS.D.018 — Hermes (SQLite = primary после архивации файлов)
- DP.FM.748 — архив во вложенном загружаемом каталоге не разгружает контекст; неполный счётчик может скрыть это.

## Bias-Annotation

_Куда систематически съезжает внимание практикующего._

| Bias | Direction of distortion |
|------|--------------------------|
| Счётчик файлов затмевает сигналы использования | Триггером архивации становится «N > 30 в директории» как самое видимое число, а проверки «не открывался > 30 дней» и «дублирован в SQLite» пропускаются — под `git mv` попадают файлы, которые агент ещё читает, и наоборот |
| Видимый порядок в hot-directory затмевает невидимую судьбу archive/ | После `git mv` задача считается закрытой; практик не возвращается к вопросу, обращается ли кто-то к archive/ через `git log -p` вообще, — «сохранено» подменяет «используется» |
