# DP.M.450 — Сузить сканируемый текст перед сопоставлением с guard-шаблоном, а не добавлять исключения к шаблону

## Определение

Текстовый guard/сканер Bash-команд сужает границы сопоставления самим текстом — что вообще является исполняемой командой — ДО применения проверочного шаблона, вместо накопления точечных исключений к шаблону при каждом новом ложном срабатывании.

## Проблема

Два живых ложных срабатывания одного дня имели общую причину: проверки матчились по сырому тексту Bash-вызова целиком, а не по границам реально исполняемых команд внутри него.

1. Запись документа через `cat > file <<'EOF' ... EOF` была отказана как `rm -rf`, потому что проверка искала `rm` + флаг recursive-ish + флаг force-ish ВЕЗДЕ в тексте вызова, включая тело heredoc (данные, которые записываются, а не команды).
2. `git add` был заблокирован, потому что одиночная точка `source`-команды стояла на ПОЗДНЕЙШЕЙ строке того же вызова, а разделитель сегментов не считал перевод строки границей команды — вызов из нескольких строк склеивался в одну команду.

## Метод

1. **Исключать только доказанно литеральные данные heredoc.** Проверить обе границы (DP.D.305): подстановки оболочки подавлены, фактический получатель не исполняет stdin. Некавыченный delimiter позволяет выполнить `$(команда)` даже перед передачей текста в cat; кавычки не мешают bash/psql/mysql или другому интерпретатору исполнить stdin. Исполняющего либо неизвестного получателя и неразобранный контекст не исключать из проверки. Исключение из проверки команд не означает исключения из проверки секретов или других свойств данных.
2. **Перевод строки считать разделителем только на синтаксической границе команды.** Не делить механически внутри кавычек, heredoc, продолжения строки или вложенной конструкции. Иначе один аргумент либо составная команда превращаются в ложные независимые команды; обратная ошибка — склеивание реально отдельных команд.
3. Применить проверочный шаблон к разобранным исполняемым сегментам, включая подстановки и интерпретируемое содержимое. Неизвестный синтаксис не объявлять безопасным сокращённым текстом: сохранить его для дальнейшей проверки либо вернуть явную неопределённость по контракту guard'а.

## Обобщение

Переносимый принцип для любого текстового guard/сканера команд: границы сопоставления сужать самим текстом (что вообще является исполняемой командой), а не постфактум городить исключения к каждому конкретному ложному срабатыванию — вторые множатся с каждым новым случаем, первое устраняет целый класс сразу.

## Когда применять

**Тест:** «Guard матчит шаблон по сырому тексту многострочного/составного Bash-вызова целиком?» Да → сначала установить синтаксические границы команд и условия исключения литеральных данных. Не заменять разбор безусловным вырезанием heredoc или разбиением по каждому переводу строки и `;`.

## Применимость

Любой текстовый guard/сканер, проверяющий Bash-вызовы агента на потенциально опасные конструкции (destructive commands, secret leaks, forbidden patterns) через сопоставление с шаблоном по сырому тексту вызова.
