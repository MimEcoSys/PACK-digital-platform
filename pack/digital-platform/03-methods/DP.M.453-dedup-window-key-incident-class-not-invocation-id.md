# DP.M.453 — Ключ окна дедупликации уведомлений — класс инцидента, не идентификатор конкретного запуска

## Определение и механизм

Технический идентификатор запуска, меняющийся при повторе одного инцидента, хранится как след конкретной попытки отдельно от ключа подавления повторных уведомлений. Если такой ID входит в ключ, каждый повтор получает новый ключ и обходит окно подавления.

Состав ключа определяется тем, какие события получатель считает повтором одного инцидента. В источнике использованы статус, источник из справочника и этап; это пример состава, а не универсальный набор полей для любой системы.

## Forces

| Давление | Требуемое решение |
|---|---|
| Трассировка отдельного запуска ↔ подавление повторов одного инцидента | Сохранять ID попытки без включения его в ключ только из-за технической уникальности |
| Снижение шума ↔ различимость независимых инцидентов | Задать область действия ключа и признаки, отличающие разные инциденты |
| Простота общего ключа ↔ сохранение сообщения о восстановлении | Проверить семантику исходов и переходов внутри окна |
| Стабильность ключа ↔ изменчивость состава события | Выбирать поля по контракту уведомления, не хешировать автоматически все доступные поля |

## Вход, действие и результат

Вход — событие с ID попытки, признаками инцидента, получателем или иной областью действия, а также параметрами окна. По контракту уведомления выделяются поля, определяющие повтор; из них строится ключ. ID запуска сохраняется отдельно для диагностики.

Результат — повтор одного инцидента распознаётся независимо от числа технических перезапусков, но другой инцидент и предусмотренное восстановление остаются различимыми.

## Границы

Одинаковый ключ двух повторов ещё не доказывает правильность: постоянный ключ удовлетворяет этой проверке и одновременно скрывает другие события. Идентификатор нельзя исключать из ключа только по его названию: если он действительно различает независимые инциденты в данном контракте, его роль отличается от меняющегося ID попытки.

Метод не задаёт универсальную длительность окна и не заменяет аудит всех путей отправки уведомлений.

## Проверка

Заранее заданные пары событий включают повтор одного инцидента с разными ID запуска, два различных инцидента с похожими техническими полями и сообщение о восстановлении. Повторы подавляются внутри окна; различные инциденты не сливаются; предусмотренное восстановление не исчезает как повтор сбоя.

Ожидаемый набор уведомлений задаётся независимо от вычислителя ключа. Наблюдаются фактически отправленные сообщения в подставном канале и сохранённые ID попыток. Дополнительно проверяется поведение после границы окна по принятому контракту повторов.

## Bias-Annotation

| Искажение | Проверка против него |
|---|---|
| «Чем больше полей в ключе, тем точнее дедупликация» | Проверить, не делает ли ID попытки или точное время каждый повтор уникальным |
| «Если два повтора имеют один ключ, всё правильно» | Добавить независимый контрпример: два разных инцидента должны остаться различимыми |
| «Статус + источник + этап годятся везде» | Проверить область действия и различимость событий для данного получателя |
| «Восстановление — ещё одно сообщение того же инцидента» | Убедиться, что предусмотренный переход к восстановлению не подавлен как повтор сбоя |
