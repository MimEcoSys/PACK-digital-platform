# DP.M.467 — Защищённая цепочка запуска read-only клиента

## Назначение

Read-only токен ограничивает операции сервера, но не защищает от подмены клиента, которому токен передан. Метод связывает ограниченный токен с проверяемой цепочкой исполнения.

## Forces

| Force | Tension |
|---|---|
| Неизменяемость клиента ↔ обновляемость | Root-owned установка уменьшает поверхность подмены, но каждое обновление требует доверенной процедуры |
| Изоляция окружения ↔ эксплуатационная доступность | Пустой рабочий каталог и игнорирование PATH снижают влияние вызывающего процесса, но требуют явной передачи только необходимых входов |

## Метод

1. Доверенный человек устанавливает клиент в root-owned каталог и сверяет состав и контрольные суммы.
2. Root-owned обёртка игнорирует PATH и конфигурацию менее доверенного процесса.
3. При каждом запуске проверяется вся цепочка каталогов: владелец root, нет записи для группы и остальных.
4. Клиент запускается из пустого одноразового каталога без доступа к репозиториям вызывающего.

Токен остаётся read-only: защищённая цепочка дополняет, а не заменяет ограничение полномочий.

## Тест

«Может ли процесс, получающий read-only доступ, изменить клиент, его родительский каталог, PATH или рабочее окружение запуска?» Да — цепочка не защищена.

## Bias-Annotation

| Bias | Direction of distortion |
|---|---|
| Якорение на правах токена | Внимание останавливается на read-only scope и не проверяет, какой код фактически получает токен |
| Доверие одной контрольной сумме | Однократная сверка содержимого подменяет проверку владельца и прав всей цепочки при последующих запусках |

## Границы

Это внутренний инженерный метод одного подтверждённого случая, не полный стандарт защиты и не SOTA-карта. Он не защищает от компрометации root или самого поставщика токена.

## Дополнение 2026-11-02: sticky-бит освобождает каталоги, не файлы

Уточнение к шагу 3 («нет записи для группы и остальных»).

- **Каталог** с записью для всех и sticky-битом (`1777`, как `/tmp`) допустим как звено цепочки: чужой пользователь не может удалить или переименовать в нём файл, которым не владеет.
- **Файл** со sticky-битом и записью для всех (`1666`) недопустим: для обычного файла sticky-бит ничего не ограничивает.
- **Проверять тип до исключения:** sticky-бит учитывается, только если объект — каталог (в коде: `S_ISDIR(mode) and mode & S_ISVTX`). Проверка «sticky-бит есть» без проверки типа пропускает открытый на запись файл.
