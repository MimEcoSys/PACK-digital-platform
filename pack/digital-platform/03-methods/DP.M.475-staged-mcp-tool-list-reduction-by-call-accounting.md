# DP.M.475 — Поэтапное сокращение набора MCP-инструментов

**Вход:** шлюз отдаёт N инструментов; клиент деградирует от размера описаний. Пример: 90 инструментов (~62 КБ описаний), 4 дают 75,8% вызовов, у 13 за 20 дней вызовов нет.

**Процесс:**
1. Тесты и учёт вызовов по каждому инструменту (окно ≥ 20 дней).
2. Скрыть из нового списка `tools/list`, сохранив маршрут вызова (старые клиенты не ломаются).
3. Решения пилота по кандидатам на удаление; ArchGate для изменения контракта — эти два шага остаются контрольной точкой (checkpoint), не частью автоматики самого метода.

**Выход:** короткий список без потери обратной совместимости.

**Анти-паттерн:** удалить «неиспользуемое» за один шаг без учёта и маршрута.

**Смежный симптом:** `DP.FM.501` — тот же каталог, но реактивная сторона: конкретный отказ провайдера модели на размере каталога и точечный обходной фикс (allowlist по клиенту). Этот метод устраняет причину на уровне всего каталога; `DP.FM.501` подсказывает, когда причина уже дала сбой.
