# DP.M.477 — Ядро знаний из заимствованной и собственной части: раздельное версионирование

## Описание

Ядро знаний сервиса (например, публичного ИИ-помощника) может собираться из частей с разными владельцами и разной физической возможностью наблюдать изменение: заимствованная часть (клиент к внешнему корпусу — версию сегодня не видит, честно фиксируется как зависимость, а не как готовый механизм) и собственная часть (таблица, которой владеет функциональная роль, не имя человека). Единое правило обновления/версии для обеих частей неверно по построению.

## Forces

| Force | Tension |
|-------|---------|
| Простота единой схемы версии ↔ разные владельцы частей | Одно правило версии проще поддерживать, но заимствованная и собственная часть физически по-разному наблюдают изменение — единая схема либо не работает для одной из частей, либо создаёт ложное чувство синхронности |
| git-commit как версия ↔ коммит версионирует весь репозиторий | Короткий хеш коммита соблазнительно прост, но коллизионен и не привязан к содержимому конкретного артефакта — путается с версией всего репо |
| Хеш внутри версионируемого файла ↔ самоссылка | Хранить хеш файла в этом же файле создаёт цикл (файл меняется от записи своего хеша) — нужен sidecar или манифест снаружи |
| Сверка только по факту правки своей части ↔ рассинхрон от чужой стороны | Проверка «моя часть не менялась → всё синхронно» пропускает случай, когда рассинхрон вызван изменением на ДРУГОЙ стороне — нужны триггеры и по событию, и по расписанию |

## Algorithm

1. Разделить ядро знаний на части по владельцу и физической наблюдаемости изменения (не по формату файла).
2. Для собственной части: версия = полный SHA-256 содержимого, записанный во внешний sidecar-файл (не внутри версионируемого файла — избегает самоссылки).
3. git-коммит рядом фиксируется только как метка происхождения (provenance) — не как версия; короткий хеш коммита не используется как идентификатор версии.
4. Для заимствованной части: зафиксировать как зависимость с честным «версию сегодня не наблюдаем», не изобретать псевдо-версию.
5. Сверка синхронности между частями — по двум независимым триггерам: по событию правки своей части И по расписанию (ловит рассинхрон, вызванный чужой стороной).

## When to use

Когда общий артефакт/корпус знаний собирается из частей с разными владельцами (внешний клиент к чужому корпусу + собственная таблица/раздел) и нужна проверяемая версия хотя бы для части, которую вы контролируете.

## Тест применимости

«Есть ли у ядра знаний часть, физическая возможность наблюдать изменение которой отличается между составляющими (внешний источник vs собственная таблица)?» Да → раздельные правила версии + content-hash sidecar для своей части.
