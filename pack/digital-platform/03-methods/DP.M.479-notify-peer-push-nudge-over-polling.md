# DP.M.479 — Push-уведомление поверх опроса

## Проблема

Периодический опрос (60 с) — единственная гарантия синхронизации между копиями, но добавляет задержку до минуты на каждое изменение, видимое на другом хосте.

## Метод

1. Отдельная подкоманда (`notify-peer`) по SSH посылает соседнему хосту фоновый толчок сразу после публикации.
2. Принимающая сторона форкается и немедленно отвечает вызывающему (fire-and-forget): иначе вызывающий ждёт весь бюджет удалённого fetch соседа.
3. Толчок не заменяет опрос: если сосед не настроен, это молчаливый no-op, а 60-секундный опрос остаётся гарантией доставки.
4. Подключение нового побочного эффекта к общим конвейерам закрытия — отдельная, самостоятельно ревьюируемая правка.

## Тест

«Если толчок не долетел или сосед не настроен — синхронизация всё равно происходит, просто на следующем тике опроса?» Да → толчок чистый ускоритель. Нет → метод нарушен.

## Границы

Толчок подтверждает попытку доставки, а не её завершение; фактическая синхронизация проверяется отдельно, после факта. Поэтому ускоритель нельзя считать причиной для ослабления опроса.
