# DP.M.481 — Самолечение на доказанном подмножестве событий

## Проблема

Безусловный fail-closed останов на грязной копии безопасен по умолчанию, но сам может стать инцидентом: по цитате capture, отслеживаемый файл журнала, оставшийся грязным в `~/.iwe-automation`, заблокировал 742 тика конвейера за 21-25.09.

## Метод

1. При грязной служебной копии не останавливаться безусловно.
2. Сравнить события локального файла с историей на origin (`ledger-event-diff --source-subset` или эквивалент).
3. Если КАЖДОЕ событие файла уже есть на origin, локальная грязь лишь копия опубликованного: отбросить её и продолжить.
4. Если хотя бы одно событие не найдено на origin, оставить fail-closed останов; по частичному совпадению ничего не отбрасывать.

## Отличие от DP.M.437

DP.M.437 требует побайтового совпадения всего набора stash с HEAD перед удалением. Здесь эквивалентность иная: «каждое событие файла уже есть на origin», а байты файла могут отличаться (порядок, форматирование). Направление ошибки тоже иное: DP.M.437 защищает от потери намерения, этот метод защищает от залипания конвейера.

## Тест

«Отбрасывается ли локальная грязь целиком при неполном совпадении с origin?» Да → метод нарушен. «Есть ли локальное событие без соответствия на origin, которое всё равно отброшено?» Да → нарушение.

## Границы

- Применим только при надёжном способе построить полное сравнение подмножества; без него остаётся безусловный fail-closed.
- Это свойство метода, а не утверждение об инциденте: при выполнении условия отбрасывание не теряет событий.
