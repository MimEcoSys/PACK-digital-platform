# DP.M.484 — Устойчивая метка материала отдельно от имени и хэша

## Проблема

Для сопоставления запусков конвейера публикации под рукой два сигнала: имя файла и SHA-256 содержимого. Имя может измениться (правка опечатки), а SHA-256 обязан измениться при новой версии того же материала. Ни один из них не годится как ключ идентичности: по имени переименование даёт ложный дубль, по хэшу обновление не находит прежнюю публикацию.

## Метод

Завести третий сигнал, устойчивую метку материала (в источнике `material_label` в `appProperties` объекта Google Диска):

1. Метка присваивается материалу один раз и не меняется между запусками, версиями и переименованиями.
2. Только по ней конвейер ищет, публиковался ли этот материал.
3. Метка не выводится ни из имени, ни из хэша.

При более чем одном совпадении по метке или по имени папки инструмент останавливается с ошибкой «почини вручную, не угадываю» и не выбирает первое совпадение.

## Тест

«Решает ли конвейер, тот ли это материал, по имени файла или по хэшу?» Да → нужна отдельная устойчивая метка.
