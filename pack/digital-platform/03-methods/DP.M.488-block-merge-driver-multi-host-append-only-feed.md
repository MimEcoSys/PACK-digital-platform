# DP.M.488 — Блочный merge-драйвер для append-only лент с нескольких хостов

## Проблема

Несколько хостов дописывают в конец одного файла (ленты/журнала); third-party правит отдельные блоки на месте. Стандартное построчное слияние git видит конфликт на каждом перекрывающемся append и при `merge=union` перемешивает строки соседних блоков — один повреждённый блок на каждые 150-400 перекрытий.

## Метод

1. **Единица слияния — блок, не строка.** Драйвер распознаёт блок по заголовку без пометок статуса и телу без служебных вставок.
2. **Сопоставление по порядку.** Блоки сопоставляются последовательно; повторы и точные копии обрабатываются корректно без размножения.
3. **Слияние только целых блоков.** Частично совпадающие/повреждённые блоки не собираются из кусков двух версий.
4. **Fallback, не отказ.** Нечитаемая структура → откат на обычное построчное слияние, а не блокировка.
5. **Сбой записи = конфликт.** Если результат не удаётся записать, драйвер возвращает статус конфликта (ручное разрешение), а не тихо теряет один из блоков.
6. **Регистрация.** `.gitattributes` + установщик драйвера; установщик не может молча не поставить драйвер (иначе merge откатится на стандартный без предупреждения).

## Проверка

Оракул «разбор ничего не меняет» (round-trip parse=no-op на корпусе реальных блоков), случайные сценарии слияния на реальных данных, мутационный прогон (48 из 50 мутаций пойманы).

## Границы

Описывает слияние ОДНОГО файла с блочной структурой между git-операциями (merge/rebase/cherry-pick) через `.gitattributes`. Не описывает прикладной протокол восстановления из бэкапов/неопубликованных коммитов при уже случившейся потере (см. DP.M.489 — трёхсторонний merge с явной валидацией полноты для случая, когда стандартное слияние уже отказало).
