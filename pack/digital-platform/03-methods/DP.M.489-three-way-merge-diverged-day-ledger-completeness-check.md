# DP.M.489 — Слияние расходящегося журнала дня с валидацией полноты

## Проблема

Два хоста (Мак и Цех) писали события в один файл дня; у каждого были события, которых не было у другого. Единственная ветка обработки такого расхождения в публикаторе — безусловный `fail()`, из-за чего публикация падала на каждом запуске подряд 6+ часов.

## Метод

1. **Снимок источника** перед слиянием.
2. **Трёхсторонний merge** через merge-driver с пустой базой: порядок берётся от origin, вставка новых записей — по временной метке (`ts`).
3. **Валидация полноты** после слияния: и весь снимок источника, и всё прежнее содержимое целиком (с учётом кратности повторов) обязаны входить в результат — иначе слияние не принимается.
4. **Источник не перезаписывается** — только читается для снимка и сверки.
5. **Защита не ослаблена:** несовпадение шапки файла, битый YAML или событие без `ts` по-прежнему уходят в fail-closed; расширено только покрытие.

## Тест

Две `--source-subset` проверки (снимок и destination оба подмножества результата с учётом кратности) + одна `--validate` — все три обязаны пройти, иначе публикатор не принимает слияние.

## Границы

Метод — для append-only журнала с несколькими независимыми писателями, где расхождение — разница в МНОЖЕСТВЕ событий (не конфликт значений одного события). Не описывает блочную merge-механику на уровне git (см. DP.M.488 — другая техника той же проблемной области).
