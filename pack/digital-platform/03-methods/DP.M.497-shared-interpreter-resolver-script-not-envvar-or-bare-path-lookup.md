# DP.M.497 — Резолвить интерпретатор через общий скрипт рядом с вызывающим

## Проблема

Скрипт проверял наличие интерпретатора через `command -v python3` и присутствие нужной зависимости (PyYAML) напрямую. На хостах с pyenv-шимом впереди в PATH это находило «не тот» `python3` (без PyYAML) — проверка каталога падала ещё до содержательной работы: голый `python3` видит только первый интерпретатор по PATH, которым на таких хостах оказывается шим, а не системный/venv-интерпретатор с нужными пакетами.

## IPO

- **Вход:** вызывающий bash-скрипт, которому нужен python3 с гарантированными зависимостями; возможно заданные, но не гарантированно корректные `$IWE_TEMPLATE`/`$IWE_DIR`.
- **Процесс:** резолвинг интерпретатора выполняется один раз через общий скрипт-резолвер, лежащий рядом с вызывающим скриптом по относительному пути (`$(dirname "${BASH_SOURCE[0]}")/lib/find-python3.sh`), а не через переменные окружения, которые вызывающий может не выставить туда, где реально лежит соседний `lib/`, и не через голый `python3` из PATH, который на хостах с шимами/несколькими версиями не гарантирует нужную сборку.
- **Выход:** путь к интерпретатору с подтверждёнными зависимостями, переиспользуемый для всех последующих вызовов python3 в том же скрипте (резолвится один раз, не на каждый вызов).

## Границы вывода

Метод решает проблему «на PATH не тот интерпретатор», но не проблему «зависимость не установлена вообще ни в одной сборке» — для этого резолвер должен явно проверять импортируемость нужного пакета в найденном интерпретаторе, не только его существование. Путь резолвится относительно расположения самого скрипта (устойчив к cwd), что требует физического соседства `lib/find-python3.sh` с каждым вызывающим — при реструктуризации дерева скриптов относительный путь нужно обновлять синхронно.

## Применимо

Любой bash-скрипт, вызывающий системный Python-интерпретатор по имени, на хостах с несколькими установленными версиями/шимами (pyenv, asdf, conda) впереди в PATH — тот же паттерн, что `DP.METHOD.059` (bash 3.2 + python3 heredoc) решает для синтаксической портируемости, здесь — для резолюции самого бинаря.
