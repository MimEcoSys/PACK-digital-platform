# DP.M.504 — Один PR с секцией на потребителя для общего файла двух независимых задач

## Проблема

Две независимые задачи (разные РП, разные владельцы, разные коннекторы/потребители) обнаруживают, что им обеим нужно добавить материал на одни и те же страницы/в один файл — с разными данными под разного потребителя. Смешать правки в один общий абзац — потерять разделение фактов, которые на самом деле не связаны. Открыть два конкурирующих PR на одних файлах — создать конфликт правок при слиянии.

## IPO-паттерн

| Элемент | Описание |
|---|---|
| Входы | Две независимые задачи, каждая обязана добавить материал в один и тот же файл/страницу; у каждой свой потребитель (коннектор, аудитория) и свои данные |
| Обработка | Один PR, затрагивающий общий файл; на каждой затронутой странице — отдельная секция под каждого потребителя, без смешения в общий абзац |
| Выходы | Один PR без конфликта правок; секции физически разделены, поэтому факты разных потребителей не перепутываются при последующем редактировании |

## Когда применять

Любая ситуация, где доставка одной задачи обнаруживает уже открытую или параллельно спланированную другую задачу с правками на тех же файлах, но для другого потребителя с другими данными.

## Антипаттерн

- Слить правки в общее описание/абзац под обоих потребителей — следующая правка одного потребителя рискует задеть факты другого.
- Открыть два отдельных PR на одних и тех же файлах — гонка слияний, конфликт.

## Прецедент

WP-581 (анонимный MCP-сервер, страницы privacy/terms/support) при реализации обнаружил уже запланированную параллельно задачу WP-304 Ф7 — те же три страницы сайта (`aisystant/aisystant-com`, VitePress), но под другой входной OAuth-коннектор. Сведены в один PR (#7) с отдельным разделом на каждой странице под каждый коннектор.
