# DP.M.506 — АрхГейт «предупреждения без блокеров» фиксируется пакетом пред-условий и тестов приёмки до фазы, не после

## Проблема

Архитектурное ревью иногда не даёт чистый pass/fail, а профиль вида «часть пунктов подтверждена, часть вызвала предупреждения, но без жёстких блокеров». Расплывчатое решение «в целом нормально, можно двигаться дальше» прячет реальный риск: часть предупреждений может остаться неразрешённой до следующей фазы, и пилот впоследствии не может восстановить, на что именно он согласился.

## IPO-паттерн

| Элемент | Описание |
|---|---|
| Входы | Профиль архитектурного ревью с k✅/(N-k)⚠️ без жёстких блокеров; список конкретных предупреждений от нескольких критиков (пир-сессия) |
| Обработка | Каждое предупреждение переводится либо в обязательное пред-условие (должно быть выполнено ДО включения в рабочий цикл следующей фазы), либо в именной тест приёмки (конкретная проверка с именем, не абстрактный пункт чеклиста); пилот одним решением принимает весь пакет рисков целиком, без правок по отдельным пунктам |
| Выходы | Явный список обязательных пред-условий + явный список именных тестов приёмки, зафиксированные ДО следующей фазы; одно пакетное решение пилота о принятии риска |

## Когда применять

Любое архитектурное ревью (АрхГейт), завершившееся профилем «есть предупреждения, нет жёстких блокеров» — ни чистый pass, ни fail.

## Антипаттерн

Зафиксировать результат ревью как расплывчатое «в целом нормально» без явного списка условий и тестов — тогда часть предупреждений неотличима от разрешённых, а пилот не может позже восстановить объём принятого риска.

## Прецедент

АрхГейт для схемы `allocation_confirmed` (WP-561 Ф33, разделение допуска и выделения эксклюзивного ресурса): профиль 2✅/5⚠️ без блокеров после критики Kimi+Codex. Шесть обязательных пред-условий (явная машина состояний выделения, fencing token на каждое новое выделение, атомарная проверка допуска+активности выделения вместе, явное отображение старого флага в новую идентичность ресурса + replay-тест, независимый наблюдатель инварианта, числовой бюджет валидатора до живых производителей) и пять именных тестов приёмки зафиксированы как обязательные до включения в Ф85, не после. Пилот принял риски пакетом, без правок по отдельным пунктам.
