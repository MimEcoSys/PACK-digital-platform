# DP.M.510 — Три независимых состояния годности строки каталога сервисов

## Проблема

Реестр сервисов/карта (например, карта MCP-серверов) легко скатывается к одной колонке «статус», куда записывается смешанная информация: «код есть», «сервер развёрнут и отвечает», «это пока только план». Читатель карты не может по одной строке понять, нужно ли что-то проверять живым пробой, или строка — чистая декларация намерения.

## IPO-паттерн

| Элемент | Описание |
|---|---|
| Входы | Строка реестра сервисов/карты с прежней смешанной колонкой «статус» |
| Обработка | Развести на три независимые оси: (1) существование кода, (2) факт развёртывания публичного адреса, (3) статус «только план» — каждая проверяется и фиксируется отдельно, плюс отдельная дата последней живой проверки |
| Выходы | Строка реестра, где «код есть» не маскирует отсутствие публичного адреса, а «план» не путается с уже созданным сервером; дата живой проверки отделена от самого факта готовности |

## Когда применять

Любой реестр/каталог компонентов (сервисов, серверов, интеграций), где колонка «готовность»/«статус» рискует смешать разные по природе факты: существование артефакта, факт его развёртывания, и намерение/план без артефакта.

## Антипаттерн

- Одна колонка «статус: готово/не готово» на три разных по природе факта — читатель достраивает недостающее по аналогии с похожими строками.
- Отметка «готово» без отдельно датированной живой проверки — по умолчанию достраивается как «проверено сейчас», хотя могла быть внесена давно.

## Прецедент

Реестр MCP-серверов (`DP.MAP.004`) переписан в рамках WP-596: прежняя версия проверяла только источник строки («нужна проверка» без прямой ссылки), новая явно разводит три независимые оси и требует для каждой строки отдельно датированную живую проверку вместо достраивания по аналогии с похожими серверами.
