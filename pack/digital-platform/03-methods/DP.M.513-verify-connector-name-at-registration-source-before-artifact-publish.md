# DP.M.513 — Сверка имени коннектора и префикса инструментов перед публикацией Artifact с MCP-capabilities

## Проблема

Peer-сессия wp578 (мониторинг-дашборд менторства): writer предложил публикацию Artifact 1:1 с заявленными MCP-capabilities. Критик (Kimi) указал на риск — рассинхронизация между именем коннектора и префиксом инструментов, заявленными в шапке Artifact, и реальным runtime-вызовом `claude.use("mcp")` даёт неразличимый фейл: пустое табло вместо явной ошибки «страница не найдена» или «инструмент недоступен». Причина — автор опирался на предположение по тексту вызывающего кода страницы, не на фактическую регистрацию сервера.

## Метод

Перед публикацией Artifact, заявляющего capabilities конкретного MCP-коннектора:

1. Найти место регистрации сервера — вызов `McpServer({name: ...})` (или эквивалент) в исходнике шлюза.
2. Сверить точное имя коннектора и префикс инструментов (например, `mentorship_*`) с тем, что заявлено в шапке Artifact.
3. Не принимать имя/префикс как факт по чтению вызывающего кода страницы — гипотеза должна быть подтверждена в месте регистрации, а не выведена по аналогии или памяти.

## Применение

Применимо к любой публикации Artifact (или аналогичного клиентского кода), заявляющей использование конкретного MCP-коннектора по имени. Расширяет тот же принцип, что и DP.M.017 («не хардкодить capability, строить по факту») — здесь принцип применён на шаге публикации автором, а не на шаге runtime-загрузки клиентом: «не предполагать состав/имя capability по коду, сверять с источником регистрации» перед тем, как заявление об этом попадёт во внешний артефакт.

## Связи

- `DP.M.017` (Runtime Tool Discovery) — тот же принцип «не доверять предположению о capability», разный момент применения: там runtime-сторона клиента (`tools/list`), здесь — pre-publish сторона автора.
- `DP.ROLE.038` (MCP Tool Consumer) — роль, реализующая discovery на runtime-стороне; этот метод — процедура на стороне публикации клиентского артефакта, не на стороне исполнения.
- `DP.MAP.004` (MCP Server Catalog) — держит актуальные имена коннекторов и префиксы инструментов как справочник; этот метод предписывает сверяться с ним (точнее — с кодом регистрации, который он документирует) перед публикацией.
- `DP.FM.593` (`2026-10-11-inbox-check.md`, кандидат #1) — смежный failure mode о том же классе риска «имя коннектора не константа»: там — авторазрешение capability на claude.ai резолвит коннектор по имени в АККАУНТЕ получателя инструкции (межпользовательский сценарий), здесь — автор перед публикацией не проверяет имя в месте регистрации (сценарий одного автора). Общая тема, разные механизмы — не дубликат.
