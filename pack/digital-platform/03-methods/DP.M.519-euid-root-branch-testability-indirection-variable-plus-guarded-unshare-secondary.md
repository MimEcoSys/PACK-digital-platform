# DP.M.519 — Тестируемость кода, ветвящегося по EUID/root: indirection-переменная + guarded secondary-тест

## Проблема

Код, ветвящийся по идентичности/привилегиям процесса (например, `EUID == 0`), нельзя протестировать напрямую изнутри того же процесса — `EUID` в bash readonly. Попытка подделать это реальным повышением привилегий (`unshare --map-root-user`) работает не везде: в части CI-песочниц с AppArmor-ограничениями unprivileged user namespaces недоступны, и тест молча скипается именно в том окружении, где покрытие нужнее всего (CI), создавая ложное чувство покрытия.

## Метод

1. Вынести проверку привилегии за переопределяемую индирекцию — тестовую переменную, которая в production-коде никогда не читается, а в тестовом окружении может быть явно установлена в любое значение.
2. Через эту переменную детерминированно покрыть обе ветки (root / не-root) без зависимости от реальных привилегий процесса или возможностей песочницы.
3. Оставить проверку через реальное повышение привилегий как ДОПОЛНИТЕЛЬНУЮ secondary-проверку реального пути — не единственную, с явным capability-гвардом: если возможность недоступна, тест пропускается заметно (явный skip с причиной), а не проваливается и не выдаёт ложный зелёный.

## Тест

«Ветвится ли код по идентичности/привилегии процесса, которую нельзя подделать изнутри самого процесса (EUID, capability, namespace)?» Да + «единственный способ протестировать обе ветки — реальная смена привилегий, доступная не на всех целевых средах (включая CI)?» → применим этот метод: добавить тестовую indirection-переменную как основной путь покрытия, реальную привилегию — вторичной guarded-проверкой.

## Применимость

Любой код, ветвящийся по привилегиям/идентичности процесса, которые нельзя подделать изнутри самого процесса — не только EUID/root: тот же приём применим к любой неподделываемой снаружи характеристике рантайма (capability sets, namespace membership и т.п.), если реальное воспроизведение характеристики недоступно во всех целевых тестовых средах.
