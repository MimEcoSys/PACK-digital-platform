# DP.M.530 — Fail-closed вычисление дедлайна при нарушенном инварианте журнала

## Проблема

Вычисление производной величины (дедлайна, SLA-срока) из цепочки событий в журнале предполагает, что цепочка не нарушает свой инвариант (например, «таймер двигается только через явный переход с доказательством разрешения»). Если часть истории повреждена или обходит инвариант, молчаливое вычисление по формуле даёт правдоподобную, но неверную дату — ошибка невидима, пока кто-то не проверит её вручную.

## IPO-паттерн

| Элемент | Описание |
|---|---|
| Входы | Цепочка событий с заявленным инвариантом перехода (например, «поле X двигается только через событие Y с доказательством Z») |
| Обработка | Перед вычислением производной величины — проверить, что история СОБЛЮДАЕТ заявленный инвариант; если нет — отказаться вычислять и сообщить о нарушении (а не подставить правдоподобное значение) |
| Выходы | Либо корректно вычисленная величина на неповреждённой истории, либо явный отказ с диагностикой (какие записи нарушают инвариант), вместо тихо неверного значения |

## Когда применять

Любой детектор/расчётчик производной временной метки (дедлайн, SLA, TTL) из append-only журнала, где возможны исторические нарушения инварианта перехода (ручные правки, миграции, баги прошлых версий).

## Антипаттерн

Вычислять дедлайн формулой по последней записи цепочки, не проверяя, что вся цепочка до неё соблюдает заявленный инвариант перехода — при повреждённой истории формула даёт синтаксически валидную, но содержательно неверную дату, которая выглядит как нормальный результат.

## Прецедент

При включении часового автозапуска детектора расхождений pilot/production холодное ревью нашло: 56 из 297 записей имели `first_seen_unmatched_at`, сдвинутый вперёд без промежуточной resolved-записи с `resolution_evidence`. Детектор сам определяет инвариант («SLA-таймер двигается только через явный resolved-переход с доказательством») и отказывается считать дедлайны, если история ему противоречит (`"SLA clock advanced without resolution evidence"`), вместо молчаливого вычисления `sla_deadline_at` из повреждённой цепочки. Повреждённое поле откатано на самое раннее значение цепочки перед включением автозапуска. Отдельно в том же прецеденте: без throttle алерт о известном backlog уходил бы в Telegram каждый час навечно — добавлено ограничение не чаще раза в UTC-сутки либо сразу при появлении нового `delta_id`.
