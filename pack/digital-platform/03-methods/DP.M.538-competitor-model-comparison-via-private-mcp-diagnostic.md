# DP.M.525 — Диагностика публичного ответа сравнением с конкурентной моделью через приватный MCP

## Проблема

Как диагностировать, что публичный ответ (сайт/бот) на некий вопрос слабый, если нет готового эталона для сравнения, а собственная оценка субъективна?

## IPO-паттерн

| Элемент | Описание |
|---|---|
| Входы | Контрольный вопрос с подозрительно слабым публичным ответом; доступен приватный/полный источник знаний (приватный MCP) через отдельный авторизованный интерфейс (например, коннектор в ChatGPT) |
| Обработка | Задать тот же контрольный вопрос через сторонний интерфейс с доступом к ПРИВАТНОМУ полному корпусу (не публичному урезанному); сравнить ответы; выделить конкретное улучшение (структура, примеры, источники), переносимое на публичную сторону БЕЗ переноса приватного содержимого как такового |
| Выходы | Конкретное улучшение публичного ответа; явное подтверждение, что публичная и приватная поверхности остались раздельны (улучшение — про форму/полноту ответа, не про утечку приватных данных) |

## Когда применять

Диагностика качества публичного AI-ответа при наличии более полного приватного источника знаний, доступного через отдельный (авторизованный, не публичный) канал — сравнение используется только как источник диагностики, не как канал переноса приватного контента.

## Антипаттерн

Теоретизировать об архитектурной причине слабого ответа вместо эмпирического сравнения с ответом на тот же вопрос при доступе к более полному источнику.

## Прецедент

WP-442 (14.10.2026, запуск tserenov.com): контрольный вопрос о системном мышлении на гостевой форме сайта получил слабый ответ. Тот же вопрос задан ChatGPT с доступом к приватному полному IWE MCP → разница показала необходимость практического первого шага и связанных источников. Публичный ответ доработан; публичная/приватная поверхности MCP остались разделены (публичный сайт — только открытый MCP и опубликованные материалы, частный IWE MCP — только в авторизованном ChatGPT).
