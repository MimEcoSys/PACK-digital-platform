# DP.M.543 — Диагностика наличия вместо измерения размера внутри бюджета времени

## Проблема

Скрипт проверки покрытия заявляет жёсткий временной бюджет (≤3 секунды на N источников). Добавление `du -sh` на каждый источник для информативности (например, показать объём резервной копии) не укладывается в этот бюджет на крупных деревьях каталогов (сотни ГБ, минуты выполнения) — особенно когда один из источников — целый домашний каталог пользователя.

## IPO-паттерн

| Элемент | Описание |
|---|---|
| Входы | Список источников из конфигурации (YAML), каждый — путь на диске произвольного размера |
| Обработка | Для каждого источника — только `os.path.exists()`; размер НЕ вычисляется на этапе проверки покрытия |
| Выходы | Статус «источник присутствует / пропущен» за время, не зависящее от размера дерева каталогов |

## Когда применять

Диагностический/проверочный скрипт с заявленным временным бюджетом должен измерять именно то, что бюджет позволяет измерить. Если вопрос — «источник на месте?», факта присутствия (`exists()`) достаточно; дорогая метрика (размер, хэш содержимого, число файлов), даже если кажется полезной рядом, не добавляется в тот же проверочный проход без пересмотра бюджета.
