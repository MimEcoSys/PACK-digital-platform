# DP.M.549 — Передача большого файла без встраивания всего бинарника в запрос инструмента

## Проблема

Если конкретная обёртка передаёт весь файл как base64 внутри JSON, крупный бинарник может превышать практические ограничения запроса и памяти. Это свойство конкретного маршрута, а не всех MCP-инструментов.

## Входы и выходы

Вход: файл, ограничения инструмента/API, разрешённые учётная запись, операция и объект назначения. Выход: подтверждённый объект в назначении либо явно незавершённая передача с допустимым способом возобновления.

## Метод

1. Выбрать поддерживаемый потоковый или возобновляемый маршрут. Расширение обёртки и прямой API — возможные варианты, выбор зависит от договора интеграции.
2. Использовать разрешённый механизм аутентификации без раскрытия секретов. Наличие токена не разрешает извлекать его или обходить ограничения среды.
3. Проверить завершение по ответу сервиса и свойствам целевого объекта. После обрыва сверить состояние загрузки и продолжить по протоколу сервиса.
4. Отдельно проверить повторы создания объекта: возобновляемая передача не гарантирует отсутствие дублей и exactly-once.

## Forces

Меньший размер запроса и устойчивость к обрыву требуют дополнительного состояния передачи. Прямой API расширяет варианты, но обязан сохранять полномочия, аудит и ограничения штатной интеграции.

## Bias-Annotation

Успешный прямой вызов провоцирует считать любую обёртку непригодной. Владение учётными данными ошибочно принимают за разрешение любого их использования; проверять конкретную операцию и назначение.

## Исторический пример и границы

Отчёт MC-sessions `2026-10/2026-10-18-WP-385.md` сообщает о загрузке видео 325 МБ через Drive API. Новая загрузка здесь не выполнялась. Google рекомендует resumable для файлов более 5 МБ и при риске обрыва; это рекомендация сервиса, не универсальная граница MCP.
