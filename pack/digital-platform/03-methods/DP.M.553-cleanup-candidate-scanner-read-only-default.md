# DP.M.553 — Поиск кандидатов на уборку выдаёт отчёт до разрешённого действия

## Входы и выходы

Вход: область сканирования, признаки остаточного состояния и доступные свидетельства. Выход: список кандидатов с основаниями и ограничениями проверки. Попадание в отчёт не разрешает удаление.

## Метод

1. Отделить обнаружение от действия. По умолчанию новый находчик сообщает результаты без удаления или перемещения пользовательских данных.
2. Для каждого кандидата обозначить, что проверено, а что неизвестно: владелец, активность, локальные изменения, неотслеживаемые файлы, неопубликованные коммиты.
3. До разрешённой уборки повторно проверить актуальность и сохранность данных в точке действия. Возраст, закрытая сессия и метка `prunable` сами по себе не разрешают удаление существующего каталога.
4. Автоматизацию уборки вводить по явному договору полномочий и риска. Отдельный коммит или отдельная сессия не являются универсальным требованием метода.

## Историческая граница

iwe-local-config `d4537da4f843e70be8060548050abb2c01eb55b6` добавил `worktree-residue-report.sh` без удаления: `git worktree prune --dry-run`, `diff --quiet` и `diff --cached --quiet`. Эти проверки не выявляют рабочую копию только с неотслеживаемыми файлами и не устанавливают публикацию всех коммитов. Отсутствие предупреждения не доказывает безопасность уборки. `prunable` описывает административную запись Git, не ценность существующего каталога. Уборка в рамках публикации знания не выполнялась.

## Forces

Простой отчёт быстро делает остатки видимыми, но неполный охват может создать ложную уверенность. Автоматизация экономит ручное время ценой необходимости строгого разрешения и повторной проверки состояния.

## Bias-Annotation

Называние объекта «мусором» склоняет сразу удалять его. Чистый diff ошибочно принимают за отсутствие ценных данных, забывая неотслеживаемые файлы и неопубликованные коммиты.
