# DP.M.557 — Отдельная именованная функция подключения на каждую базу

## Описание

Когда сервису нужны данные из нескольких баз/источников, для каждой базы заводится отдельная, явно поимённая функция подключения (`getPersonaSql`, `getLmsSql`, ...), а не один общий коннектор (`getSql(target)`), выбирающий базу по параметру/флагу.

## IPO

**Вход:** сервис с одной существующей функцией подключения (настроенной по умолчанию на один домен), которому для нового инструмента нужны данные ещё из одной-двух баз.

**Процесс:**
1. На каждую дополнительную базу — отдельный файл/функция с именем, называющим базу (`getPersonaSql` для базы персон, а не `getSql('persona')`).
2. Для источников с урезанными правами — отдельный файл модуля через ограниченную read-only роль, не переиспользование функции с полными правами и условным ограничением внутри кода.
3. Не добавлять параметр/флаг выбора базы к существующей общей функции подключения.

**Выход:** вызов не той базы из-за забытого/перепутанного параметра структурно невозможен — для обращения к другой базе нужно вызвать другую функцию, а не передать другое значение параметра в ту же функцию.

## Тест применимости

«Можно ли по ошибке обратиться не к той базе, передав неверное значение параметра/флага в общую функцию подключения?» Да → завести отдельную именованную функцию на каждую базу. Нет (на каждую базу уже своя функция) → метод уже применён.

## Антипаттерн

Одна функция подключения с параметром выбора целевой базы — выбор базы становится значением параметра, которое можно забыть передать или передать неверным при копировании вызова.

## Отличие от смежного

`DP.M.201` (Separate API Keys per Workload) — тот же общий приём «раздельный именованный доступ вместо одного общего с параметром», но другой триггер и другая опасность: DP.M.201 разделяет credentials, чтобы один workload не исчерпал квоту другого (blast radius по rate-limit); DP.M.557 разделяет функции подключения, чтобы вызов структурно не мог адресоваться не той базе (blast radius по неверной цели запроса, не по квоте). Смежные, не дубли — можно применить оба одновременно к одному сервису.
