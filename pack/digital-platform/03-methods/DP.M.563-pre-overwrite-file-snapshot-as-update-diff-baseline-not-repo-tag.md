# DP.M.563 — Снимок файла до перезаписи как источник «прежней» версии

## Проблема

Для шага «показать диф, что изменилось при обновлении» нужен надёжный источник «прежнего» состояния. Резервный вариант — git tag текущего репозитория (на случай отсутствия файла версии) — не доказывает, какая версия была установлена у пользователя до обновления: тег характеризует состояние репозитория-источника, может быть создан позже, отсутствовать вовсе, или не совпадать с реально развёрнутой версией.

## IPO

- **Вход:** артефакт, который будет перезаписан при обновлении (например, CHANGELOG.md), момент непосредственно перед перезаписью.
- **Процесс:** сделать снимок (копию) самого файла во временный путь непосредственно перед перезаписью; после обновления сравнивать новый файл с этим снимком, а не с метаданными репозитория-источника (git tag, манифест версии).
- **Выход:** диф, достоверно отражающий то, что реально изменилось на этой конкретной машине, а не то, что изменилось в репозитории-источнике между произвольными тегами.

## Прецедент

При обновлении Kimi предложил резервный источник старой версии — git tag (на случай отсутствия `.iwe-runtime/iwe-release.json`). Codex возразил, и это возражение принято как основной контракт вместо резерва: снимок файла непосредственно перед перезаписью — надёжный источник, тег — не надёжен.

## Переносимость

При реализации «показать, что изменилось при обновлении» источником истины о прежнем состоянии должен быть снимок фактического артефакта, сделанный непосредственно перед мутацией на этой машине — не внешние метаданные источника.
