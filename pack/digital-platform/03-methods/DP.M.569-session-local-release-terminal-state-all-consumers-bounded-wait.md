# DP.M.569 — Локальное освобождение сессии: третий терминальный исход + аудит потребителей

## Назначение

Добавить в конечный автомат жизненного цикла сессии безопасный третий исход закрытия — «освободить локально, без публикации» — так, чтобы ни один существующий потребитель состояния не «оживил» освобождённую запись.

## Метод

1. Новый терминальный исход фиксируется отдельным событием журнала (`session_closed_local`) — квитанция о намерении, а не публикация содержимого.
2. Запись сохраняет удержание изолированной рабочей копии (воркдерево не освобождается для повторного использования).
3. Все существующие потребители состояния сессии — публикаторы, механизм уборки изолятов, обработчики остановки, проверка перед коммитом, расчёт owner-status — получают проверку «эта запись удержана локально?» и при положительном ответе не считают её активной и не пытаются восстановить обязательство публикации.
4. Конкурирующие операции над той же записью ждут освобождения блокировки ограниченное время (30 с для публикаторов, 2 с для обработчиков), а не падают немедленно при первом конфликте.

## Forces

Безопасность нового терминального состояния ↔ полнота обхода потребителей: пропущенный потребитель — это не ошибка самого состояния, а дыра в охвате аудита. Мгновенный отказ при конфликте блокировки ↔ ложные срабатывания на короткоживущих гонках: ограниченное ожидание снижает долю ложных отказов, но не устраняет конфликт полностью.

## Тест

«В конечный автомат жизненного цикла добавляется новое терминальное состояние?» Да → перечислить всех существующих потребителей текущих состояний (кто читает/реагирует на статус записи) и явно решить для каждого: считает ли он новое состояние активным, завершённым или требующим действия. Пропуск хотя бы одного потребителя воспроизводит эту FM-класса дыру.

## Bias-Annotation

Склонность считать конечный автомат «закрытым» после правки точки входа (там, где состояние создаётся), не проверяя все точки выхода (где состояние читается). Это создаёт ложную уверенность в полноте изменения.
