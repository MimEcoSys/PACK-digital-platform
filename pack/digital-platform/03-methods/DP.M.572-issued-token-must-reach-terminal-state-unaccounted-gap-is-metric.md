# DP.M.572 — Выданный токен допуска всегда завершается конечным состоянием

## Проблема

Билеты закрытия выдавались без конечного состояния. За день: выдано 14, использовано 3; в хвосте 232 висящих билета и 52 `.open.lease` без `.open`. По такому следу потерянную работу невозможно отличить от забытого билета: «тихий хвост» не несёт сигнала.

## Метод

1. Каждый выданный билет обязан закончиться одним из трёх конечных состояний: **использован**, **истёк**, **аннулирован**.
2. Просроченные билеты истекают лениво — под сессионной блокировкой, при следующем обращении, без отдельного демона.
3. Отказавший запуск аннулирует свой билет только после подтверждения владельца (чужой живой билет не трогается).
4. Метрика `close_tickets` показывает: выдано против использовано / истекло / аннулировано и **неучтённый разрыв**. Ненулевой растущий разрыв — сигнал, а не фон.

## Тест применимости

«Для любого выданного токена допуска (билета, лиза) можно ли назвать, чем он закончится, если владелец исчез?» Нет → метод не применён; «есть ли метрика разницы между выданным и учтённым?» Нет → хвост растёт молча.

## Границы

- Источник — сообщение коммита и пересказ в capture; сам коммит в снимках не смонтирован и не сверялся. Числа (14 / 3 / 232 / 52) — наблюдение одного дня, не норма.
- Пиры отвергли дедупликацию и вытеснение билетов: билет вшит хуком в команду, и вытеснение могло бы убить ещё не запущенную работу. Метод не требует и не рекомендует их.
- Метод не определяет срок истечения — он зависит от длительности закрытия в конкретной системе.
