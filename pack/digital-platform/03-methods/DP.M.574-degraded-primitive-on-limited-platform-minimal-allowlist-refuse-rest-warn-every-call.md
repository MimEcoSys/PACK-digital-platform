# DP.M.574 — Деградированная реализация примитива на ограниченной платформе

## Проблема

Примитив (замок, семафор, атомарная запись) построен на системных вызовах, которых нет на части платформ. Два плохих выхода: отказывать на любой операции, и тогда критический контур не стартует вовсе; либо тихо пропускать охрану или имитировать гарантию, и тогда потеря гарантии остаётся скрытой (`DP.FM.461`).

## Метод

1. Определить минимальный белый список операций, без которых критический контур не запускается и которые безопасно реализовать упрощённо.
2. Для этих операций включить упрощённую реализацию по признаку платформы; остальным операциям — отказ сразу, до любых изменений состояния.
3. На каждом вызове печатать предупреждение с названием потерянной гарантии. Не один раз за сессию: гарантия отсутствует на каждом вызове.
4. Сохранить формат состояния совместимым с полной реализацией в обе стороны: состояние, созданное упрощённой реализацией, читает полная, и наоборот.
5. Сохранить проверки подлинности и запрет внедрения в данные, которые не зависят от недостающего вызова.
6. Чужой замок не забирать автоматически (по номеру процесса или по давности): при конфликте — сообщение с путём для ручного снятия.

## Тест применимости

«Платформа не даёт вызов, на котором построен примитив; есть ли соблазн тихо пропустить охрану, имитировать гарантию или распространить упрощённую реализацию на все операции?» Любое «да» → метод применим. Если безопасной упрощённой реализации для нужных операций нет — явный отказ.

## Пример

Windows Git Bash: нет синхронизации каталога на диск и блокировок через `fcntl`. Упрощённая реализация на чистом bash включается по имени платформы для трёх команд ночного контура; замок строится на создании каталога; предупреждение о недолговечности при сбое питания печатается на каждом вызове. Отвергнуто: тихий пропуск охраны, авто-захват замка по номеру процесса (номер переиспользуется, живой потомок), распространение на все команды.

## Границы

- Упрощённая реализация не даёт долговечности после сбоя питания; метод только честно сообщает об этом.
- Список операций и признак платформы зависят от системы; пример иллюстрирует принцип, а не рецепт.

## Отличие от соседей

- `DP.FM.563` — модуль падает при загрузке из-за платформенного импорта; `DP.FM.538` — отказы замка на каталогах и номерах процессов; `DP.FM.461` — тихий fallback скрывает поломку. Здесь — способ действовать при недоступном примитиве.
