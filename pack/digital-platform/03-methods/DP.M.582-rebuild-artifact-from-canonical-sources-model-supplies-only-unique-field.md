# DP.M.582 — Пересборка из канонических источников поверх ответа модели

## Контекст

Таблицу РП в плане дня писала модель, а шаг 4.45 точечно правил её строки. После каждой правки снова появлялись значения вне легенды ТВС («Н», 🔴 без реальной аварии): правка ловила известные отклонения, а модель производила новые.

## Метод

1. **Пересобирать, а не править.** Программа строит строки артефакта целиком из канонических источников (приоритеты, перенос с прошлого дня, пул недели). Строки модели не исправляются, а заменяются.
2. **От модели — только незаменимое.** Для каждого поля задаётся вопрос: «можно ли вывести его из данных?» Да → поле строит программа. Нет → поле берётся у модели. В плане дня таким полем оказалась одна отметка: «С» в день реальной аварии.
3. **Значение вне легенды выводится, а не хранится.** Недопустимое значение не переносится в результат и не заменяется по умолчанию. Его выводит правило из источника: ТВС вне легенды → В/Т по направлению пула; 🔴 без реальной аварии → 🟡.
4. **Ненадёжный вход виден.** Если пункт переноса не распознан (нет номера РП), лишние строки модели не удаляются молча, а называются в разделе «Требует внимания»; отсутствие таблицы или колонок тоже попадает туда отдельной строкой.
5. **Приёмка — детерминизм.** Три прогона подряд на одних входах дают байт-в-байт одинаковый результат. Расхождение означает, что в результат ещё проходит вклад модели сверх разрешённого поля. Одинаковые прогоны подтверждают детерминированность, но не правильность поля, которое дала модель: искажённое поле пересборка воспроизведёт так же стабильно.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|--------|--------|-------------------------|
| Гибкость модели: она видит контекст дня и пишет связный план | Предсказуемость артефакта: значения только из легенды, строки только из данных | Модели оставлено одно явно названное поле, всё остальное строит программа |
| Дешёвая точечная правка известных отклонений | Полная замена строк даёт больше кода и риска регрессии | Пересборка заменяет бесконечный список правок одним правилом «строка = функция от источников» |
| Тихая нормализация, чтобы артефакт выглядел чистым | Видимость ненадёжного входа для человека | Нераспознанное не удаляется молча, а выводится в «Требует внимания» |

## Bias-Annotation

- **Смещение к детерминизму (в сторону программы):** метод перетягивает вклад от модели к коду; направление — потеря информации, которую знает только модель. Защита: вопрос «можно ли вывести из данных?» задаётся по каждому полю, а список полей модели пересматривается при замере.
- **Смещение приёмки (в сторону проверяемого):** «три прогона байт-в-байт» легко проверить, поэтому его принимают за доказательство правильности; на деле оно доказывает только отсутствие дрейфа. Защита: поле модели («С») проверяется отдельно человеком или независимым источником.
- **Смещение одного прецедента:** метод выведен из одной таблицы плана дня; переносимость на другие артефакты утверждается по логике, а не по замерам.

## Тест применимости

«Сколько полей артефакта модель знает лучше данных?» Если меньше, чем пишет сейчас, — пересобирать, оставив модели только эти поля.
