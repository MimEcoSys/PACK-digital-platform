# DP.M.583 — Охранник вычисляет цель, а не угадывает по тексту

## Проблема

Хук искал `git add` в тексте команды. Текстовый поиск ошибается в обе стороны: блокировал `(cd <другой репозиторий> && git add)`, где индекс канона не затрагивается, и пропускал обходы через `$(…)`, `GIT_DIR`, `--git-dir`, `GIT_INDEX_FILE`. В базе уже шесть карточек об охранниках, слепых к устройству команды (DP.FM.417, 421, 423, 605, 624, AS.FM.147), но метода лечения в этом Pack не было. Правило AR.302 задаёт тот же принцип для удаления через рантайм-обёртку, проверяющую цель в момент исполнения; здесь разбор команды до исполнения с отказом при неопределённости.

## Метод

1. **Разбор как при исполнении.** Команда разбирается последовательно: подоболочки, `cd` через `&&` и `;`, цепочка `-C`, `env -u`, `bash -c`.
2. **Вычисление цели.** Определить файл индекса, который реально изменится, и сравнить его с индексом канона, а не искать слова в тексте.
3. **Неопределённая цель блокируется.** Если разобрать команду так, чтобы назвать цель, не удалось, охранник отказывает (решение пилота 29.10.2026). Отказ называет причину и просит указать репозиторий литерально.
4. **Границы записаны.** Осознанно не закрыты склейки имени (`g''it`), алиасы и `cd` через `;` в отдельных формах. Граница зафиксирована в коммите, тест из 49 сценариев покрывает ложные блоки и обходы.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|--------|--------|-------------------------|
| Не мешать законной работе (ложные блоки) | Не пропускать обходы | Вычисление фактической цели вместо поиска слов |
| Разбирать любой синтаксис shell | Разбор всегда неполон | Неопределённость считается отказом, границы названы открыто |
| Простота охранника | Охранник становится мини-интерпретатором | Разбор вынесен в отдельный помощник под тестом |

## Bias-Annotation

- **Смещение к безопасности:** блокировка при неопределённости увеличивает число отказов в нетипичных, но законных командах; платой считается указание репозитория литерально.
- **Смещение одного прецедента:** метод выведен из запрета стейджинга; переносимость на другие охранники (удаление, запись) утверждается по сходству семейства, а не по замеру.
- **Неполнота разбора:** любой разбор shell обходим; границы названы, но не исчерпаны.

## Тест применимости

«Решает ли охранник по тексту команды или по тому, что команда изменит, и что он делает, когда цель определить не удалось?» Решает по тексту или пропускает при неопределённости → метод не применён.
