# DP.M.584 — Диагностика зависания фонового шага: свидетельства до убийства

## Определение

Способ получить разбираемые свидетельства о зависшем дочернем шаге: вывод шага течёт в файл с первой строки, а сторож, сработавший раньше таймаута, пишет в журнал снимок живого процесса: хвост вывода, дерево процессов и открытые файлы. Только после этого таймаут убивает шаг.

## Проблема

Шаг освобождения завис на 900 секунд внутри закрытия, был убит по таймауту, а журнал хранил одну строку «start»: вывод шага попадал в журнал только при отказе, а убийство по таймауту отказом в этом смысле не было. Зависание не оставило ни строки вывода, ни снимка состояния, разбирать было нечего.

От соседних карточек метод отличается предметом: DP.FM.536 о критерии, по которому раннер убивает шаг; DP.FM.705 о том, что таймаут внутри подстановки команды не ограничивает время; здесь о том, какие свидетельства остаются после срабатывания таймаута.

## Схема «вход — обработка — выход»

| Элемент | Описание |
|---------|----------|
| Входы | Дочерний шаг обработчика (команда и аргументы), общий таймаут шага, порог сторожа в секундах (в источнике по умолчанию 120), путь к журналу обработчика |
| Обработка | Шаг запускается в фоне, stdout и stderr идут в файл с первой строки. По истечении порога сторож проверяет, жив ли процесс; если жив, дописывает в журнал хвост файла вывода, `ps` по процессу и его детям, `lsof` по обычным файлам процесса. Затем действует обычный таймаут. |
| Выходы | Журнал со снимком живого зависшего процесса до убийства; файл с полным выводом шага независимо от исхода |

## Шаги метода

1. **Вывод в файл сразу.** Шаг запускается в фоне, stdout и stderr перенаправлены в файл с первой строки, не копятся до конца и не попадают в журнал «только при отказе».
2. **Сторож раньше таймаута.** Через N секунд (меньше общего таймаута) сторож проверяет, жив ли процесс.
3. **Снимок живого процесса.** Если процесс жив, сторож дописывает в журнал обработчика хвост файла вывода; `ps` по процессу и его детям (дерево, а не один PID: зависание бывает в потомке, ср. DP.FM.705); `lsof` по обычным файлам процесса (какой файл или замок он держит).
4. **Таймаут как прежде.** Убийство по общему таймауту не меняется, но теперь сопровождается снимком.
5. **Регрессионный тест.** Тест воспроизводит зависание на старом обработчике и падает (в журнале нет снимка); на новом проходит. Он фиксирует, что свидетельства собираются, а не только что таймаут срабатывает.

## Инвариант

Свидетельства собираются, пока процесс жив, до убийства, а не восстанавливаются после по косвенным следам. После убийства дерево процессов и открытые файлы уже недоступны.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|--------|--------|-------------------------|
| Убить зависший шаг вовремя (таймаут) | Сохранить свидетельства о том, почему он завис | Сторож срабатывает раньше таймаута, таймаут остаётся прежним |
| Полнота снимка (вывод, дерево, файлы) | Сторож сам не должен ломать шаг и падать | Утилиты снимка необязательны, их отсутствие не роняет сторожа |
| Подробный журнал для разбора | Журнал не должен разрастаться от здоровых шагов | Снимок пишется только если процесс жив по истечении порога |

## Bias-Annotation

- **Смещение одного прецедента:** метод выведен из одного случая (WP-539 Ф21); переносимость на другие обработчики утверждается по сходству, не по замеру.
- **Смещение к «вывод есть, значит причина видна»:** снимок показывает состояние на момент порога, а не причину зависания; направление искажения: переоценка объяснительной силы снимка.
- **Смещение порога:** значение 120 с взято из одной настройки; для других шагов оно может срабатывать слишком рано (шум) или слишком поздно (ничего не успеет собраться).

## Границы

- Один прецедент (WP-539 Ф21), подтверждён регрессионным тестом.
- `lsof` может отсутствовать на хосте (DP.D.308): отсутствие строки lsof в снимке означает «неизвестно», а не «файлов не держал».
- Порог N настраивается под конкретный обработчик; 120 с не универсальная константа.

## Отличие от соседей

- **DP.FM.536:** раннер измерял «не вернулся канал вывода», а не «не завершилась задача»; здесь о том, что остаётся после срабатывания таймаута.
- **DP.FM.552 и DP.FM.690:** потеря сигнала об исходе (только stderr, алерты только на ошибки); здесь потеря свидетельств о процессе, который ещё не завершился.
- **AS.D.033 и AS.M.128:** различение и обнаружение зависания агента по журналу; здесь снимок процесса обработчика в ОС.
- **DP.FM.705 и DP.FM.694:** режимы отказа ограничения времени в shell-обработчиках; метод их не заменяет.

## Тест применимости

«Если фоновый шаг убьют по таймауту, останется ли в журнале хвост его вывода и снимок процессов?» Нет → метод не применён.
