# DP.M.587 — Классифицировать сверху вниз, проверяя результат раньше курсора

## Правило

Для контракта «событие → правило → операция» классифицировать сверху вниз по первому совпадению:

1. Есть достоверный сохранённый ряд расчёта, связанный с событием и правилом — applied; остаток очереди ошибок отметить отдельно как dlq_residual.
2. Есть ожидающая запись очереди — pending.
3. Есть окончательно упавшая запись очереди — failed.
4. Событие выше сохранённого курсора — pending.
5. Иначе — not_credited с подсказкой по текущей конфигурации.

Ряд проверять раньше курсора: пакетное сохранение курсора может отставать от записи результата. Имена состояний зависят от контракта. Классификация описывает текущий снимок; возможность повтора подтверждать отдельно. Нулевой эффект объяснять только сохранённым свидетельством, иначе причина неизвестна. Текущая конфигурация не доказывает историческую причину; расчёт не доказывает зачисление.

## Forces

Быстрый вывод по курсору ↔ достоверный вывод по сохранённому результату.

## Bias-Annotation

Фиксация на курсоре смещает оценку к отставанию обработки, хотя результат уже записан; ряд проверяется первым.

## Проверка применения

При ряде выше курсора и при ряде вместе с очередью ошибок побеждает первое совпадение — applied. Ноль без сохранённого объяснения остаётся с неизвестной причиной; текущая конфигурация не выдаётся за историю; расчёт не выдаётся за зачисление.
