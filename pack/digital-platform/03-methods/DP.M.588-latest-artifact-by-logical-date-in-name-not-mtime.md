# DP.M.588 — Последний артефакт выбирать по логической дате в имени, а не по mtime

## Проблема

Скрипт выбирает «последний отчёт» через `ls -t` (по mtime). В той же директории несвязанный ночной процесс трогает старые файлы. В результате сентябрьский отчёт оказывается «новее» сегодняшнего, и проверка свежести читает не тот файл.

## Метод

1. **Вход:** директория с артефактами, имена которых содержат логическую дату (`YYYY-MM-DD.md` или аналог).
2. **Процесс:**
   - отбирать кандидатов строгим шаблоном имени (только `^[0-9]{4}-[0-9]{2}-[0-9]{2}\.md$`, без посторонних файлов);
   - сортировать по дате, разобранной из имени. Для ISO-формата достаточно лексикографической сортировки;
   - возраст артефакта считать от даты в имени, а не от mtime.
3. **Выход:** артефакт с максимальной логической датой и его возраст. Результат не зависит от посторонних касаний файлов.

## Когда mtime допустим

Только если директорию пишет единственный процесс-производитель и никто больше не трогает файлы: ни бэкап, ни синк, ни ротация, ни `touch`. Это свойство окружения, а не файла, и при переносе на другой хост оно не сохраняется. Поэтому по умолчанию лучше брать дату из имени.

## Пределы

- Дата в имени — заявление производителя. Она не доказывает, что содержимое за этот день полное: качество отдельно проверяет DP.FM.664, «свежий отчёт ≠ живость сейчас».
- Если имя не содержит даты, метод неприменим. Тогда дату нужно писать внутрь артефакта (frontmatter) и читать оттуда.
- Выбор по дате не заменяет фильтр статуса (DP.FM.336).

## Тест

Подложить в директорию старый файл с более свежим mtime (`touch`). «Последним» должен остаться файл с максимальной датой в имени.
