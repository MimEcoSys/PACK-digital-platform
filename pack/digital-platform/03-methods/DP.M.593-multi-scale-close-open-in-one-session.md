# DP.M.593 — Несколько масштабов закрытия и открытия в одной сессии

## Задача

На стыке периодов (последний день недели и месяца) в одну сессию сходятся до шести процессов: закрытие дня, недели и месяца, открытие месяца и недели (стратегическая сессия) и открытие дня. Проходить их по отдельности — значит несколько раз задавать человеку одни и те же вопросы. Сливать их в один процесс — значит потерять отметки и проверки каждого.

## Метод

1. **Порядок по зависимости.** Сначала все закрытия по возрастанию масштаба: день → неделя → месяц. Затем открытия по убыванию: месяц → неделя → день. Открытия опираются на итоги закрытий, а большее закрытие — на итоги меньшего.
2. **Сливается диалог с человеком.** Совпадающие вопросы (ретро недели и ретро месяца, итоги и рамка) задаются один раз. Ответ используется во всех процессах, которым он нужен.
3. **Не сливаются гейты и записи.** У каждого процесса свои обязательные отметки, свой сохраняемый результат и своя проверка в границах своего масштаба (DP.METHOD.223). Общий разговор не заменяет ни одну из них.
4. **Механику — после человека.** Сбор, сохранение и проверку записей процессов агент (в том числе фоновый) делает после того, как человек свободен, а не прерывая общий разговор.

## Наблюдённый случай

Сессия 2026-11-02: недоделанная часть закрытия W44 (ретро пилота) встроена в этап ревью стратегической сессии. Механику закрытия доделал фоновый агент. Открытие месяца прошло как месячный вариант той же стратегической сессии.

## Тест применимости

«В сессии больше одного процесса закрытия или открытия?» Да → выстроить порядок по п. 1, выписать общие вопросы и для каждого процесса отдельно — его отметки и запись. Процесс считается закрытым только по его собственной проверке.

## Границы

- Метод не сокращает содержание процессов: он убирает повторы в разговоре, а не шаги.
- Если закрытие меньшего масштаба не завершено, открытие большего не начинают; порядок важнее экономии времени.

## Связи

- DP.METHOD.223 — проверяющий каждого масштаба смотрит только в свой масштаб; это условие раздельных гейтов в п. 3.
- DP.D.288 — быстрое ≠ полное закрытие: глубина каждого закрытия выбирается отдельно.
- DP.SC.201 — ORZ-конвейер: идентичность сессии и записей процессов.
