# DP.M.595 — Массовая косметическая правка: сначала часть без влияния на поведение, с инвариантом на каждый файл

## Проблема

Массовая «косметическая» правка (перевод, форматирование, переименование в тексте) затрагивает сотни файлов. Если смешать в одном шаге комментарии и строки, которые попадают в вывод, ревью не может отличить безопасные изменения от меняющих поведение, а упавший тест не указывает на причину.

## IPO

| Элемент | Описание |
|---|---|
| Входы | Набор файлов кода; правка, часть которой не влияет на поведение (комментарии), а часть влияет (строки сообщений, данные, heredoc) |
| Обработка | (0) исключить из охвата файлы с авторским источником: их правят в источнике (AR.329); (1) шаг 1 — только часть без влияния на поведение; (2) на каждом файле проверить инварианты: число строк прежнее, синтаксис проходит (`bash -n`, `python -m py_compile` и т. п.), дифф затрагивает только комментарии; (3) шаг 2 отдельным PR — строки, данные, heredoc, с прогоном тестов вывода |
| Выходы | Два PR: первый безопасен по построению и проверен механически, второй мал и ревьюится по существу |

## Инварианты шага 1

1. Число строк в каждом файле прежнее.
2. Синтаксическая проверка проходит на каждом файле.
3. Сверка с предыдущей версией показывает изменения только в комментариях.

Проверка выполняется на каждом файле, а не выборочно: у массовой правки отказ обычно в одном файле из сотен.

## Прецедент

WP-610 Ф9 (02–03.11.2026, PR #1424, коммит 1c2649d3 в FMT-exocortex-template): изменены только комментарии в 331 файле, три инварианта пройдены на каждом. Строки сообщений, данные и heredoc оставлены на шаг 2. Тот же PR показал границу метода: 22 файла имели авторский источник, и `template-sync.sh` увидел их как класс repair (см. AR.329). Инварианты прошли, а расхождение с источником осталось.

## Границы

- Инварианты доказывают только «поведение не изменилось», но не «правка сделана в правильном месте». Направление доставки (источник → шаблон) проверяется отдельно: шаг 0 и AR.329.
- «Только комментарии» — инвариант для языков, где комментарий не влияет на выполнение. Директивы в комментариях (shebang, `# shellcheck`, `# type:`, кодировка) выводятся из охвата шага 1.

## Тест применения

«Можно ли механически доказать для каждого файла первого шага, что поведение не изменилось?» Нет — шаг смешан, разбить.
