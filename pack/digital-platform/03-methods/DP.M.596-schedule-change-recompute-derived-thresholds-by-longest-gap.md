# DP.M.596 — Смена расписания: пересчитать производные пороги по самому длинному промежутку

## Проблема

Сторож пропусков считает запуск пропущенным, если с прошлого прошло больше N шагов ожидания. Шаг обычно выводят из частоты процесса. При равномерном расписании средний и максимальный промежутки совпадают. При неравномерном (дневные слоты и ночной перерыв) шаг, взятый по среднему или по старой частоте, каждую ночь даёт ложный «пропуск». Кроме того, частота процесса записана не в одном месте: каталог процессов, пороги нескольких сторожей, комментарии, таймер на хосте. Смена расписания в одном месте оставляет остальные пороги от старой частоты.

## IPO

| Элемент | Описание |
|---|---|
| Входы | Новое расписание планового процесса (список слотов); все места, где записана старая частота или выведенный из неё порог |
| Обработка | (1) выписать промежутки между соседними слотами, включая переход через ночь; (2) шаг ожидания сторожа взять по самому длинному промежутку, а не по среднему; (3) найти все пороги, выведенные из старой частоты (`grep` по старому значению и по имени процесса: каталог, сторожа, комментарии, таймер), и пересчитать каждый; (4) проверить пороги каждого сторожа против самого длинного окна без запусков |
| Выходы | Сторожа не принимают плановый перерыв за пропуск; ни один порог не остался от старой частоты |

## Прецедент

03.11.2026 (DS-my-strategy 9deaf15db4): сводка уведомлений переведена с шести слотов через 3 ч на 07/14/21, промежутки 7, 7 и 10 ч. Шаг `interval` в каталоге процессов изменён с 10800 на 25200. `date-watchdog` ждёт до 3 шагов (21 ч) и не принимает ночной перерыв 21:00–07:00 за пропуск. Пороги второго сторожа (14 ч) проверены против нового ночного окна. Таймер на хосте лежит вне репозитория и применён вручную, то есть расписание живёт в двух местах.

## Границы

- Шаг по самому длинному промежутку снижает чувствительность к пропуску дневного слота. Если важен каждый слот, нужен сторож по ожидаемому времени конкретного слота, а не единый шаг.
- Метод не устраняет второе место хранения расписания (таймер на хосте вне репозитория). Его надо учитывать в шаге (3), пока расписание не берётся из одного источника.

## Тест применения

«Какой самый длинный промежуток без запусков в новом расписании, и укладывается ли он в порог каждого сторожа?» Если хотя бы один порог меньше — будет ложный пропуск.
