# DP.M.597 — Доказывать «отказ до действия» следом начала

**Проблема.** Охранник возвращает один код и при отказе до записи (замок у другой сессии, конфликт хэша), и при упавшей записи. По коду нельзя понять, что ничего не сделано, и удержание снимает только пилот.

**Метод.**
1. Команда записи первым действием создаёт метку начала в приватном каталоге (`mktemp -d`).
2. Код «ничего не сделано» (в источнике — 4) выдаётся только при одновременном выполнении: метки нет; код охранника ≤ 128; папки назначения нет.
3. Выход по сигналу (> 128) никогда не считается «ничего не сделано»: ребёнок мог остаться жив и создать метку позже.
4. Любая неопределённость → прежний код 1. Каталог с меткой при неопределённости остаётся уликой.

**Почему не сверка хэша.** Поздняя сверка не отличает A→B→A: другой писатель может вернуть исходные байты после частичной записи.
