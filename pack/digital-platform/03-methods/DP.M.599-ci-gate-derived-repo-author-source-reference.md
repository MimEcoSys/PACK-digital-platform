# DP.M.599 — Проверка CI: правка производного файла ссылается на правку источника

## Проблема

Правило «шаблон — производный, правь источник» без механической проверки остаётся только декларацией. Пример: PR затронул 339 файлов, и ни одна из 17 проверок CI не знала, что у 22 из них есть авторский источник. О нарушении узнали только после слияния, когда вырос счётчик конфликтов синхронизации.

## Метод

**Вход:** PR в производный репозиторий (шаблон), список изменённых файлов, описание PR.

1. **Список строит синхронизатор.** Перечень файлов с авторским источником генерирует сам инструмент синхронизации из своего манифеста или хешей. Ручной список отстанет от реального набора.
2. **Проверка PR.** Если PR меняет хотя бы один файл из списка, в описании должна быть строка `Author-Source: <репо>#<PR|коммит>`, указывающая, где сделана та же правка в источнике.
3. **Красный статус.** Нет строки — проверка падает до слияния.
4. **Исключение для синхронизатора.** PR, которые создаёт сам синхронизатор (доставка из источника), проходят без строки: для них источник уже задан.

**Выход:** нарушение направления правок видно до слияния, а не по счётчику конфликтов после.

## Тест применения

«Узнает ли CI до слияния, что PR правит производную копию файла с авторским источником?» Если нет, правило направления правок держится только на дисциплине.

## Ограничения (на 2026-11-03)

- Живой PR с нарушением через проверку ещё не проходил: срабатывание не подтверждено.
- Проверка не входит в обязательные для `main`, поэтому её можно обойти.
- Строка `Author-Source:` — заявление автора PR. Совпадение правки в источнике она сама не доказывает (см. DP.D.375).
