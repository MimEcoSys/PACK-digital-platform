# DP.M.600 — Сведение очередей уведомлений нескольких хостов

## Проблема

Каждый хост слал свою утреннюю сводку, и в чат приходили две. Получатель видит два неполных сообщения вместо одного полного.

## Метод

**Вход:** очереди уведомлений на нескольких хостах; один хост объявлен концентратором.

1. **Пересылать, а не отправлять.** Второстепенный хост передаёт записи на концентратор (в источнике — по SSH), а не в мессенджер.
2. **Атомарная передача.** Временный файл → сверка числа строк → дописывание в очередь концентратора. При обрыве ничего не дописывается.
3. **Удалять локально только после успеха.** Локальная очередь очищается только после подтверждённой пересылки (тот же принцип, что DP.M.472).
4. **Метка источника.** Каждая запись получает поле `host`, чтобы в сводке было видно, откуда событие.
5. **Запасная отправка по возрасту.** Если концентратор недоступен, а самая старая запись старше порога (в источнике 24 ч), второстепенный хост отправляет сам, как раньше.
6. **Читатели пропускают незавершённое.** Подсчёт метрик и сборка сводки не читают временные файлы (`*.tmp`).

**Выход:** одна сводка за слот со всех хостов; при длительной недоступности концентратора события не теряются.

## Тест применения

«Сколько сводок придёт получателю за слот, если работают два хоста? Что станет с записями второстепенного хоста, если связь оборвётся посреди передачи?» Больше одной сводки или частичная дозапись — метод не применён.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|---|---|---|
| Одна сводка на получателя | Независимость хостов от концентратора | Пересылка на концентратор плюс запасная отправка по возрасту |
| Не терять записи при обрыве | Не дублировать записи | Атомарная дозапись со сверкой строк; локальная очередь удаляется только после успеха |
| Быстрая доставка | Меньше сообщений | Порог возраста ограничивает задержку при сбое концентратора |

## Bias-Annotation

- **Смещение одного прецедента:** метод выведен из случая двух хостов (Мак и сервер); на большее число хостов он переносится по сходству, не по замеру.
- **Смещение к одному сообщению:** запасная отправка по возрасту при недоступном концентраторе снова даёт отдельные сообщения; порог 24 ч — значение источника, не обоснованная норма.
- **Непроверенная граница:** что происходит с записями, пересланными на концентратор, когда отказывает уже сама сводка концентратора, этот метод не решает (см. DP.M.610).

## Границы

- Метод не задаёт, что делать при сбое сводки на самом концентраторе: это DP.M.610 (копить и слать одно сообщение о сбое).
- Запасная отправка второстепенного хоста — путь на случай технической недоступности концентратора, а не штатный режим.

## Связи

- DP.M.570 — явная роль хоста (исполнитель / наблюдатель); роль концентратора объявляется так же явно.
- DP.M.592 — сводка, собранная с нескольких хостов, длиннее: урезать целыми записями и мерить длину в единицах получателя.
- DP.M.472 — очередь очищается только после подтверждённой доставки (шаг 3).
- DP.M.610 — поведение при сбое самой сводки концентратора.
- DP.M.542 — смежное: обнаружение конфликтов между хостами, другая задача.
