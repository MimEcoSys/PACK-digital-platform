# DP.M.601 — Односторонний перенос заметок между хостами без затирания

## Проблема

У агента на двух хостах накопилась память (заметки `memory/`). Нужно перенести новое с одного хоста на другой, не потеряв местные правки, не воскресив удалённое здесь и не перенеся вместе с заметками действующие секреты.

## Метод

**Вход:** память двух хостов; детектор секретов. **Выход:** новые заметки перенесены, спорные — в отчёте. **Условие отказа:** нет проверки секретов.

1. **Только имена, которых здесь никогда не было.** Кандидат на перенос — заметка, имени которой нет ни в текущем дереве, ни в истории git приёмника. Проверка по истории не даёт воскресить заметку, удалённую здесь намеренно.
2. **Ничего не перезаписывать.** Заметка с существующим именем не трогается.
3. **Проверка секретов обязательна (fail-closed).** Каждый кандидат проверяется до переноса; если проверка недоступна, перенос не выполняется.
4. **Генерик-сканера недостаточно.** Сканер по форме токена (gitleaks и подобные) пропускает подписанные значения в прозе («Пароль: X»), SQL-литерал `PASSWORD '...'` и учётные данные в URI (DP.FM.724). Поверх сканера нужен свой детектор этих форм записи с исключением заглушек (`<...>`, `***`, `$VAR`). Найденный секрет — стоп и ротация (DP.FM.026).
5. **Контрольная запись хешей источника.** После переноса записать «имя → sha256 источника». Следующий прогон по ней видит заметки, изменённые на источнике после переноса.
6. **Спорное — в отчёт.** Изменённое на источнике после переноса и заметки с новыми строками на обоих хостах не перезаписываются, а попадают в недельный отчёт для ручного решения.

## Тест применения

«Перенесено ли только то, чего не было ни в дереве, ни в истории? Есть ли проверка секретов, которая ловит „Пароль: X“ в прозе, и останавливает ли её отсутствие перенос? Записаны ли хеши источника?» Нет хотя бы на один вопрос — метод не применён.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|---|---|---|
| Перенести всё новое | Не затереть местное и не воскресить удалённое | Только имена, которых не было ни в дереве, ни в истории |
| Автоматический перенос | Секреты в прозе не видны сканеру | Свой детектор поверх сканера, отказ без проверки |
| Полнота синхронизации | Безопасность при конфликте | Спорное в отчёт, а не автоматическое слияние |

## Bias-Annotation

- **Смещение к сохранности:** спорное никогда не сливается автоматически; на первом прогоне в отчёт ушло 97 заметок против 240 перенесённых — ручная работа растёт.
- **Смещение доверия к инструменту:** исходная версия метода полагалась на gitleaks как на достаточный барьер; прецедент DP.FM.724 показал, что это не так. Свой детектор покрывает только известные формы записи.
- **Один источник:** вывод по одному РП и одной паре хостов.

## Наблюдённый случай

Первый прогон: 240 заметок перенесено, 97 расходятся и ушли в отчёт.

## Связи

- DP.FM.724 — детекторы секретов по форме токена слепы к подписанным значениям в прозе: почему одного gitleaks мало (шаг 4).
- DP.M.602 — встречная схема: обновление изменяемых копий из канона без затирания местных правок (там источник — канон, здесь — другой хост, и переносятся только новые имена).
- DP.FM.026 — секрет в истории git и в памяти агента: ротация.
- DP.FM.720 — все механизмы над одной памятью должны разрешать её расположение одинаково.
