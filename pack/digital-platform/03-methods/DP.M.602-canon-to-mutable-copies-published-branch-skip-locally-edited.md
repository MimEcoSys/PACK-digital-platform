# DP.M.602 — Раздача канона в изменяемые копии без затирания локальных правок

## Проблема

Канонический файл раздаётся в несколько копий, которые могут правиться на месте (например, заметки памяти агента). Наивное «скопировать канон поверх» затирает локальные правки. Копирование из рабочего дерева разносит по копиям неопубликованные и непроверенные правки.

## Метод

**Вход:** канонический репозиторий, набор целевых копий, контрольная запись «что было записано в каждую копию».

1. **Источник — опубликованная ветка.** Содержимое канона брать из `origin/main` (или другой опубликованной ветки), а не из рабочего дерева. Неопубликованные правки по копиям не расходятся.
2. **Контрольная запись.** После каждой записи сохранять отпечаток записанного (имя → хеш).
3. **Локально правленную копию не трогать.** Если текущая копия ≠ последней записанной, её правили мимо канона. Обновление этой копии пропускается и попадает в отчёт.
4. **Первый запуск без базы.** Контрольной записи ещё нет, поэтому базой считаются все прежние версии канона из истории git. Копия, совпадающая с любой из них, обновляется, остальные остаются как есть.
5. **Сбой git → ничего не менять.** Любая ошибка при получении канона (fetch, show, разбор истории) оставляет все копии нетронутыми (fail-closed).
6. **Путь к копиям разрешать так же, как другие механизмы.** Если ту же память читают или пишут другие механизмы (бэкап, зеркало), они обязаны приходить к одному каталогу (DP.FM.720), иначе контрольная запись сверяет не ту копию.

**Выход:** копии получают только опубликованный канон, локальные правки не теряются и видны в отчёте.

## Тест применения

«Может ли обновление из канона перезаписать копию, которую правили на месте, или разнести неопубликованную правку?» Если да — нет шагов 1–3.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|---|---|---|
| Свежесть копий | Сохранность местных правок | Отпечаток записанного: правленая копия пропускается и попадает в отчёт |
| Обновлять сразу | Не разносить непроверенное | Источник — только опубликованная ветка |
| Обновить хоть что-то при сбое | Не испортить копии частичным обновлением | Любой сбой git — копии нетронуты |

## Bias-Annotation

- **Смещение к сохранности:** правленая копия перестаёт получать обновления канона, пока её не разберут вручную; копии могут надолго отстать.
- **Эвристика первого запуска:** совпадение с прежней версией канона считается признаком «не правили». Копия, случайно совпавшая со старой версией после ручной правки, будет обновлена.
- **Описание без наблюдения:** поведение на реальном конфликте не наблюдалось, метод описан по коммиту и capture.

## Ограничения (на 2026-11-02)
