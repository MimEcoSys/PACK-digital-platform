# DP.M.608 — Сведение авторской копии с шаблоном через зоны AUTHOR-ONLY:drop

## Проблема

Автор ведёт свою копию файлов (например, протоколы памяти агента), из которой собирается общий шаблон для пользователей. Шаблон тем временем правят отдельно, а копия обрастает авторским: шагами на скриптах, которых в шаблоне нет, своими путями конфигурации, фактами, проверенными только у автора. Пока граница между общим и авторским не размечена, расхождение автор ↔ шаблон не сводится к нулю, и по счётчику нельзя отличить законную авторскую добавку от дрейфа. Чистка авторского при сборке по словарю известных выражений пропускает неучтённое (DP.FM.660). В шаблон уходят обещания, проверенные только у автора.

## Метод

| Элемент | Описание |
|---|---|
| Входы | Авторская копия файла; текущая версия шаблона; сборка шаблона, которая понимает зоны drop |
| Обработка | Построчная сверка от текста шаблона, решение по каждой строке, разметка авторских фрагментов |
| Выходы | Копия = текст шаблона + зоны drop с причинами; после вырезания зон расхождение по файлу равно нулю |

1. **Сводить от текста шаблона, а не от авторского.** Идти по строкам шаблона и решать по каждой. Сведённая версия, собранная из авторского текста целиком, теряет правки, сделанные в шаблоне. В наблюдённом случае первый такой кандидат потерял три правки шаблона; это поймали до записи.
2. **Общая строка — дословно из шаблона.** Если строка верна для любой установки, в копии остаётся текст шаблона, даже когда у автора была своя формулировка. Лучшую авторскую формулировку доставляют в шаблон отдельно (AR.329), а не держат как расхождение.
3. **Необязательный компонент — в общем виде.** «Если заведён X…» вместо утверждения, что X есть. В шаблон идут только шаги без обещаний сверх проверенного (тот же принцип, что в DP.M.518, п. 2).
4. **Авторский фрагмент — в зону drop с причиной.** Строку, которая опирается на то, чего в шаблоне нет, заключают в `<!-- AUTHOR-ONLY:drop <РП>: причина -->…<!-- /AUTHOR-ONLY -->`. Номер РП и причина обязательны: по ним зону можно пересмотреть. Смешанную строку делят: общий текст — как в шаблоне, авторский путь — в зону.
5. **Сборка шаблона вырезает зону drop целиком, без заглушки.** Этим она отличается от пользовательских зон AUTHOR-ONLY (DP.IWE.002 §4b), на месте которых в шаблоне остаётся заглушка для своего блока.
6. **Приёмка.** Копия без зон drop побайтно равна шаблону, расхождение по файлу — ноль. Ненулевой остаток после этого — новый дрейф, а не «авторская специфика».

## Почему не фильтр по ключевому слову

Очевидная альтернатива разметке — фильтр сборки, который вырезает строки по вхождению приватного имени (например, имени закрытого репозитория). Он не отличает авторский шаг от общей строки, где это имя лишь упомянуто. Наблюдённый случай (03.11.2026, WP-485 Ф16): строка про служебную сессию охраны в `week-review` содержала имя приватного репозитория, и конвейер вырезал её вместе с авторскими шагами — шаблон потерял законную строку из коммита, ошибки нигде не было. Нашла это проверка субагента сравнением преобразованного источника с целевым файлом.

Отсюда три следствия для метода:

- граница общего и авторского задаётся явной зоной в источнике, а не угадывается по словам (шаг 4);
- результат сборки сверяется с целевым файлом (шаг 6), иначе тихая потеря строки не видна;
- при ложном срабатывании защищённого фильтра переформулировать строку в источнике, а не править сам фильтр.

## Тест применения

«Если вырезать из авторской копии все зоны drop, совпадёт ли она с шаблоном байт в байт, и записана ли у каждой зоны причина?» Нет на первый вопрос — копия не сведена. Нет на второй — зону нельзя пересмотреть, и в ней может прятаться общий текст.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|---|---|---|
| Автору нужны свои шаги и факты | Шаблон не должен обещать непроверенное | Авторское — в зонах, которые сборка вырезает |
| Автоматическая чистка авторского | Чистка по словам режет законные строки | Явная разметка в источнике вместо фильтра по ключевому слову |
| Своя формулировка автора | Нулевое расхождение с шаблоном | Общая строка дословно из шаблона, улучшение — отдельной доставкой |

## Bias-Annotation

- **Смещение к нулевому счётчику:** приёмка по нулевому расхождению поощряет прятать спорный общий текст в зону drop; против этого — обязательная причина у каждой зоны.
- **Смещение одного автора:** метод проверен на одном РП, трёх файлах и одном авторе; переносимость на скрипты не утверждается (для них зоны — крайний случай).
- **Описание по записям:** коммиты-источники и код сборки, вырезающей зоны, при извлечении не перечитаны.

## Границы

- **Проза и протоколы.** Для скриптов зоны — крайний случай. Частное значение автора выносится в настройку шаблона, а само значение остаётся у автора (AR.219, DP.M.518 п. 3). Файл, повторяющий чужой факт, спрашивает владельца этого факта (правило сортировки WP-529 Ф248, решение пилота 04.11.2026).
- **Не противоречит DP.M.009.** Там размеченные зоны — антипаттерн расширяемости: платформа размечает места для правок пользователя, и каждая новая точка требует изменения платформы. Здесь зоны ставит сам автор в своей копии-источнике, и к пользователю они не попадают.
- **Нулевой остаток достаточен для прозы.** Для кода совпадение текста не доказывает сходимость поведения (DP.D.378).
- **Один файл за раз.** Метод не задаёт порядок сведения, когда обе стороны правили файл после последнего совпадения.

WP-529 Ф248, 03–04.11.2026, пир-сессия Claude, Kimi и Codex. В `memory/protocol-open.md` авторские шаги на скриптах, которых нет в шаблоне, вынесены в зоны drop (новый вид зоны, без заглушки); шаг DayPlan Gate — текст шаблона плюс авторский путь конфигурации в зоне. Расхождений автор ↔ шаблон стало 16 вместо 17. Затем так же сведены `agent-architecture-framework.md` и `navigation.md`: общий текст — в шаблоне, установка и история переездов автора — в зонах. Расхождений стало 14 вместо 16, файлов памяти среди них не осталось.
