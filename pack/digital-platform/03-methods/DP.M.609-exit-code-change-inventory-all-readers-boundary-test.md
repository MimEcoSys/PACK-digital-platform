# DP.M.609 — Смена кода выхода: опись читателей и тест на стыке

## Проблема

Код выхода общего инструмента читают несколько сторон: скрипты-обёртки, циклы, планировщик, юниты systemd. Отправитель тестируется сам по себе, каждый читатель — тоже. Но смысл кода у сторон может разойтись, а смена кода молча меняет поведение тех, о ком автор правки не вспомнил.

Два наблюдённых случая одного класса:

- **Расхождение смысла (02.11.2026, WP-568 Ф11).** Код 12 «занято другим хостом» (временно) недельный цикл принял за окончательный отказ — план недели не опубликовался. Код 76 «сдался на сегодня» планировщик принял за временный сбой — запущен лишний 30-минутный прогон. Коды различимы, но стороны понимают их по-разному.
- **Смена кода без описи (04.11.2026).** `iwe-tg` начал отдавать код 4 при сбое записи в сводку. Проверяющий прошёл по вызывающим: часть под `set -e` от кода 4 не падала, а два сторожевых скрипта раньше при сбое получали 0 и помечали тревогу отправленной, теперь же выходят с ненулевым кодом — и код выхода их юнита может запустить эскалацию через OnFailure.

## Метод

**Вход:** общий инструмент, у которого появляется новый код выхода или меняется смысл старого.

1. **Опись читателей.** Найти всех, кто читает код: прямые вызовы в скриптах (в том числе вне тестов), обёртки, циклы с повтором, планировщик, юниты systemd и их OnFailure. Поиск — по всему коду, а не по памяти (тот же принцип, что «найти всех потребителей до переименования», DP.FM.365, DP.D.314).
2. **Разложить читателей на группы:** (а) код прерывает выполнение под `set -e`; (б) код обрабатывается явно (`|| RC=$?`, `case`); (в) код уходит в код выхода юнита и может запустить OnFailure-эскалацию.
3. **Для каждого читателя записать трактовку:** «временно — повторить», «окончательно — остановиться», «отказ по политике — тихий пропуск» (AR.325), «тревога». Трактовка у всех читателей одного кода должна совпадать с той, что задумал отправитель.
4. **Группу (в) решить отдельно:** нужна ли эскалация на новый код, или юнит должен переводить его в успех с записью в журнал.
5. **Тест на стыке.** Для каждой пары «отправитель → читатель» — тест, который подаёт читателю этот код и проверяет его реакцию (повтор при «временно», дневная пауза при «сдался»; в источнике — смоук `week-review-gave-up-pause-smoke.sh`).
6. **Выкладывать только после шагов 1–5.**

**Выход:** у кода один смысл для всех читателей, и это закреплено тестами на стыках, а не только тестами сторон по отдельности.

## Тест применения

«Есть код выхода, который читают минимум два разных компонента, и нет теста, который подаёт этот код каждому из них?» Да → смысл может разойтись. «Меняется код общего инструмента, а списка всех его читателей, включая юниты с OnFailure, нет?» Да → метод не применён.

## Forces

| Сила 1 | Сила 2 | Как метод их удерживает |
|---|---|---|
| Быстро выкатить новый код | Не сломать неизвестных читателей | Опись читателей до выкладки |
| Каждая сторона протестирована | Стык сторон не протестирован никем | Тест на каждую пару «отправитель → читатель» |
| Ненулевой код делает сбой видимым | Ненулевой код запускает лишнюю эскалацию | Отдельное решение для юнитов с OnFailure |

## Bias-Annotation

- **Смещение к полноте описи:** опись по поиску в коде пропускает читателей вне репозитория (копии на других хостах, ручные вызовы); полнота не гарантирована.
- **Смещение двух прецедентов:** оба случая — из одной среды (скрипты и юниты IWE, WP-568); перенос на другие межпроцессные контракты — по сходству.
- **Смещение к тестам:** тест на стыке проверяет известные пары; новый читатель, добавленный после выкладки, тест не покрывает.

## Границы

- Что должен значить код и почему отказ по политике отличается от сбоя — не здесь: AR.325 (именованный код отказа), DP.M.591 (повтор при «занято другим хостом» — снаружи), DP.FM.476 (словари отправителя и потребителя расходятся). Этот метод — шаг проверки перед сменой кода.
- Успех при несостоявшейся записи (код 0 вместо честного ненулевого) — DP.FM.591.

## Связи

- AR.325 — отказ по политике использует именованный код, отличный от кода сбоя.
- DP.M.591 — «занято другим хостом» повторяется снаружи целым вызовом: пример трактовки «временно».
- DP.FM.476 — отправитель и потребитель сравнивают значение по разным словарям: тот же класс расхождения на метках severity.
- DP.D.314 и DP.FM.365 — найти всех потребителей контракта до его изменения.
- DP.FM.591 — код 0 при потерянной записи; новый ненулевой код в случае 04.11 лечит именно это.
- DP.FM.622 — новый юнит не наследует общую OnFailure-конвенцию: группа (в) зависит от того, у какого юнита она есть.
- DP.FM.266 — код выхода не доказывает структурной корректности результата.
