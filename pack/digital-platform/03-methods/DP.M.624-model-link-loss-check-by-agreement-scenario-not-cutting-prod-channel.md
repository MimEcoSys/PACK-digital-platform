# DP.M.624 — Проверка обрыва связи по сценарию договорённости

## Вход

Критерий приёмки вида «обрыв связи не теряет данные».

## Шаги

1. Уточнить «обрыв» как обрыв между двумя шагами протокола (например, запись → запуск).
2. Смоделировать сценарий: обрыв → повтор → совместное восстановление.
3. Не отключать рабочий канал (в источнике — доставку от сервера к внешней системе): это останавливает рабочую доставку для всех.
4. Живую контрольную заявку на рабочем пути — только по разрешению пилота.

## Выход

Подтверждение восстановления без остановки рабочего пути.

## Forces

- Реалистичный стимул (настоящее отключение) даёт больше уверенности ↔ он останавливает рабочую доставку для всех, кто ею пользуется.
- Сценарий на уровне протокола безопасен ↔ он проверяет только те точки обрыва, которые явно смоделированы.

## Bias-Annotation

- Желание «проверить по-настоящему» смещает к отключению рабочего канала; ограничение — стимул выбирается на уровне протокола, живая проверка только с разрешения пилота.
- Успешный сценарий смещает к выводу «обрыв в любой точке безопасен»; ограничение — вывод касается только смоделированных точек.

## Отличие от соседей

- DP.M.517 — приёмка оповещений искусственным сбоем: синтетический сигнал идёт по рабочему пути, не выключая его. Здесь — тот же принцип для проверки обрыва: стимул не должен выключать рабочий канал.

## Границы

Один случай-источник (РП-561 Ф55 / DR-06: обрыв между записью и запуском в мосте приёмника событий плана), поэтому `trust: low`.
