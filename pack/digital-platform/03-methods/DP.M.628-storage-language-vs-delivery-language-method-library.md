# DP.M.628 — Язык хранения ≠ язык выдачи

## Проблема

Публичная библиотека методов нужна людям на разных языках. Несколько языковых редакций одной карточки могут разойтись между собой; при этом без смыслового поиска сервер библиотеки получает только имя метода, не текст человека.

## Метод

1. Хранить на сервере одну редакцию — английскую публичную карточку.
2. Русский метод остаётся исходником в паке. В карточке — ссылка на версию русского первоисточника: по ней видно, что английская редакция отстала.
3. Переводить дважды в разное время: заранее и один раз — русский источник → английская карточка (по утверждённому словарю терминов); в каждом разговоре — английская карточка → язык человека (ИИ пользователя).
4. «Список методов» и «карточка» получают только имя метода, не текст затруднения человека. Операция смыслового поиска меняет это — см. «Дополнение 2026-11-18».
5. В инструкции подключения — строка: «карточки на английском, объясняй своими словами на языке человека, не цитируй». Инструкция должна доходить до модели (описания инструментов).
6. Поле языка и русские карточки на сервере не заводить (отвергнуто пилотом).

## Тест применения

- На сервере появилась вторая языковая редакция той же карточки → нарушен шаг 1.
- «Список» или «карточка» принимают текст запроса человека → нарушен шаг 4. Поиск принимает запрос по замыслу; что в нём допустимо — по «Дополнению 2026-11-18».
- В карточке нет ссылки на версию первоисточника → отставание редакции не обнаружить.

## Forces

| Сила | Напряжение |
|---|---|
| Одна редакция ↔ точность на языке человека | Одна копия не расходится, но перевод в разговоре зависит от качества ИИ пользователя |
| Приватность запроса ↔ серверный подбор | Без поиска сервер не видит текст человека, и подбор метода под задачу делает ИИ клиента (DP.M.622); с поиском на сервер уходит короткий запрос, составленный ИИ человека (Дополнение 2026-11-18) |

## Bias-Annotation

- **Привычка «локализация на сервере»** → тянет завести языковые копии; по методу копия одна.
- **Доверие к машинному переводу** → смещает к цитированию карточки дословно; инструкция просит объяснять своими словами.

## Границы

Один источник (РП-581, тестовый Open MCP). Модель хранения Библиотеки методов в паке экосистемы (`ECO.M.033`, `ECO.ARCH.001` §3.1: «Библиотека хранит сведения и указатель») с этим решением пока не сведена — вопрос пилоту отложен вместе с кандидатом о критерии готовности карточки.

## Дополнение 2026-11-18: смысловой поиск меняет контракт данных

Решение пилота 10.11 (РП-581, после оперативки ИТ): тестовый MCP делается сразу со смысловым поиском — третьей операцией к «списку методов» и «карточке». Оно заменило решение 09.11 «смыслового поиска нет» (РП-581 Ф28 п.6), на котором стоит шаг 4.

1. **Набор операций сервера задаёт границу приватности.** «Список» и «карточка» получают только имя метода. Операция, принимающая свободный текст, переносит на сервер запрос человека.
2. **Инструкцию для ИИ и обещание о данных правят до проверки, а не после.** Проверка на живых разговорах уже отправляет запросы на сервер. Что отправлять в поиск, ИИ узнаёт из описания инструмента поиска (шаг 5, `DP.M.505`). Доходит ли описание инструмента до модели, зависит от клиента и проверяется в каждом (замечание повторного ревью Coder, РП-581).
3. **Что уходит в поиск** (утверждено пилотом 10.11): короткий запрос, который составил ИИ человека, — суть затруднения своими словами, на английском, до 300 знаков. Без имён, названий компаний, контактов, дат и других сведений, по которым можно узнать человека или третьих лиц. Переписку и файлы ИИ не отправляет.
4. **Правило составления запроса — указание ИИ, а не гарантия сервера.** Предел длины (300 знаков): по проекту договора 10.11 сервер отклоняет запрос длиннее 300 знаков, но исполнитель MCP реализуемость пока не подтвердил; до подтверждения предел остаётся указанием ИИ. Отсутствие личных сведений в запросе сервер тоже не гарантирует, поэтому обещание о данных не обещает обезличивания. Не обещает оно и неподтверждённого: что сервер не хранит текст запроса (ждёт сведений о журналах сервера) и что человек видит аргументы вызова (в части клиентов видит, спецификация MCP этого не гарантирует).
5. **Остаётся в силе:** «список» и «карточка» текст человека по-прежнему не получают. `DP.M.622` сформулирован условно («если сервер получает только имя метода») и не меняется.

Шаг 4 в редакции 17.11 записан по решению 09.11, хотя 10.11 его уже заменили. Тот же механизм, что в `DP.FM.786`: пункт, записанный по решению, которое более позднее решение пилота заменило, остался в силе, потому что захват 09.11 обработали 15–17.11 без сверки с решением 10.11. `DP.FM.785` смежно: там устная договорённость не попала в записанные решения.

**Открыто:** хранит ли сервер текст запроса — вопрос исполнителю MCP (РП-581 Ф16); до ответа это не обещается.
