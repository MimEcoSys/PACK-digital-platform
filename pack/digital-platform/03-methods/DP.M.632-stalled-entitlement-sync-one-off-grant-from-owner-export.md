# DP.M.632 — Разовая выдача прав из выгрузки владельца данных при остановленной синхронизации

## 1. Определение

Обходной путь для интеграции, которая выдаёт права доступа по данным внешней системы. Пока источник недоступен, права выдаются разово из выгрузки, которую дал владелец данных, по тем же правилам сопоставления и записи, что и при штатной синхронизации.

## 2. Проблема

Синхронизация прав из внешней системы остановилась, потому что источник недоступен. Пользователи, которые уже заплатили, не получают доступ, и с каждым днём их больше. Ждать восстановления источника — значит переложить чужой сбой на пользователей.

## 3. IPO-паттерн

| Элемент | Описание |
|---------|----------|
| Входы | Выгрузка владельца данных с датой; локальный реестр учётных записей |
| Обработка | Сопоставление учётных записей по порядку ключей; запись прав по правилам штатной синхронизации; повышение уровня доступа |
| Выходы | Выданные права с отметкой источника (выгрузка, дата) и способа сопоставления; вывод несопоставленных записей; счётчики «до/после» |

## 4. Шаги метода

1. **Пробный прогон по умолчанию.** Выдача работает в транзакции, которая по умолчанию откатывается; запись — только по явному флагу (`--apply`). Сначала смотрят счётчики пробного прогона, потом применяют.
2. **Порядок ключей: стабильный внешний id, потом email.** Внешний id провайдера идентичности не меняется при смене почты, поэтому он первый. Почта сравнивается в канонической форме (без пробелов по краям, в нижнем регистре), как требует DP.M.062.
3. **Известный id без локального профиля тоже получает право.** Если пропустить такую запись, потому что для неё нет строки профиля, право пропадёт молча. Право привязывается к id и становится доступным при первом входе.
4. **Тот же ключ конфликта и то же правило обновления, что у штатной синхронизации.** Тогда, когда источник вернётся, штатная синхронизация обновит эти же записи, а не создаст рядом вторые.
5. **Отметка источника.** Каждая выданная запись несёт метку разовой выдачи (выгрузка и её дата) и способ сопоставления (по id, по почте, по id без профиля), а не выдаёт себя за штатную синхронизацию.
6. **Уровень доступа только повышается.** Выдача поднимает уровень тем, у кого он ниже, и никогда не понижает уже более высокий.
7. **Счётчики до и после.** Вывод показывает число прав и активных записей до и после и способы сопоставления; несопоставленные записи печатаются для разбора.

## 5. Тест применения

«Если пользователь сменил почту или у него ещё нет локального профиля, получит ли он право по этой выдаче? И что сделает штатная синхронизация с этой записью, когда источник вернётся?» Нет на первый вопрос — порядок ключей неверен; «создаст вторую запись» на второй — ключ конфликта отличается от штатного.

## 6. Границы

- Метод — обходной путь на время недоступности источника, а не замена синхронизации.
- Выгрузка — снимок на дату; всё, что изменилось после неё, приедет только со штатной синхронизацией.
- Рекомендация (в источнике не проверялась): запасное сопоставление по почте выдаёт платное право по совпадению адреса, поэтому оно допустимо только для подтверждённых адресов.

## 7. Наблюдённый случай

09.11.2026, WP-467 Ф6. База LMS была недоступна с 01.11, синхронизация договоров встала, пользователи с оплатой не получали доступ. Разовая выдача из выгрузки владельца данных от 08.11 (payment-registry `15c7583`, `scripts/grant-contracts-from-export.sh`): добавилось 10 договоров, активных стало на 45 больше. Разница объясняется тем, что выдача не только создаёт новые договоры, но и обновляет срок и статус существующих.
