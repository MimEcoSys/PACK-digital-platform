# DP.M.633 — Сверка оценки архитектурного варианта с кодом вторым агентом

## 1. Определение

Способ проверить оценку трудозатрат варианта архитектуры до того, как принят план работ: второй агент с доступом к коду сверяет чертёж с кодом и уточняет оценку.

## 2. Проблема

Оценка по чтению основных путей (в случае-источнике путей выдачи) занижена, если стоимость сидит в путях записи и удаления, которые чертёж не называет или называет не полностью. Такие места требуют отдельных этапов или противоречат допущению чертежа. План, составленный по такой оценке, занижает срок и состав этапов.

## 3. Шаги метода

1. **Чертёж с оценкой готов, план работ в черновике и не принят.** Сверка идёт до принятия плана.
2. **Агент с доступом к коду, не составляющий план работ, проходит по коду второй раз.** Он проверяет каждое утверждение чертежа вида «здесь записывается / здесь удаляется / здесь читается» и ищет места, которых чертёж не называет.
3. **Находки записываются с адресом в коде** (файл и строки) и уточнённой оценкой.
4. **Тот, кто составляет план, проверяет находки по самому коду**, а не принимает их на слово.
5. **Оценка и состав этапов пересматриваются.** Новую оценку показывают тому, кто принимает решение, до начала работ.

## 4. Тест применения

«Есть ли в чертеже утверждение о коде, которое проверял только его автор?» Да — сверка не проведена.

## 5. Границы

- Один случай. Сбудется ли оценка 13–20 дней, неизвестно: разработка по РП-604 не завершена.
- В случае-источнике исходную оценку тоже дал Кодекс, по чтению путей выдачи, а второй проход по путям записи и удаления сделал он же; план составлял писатель сессии. Нужен ли для второго прохода другой агент, случай не показывает.
- По методу проверяют оценку по коду; оценку по сложности предметной области это не заменяет.

## 6. Наблюдённый случай

10.11.2026, РП-604 Ф3 п.5 (индекс знаний: хранение «источник + основания доступа», DP.D.385). Оценка варианта B в чертеже — 10–16 дней разработчика (в отчёте сессии записана как 10–15); её дал Кодекс по чтению путей выдачи. Когда писатель составил черновик плана с этапами, Кодекс сверил с кодом чертёж и этот черновик и нашёл три места в сервисе интеграции с GitHub, которые размножают или удаляют копии командного источника (`webhook.ts:786–790`, `team-access-reconcile.ts:95–102`, `api.ts:323–328`), и отсутствие чтения статуса подписки в сервисе знаний (`auth.ts:27` берёт только `sub`). Писатель проверил обе находки по коду. Кодекс назвал 14–20 дней; в плане, который составил писатель, итог 13–20 дней разработчика плюс 7 календарных дней теневой проверки; пилот принял нижнюю границу (13 дней) и поручил заранее сообщать о приближении к верхней. Удаление при отзыве участника чертёж уже называл; новыми были рассылка переиндексации и удаление при отключении.
