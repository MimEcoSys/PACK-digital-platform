# DP.M.639 — Рассказ об изменениях по журналу метки поставки, не по main

## Проблема

Когда шаблон доставляется по каналам (выпуск, кандидат, main), основная ветка уходит вперёд: в main уже лежат правки, которых нет ни в выпуске, ни в кандидате. Если навык обновления читает журнал изменений (CHANGELOG) с main, пользователь выпуска или кандидата может получить описание не своего состава. Случай, когда пользователю так и рассказали неверно, не описан: основание метода — устройство поставки, а не наблюдённый сбой.

## Метод

1. Определить метку, которую ставит это обновление. В IWE её называет строка вывода `update.sh` (печатается и при `--check`): «Канал поставки: кандидат <метка> (снимок …)» или «Канал поставки: релиз <метка> (снимок …)»; у выпуска бывает и вариант «(закреплён по тегу)».
2. Читать журнал изменений с этой метки, а не с main (в IWE — по raw-URL метки). Main — источник только для того, кто сам обновляется с канала main (`IWE_UPDATE_CHANNEL=main`).
3. В выводе `update.sh` нет строки «Канал поставки» — не подставлять main. Сказать пользователю, что источник изменений не определён.
4. Служебные подпункты записи журнала («Цель:», «Как проверить:», «Как откатить:») адресованы Выпускающему (DP.ROLE.120). Пользователю их не пересказывать; генератор анонса выпуска их тоже вырезает.

## Тест применения

- Канал «релиз» или «кандидат», а журнал прочитан с main? → нарушен шаг 2.
- Строки «Канал поставки» нет, а рассказ об изменениях всё равно построен по main? → нарушен шаг 3.
- В рассказе пользователю есть «как проверить» или «как откатить» из записи журнала? → нарушен шаг 4.

## Границы

- Метод — об источнике рассказа о ещё не применённом обновлении. Что изменилось в уже установленном, навык читает из локального журнала в папке шаблона (состояние навыка на 20.11, более поздняя правка, не коммит-прецедент): он приходит с обновлением и совпадает с установленным.
- База сравнения «было/стало» на машине пользователя — DP.M.563 (снимок файла до перезаписи).
- Критерии анонса выпуска (коротко, по журналу этой версии, без служебной разметки) — DP.SC.043. Метод добавляет к ним выбор источника для навыка обновления и исход «источник не определён».
- На канале main поставляемое состояние и есть main (модель raw-main, DP.M.155), и вопрос не возникает. Метод нужен, когда поставка идёт по меткам выпуска или кандидата.

## Прецедент

РП-529 Ф240, FMT-exocortex-template PR #1516 (коммит 7c70896b, 10.11.2026): навык `iwe-update` переведён с чтения журнала с main на чтение с метки, которую ставит обновление. Отдельный случай неверного рассказа пользователю в захвате не описан.
