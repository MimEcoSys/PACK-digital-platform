# DP.M.641 — Подтверждение следа сессии заявкой по id из своего семафора, только заполненные файлы

## Проблема

Перед закрытием пир-сессии проверка ищет её след: папку журнала по ключу (slug) семафора. У сессии Кими, открытой с ключом вида `WP-7`, папка журнала названа полным идентификатором сессии, поэтому поиск по ключу отвечал «нет», хотя журнал был. Чинить сопоставление имён на стороне проверки — значит угадывать: перебирать все сессии или верить ссылке в свободном тексте.

## Метод

1. **Связь заявляет производитель.** Писатель журнала после заполнения `meta.yaml` и `00-writer.md` заявляет оба файла в семафоре своей сессии (`session-guard.sh note-file`).
2. **Идентификатор — из своего семафора, не угаданный.** Кими берёт `session_id` из семафора, выбранного на шаге 0а (`$SEM_FILE`), а не «самый свежий семафор». Писатель Claude заявляет файлы с ключом своей пир-сессии (`--slug "$SESSION_ID"`).
3. **Пустое не заявлять.** Пока любой из двух файлов пуст, заявки нет.
4. **Проверка: сначала прежний поиск, потом заявка.** Поиск папки по ключу сохраняется; заявка проверяется после него как дополнительный путь. Принимается только пара, заявленная этим семафором: оба файла из одной папки (заявки на несколько папок отвергаются), `00-writer.md` непуст, `session_id` в `meta.yaml` совпадает с именем папки, символические ссылки не принимаются. Остальные сессии не перебираются, ссылкам в тексте не верят.

## Тест применения

- Проверка следа нашла журнал, перебирая все сессии или по свежести семафора? → нарушены шаги 2 и 4.
- Заявка сделана на пустой файл журнала? → нарушен шаг 3.
- Одна заявка указывает файлы из двух разных папок, а проверка ответила «да»? → нарушен шаг 4.

## Границы

- Метод — о подтверждении следа при закрытии. Атрибуция расходящихся файлов по заявкам («заявлял», а не «менял») — DP.M.577.
- Правило про `$SEM_FILE` относится только к Кими; у Claude ключ заявки — идентификатор пир-сессии.
- Проверка следа в источнике только предупреждает и не блокирует закрытие: блокировку пилот включает, когда число ответов «нет» станет нулевым (из комментария в коде).
- Неоднозначность самих семафоров (две живые записи одной сессии под разными именами агента) метод не снимает — DP.FM.685.

## Прецедент

РП-7 Ф302, коммит e5c9775 в iwe-local-config (10.11.2026). Из захвата, не проверено: на журнале 08.11 при ключе `WP-7` проверка отвечала «нет», при полном имени папки — «да»; регресс-тест 20/20. Тест `session-guard-peer-evidence-smoke.sh` при записи карточки не запускался.
