# DP.M.643 Метод формирования структуры IWE

## 1. Назначение и границы

Метод отвечает на вопрос «какие дома есть в IWE, как они устроены и какой вид материала в каком доме лежит». Результат метода — решение о структуре с условиями пересмотра. Структура меняется редко и дорого; карта маршрутизации ([[DP.KR.002]] §9) отвечает на вопрос «какой материал в какой дом идёт» и меняется часто. Карта опирается на структуру. Соотношение частот — рабочая гипотеза, не установленная величина.

Границы:
- Метод ≠ исполнение переноса. Перенос файлов идёт по правилу исполнения (§5) и только после решения человека.
- Два уровня применения. Платформенный архитектор (R5) применяет метод к общей структуре для всех пользователей: шаблон IWE, реестр доменов, образец карты. Архитектор личной структуры ([[DP.ROLE.131]]) применяет тот же метод к хранилищам одного человека: шаги 1 и 2 сливаются, общую схему он не меняет; раскладку и новые дома внутри неё — может. Отклонение пользователя от рекомендуемой карты домов допустимо по его решению (ADR-004 шаблона IWE); оно не меняет общую схему.
- Порядок доверия «принципы → пак → производное» ([[DP.M.008]] правило 4, [[DP.KR.001]] §3) метод не пересматривает, а применяет.

## 2. Входы и результат

**Входы:** действующие описания структуры (реестр доменов, карта домов шаблона, [[DP.KR.001]] §3–§3.4), опись хранилищ, для личного уровня — личная карта маршрутизации и наблюдения Разметчика ([[DP.ROLE.085]] §1б, сигналы Архитектору личной структуры).

**Результат:** запись решения о структуре: выбранный вариант, принятые потери, проверки результата, условия пересмотра. Решение не правится: изменённое решение — новая запись со ссылкой на заменяемую.

## 3. Шаги

1. **Потребитель и обязательство.** Для кого решение, какое затруднение, какое структурное обязательство от решения зависит.
2. **Опись.** Виды материала и действующие дома. У каждого вида и дома: природа (данные / знание / код / машинное), модель использования, кто фактически пишет и кто фактически читает (предполагаемый читатель помечается гипотезой с проверкой), владелец, чувствительность, темп изменения, срок хранения.
3. **Проверка действующего решения.** Таблица «решение → исходная предпосылка → новое свидетельство → затронутое ограничение → сохранить / уточнить / разработать варианты». Решение выдерживает — записать, почему; дальше шаг 5.
4. **Варианты и сравнение (только для открытого выбора).** Минимально достаточное число существенно разных вариантов; текущий — если он допустим. Сравнение по немногим характеристикам (§6). Находимость мерится задачами «где лежит …» для человека и для агента по каждому варианту. На личном уровне области человека выявляются открытой сортировкой его примеров: человек сам группирует 15–20 своих материалов и называет группы.
5. **Предложение человеку.** Рекомендация, цена перехода, принятые потери, проверки результата, условия пересмотра — наблюдаемые события, а не только дата.

Опоры шагов в своде FPF: разработка существенно разных вариантов — SYSE.5; выбор немногих характеристик модульности — C.31; решение с условиями пересмотра и пересмотр по изменившейся предпосылке — SYSE.6.

## 4. Принципы П1–П8 и их основания

| Принцип | Формулировка | Основание | Сила основания |
|---|---|---|---|
| П1 | Одно хранилище — одна природа данных | Решения пилота 18.08.2026 и наблюдённые проблемы смешения (замер 13.08: машинный шум в истории хранилища стратегии). Различение ограниченных контекстов (FPF A.1.1) поддерживает, но не выводит правило «одна природа — одно хранилище»: граница модели и граница физического хранилища не тождественны | местное решение, подтверждено практикой |

| П3 | Приставка имени хранилища = семья, подтип — в паспорте хранилища | Соглашение об именах с архитектурным назначением; соответствие роли и семьи частичное (многие роли → одна семья) | правило именования, не принцип структуры |
| П4 | Проект ≠ данные проекта | Решения пилота по случаям «фортепиано» (проект) и «плавание» (измерения), 28.08.2026 | подтверждён решениями |
| П5 | Производное хранилище строится на основе пака | Порядок доверия ([[DP.M.008]] правило 4). Относится только к производным хранилищам (DS): хранилища личных и машинных данных от пака не производны ([[DP.KR.001]] §3.4) | подтверждён, область ограничена |
| П6 | Секреты, платёжное и чужие личные данные — по умолчанию вне git; исключения только поимённые | Решение пилота 27.11.2026. Действующее исключение одно: диалоги на карантине в хранилище диалогов с ограничением доступа (риск принят пилотом 01.09.2026) | решение пилота |
| П7 | Темп изменения — вторая ось после природы данных | Местное правило приоритета осей; опирается на замер 13.08.2026, текст замера в обосновании не предъявлен — достаточность не проверена | слабое |
| П8 | Перенос: копия → проверка → удаление последним | Решения и практика миграции августа 2026, урок потери данных РП-520 | подтверждён; это правило исполнения (§5), не принцип структуры |

## 5. Правило исполнения

Перенос материала между домами выполняется только после решения человека и по порядку: копия в новый дом → проверка совпадения содержимого (побайтово или по хешу, не по имени файла) → удаление из старого дома последним. До переключения старый дом остаётся единственным источником истины, новый — проверочной копией (инвариант внешних входов, концепция структуры РП-526).

## 6. Характеристики для сравнения вариантов

- Безопасность и эволюционируемость — критические характеристики по решению пилота (АрхГейт 16.08.2026).
- Зона поражения при сбое: сколько материала затронет отказ или порча одного дома.
- Разграничение доступа: можно ли дать доступ к одному виду материала, не открывая другие.
- Находимость: доля задач «где лежит …», решённых с первой попытки человеком и агентом.
- Срок хранения: есть ли у дома правило, когда материал уходит в архив или удаляется.

Один общий балл не считается: характеристики оцениваются по отдельности (FPF C.31: единый балл модульности скрывает несовместимые характеристики).

## 7. Условия пересмотра

Пересмотр запускается наблюдаемым событием: изменилась предпосылка из таблицы шага 3; появился новый вид материала без дома; Разметчик повторно сообщает о неоднозначном маршруте или расхождении карты и факта; меняется способ работы пользователя (например, работа только из браузера). Дата пересмотра — дополнительное условие, не единственное. Результат пересмотра — новая запись решения со ссылкой на заменяемую.

## 9. Открытые вопросы

Пересмотр решения о структуре августа 2026 (срок пересмотра 2026-11-16 прошёл, пересмотр не записан) — кандидаты для таблицы шага 3:
1. Ярлыки 2.5/2.6: концепция структуры сняла их 08.09, карта домов шаблона (ADR-004) и реестр доменов держат — кандидат на синхронизацию.
2. Дом сырых знаний 2.3: в концепции — помесячные записи в хранилище стратегии, карта домов шаблона этот дом не называет — сначала установить авторитетный дом.
3. Связь личной карты маршрутизации и структуры — проверить гипотезу «структура меняется редко, карта часто».
4. Работа из браузера без локальной копии — проверяемая гипотеза для П6 и дома «служебное состояние вне git».
5. Размещение сессий новичка в хранилище стратегии (решение 29.08) — проверить годность.

Особое мнение (Kimi, пир-сессия 27.11): на личном уровне метод применяется с суженным выбором вариантов, а не только в сокращённом виде; ISO 15489 избыточен на обоих уровнях. Против (Codex): отклонение от рекомендуемой карты не разрешает менять общую схему; исключение ISO 15489 не обосновано.
