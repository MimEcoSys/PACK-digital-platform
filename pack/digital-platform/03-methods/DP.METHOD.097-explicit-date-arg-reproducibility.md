# Explicit --date arg для воспроизводимости генерации (DP.METHOD.097)

## Описание

Любой скрипт-генератор или рендерер, производящий output зависящий от текущей даты, принимает дату как явный параметр командной строки.

## Проблема со скрытым datetime.now()

Скрипт с `datetime.now()` внутри:
- Нетестируем для прошедших дат
- Не поддерживает ретроактивное восстановление пропущенных дней
- Даёт разные результаты при каждом запуске (не воспроизводим)

## Паттерн

```python
parser.add_argument('--date', type=str, help='Render date (YYYY-MM-DD), default: today')
render_date = args.date or datetime.now().strftime('%Y-%m-%d')
```

Scheduled-job явно передаёт целевую дату:
```bash
python render.py --date "$(date +%Y-%m-%d)"
```

## Применение

- Рендеры персональных руководств, дневных отчётов
- Любой pipeline с date-dependent output (дайджесты, снапшоты)
- CI/CD jobs с temporal dependencies

## Инвариант

Дефолт = «сегодня», явный аргумент переопределяет. Это позволяет:
1. Ретроактивный рендеринг пропущенных дней
2. Детерминированное тестирование (конкретная дата = конкретный output)
3. Scheduled-job явно передаёт свою дату-цель

Граница инварианта: дефолт «сегодня» годится для рендера «за сейчас», но не для закрытия прошедшего периода — там действует цепочка источников даты из уточнения ниже.

## Уточнение: цепочка источников даты для ритуалов «закрыть период» (WP-7 Ф286, 2026-11-02)

Дефолт «сегодня по часам» неверен для скриптов, которые **закрывают прошедший период** (закрытие дня, недели), если их запускают после полуночи. Подготовка сводки закрытия дня в 00:30 брала следующие сутки. Коммиты, сессии, учёт времени и проверки смотрели не на тот день.

Порядок определения даты закрываемого периода:

1. **Явно переданная дата** (`--date YYYY-MM-DD`). Невалидная дата (`2026-02-30`) — отказ с отдельным кодом выхода, а не тихий откат на «сегодня».
2. **Граница суток пользователя** — та же, что у открытия дня. При границе 04:30 запуск в 00:30 закрывает вчерашний день, коммит в 00:30 входит в окно этого дня.
3. **Часы** — только если нет ни явной даты, ни границы.

Правила:

- **Одна переменная** даты закрываемого периода на весь скрипт. Поздние шаги не вызывают часы заново.
- **Одна граница** для открытия и закрытия. Окно дня у обоих ритуалов считается одинаково.
- **Без границы после полуночи — подсказка, а не догадка.** Скрипт печатает, что нужно передать дату явно, и не выбирает день сам.
- **Источник даты печатается** в заголовке результата («дата: передана / по границе суток / по часам»), чтобы ошибку было видно в самом артефакте.

Тест применимости: «Может ли этот скрипт запуститься после полуночи для периода, который закончился до неё?» Если да — нужен шаг 2 цепочки и одна переменная даты. Регрессионные тесты: граница 04:30 включает коммит 00:30; невалидная дата даёт отдельный код выхода.

## Явная дата и при чтении источника

Параметр `--date` в самом генераторе не спасает, если внутри он берёт данные у источника в режиме «за сегодня» (`--today`, `/summaries?range=today`, `WHERE day = current_date`). Такой источник отдаёт день *вызова*, а не отчётный день. Типовые сбои:

- закрытие дня после полуночи берёт пустой или уже следующий день;
- на установке, где источник в режиме «сегодня» работает неполно, вывод пуст, хотя данные за дату есть.

**Правило:** отчётная дата, переданная генератору, передаётся дальше в каждый запрос к источнику как явный параметр. Режим «сегодня» у источника не используется, даже когда отчёт строится «за сегодня».

**Тест:** запустить закрытие дня D в 00:30 дня D+1. Метрика должна относиться к D.

**Прецедент:** протокол закрытия дня брал время кодирования через `wakatime-cli --today`. Его заменили на сводку за явную дату закрытия (`wakatime-day-total.py YYYY-MM-DD`; iwe-local-config PR #82, WP-529 Ф248).
