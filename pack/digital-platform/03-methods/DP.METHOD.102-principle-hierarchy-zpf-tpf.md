# Лестница сводов принципов: ядро FPF → DPF → LPF (DP.METHOD.102)

## Описание

Иерархия сводов принципов по оси общности применения. Каждый уровень конкретизирует принципы предыдущего для своей области. Публичный стек FPF Library: ядро FPF (трансдисциплинарные понятия и методы) → DPF (предметные своды, применимые в разных организациях) → LPF (свод местной практики). Основание: FPF Library.Reference:10, E.4.DPF; MIMDEV52:9.

## Уровни

| Уровень | Что это | Где в IWE |
|---------|---------|-----------|
| **ZPF** (внутреннее обозначение IWE) | Нулевые принципы: логика, онтология | Base / ZP |
| **FPF** (ядро) | Трансдисциплинарные понятия и методы | Base / FPF |
| **DPF** (у нас SPF-инстанс, Pack) | Предметный свод: методы домена, применимые в разных организациях | Pack |
| **LPF** (свод местной практики) | Руководство для ограниченной местной практики — организации, проекта, устройства инструментов, обстановки практика — в её фактических условиях (Library.Reference:10) | Практика нашей IWE: CLAUDE.md, протоколы ОРЗ, гейты, хуки, скиллы (у нас прежде «TPF-процессный»); практики МИМ или компании |

ZPF, SPF, TPF в FPF — входные псевдонимы без установленных публичных имён (FPF-Spec, F.18); в IWE остаются внутренними обозначениями. Личная практика носителя роли (Lifework, траектория решений, DP.D.178) — частный случай местной практики, не определение LPF. До 29.10.2026 LPF здесь ошибочно расшифровывался как «Locally Particular Framework — практика конкретного носителя роли».

## Алгоритм поиска применимого принципа

**Направление: сверху вниз (общее → местное)**

1. Есть ли общий принцип ядра FPF (или ZPF) для ситуации?
2. Если нет → DPF (принципы домена из Pack)
3. Если нет → LPF (принципы местной практики: нашей IWE, организации, проекта)
4. Если нет → личная практика носителя роли (DP.D.178)

## Алгоритм загрузки в агента (/fpf скилл)

**Направление: снизу вверх (местное → общее)**

Наиболее местные принципы загружаются первыми — они перевешивают общие при конфликте (конкретное специфичнее общего), если не нарушают условия более общих уровней.

## Инвариант

**Местный принцип не работает без предметного контекста.** При применении принципа LPF проверять, удовлетворены ли условия DPF и ядра. Местный свод ссылается на поставщика (ядро, DPF) и описывает только нужную конкретизацию; полные методы не копирует (MIMDEV51:7, E.4.DPF).
