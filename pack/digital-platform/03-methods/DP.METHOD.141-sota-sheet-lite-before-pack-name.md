# DP.METHOD.141 — SoTA-Sheet-lite до имени домена

## Описание

При создании нового Pack — собрать облегчённый лист источников домена (SoTA-Sheet-lite) ДО выбора имени Pack. Имя домена выбирается по результатам SoTA, а не навязывается заранее.

Инверсия стандартного порядка: не «назвали домен → нашли источники», а «нашли источники → уточнили имя».

Уточняет `DP.M.103` (процесс создания Pack, 7 фаз) — Ф1 того метода уже включает «онтология + SOTA-сбор», этот метод специфицирует конкретную деталь порядка внутри `pack-new`: сбор источников идёт отдельным шагом ДО выбора имени, а не одновременно с онтологией.

## IPO

**Input:** намерение создать Pack + неопределённость о точном имени/границах домена

**Process:**
1. Собрать SoTA-Sheet-lite: 5–10 ключевых источников предметной области
2. Выявить устоявшийся термин, которым отрасль называет домен
3. Зафиксировать границы домена (что входит / что нет), выявленные из SoTA
4. Только после этого — выбрать имя Pack (существительное-домен)

**Output:** SoTA-Sheet-lite + обоснованное имя Pack + уточнённые границы домена

## Когда применять

- Имя домена неочевидно или выбирается произвольно
- Первоначальное имя — «тема» (не «домен»)
- Есть риск создать Pack с неверными границами

## Тест применимости

«Отрасль уже как-то называет этот домен? Совпадает ли это с выбранным именем Pack?» Несовпадение → повод пересмотреть имя после SoTA.

## Пример

Peer-сессия 2026-07-09: имя Pack уточнилось по результатам SoTA-Sheet-lite — обнаруженный термин из источников точнее отразил предметную область. Результат применён в FMT-exocortex-template: шаг 0 pack-new изменён — сбор источников предшествует выбору имени.
