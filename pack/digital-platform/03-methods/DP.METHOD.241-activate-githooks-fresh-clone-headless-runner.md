# DP.METHOD.241 — явная активация .githooks во фреш-клоне

## Суть метода

Init-скрипт headless-раннера, работающего со свежим git-клоном (а не с ранее настроенным рабочим окружением пилота), явно выполняет `git config core.hooksPath .githooks` — git по умолчанию не активирует нестандартную директорию хуков автоматически даже при их физическом наличии в репозитории.

## Обоснование

`core.hooksPath` — локальная git-настройка, не переносимая вместе с клоном репозитория. Без явной установки во фреш-клоне все pre-commit/pre-push хуки репозитория молча не срабатывают — headless-агент коммитит без защиты хуков, даже если репозиторий формально их содержит.

## Применение

Init/bootstrap-скрипт любого headless-раннера, клонирующего репозиторий с нестандартным путём git-хуков.

## Доставка файлов и проверка активации

До активации хуки должны попасть в клон как отслеживаемые файлы, например `.githooks/`. Содержимое локальной `.git/hooks/` не переносится обычным клонированием репозитория. Bootstrap задаёт `core.hooksPath` для клона; наличие файлов, настройка активного пути, executable bit и фактическое исполнение проверяются отдельно. Проверка выполняет безопасное действие, для которого ожидается наблюдаемый эффект нужного хука.

Старые локальные копии не удаляются автоматически: сначала устанавливаются действующий путь и назначение копий. DP.FM.193 описывает путаницу после миграции. Историческое основание: MC-sessions `4e33baf13`, перенос хуков в отслеживаемую `.githooks`. Контракт Git: https://git-scm.com/docs/githooks.
