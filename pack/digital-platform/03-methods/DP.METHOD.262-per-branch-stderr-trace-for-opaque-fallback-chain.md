# DP.METHOD.262 — Per-branch stderr trace для непрозрачной fallback-цепочки

## Описание

`close` и `note-commit --forget` расходились в вердикте по одному и тому же claim после разделения коммита на два, и не было способа понять, какая из ~12 fallback-проверок у каждого консьюмера сработала — цепочка проверок (`||`-chain) непрозрачна: виден только финальный булев результат, не то, какая конкретная ветка его дала.

## Метод (IPO)

**Input:** цепочка из N fallback-проверок (`||`-chain или аналог), определяющая результат без диагностируемости того, какая ветка сработала.

**Process:**
1. Переписать `||`-chain в явный if/elif, где каждая ветка сама себя называет через print-only trace-строку в stderr (например, `claim-proof-trace: <какая-проверка-matched>`).
2. Поведение (возвращаемое значение/exit code) не меняется — изменение чисто диагностическое.
3. Подтвердить холодным ревью и новым smoke-тестом, что это именно print-only добавление, не затрагивающее логику.

**Output:** при расхождении вердиктов двух консьюмеров одной fallback-логики по одному и тому же входу — сразу видно по stderr каждого прогона, какая конкретная ветка сработала, без бинарного поиска по N веткам вручную.

## Тест применимости

«Можно по одному прогону (без дополнительной инструментации) отличить, какая из N веток fallback-цепочки сработала?» Нет → добавить именующие trace-строки per-branch в stderr, не меняя сам предикат или порядок проверок.

## Применимость

Любая `||`/elif-цепочка из нескольких fallback-проверок, где два разных консьюмера (команды/процесса/CLI) могут прийти к разным вердиктам по одному и тому же входу, и расхождение нужно диагностировать без изменения поведения ни одной из веток.
