# DP.METHOD.263 — Разбор завершённой сессии по отношениям сведений к работе

> **Статус: кандидат, не признанный метод.** Применений пока нет. Признание - после двух разборов закрытых сессий со свидетельствами (концепция РП-608 §18.5, путь через аудит и загрузку наших методов).

### Definition

Разбор закрытой сессии, в котором каждое затруднение помечается отношением сведений к работе, которого не хватило (DP.D.371), вместо общего вывода «ИИ плохо справился».

### Purpose

Отличить, что развивать: описание метода, получение сведений о предмете, постановку задания, разрешения, проверки или сохранение результатов. Без разбора исправления сводятся к случайной правке промптов.

### Forces

| Force | Tension |
|-------|---------|
| Точность против стоимости | Подробный разбор каждой сессии остановит работу; разбор делается по запросу пилота или при заметном затруднении |
| Метка против объяснения | Одна метка удобна для подсчёта, но не заменяет разбор причины; метка ставится к названному затруднению, не вместо него |
| Своя классификация против свода | Соблазн завести таблицу «использований»; FPF запрещает общую связь использования, поэтому разбор - одно описание со ссылками |

### Inputs

| Input | Description | Required? |
|-------|-------------|-----------|
| Закрытая сессия | Отчёт сессии, стенограмма или ретро закрытия | Yes |
| Карточка РП | План, решения пилота, передача работы | Yes |
| Профиль ошибок агента | Повторяющиеся косяки исполнителя | No |

### Action

1. Найти затруднения сессии: переделки, эскалации, места, где пилот менял решение агента, ошибки.
2. Для каждого назвать одну метку пробела: не хватило описания метода, сведений о предмете, плана, обязательств и разрешений, решений гейтов, наблюдений по ходу работы или результатов прошлой работы. Метки плана, обязательств и разрешений, решений гейтов относятся к одному отношению - управляющим сведениям (DP.D.371), метки нужны, чтобы различить, чего именно не хватило. Отдельно ответить на вопрос об исполнителе: кто выполнял, с какими возможностями и профилем ошибок.
3. Для каждой метки указать, где эти сведения должны были быть (Ритуал открытия, карточка, передача работы, описание метода, профиль ошибок).
4. Проверить, закрывает ли пробел существующее поле; если нет - записать пробел как кандидат на изменение среды.

### Outputs (Work Products)

| Output | Link | Description |
|--------|------|-------------|
| Описание разбора | (помещается в отчёт сессии) | Одна эпистема о разбираемой работе со ссылками на метод, план, готовность, свидетельства и решения гейтов (FPF A.15:4.4a), без отдельного журнала связей |
| Метки пробелов | ретро закрытия, запись косяка | Одна метка на затруднение (РП-484, строка-метка) |

### Roles Involved

| Role | Responsibility in This Method |
|------|------------------------------|
| Агент, ведущий РП | Делает разбор |
| Пилот | Читает разбор, решает, что менять в среде |

### Key Distinctions

- [DP.D.371](../02-domain-entities/DP.D.371-information-function-relative-to-work-vs-information-kind.md): метка - отношение сведений к этой работе, а не вид документа.

### Bias-Annotation

Склонность разборщика ставить метку «не хватило описания метода», потому что её проще всего исправить новым текстом. Противовес: сначала проверить, были ли сведения о предмете и задание, и только потом метод.
