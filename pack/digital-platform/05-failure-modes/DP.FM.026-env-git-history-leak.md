# DP.FM.026 — .env в git history: нарушение 12-factor F3

## Паттерн

Файл `.env` с реальными секретами случайно добавлен в `git add .` и закоммичен. Даже после `git rm .env` файл остаётся в истории — доступен через `git log --all --full-history -- .env`.

## Сигнал аудита

```bash
# Проверить, был ли .env в истории
git log --all --full-history -- .env
# Проверить содержимое по всей истории
git grep -I 'API_KEY\|SECRET\|TOKEN' $(git rev-list --all)
```

## Обязательные шаги при обнаружении

### Шаг 1 — Ротация (немедленно)

Ротировать ВСЕ скомпрометированные secrets, даже если репо приватный. История могла быть склонирована коллаборантами.

### Шаг 2 — Очистка истории

```bash
# Вариант A: BFG Repo-Cleaner (быстрее)
bfg --delete-files .env
git reflog expire --expire=now --all && git gc --prune=now --aggressive
git push --force-with-lease

# Вариант B: git filter-repo
git filter-repo --path .env --invert-paths
```

### Шаг 3 — Защита от повторения

`.gitignore` должен покрывать ВСЕ варианты:
```
.env
.env.*
**/.env
**/env/
```

`.env.example` (без secrets) — обязательный артефакт.

## Паттерны защиты (превентивные)

- `pre-commit` hook: `git-secrets` или `detect-secrets`
- CI-сканер: Gitleaks, truffleHog
- Template `.gitignore` для всех новых репо

## Повторный инцидент: секрет не только в `.env`, но и в файлах памяти агента; рецидив после первой находки (2026-10-05)

Паттерн воспроизводится не только для `.env`, но и для ЛЮБОГО отслеживаемого git текстового файла, в который буквально записано значение секрета — например, файлы памяти агента (`memory/*.md`). Находка 01–02.10.2026: пароль продуктовой базы лежал открытым текстом в двух отслеживаемых копиях заметок памяти; правка заменила значение пометкой в текущей версии, но история git значение сохранила — ротация обязательна так же, как для `.env` (Шаг 1 выше). Отдельно в тот же период зафиксирован **рецидив**: «боевые» значения доступа снова появились в тексте сессии уже после первой находки.

**Дополнение к Шагу 1 (Ротация):** если после находки и правки текста секрет появляется повторно — проблема не исчерпывается одним инцидентом: не устранён источник копирования секрета в текст (привычка/процесс, который продолжает вставлять значение). Одна лишь ротация без устранения источника копирования не исключает третий рецидив того же значения.
