# [DP.FM.038] Silent-Pass Validator on Missing Input

## Суть паттерна

Валидатор на пустом или несуществующем входе возвращает exit 0 («ничего не нарушено»). В CI это выглядит как зелёный билд. Опечатка в пути, несостоявшаяся checkout-команда или удалённая директория → нулевая проверка → ложно-положительный сигнал.

Обобщение HD #51 («HTTP 200 + 0 bytes = false-green») от HTTP-ответов на любой validator output.

## Механизм

1. Валидатор принимает путь как аргумент (`v4-lint structure $PATH`).
2. На входе `$PATH = /tmp/nonexistent` (опечатка) или пустая директория после неудачного checkout.
3. Внутренний loop по файлам не находит ничего → 0 нарушений → exit 0.
4. CI green — но проверки не было.

## Защита

Валидатор обязан:

1. **Явно проверять существование входа** — `[ -e "$path" ]` → exit 1 с сообщением «путь не существует».
2. **Явно проверять non-empty корпус файлов** — если `len(files) == 0` → exit 1 с сообщением «не найдено файлов для проверки».
3. **Возвращать ненулевой код в обоих случаях** + явное сообщение в stderr.

```python
def validate(path):
    if not os.path.exists(path):
        sys.exit(f"ERROR: путь не существует: {path}")
    files = collect_structure_files(path)
    if not files:
        sys.exit(f"ERROR: не найдено файлов для проверки в {path}")
    # ... обычная валидация
```

## Применимость

Любой tool с pipeline-интеграцией: pre-commit hooks, CI gates, scheduled audits, lint-инструменты, schema-validators.

## Вариант: отсутствующий обязательный вход исключён до проверки

Генератор сначала отбирает только существующие файлы, а проверяющий получает уже урезанный список. Даже если проверяющий умеет отмечать отсутствующие входы, он не увидит ожидаемый файл, который генератор исключил. Непустой список остальных файлов не доказывает полного охвата.

**Прецедент.** В `DS-my-strategy@89d57e016` генератор `scripts/generate-hot-files-list.sh:32–34` добавляет обязательный файл инструкций выбранного управляющего репозитория только под `if [ -f ... ]`. Исправление чтения кавычек из настройки устранило одну причину неверного пути, но условное исключение отсутствующего файла осталось. Потребитель `scripts/verify-context-budget.sh:13–32` проверяет только перечисленные пути. Более того, ветка `MISSING > 0` в строках 174–177 лишь предупреждает и не переводит итог в отказ.

**Предлагаемое противодействие.** Перечень ожидаемых обязательных входов получают из контракта, не фильтруют по факту наличия. Отсутствующий обязательный вход либо прекращает генерацию с явной ошибкой, либо передаётся потребителю как отсутствующий; потребитель обязан завершить проверку неуспехом. Явно необязательный вход обрабатывают по отдельному контракту. Одного добавления пути в список недостаточно, если потребитель только предупреждает.

**Тест.** Убрать один обязательный файл при наличии остальных. Генератор не должен незаметно уменьшить ожидаемый перечень, а итоговая проверка не должна объявить соблюдение бюджета по неполному набору. Проверить также вариант, когда отсутствующий путь принудительно оставлен в списке: предупреждение без неуспеха не выполняет этот критерий.

**Статус.** В локальной временной копии исходных скриптов воспроизведены оба пропуска: генератор исключил отсутствующий файл и вернул 0; потребитель с явно добавленным отсутствующим путём сообщил `MISSING`, затем `PASS` и вернул 0. Рабочие скрипты не изменялись. Предложенное противодействие не внедрено этим разбором.
