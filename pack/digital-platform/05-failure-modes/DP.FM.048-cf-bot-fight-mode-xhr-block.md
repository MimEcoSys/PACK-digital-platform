# DP.FM.048 — CF Bot Fight Mode блокирует Python XHR но не curl

## Симптом

CLI-инструмент (Python `requests.post` / `httpx`) получает HTTP 403 с Challenge при обращении к CF Worker endpoint с включённым Bot Fight Mode.

## Причина

CF классифицирует автоматизированные Python HTTP-клиенты как бот-трафик по User-Agent + TLS fingerprint. `curl` не классифицируется как бот.

## Диагностика

HTTP 403 от CF Worker при автоматическом запросе, но тот же запрос через `curl -X POST <url> -d <payload>` возвращает 200.

## Fix

```python
subprocess.run(["curl", "-X", "POST", url, "-d", payload])
```
вместо `requests.post()`.

## Альтернатива

Отключить Bot Fight Mode для конкретного route через WAF rule в CF dashboard (требует доступа к CF dashboard).

## Применимо к

Любой headless Python-скрипт, записывающий данные на CF Worker endpoint с включённым Bot Fight Mode.

## Второй случай (2026-11-04): стандартная подпись Python, код 1010 и повтор дефекта в новом скрипте

Дополнение 2026-11-10 (РП-170, отчёт 2026-11-09-inbox-check-10, кандидат 4).

**Симптом.** Скрипты, отправляющие факты в журнал событий через шлюз, получали HTTP 403 с кодом 1010: край шлюза отклоняет стандартную подпись Python-клиента (`Python-urllib`). Код 1010 у Cloudflare означает запрет по подписи клиента, так что ключи и права проверять не нужно. При разборе неотправленных фактов сессии 2026-11-04 нашлось 17 фактов, не дошедших до журнала.

**Повтор.** Тот же дефект был у `post-culture-fact.py` и исправлен там до 29.10, но только в этом скрипте (тот же случай записан уроком памяти 01.11, `lessons_cloudflare_workers_dev_403_default_python_user_agent.md`). Два новых скрипта того же рода (`post-role-install-facts.py`, `post-structure-used-fact.py`) повторили его.

**Исправление.** Каждый скрипт отправки называет себя явно (`User-Agent: iwe-<скрипт>/1.0`), а тест проверяет этот заголовок (git commit `108a646d2` в DS-my-strategy). Здесь явной подписи хватило, `curl` не понадобился. Если край отвечает проверкой-вызовом (challenge), как в основной части карточки, одной подписи может не хватить.

**Переносимое.** Исправление класса закрепляют там, где его не обойдёт следующий клиент: в общей функции отправки или в тесте на заголовок у каждого клиента. Точечная правка защищает только исправленный скрипт. Общий принцип — `VR.M.023` (исправленный класс ищут во всех соседних местах) и `VR.M.034` (повтор ошибки того же типа — повод перейти от точечных правок к машинной проверке).

**Тест обнаружения.** «Сколько скриптов шлют запросы через этот край, и у каждого ли задана своя подпись и тест на неё?» Если не у каждого, дефект вернётся с первым новым скриптом.
