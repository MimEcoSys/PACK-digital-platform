# DP.FM.249 — Env-var с устаревшим дефолтом переименованного репо

## Описание

Env-var определена с bash-дефолтом `${VAR:-legacy-name}`. При переименовании репо обновляется объявление переменной, но не код, где дефолт встроен inline. `cd "$IWE/${VAR:-legacy-name}"` молча упал — bash `cd` возвращает ненулевой exit code, но скрипт без `set -e` продолжает выполнение в неверном каталоге.

## Симптом

Day Open возвращал «нет данных» для блока commits/WP-closed, хотя данные были. Ошибки нет, скрипт завершается успешно, вывод выглядит корректно. Диагностика без `set -e` затруднена.

## Механизм

```
T0: экспорт IWE_GOVERNANCE_REPO=DS-strategy
    cd "$IWE/${IWE_GOVERNANCE_REPO:-DS-strategy}"  →  ✓ работает

T1: репо переименовано → DS-my-strategy
    Переменная обновлена: IWE_GOVERNANCE_REPO=DS-my-strategy
    Код скрипта: cd "$IWE/${IWE_GOVERNANCE_REPO:-DS-strategy}"
                                                          ↑ дефолт не обновлён

Сценарий отказа: переменная не экспортирована в env текущей сессии
    → bash использует дефолт: DS-strategy
    → cd "/home/tseren/IWE/DS-strategy" — не существует
    → exit code ≠ 0, но без set -e → продолжение в текущем каталоге
```

## Профилактика

1. `set -e` в начале скриптов IWE — любой `cd` failure = abort
2. Явная проверка: `cd "$dir" || { echo "path not found: $dir"; exit 1; }`
3. При переименовании репо: `grep -rn ":-${OLD_NAME}" ~/IWE/` → обновить все встреченные дефолты

## Второй прецедент: задача планировщика несёт только HOME и PATH

Тот же класс «встроенный дефолт указывает на старый путь», но триггер другой: не переименование репо, а минимальное окружение запуска. Задача планировщика (launchd) получает только `HOME` и `PATH`. Сторожевой скрипт `knowledge-audit-watchdog.sh` запускал устаревшую копию экстрактора из `DS-ai-systems`, а не доставленный рантайм. Без явно заданной `IWE_GOVERNANCE_REPO` рантайм откатывался бы на каталог `DS-strategy`, который существует и в другом месте под `~/IWE`. В комментарии к коду сказано, что этот каталог «взял бы изоляцию»; это слова автора кода, в карточке они не утверждаются как проверенный факт.

Исправление (commit `3b66946f5` в DS-my-strategy, WP-530 Ф72): окружение рантайма выставляется явно в точке запуска (`IWE_WORKSPACE`, `IWE_TEMPLATE`, `IWE_RUNTIME`, `IWE_GOVERNANCE_REPO`, `PATH`); если в рантайме нет нужной команды (`audit-scheduled`), скрипт выходит отдельным кодом 3 с сообщением «пересобери рантайм», а не работает по старому пути молча.

Тест: «Что из окружения задача получает от планировщика? Какой путь выбирается при отсутствии переменной, и заметит ли это кто-нибудь?»
