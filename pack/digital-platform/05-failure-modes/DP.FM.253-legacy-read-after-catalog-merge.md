# DP.FM.253 — Инструмент читает legacy-источник после переезда source of truth

## Паттерн

При создании нового единого источника данных (catalog merge, rename, migration) производственный инструмент продолжает читать прежний путь. Данные выглядят правдоподобно, инструмент не падает — явной ошибки нет.

**Пример (WP-465):** `render-pilot-guides.py` читал `DS-autonomous-agents/agents/tailor/memes.json` (91 M-мем, 0 P-мемов, синхронизация 31 мая) вместо нового `SA.CAT.001`. Объединение каталогов произошло 20 июня — инструмент не был переключён.

## Следствие

- Инструмент работает штатно, результаты выглядят корректными
- Прод не видит ни одной записи из нового источника
- «Тихая регрессия»: данные правдоподобны, но отражают устаревшее состояние (в примере — данные на 31 мая вместо актуальных)

## Условия возникновения

1. Создаётся новый source of truth (объединение каталогов, переименование, миграция)
2. Список потребителей legacy-пути не составлялся
3. Инструмент не переключается атомарно вместе с созданием нового источника

## Тест обнаружения

«Данные в проде обновились после объединения каталогов?»
- Нет → проверить что читает каждый инструмент-потребитель (grep по legacy-пути)

## Профилактика

При слиянии/переезде источника данных: (1) `grep -r "<legacy-path>"` по всем инструментам-потребителям; (2) переключить всех потребителей атомарно с созданием нового источника; (3) удалить legacy-файл или оставить stub с явным `DEPRECATED` и ссылкой на новый путь.

## Вариант 2026-10-24: дефолтный путь, который не исполняет ни один тест

Каталог `indexes/` убрали 07.07, а умолчание пути к реестру в гейте нумерации осталось прежним: каждый вызов без `--registry` падал с «registry not found». Сбой был громким, но месяцами не замечен — все тесты передавали путь явно, и умолчание не исполнялось ни разу.

**Тест обнаружения:** «Есть ли тест, который вызывает инструмент без явного пути и проверяет, что умолчание указывает на существующий непустой источник?» Нет → переезд источника сломает умолчание незаметно.

**Контрмера:** при переезде source of truth проверять не только читателей с явным путём, но и умолчания в коде; держать отдельный тест на умолчание.

Источник: git commit `f8d75170f` в DS-my-strategy (WP-388 Ф23). Захват: `DS-my-strategy/inbox/captures/2026-10.md:6565`; extraction-report `2026-10-24-inbox-check-4.md`, кандидат #3.

## Вариант 2026-11-03: клиент на старом пути полной выгрузки — данные полные, растёт стоимость

Дополнение 2026-11-10 (РП-170, отчёт 2026-11-08-inbox-check-7, кандидат 2).

Приёмник событий уже умел отдавать данные постранично по курсору (`?protocol=1`), но клиент по расписанию (96 раз в сутки) вызывал старый путь `GET /export` без параметра протокола. Старый путь при каждом вызове отдаёт весь накопленный `events.jsonl`. Файл вырос примерно до 3 ГБ, и опрос давал около 2,5 ТБ исходящего трафика в месяц: $124 в месяц, 67% всего счёта аккаунта. Ошибок не было, данные доходили полностью, поэтому тест основного паттерна («данные в проде обновились?») этот вариант не ловит.

**Отличие от основного паттерна:** потребитель так же не переключён на новый путь, но вред другой. Данные не устаревают, а стоимость каждого опроса растёт с общим объёмом журнала, а не с объёмом новых данных.

**Тест обнаружения:** «Зависит ли стоимость одного опроса периодического клиента от прироста данных или от их общего объёма? Если сервер поддерживает оба пути, какой из них клиент вызывает на самом деле?» От общего объёма или старый путь → этот вариант.

**Контрмера (из источника):** вызывать курсорный путь (`?protocol=1`) и хранить курсор на диске между запусками. Отставание выбрано за два прогона, дальше опросы почти пустые.

Источник: git commit `812a99ba4` в DS-my-strategy (WP-470). Захват: `DS-my-strategy/inbox/captures/2026-11.md:1353`; extraction-report `2026-11-08-inbox-check-7.md`, кандидат #2.

## Связи

- **DP.FM.224** — инструмент видит smart-sync stub вместо локального файла: схожий класс (инструмент читает не тот источник), другой механизм
- **DP.FM.360** — прод-сервис в обход LLM-прокси: тоже работает без ошибок, а расход не виден. Там обход обязательного шлюза, здесь (вариант 2026-11-03) — старый путь при уже поддержанном новом.
- **AS.FM.071**, **DP.FM.599** — общий принцип варианта 2026-11-03: стоимость растёт с накопленным объёмом и не видна на одном замере. Другой субстрат: сложность алгоритма; разбор команды в хуке.

Производственный конвейер Портного (`render-pilot-guides.py`) не был переключён — продолжал читать legacy `memes.json` (91 M-мем, 0 P-мемов) вместо 54 продуктивных мемов и 128 актуальных непродуктивных. Обнаружено как побочная находка при WP-465 fact-check вне scope сессии.
