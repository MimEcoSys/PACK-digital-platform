# DP.FM.435 — Гонка проверки и чтения файла; неполная обработка ошибок чтения

## Тезис

Предварительная проверка существования файла не гарантирует успешного последующего открытия. Ошибка чтения также не доказывает физического отсутствия источника. При обработке набора файлов необходимо сохранять различие между отсутствием, недоступностью чтения и некорректным содержимым.

## Механизм 1: состояние меняется между проверкой и чтением

Между isfile()/exists() и open() файл может исчезнуть, сменить тип или стать недоступным. Результат предварительной проверки не описывает состояние последующей операции. В описанном случае ошибка чтения дневного журнала могла включить запасной поиск по git log, предназначенный для иного условия — отсутствия самого источника.

Решение о запасном пути должно опираться на фактическую классификацию отказа согласно контракту источника, а не на предположение, что состояние после exists() неизменно.

## Механизм 2: обработчик покрывает только ошибки парсера

Перехват только yaml.YAMLError не покрывает ошибки открытия, прав доступа или декодирования. Эти ошибки возникают до разбора либо вне библиотеки парсера; исправление окна гонки само по себе не расширяет их обработку.

Набор ожидаемых отказов определяется всем путём чтения. Разные причины не следует сворачивать в один успешный запасной результат.

## Дополнение 2026-11-20 (пакет 33, РП-170 Ф21): запасной путь при «данных нет» и при «данные не читаются» — второй субстрат «Механизма 1»

Тот же вопрос, что в «Механизме 1» (какой исход включает запасной путь), на другом источнике. Сводка связанных РП (`.claude/scripts/wp-sync-bundle.sh`, iwe-local-config) берёт список открытых фаз из шапки карточки РП (блок `phases:`), а если его нет — считает незакрытые галочки `- [ ]` в тексте. Если нечитаемая шапка молча уходит в подсчёт галочек, вызывающий получает другой счёт и принимает его за ответ основного пути.

**Состояние 10.11.2026 (коммит e5c9775).** Разбор шапки библиотекой YAML давал три исхода: 0 — разбор прошёл (печатаются открытые фазы; вывод пуст и тогда, когда блок есть, но открытых фаз нет); 1 — ключа `phases` нет → запасной подсчёт галочек; 2 — файл или шапка не читаются (ошибки открытия, значения, разбора YAML) → отказ с записью `phase_parse_error` в журнал синхронизации. Вызывающий включал запасной путь только при коде 1: «данных нет» вело в запасной путь, «данные не читаются» — в отказ.

**Состояние 11.11.2026 (коммиты 0ccbec5 и cc24fb9, РП-484 Ф299 п. 4; действует на 20.11).** Разбор переведён на общий модуль `scripts/lib/phase_status.py`, который читает строки шапки без библиотеки YAML. Если блок `phases:` есть, но не прочитано ни одной записи (латинские номера, свободная форма), — теперь сознательно код 1: сводка откатывается на галочки, как и при отсутствии блока; довод сообщения коммита — пустой разбор не должен означать «открытых фаз нет» для карточки, которую не прочитали. Предупреждение `phases_unreadable` выдают архиватор закрытых фаз и писатель снимка фаз (проверено по коду), а по сообщению коммита — и гейт фаз; в самой сводке возврат на галочки идёт без сообщения. Код 2 (отказ, `phase_parse_error`) остался только для сбоев: нет модуля разбора, файл не читается (ошибка открытия или декодирования), у карточки нет шапки.

**Что из этого следует.** Различимость исходов из «Тезиса» сохраняется в обоих состояниях, но куда вести нечитаемое — решение по цене ошибки: 10.11 нечитаемое вело к отказу; 11.11 нечитаемый блок ведёт в запасной путь, у части потребителей — с явной пометкой, а отказ оставлен для сбоя чтения. Правило «запасной путь только при «данных нет»» в общем виде поэтому неверно; вывод при записи дополнения (не правило источника): запасной путь не должен включаться исходом, которого для него не предусматривали, без того, чтобы это было видно вызывающему.

**Не проверено.** Исход для синтаксически битой шапки в `phase_status.parse_phases` (после отказа от библиотеки YAML) не проверялся; живое воспроизведение ни одного из состояний не заявляется — всё выше установлено по коду и сообщениям коммитов. Источник: захват `DS-my-strategy/inbox/captures/2026-11.md`, «Запасной разбор включать только при «данных нет»…»; отчёт `DS-my-strategy/inbox/extraction-reports/2026-11-20-inbox-check-4.md`, кандидат 4.

## Границы

Пропуск повреждённого элемента допустим только по контракту обработки, с явной отметкой неполноты результата. Если обязательный вывод требует всех источников, недоступность одного не превращается в «всё проверено». Этот документ не рекомендует безусловно перехватывать любые исключения или продолжать после каждого отказа.

## Проверка

Для первого механизма отдельно внедряется удаление между проверкой и открытием; проверяется классификация и допустимость запасного пути. Для второго независимо внедряются отказ доступа, неверная кодировка и ошибка разбора.

Ожидаемые исходы задаются до прогона: состояние источника и итоговый вывод остаются честными, другие элементы обрабатываются только там, где это разрешено контрактом. Прохождение одного набора сценариев не засчитывает второй механизм.
