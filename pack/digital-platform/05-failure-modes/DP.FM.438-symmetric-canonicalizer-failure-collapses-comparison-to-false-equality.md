# DP.FM.438: Симметричный отказ канонизатора вырождает сравнение в ложное равенство

## Симптом

Детектор дрейфа «текущее состояние vs каноническое» отвечает «различий нет», хотя сравнение не состоялось: обе стороны перед сопоставлением проходили через внешнюю команду (`jq`) для канонизации, канонизация падала (в таблице пересчёта единиц длительности не было `ms`/`y`), код возврата `jq` не проверялся — переменные на обеих сторонах остались пустыми строками, и `"" == ""` дало «совпадение». Найдено не штатным ревью, а отдельным холодным (cold-context) проходом уже после боевой записи.

## Причина

Результаты обоих канонизаторов присваивались переменным, но успешность каждого вызова перед сравнением не проверялась. Обычное присваивание `x=$(canon ...)` возвращает статус подстановки; если код его игнорирует, выполнение может дойти до сравнения результатов неудачных вычислений. В данном случае оба результата оказались пустыми и равенство дало ложный вывод «нет дрейфа». Отдельная конструкция `local x=$(...)` может маскировать статус подстановки статусом команды `local`, но это не механизм показанного исходного кода: там переменные объявлены отдельно.

## Почему это опаснее обычного «тихого exit 0»

Обычный тихий сбой даёт пропуск одной проверки. Здесь сбой маскируется под ПОЛОЖИТЕЛЬНЫЙ результат именно той проверки, ради которой написан скрипт: детектор дрейфа слепнет ровно на тех входах (неизвестная единица, новый формат), где расхождение наиболее вероятно — то есть отказывает избирательно в худшем месте. Ни лог, ни код возврата скрипта, ни результат сравнения не несут признаков сбоя.

## Антипаттерн → Паттерн

- **Антипаттерн:** `a=$(canon "$x"); b=$(canon "$y"); [ "$a" = "$b" ] && echo "no drift"` — код возврата `canon` не проверяется, пустая строка — легитимный операнд.
- **Паттерн:** (1) проверять код возврата каждого канонизатора и прерываться с явной ошибкой (`if ! a=$(canon "$x"); then fail "canon failed: $x"; fi`) — не `|| true`; (2) считать пустой результат канонизации ошибкой, если пустое значение не является валидным каноном для этого типа; (3) канонизатор при неизвестной единице/формате обязан падать громко (fail loud), а не возвращать пустое/исходное значение; (4) вывод «нет расхождений» допускать только после успешной канонизации обеих сторон и проверки допустимости результатов (включая пустое значение по контракту типа) — «равны» и «равны, потому что обе не вычислились» должны быть различимы.

## Переносимый принцип

Когда операнды сравнения проходят через преобразователь (парсер, канонизатор, нормализатор, decrypt), непроверенный отказ может сделать результат сравнения недостоверным. Если оба вычисления отказали и дали одинаковый результат — например, пустую строку, — сравнение может ошибочно признать совпадение. Но может отказать только одна сторона или сохраниться частичный stdout: ни ошибка, ни её форма не гарантируют одинаковых пустых результатов. При любой ошибке одной из сторон сравнение запрещено; к нему переходят только после подтверждённого успеха обоих вычислений и проверки допустимости результатов.

## Тест обнаружения

«Есть сравнение, обе стороны которого вычисляются одной внешней командой/функцией, и её код возврата или пустой результат не проверяются перед сравнением?» Да → подать на вход значение, которое преобразователь заведомо не понимает (неизвестная единица, новый формат): если детектор отвечает «совпадает / нет дрейфа» вместо ошибки — DP.FM.438.

## Применимость

Drift-детекторы desired-vs-actual, idempotent provisioning, сравнение конфигов после нормализации, сверка контрольных сумм/канонических JSON, любые shell-сравнения, где операнды получаются через `$(...)`.

## Отличие от смежного

- **DP.FM.040 (silent-null parser):** парсер возвращает пустое на нераспознанный синтаксис, и пустое ПРОХОДИТ валидацию — односторонний механизм; здесь пустое возникает на обеих сторонах равенства, и ложным становится не «пропуск», а «положительное совпадение».
- **DP.M.415 (захват реального кода возврата вместо `|| true`):** антидот для явного подавления ошибки одного защитного шага; здесь статус канонизации не проверяется перед сравнением; ущерб возникает в семантике равенства двух невычисленных операндов.
- **DP.D.299 (код возврата конвейера — только последняя команда):** другой источник потери статуса (pipe), тот же класс «статус потерян до проверки».
- **DP.FM.288 (0 итераций → exit 0), DP.FM.266 (exit 0 ≠ структурная корректность):** тихий успех при отсутствии работы; здесь работа как бы сделана и результат как бы положительный.
- **DP.FM.437 (форма стороннего контракта предположена):** тот же коммит — канонизация длительностей введена как лечение нормализации сервером при записи; этот FM — о том, как само лечение отказывает молча.
