# DP.FM.441 — Обёртка публикации довезла только вершину цепочки и вернула полный успех: второй триггер того же класса после фикса первого

## Симптом

Один вызов обёртки публикации (`publish_commit`), которому передали цепочку из трёх последовательных коммитов, довёз до `origin/main` только последний из трёх и вернул вызывающему коду честный на вид «OK: published». Частичная потеря изнутри вызова не была видна и обнаружилась случайно: следующий, не связанный коммит упёрся в конфликт modify/delete на не долетевших изменениях.

Днём раньше (11.09) у той же обёртки был закрыт другой триггер того же класса симптомов: вызывающий код пересчитывал SHA после сбоя вместо явно зафиксированного значения. Фикс стоял на месте и не регрессировал. Рецидив — не откат фикса, а другой, независимый путь к тому же результату «часть не опубликована, доложен успех».

## Причина

Два уровня.

1. **Механизм (арность примитива).** Примитив публикации по контракту переносит один коммит (в DP.M.414 паттерн шлюза — `git cherry-pick <prepared-commit-sha>`). Получив вершину цепочки, он переносит только патч вершины; `push` проходит; изнутри обёртки все шаги успешны. Тот же диапазонный дефект («диффать только `sha^..sha` тихо роняет остальные коммиты цепочки») в режиме retry-wrapper того же скрипта был найден cold-review 18.08 до деплоя — но на пути одиночного вызова аналогичной проверки не было.
2. **Класс (критерий успеха).** Критерий успеха обёртки — «мои внутренние шаги завершились», а не «origin теперь содержит то, что ожидал вызывающий». Любой внутренний путь, заканчивающийся успешным `push`, докладывает успех. Фикс одного триггера не меняет критерий — следующий триггер врёт тем же способом.

## Антипаттерн → Паттерн

- **Антипаттерн:** после фикса найденного триггера считать класс «операция сообщает успех при частичном результате» закрытым; успех = «push вернул 0».
- **Паттерн:**
  1. Точка успеха проверяется независимо от пути исполнения: после публикации сверить итоговое состояние `origin` с ожиданием вызывающего — набор коммитов по patch-id (`git cherry origin/main <expected-tip>`, DP.M.439) или итоговое содержимое затронутых путей (DP.M.430), не код возврата `push`. Расхождение → ошибка, не OK.
  2. Контракт примитива явно фиксирует арность: один коммит или диапазон merge-base..tip. Вершину цепочки либо переносить как диапазон, либо громко отвергать — не молча усекать.
  3. Рецидив того же класса симптомов вскоре после фикса — сигнал, что класс определяется отсутствующей проверкой результата, а не найденным триггером.

## Переносимый принцип

Закрытие одного найденного триггера у бага класса «операция сообщает успех при частичном результате» не гарантирует закрытия класса. Множество внутренних путей, способных соврать, открыто; класс закрывается только независимой проверкой в точке успеха — постусловием на целевое состояние, а не на собственные шаги.

## Тест обнаружения

«Обёртка докладывает успех по завершении собственных шагов, а не по сверке целевого состояния с ожидаемым?» Да → любой ещё не найденный внутренний путь может вернуть ложный успех. Практическая проверка: после каждой публикации `git cherry origin/main <expected-tip>` (или diff содержимого затронутых путей против `origin/main`) должен быть пуст; непустой результат при возвращённом OK — этот класс. Усиливающий признак: рецидив в течение суток после фикса триггера того же класса.

## Применимость

Любая обёртка с побочным эффектом на удалённую/общую цель (публикация, деплой, синхронизация, батч-загрузка), которая может применить часть и всё равно вернуть успех; в первую очередь многошаговая git-публикация в многоагентной среде, где вызывающий код передаёт вершину цепочки коммитов.

## Триггер 3: блок публикации изолированной копии (FMT-exocortex-template)

Третий независимый триггер того же класса, в другом репозитории. В реализации `ds-publish.sh` шаблона FMT-exocortex-template контракт — один коммит за вызов (`--from-commit`, по умолчанию HEAD); это не та же реализация, что `publish_commit` из `publish-gate.sh` в DS-my-strategy; блок публикации скилла `strategy-session` считал один вызов публикацией всей изолированной копии. С двумя коммитами в копии (план недели, затем inbox) блок вышел с кодом 0, а `origin/main` получил только последний: план недели остался локальным, вывод читался как успех.

Исправление (commit `b14d9c26`, WP-7 F193, #989) реализует п.2 паттерна: блок перебирает `git rev-list --reverse origin/main..HEAD` копии, публикует каждый коммит по порядку и останавливается на первом отказе с кодом самого публикатора. Уже опубликованный коммит для публикатора no-op, повтор безвреден. «Нет коммитов» печатается одной строкой «Публиковать нечего» без заявления о публикации; копия без `origin/main` — ошибка, а не «нечего публиковать». Тест: два коммита в копии доходят до `origin/main` от старого к новому, в bash и в zsh; повторный запуск `origin` не меняет.

Сопутствующая ловушка того же блока (отказ перечисления прочитан как пустой список) описана в `DP.FM.288`, причина 2.

Источник: кандидат 10/02.3#1, часть (б) (`2026-10-02-inbox-check-3.md`).

- **DP.FM.347** (partial fix одного экземпляра класса) — там лечение — перечисление всех мест кода (grep) и закрытие класса целиком; здесь перечислить триггеры нельзя в принципе, лечение — независимая проверка результата. Дополняют друг друга: 347 для мест в коде, эта — для классов симптомов с открытым множеством триггеров.
- **DP.FM.408** (watchdog докладывает «починил» без post-check) — то же лечение (проверка состояния после действия), другой субстрат (состояние сервиса vs удалённый git) и без динамики рецидива; здесь добавлены арность примитива и «второй триггер после фикса».
- **DP.M.196** (runtime-verify UPSERT), **AS.M.110** (ответ инструмента ≠ наступление эффекта) — то же семейство «формальный успех ≠ фактический эффект», другие субстраты.
- **DP.FM.391 / DP.FM.387 / DP.FM.388** — провал был зафиксирован и потерян на выходе; здесь провал не обнаружен вовсе.
- **DP.FM.038 / DP.FM.366 / DP.FM.413** — ложная зелень проверки; здесь ложная зелень мутирующей операции.
- **DP.M.414** — шлюз, чей однокоммитный паттерн и есть предположение об арности; эта карточка — его режим отказа при вершине цепочки. **DP.M.439 / DP.M.430** — примитивы независимой сверки (patch-id / содержимое), используемые здесь как лечение, а не как измерение расхождения веток или детекция no-op до публикации.
- **DP.FM.154** (commit без push) — похожий остаток (локальные коммиты не на origin), но push там не вызывается; здесь push прошёл частично и доложил успех.
