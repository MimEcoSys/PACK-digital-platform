# DP.FM.508 — Гейт владения открыт при неразрешённой личности сессии

## Симптом

Проверка `check-edit` обязана подтвердить, что редактирует владелец сессии. Она читала личность сессии из переменной окружения `CLAUDE_CODE_SESSION_ID`, и при её отсутствии (по умолчанию для любого вызывающего без неё, например Kimi или Codex) молча пропускала верификацию владения.

## Причина

Защита проектировалась под один рантайм: только там она реально включалась, а остальные вызывающие получали её отсутствие незаметно. Отсутствие ожидаемого сигнала личности трактовалось как «нечего проверять», а не как «проверить нечем — отказать». Найдено холодным ревью кода.

## Антипаттерн → Паттерн

- **Антипаттерн:** гейт, который при неразрешённой личности (нет ожидаемого сигнала) пропускает проверку.
- **Паттерн:** fail-closed: неопределённая личность сессии — отказ, а не пропуск. В исправлении личность задаётся явным аргументом `--session-id`.

## Тест обнаружения

«Есть ли путь вызова проверки владения, где отсутствие ожидаемого сигнала личности трактуется как „нечего проверять“, а не как „отказать“?» Да → это DP.FM.508.

## Второй случай и граница: охранник открытия сессии (РП-7 Ф275, 29.10.2026)

Тот же класс в хуке гейта открытия сессии: при пустом или небезопасном `session_id` хук делал `exit 0` (fail-open), хотя Claude Code передаёт идентификатор всегда. Для рантайма, которому платформа идентификатор гарантирует, пустое значение означает сбой окружения, а не законный путь. Исправление (коммиты `4511e586` в FMT-exocortex-template-index и `dba8df0` в iwe-local-config; пир-сессия 2026-10-29-32-wp7-f275-author-gate-port): отдельная ветка для пустого идентификатора блокирует только `commit` и `push` со своим понятным текстом, прочие команды не затрагиваются; явный ключ пропуска проверяется раньше блока. Алиасы одного агента (`claude`, `claude-code`) сводятся к одному семейству до выбора режима, собственный семафор опознаётся по строгой единственной строке `agent:` (смежно: DP.FM.685). Копии хука (авторская и шаблонная) приведены к одной версии с общим тестом из 100 проверок: расхождение копий само было дефектом.

Граница: правило относится к рантаймам, у которых платформа гарантирует идентификатор (Claude Code). Для агентов без такой гарантии действует AR.250 (не привязываться к переменной окружения), конфликта нет. Инцидентов с числами нет, довод логический, доверие среднее. Смежные карточки с другим объектом: DP.M.298 (fail-closed при недоступности сервиса), DP.FM.631 (отсутствие IWE_AGENT роняет pre-commit).
