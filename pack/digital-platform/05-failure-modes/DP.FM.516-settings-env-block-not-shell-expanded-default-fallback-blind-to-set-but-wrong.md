# DP.FM.516 — env-блок settings.json не раскрывает $HOME, запасное значение не видит «задано, но неверно»

## Симптом

В блоке `env` файла `settings.json` запись вида `$HOME/...` не проходила через оболочку: в каждом подпроцессе переменная содержала буквальный текст `$HOME/...`. Скрипт `rule-engine.sh` обращался к ней как `${RULE_REGISTRY:-default}`, и запасное значение ни разу не сработало. Функция `dispatch_event()` молча возвращала «ни одно правило не подходит» на любое событие, не менее 15 дней.

## Причина

Два независимых звена. Первое: загрузчик env-блока не выполняет подстановку переменных, хотя запись выглядит как shell-синтаксис. Второе: конструкция `${VAR:-default}` подставляет запасное значение только когда переменная не задана или пуста; переменная, заданная в несуществующий литеральный путь, для неё «в порядке». Вместе они превратили ошибку конфигурации в молчаливое «правил нет».

## Антипаттерн → Паттерн

- **Антипаттерн:** считать, что значение с `$VAR` в конфигурационном файле раскрыто, и полагаться на `${VAR:-default}` как на защиту от неверной конфигурации.
- **Паттерн:** проверять фактическое раскрытие в том процессе, который читает значение; не принимать «задано» за «верно».

## Тест обнаружения

«Значение с `$VAR` в конфигурационном env-блоке проверено на реальное раскрытие тем процессом, который его читает?» Нет → возможно воспроизведение DP.FM.516: переменная задана буквальным текстом, запасное значение не сработает, зависимая проверка молча перестанет совпадать.
