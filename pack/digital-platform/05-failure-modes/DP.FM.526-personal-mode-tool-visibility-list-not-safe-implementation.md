# DP.FM.526 — Список видимости инструментов личного режима не равен безопасной реализации

## Симптом

Пир-сессия разбирала жалобу пользователя iwe.system-school.ru на ошибку «таблица не существует». Список доступных инструментов личного режима отдавал почти все публичные инструменты, кроме одного явно исключённого. Остальные, включая «обратную связь», «статистику обратной связи» и «переиндексацию источника», исполнялись в личном режиме как есть и обращались к таблицам общей платформенной базы, которых в личной базе пользователя нет. Безопасный путь к данным конкретного пользователя имели только 5 инструментов.

## Причина

Список был устроен как исключения из общего публичного набора (открыт по умолчанию), а не как проверка «есть ли у инструмента отдельная личная реализация». Видимость инструмента в режиме не гарантирует, что у него есть реализация, рассчитанная на данные этого режима.

## Что сделано

Применённое исправление: список запрещённых для личного режима расширен на 4 имени инструментов. На список разрешённых (allowlist) переход в источнике не зафиксирован. Принцип «разрешать только инструменты с проверенной безопасной реализацией под режим» — вывод из этого случая, а не принятое решение.

## Побочная находка

Инструмент «переиндексация источника» оказался доступен вообще без входа в систему: тот же класс (доступность инструмента не сверена с контекстом вызова).

## Тест обнаружения

«Список инструментов режима построен как "весь набор минус исключённые" или как явный перечень инструментов с безопасной реализацией под этот режим?» Первое → непроверенные инструменты наследуют доступ к данным, для которых не рассчитаны.

## Связанные документы

- DP.METHOD.163 (CI: allowlist вместо blocklist для env-bindings) и DP.METHOD.164 (fail-closed при неизвестном MODE): близкий принцип на другом уровне. Здесь режим известен, сервис стартует нормально, а реализация каждого видимого инструмента под режим не проверена.
