# DP.FM.529 — Запрос в ретривер равен буквальному короткому ответу

## Симптом

После починки памяти диалога симптом «не в базе знаний» остался. Для реплики «да» в ответ на предложение бота поиск по базе знаний возвращал посторонние фрагменты; промпт велел модели использовать их как «результаты по запросу пользователя», и модель опиралась на усечённую историю либо отвечала «этого нет в базе знаний».

## Причина

Все предпоиски (сборка контекста, инъекция P3, синтетический tool_use) брали текст реплики как есть. Короткий ответ в многоходовом диалоге несёт смысл только вместе с предыдущим вопросом или предложением, а сам по себе поисковым запросом не является.

## Исправление

Функция `build_retrieval_query`: ответ короче порога в многоходовом диалоге ищется вместе с последним содержательным вопросом пользователя. Пороги «только в источнике»: короткий ответ — меньше 25 символов; содержательный вопрос — не менее 25 символов и не длиннее 300; ранние короткие ответы пропускаются. Промпт и история для модели не менялись; модель может повторить поиск своим запросом. Принятый риск: размывание запроса для коротких самостоятельных вопросов.

## Тест обнаружения

«Может ли в многоходовом диалоге в ретривер уйти реплика из нескольких символов без контекста предыдущих ходов?» Да → этот отказ.
