# DP.FM.531 — Пустой плейсхолдер «нет данных» скрывает сбой сборки

## Симптом

02.10 в 03:03 день открылся сообщением «День открыт: Сегодня: нет данных». Текст выглядел как нейтральное состояние (легитимно нет задач на сегодня), хотя на деле сборка плана дня упала.

## Причина

Пустой вывод обязательного по контракту конвейера (сборка плана обязана быть непустой при живом источнике) и честное «данных действительно нет» рендерились одной и той же нейтральной формулировкой. Нет сигнала действия ни в тексте, ни в оформлении.

## Исправление

Сообщение о пустом результате ОБЯЗАТЕЛЬНОГО шага сборки меняется на явное предупреждение с конкретным действием («⚠️ план не собран — проверь источник»), а не на нейтральный «нет данных»; нейтральная формулировка остаётся только там, где пустой результат — ожидаемое легитимное состояние источника.

## Тест обнаружения

«Этот пустой результат — из шага, который контракт обязывает быть непустым?» Да → текст сообщения обязан требовать проверки, не констатировать отсутствие данных нейтрально.

## Границы

Касается конкретно сообщения day-open-pipeline о плане дня. Общий класс «пустой результат ≠ легитимное отсутствие данных» шире (DP.FM.080, DP.FM.100) — эта карточка фиксирует частный, живой инцидент в конкретном сообщении.
