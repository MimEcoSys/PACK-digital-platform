# DP.FM.535 — Best-effort запись session_closed может молча не произойти

## Симптом

Приёмочная проверка закрытия пир-сессии нашла расхождение: семафор сессии закрылся и доставка результатов подтверждена, но ожидаемая по коду запись `session_closed` не попала в дневной журнал — ни за текущий день, ни за следующий (на случай смещения суток). Причина не устанавливается без построчного чтения функции `emit_session_closed`.

## Причина

Код рядом с записью события документирован как best-effort: «never fails the close» — ошибка внутри записи события по контракту не должна всплывать и не блокирует основную операцию close. Из этого прямо следует, что запись может тихо не произойти: раз ошибка не всплывает никуда, то и успех этой побочной записи ничем не доказан, кроме отдельной проверки её результата.

## Противодействие

Побочная запись (метрика, событие, аудит-лог), помеченная «не блокирует основную операцию», по определению может тихо не произойти. Её исправность нельзя считать доказанной отсутствием ошибки в основном потоке — нужна отдельная проверка результата (наличие записи в журнале на диске/в API), а не только кода возврата главной операции.

## Тест обнаружения

«Есть ли рядом с записью события комментарий/контракт вида «best-effort», «never fails X», «не блокирует основную операцию»?» Да → успешное завершение главной операции не доказывает, что эта запись произошла; нужен отдельный read-back журнала за соответствующее окно.
