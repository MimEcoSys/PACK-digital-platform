# DP.FM.537 — Автокоммит сверяет предусловие, которое соседний шаг уже снял

## Симптом

Раннер автокоммитил терминальную карточку сессии через путь (`note-file --session-id`), который сверяет файл с открытым семафором сессии. К моменту записи терминального статуса семафор уже закрыт шагом `session-guard-release`, выполненным раньше в том же close. Проверка владения не резолвится, но `git add` уже выполнен; pre-commit Scope gate режет коммит («новый файл вне scope активных сессий»), и карточка остаётся staged. Откатная правка снимает только свой `git add`, но не уже присутствовавшую запись в индексе. Карточки (и упавшие, и успешно завершённые) накопились до 14 штук за 3 суток, а `canon-reconcile-published.sh` отказывает fail-closed при ЛЮБОМ staged-элементе индекса («staged changes present in index») — то есть канон перестаёт сводиться к origin целиком, а не только для этой карточки.

## Причина

Side-effect-коммит (автокоммит терминальной карточки) проверяет предусловие — владение/блокировку семафором — не учитывая, что это предусловие может стать ложным к моменту его проверки, если коммит выполняется ПОСЛЕ шагов, которые это предусловие снимают (здесь: освобождение семафора раньше в том же close).

## Противодействие

1. Side-effect-коммит, проверяющий предусловие, должен либо выполняться ДО шагов, снимающих это предусловие, либо не зависеть от него вовсе (альтернативный признак владения, переживающий закрытие семафора).
2. Если downstream-процесс (здесь: сведение канона) fail-closed на любом «грязном» элементе индекса — накопление даже редких, несвязанных между собой огрехов со временем блокирует весь процесс. Ошибку нужно не только чинить вперёд, но и чистить задним числом — с сохранением аудиторского следа (публикация содержимого перед снятием из индекса, не удаление вслепую).

## Тест обнаружения

«Выполняется ли side-effect-коммит после шага, который снимает проверяемое им предусловие (владение/блокировку)?» Да → возможна staged-запись без разрешённого владельца, накапливающаяся невидимо для обычного `git status` чистого рабочего дерева и блокирующая fail-closed downstream.
