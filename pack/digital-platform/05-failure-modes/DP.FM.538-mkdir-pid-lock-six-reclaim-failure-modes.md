# DP.FM.538 — Шесть скрытых дырок одного паттерна mkdir+pid блокировки

## Симптом

Пять сторожевых скриптов делят один и тот же паттерн файловой блокировки: `mkdir` каталога-замка как атомарная операция захвата + файл `owner` внутри с полями `host=`/`pid=` + снятие чужого замка по `kill -0` над записанным PID. Независимый холодный ревью без контекста плюс последующий разбор нашли в этом паттерне 6 разных скрытых дефектов:

- **H1 — переиспользованный PID.** Владелец давно умер, но его номер процесса взял долгоживущий процесс того же пользователя; `kill -0` проходит, замок «занят» навсегда.
- **H2 — обрыв до записи владельца.** Процесс, упавший между `mkdir` и записью файла `owner`, оставляет замок, который никто не снимет (нет файла `owner` — проверка живости не проходит).
- **H3 — сравнение хоста строкой.** Ломается, если имя хоста зависит от сети (меняется между запусками).
- **H4 — чужой замок в обработчике выхода.** Четыре из пяти скриптов в `trap ... EXIT` делают `rm -rf` каталога замка безусловно; если к этому моменту замок уже снят и занят другим процессом, выход старого процесса снимает чужой новый замок.
- **H5 — одновременный реклейм.** Два «реклеймера» (скрипта, снимающих чужой зависший замок) могут сработать одновременно, и второй снимет уже новый замок первого.
- **H6 — тишина.** Занятый замок (в т.ч. залипший по H1-H3) даёт строку «lock busy» и код выхода 0 — внешне неотличимо от штатной занятости; проблема, стоящая неделями, не поднимает тревогу, канон не сводится, и это остаётся незамеченным.

## Причина

Самодельная advisory-блокировка по PID: (а) не записывает время старта процесса-владельца, только номер — отсюда H1; (б) не атомарна между `mkdir` и записью `owner` — отсюда H2; (в) сравнивает идентичность хоста/владельца текстом без устойчивого идентификатора — отсюда H3; (г) обработчик выхода не проверяет актуальное владение перед безусловным удалением — отсюда H4-H5; (д) не различает по громкости сигнала «занято штатно» и «занято аномально долго» — отсюда H6.

## Противодействие

1. Хранить время старта процесса-владельца (не только PID) для обнаружения переиспользования номера (H1).
2. Писать `owner` атомарно в рамках самой операции захвата, либо считать владельцем только каталог с уже записанным `owner` (H2).
3. Сравнивать владельца по устойчивому идентификатору, не зависящему от сети (H3).
4. В `trap ... EXIT` проверять текущее фактическое владение ПЕРЕД безусловным `rm -rf` (H4); сериализовать или идемпотентно защищать сам реклейм от параллельного срабатывания (H5).
5. Различать по громкости сигнала «замок занят» (тихо, штатно) и «замок занят дольше порога N» (громко, в лог/алерт) (H6).

## Тест обнаружения

«Самодельная файловая блокировка реклеймится по PID через `kill -0`, и `trap ... EXIT` снимает каталог замка безусловно, без проверки текущего владельца?» Да на оба вопроса → воспроизводимы как минимум H1 и H4 из этого набора.
