# DP.FM.542 — Git-история фикстуры ≠ совпадение байтов с реальным репозиторием

## Тезис и механизм ошибки

Тест, имитирующий «git-клон шаблона» для функции, которая определяет «менялось ли» по git-истории, два раза подряд падал на проверке «старое→новое», хотя оба раза для «старой» стороны подставлялся байт-идентичный реальный исторический SHA из внешнего репозитория. Причина на два слоя глубже: (1) фикстура не содержала скрипт-классификатор по пути, который вызывающий код ожидает внутри `$SCRIPT_DIR`, и код молча проваливался в default «нет классификатора»; (2) классификатор читает `git rev-list HEAD -- <path>` внутри git-истории САМОЙ фикстуры, а не внешнего репозитория — если тестовый коммит фикстуры сделан до того, как нужный файл туда скопирован, путь имеет ноль коммитов в этой истории независимо от того, насколько реален подставленный снаружи SHA.

## Диагностический принцип

Совпадение контента с реальным репозиторием — не та модель для теста функции, которая смотрит на ИСТОРИЮ (а не на текущее содержимое). Фикстуре нужна собственная самодостаточная git-история (закоммитить синтетическое «старое», затем перезаписать рабочее дерево «текущим») и копия каждого скрипта, который тестируемая функция вызывает, а не только тех, что тест явно проверяет.

## Границы

Применимо к тестам функций, которые читают git-историю (`rev-list`, `log`, `blame`) внутри копии/фикстуры репозитория, а не текущее содержимое файлов. Отличие от `DP.FM.509` (та же семья «git test-фикстура даёт ложно-зелёный результат по скрытой причине», другая ось): 509 — фикстура наследует КОНФИГУРАЦИЮ хоста (default branch, identity) при создании git-объектов; здесь — фикстура имеет git-объекты с правильной конфигурацией, но ИСТОРИЮ, не совпадающую с тем, что тестируемый код фактически читает, и дополнительно — отсутствующую зависимость (сам классификатор-скрипт) внутри фикстуры.

## Проверка

«Функция/классификатор, тестируемая на fixture-репозитории, читает git-ИСТОРИЮ (rev-list/log/blame) конкретного пути? Коммит в истории фикстуры, формирующий «старую» версию этого пути, сделан ДО того, как файл реально там появился (в хронологии самой фикстуры, не внешнего репозитория)?» Нет синхронизации хронологии фикстуры с тем, что проверяет код → тест может давать ложный результат независимо от того, насколько реалистичен контент.

Дополнительно: «Фикстура содержит копии ВСЕХ скриптов/зависимостей, которые вызывает тестируемая функция — не только те, что тест явно проверяет?» Нет → молчаливый default-fallback может маскировать реальную проверку.
