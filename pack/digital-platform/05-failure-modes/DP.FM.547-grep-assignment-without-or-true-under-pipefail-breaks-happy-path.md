# DP.FM.547 — grep без `|| true` под pipefail ломает happy path

## Тезис и механизм ошибки

Подготовленный (но ещё не применённый) патч для пересылки алертов сторожа читал его вывод через `grep` в переменную без `|| true`: `result=$(grep pattern "$log")`. Под `set -euo pipefail` `grep` без совпадений возвращает код 1 — не ошибка окружения, а штатный, ожидаемый исход «совпадения нет». `set -e` не различает эти два смысла и обрывает скрипт сразу после присваивания, причём именно в тот момент, когда реального алерта нет — то есть на нормальном успешном прогоне публикации, а не на случае, который патч должен был поймать.

Независимый разбор перед применением (мутационный тест воспроизвёл 7 падений) дополнительно нашёл, что код смотрел только вывод собственного вызова `ds-publish`, хотя сторож обычно делегирует в `isolate-push.sh` с другим префиксом вывода — реальный алерт прошёл бы незамеченным даже без первого дефекта (второй, независимый дефект того же патча).

## Диагностический принцип

`grep`/`egrep`/`fgrep` без совпадений — не ошибка, а валидный, частый исход. Присваивание результата такой команды переменной под `set -e` (без пайпа, то есть не SIGPIPE-механизм DP.FM.457, а прямой ненулевой exit code самого grep) убивает скрипт на этом исходе, если нет `|| true`, `grep -c` с явной проверкой, или проверки `$?`.

## Границы

Применимо к любому `var=$(grep ...)` или аналогичной command substitution под `set -e`/`errexit`, где «нет совпадения» — ожидаемый, не ошибочный исход. Не относится к пайп-конструкциям `cmd1 | grep -q` (там при early-exit читающей стороны механизм — SIGPIPE, см. DP.FM.457) и не относится к случаям, где отсутствие совпадения — действительно ошибка (там падение корректно).

## Проверка

«Есть `var=$(grep ...)` (или `egrep`/`fgrep`) под `set -e`, и отсутствие совпадения для этой проверки — ожидаемый, не ошибочный исход?» Да, и нет `|| true`/явной проверки кода возврата → воспроизведён DP.FM.547: скрипт падает именно тогда, когда всё в порядке. Дополнительно: при ревью алертинг-кода проверять, что проверяемый источник вывода совпадает с реальным путём делегирования (не только с собственным прямым вызовом) — независимый второй дефект того же класса патчей.
