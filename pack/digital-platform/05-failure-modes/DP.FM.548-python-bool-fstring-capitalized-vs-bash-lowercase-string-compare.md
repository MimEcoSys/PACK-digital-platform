# DP.FM.548 — Python bool → bash string: регистр ломает сравнение молча

## Тезис и механизм ошибки

Python-скрипт читал YAML-каталог, где `deterministic: true` парсится в Python как булев тип (`bool`), и печатал его в bash через f-строку: `f"deterministic={r.get('deterministic', 'false')}"`. Python интерполирует bool через стандартное `str(bool)`, которое капитализирует значение (`True`/`False`), а не отдаёт `true`/`false`. Bash-сторож дальше сравнивал результат строкой `[[ "$deterministic" == "true" ]]` — сравнение никогда не совпадает ни для одной реальной записи каталога с `deterministic: true`, потому что фактическое значение всегда `True` (с большой буквы). Гейт молча не срабатывал на 100% таких записей: не было ни исключения, ни предупреждения — просто ветка `if` никогда не выполнялась.

## Диагностический принцип

На границе язык-со-строгой-типизацией → язык-со-строковым-сравнением (Python→bash, но тот же класс верен для любой пары «типизированный источник» → «потребитель, сравнивающий строкой») печать булева/перечисления через стандартную интерполяцию языка-источника может не совпасть по регистру/формату с константой, которую ожидает язык-потребитель. Опасность именно в молчании: код технически работает, просто условие никогда не истинно.

## Границы

Применимо к любой передаче булева/enum значения через текстовый интерфейс (f-строка, `print`, переменная окружения, CLI-аргумент) от языка с собственным представлением типа к потребителю, который сравнивает результат как строку с жёстко заданным литералом. Не относится к случаям, где потребитель сам нормализует регистр (`tr '[:upper:]' '[:lower:]'`) или сравнивает через типизированный парсер (`jq -r '.deterministic == true'` на JSON, а не на произвольной текстовой строке).

## Проверка

«Значение типа bool/enum печатается через стандартную интерполяцию языка-источника (f-строка, `str()`, `print()`) и сравнивается потребителем как строка с конкретным литералом (`"true"`, `"false"`, `"yes"`)?» Да → возможен DP.FM.548: сверить фактический регистр/формат печати с ожиданием потребителя на реальном значении, не по документации типа. Фикс — явное форматирование на границе (`'true' if x else 'false'`), а не дефолтная интерполяция.
