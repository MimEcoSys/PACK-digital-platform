# DP.FM.555 — Publish-proof предполагает канонический репозиторий; сторонний получает нулевую проверку

## Симптом

Note-commit claim о публикации в сторонний (не продуктовый, не бот-репозиторий автора) GitHub-репозиторий структурно не проходит ни один из пяти существующих publish-proof механизмов. Claim необратимо замораживается после первой попытки публикации — не потому что проверка не успела завершиться, а потому что ни один из пяти механизмов не умеет её подтвердить в принципе.

## Причина

Все пять существующих механизмов доказательства публикации (anchor/3-way-merge — `DP.M.465`, прочие) спроектированы и проверены на канонических/продуктовых репозиториях автора (известны default branch, структура коммитов, права доступа). Сторонний репозиторий — целевая система вне этого неявного класса — не удовлетворяет предпосылкам ни одного механизма сразу, поэтому получает не ослабленную, а нулевую проверку: вопрос «долетела ли публикация» становится структурно неразрешимым этим набором инструментов, а не просто медленным или ненадёжным.

## Открытый вопрос (не решён этой карточкой)

Нужен шестой, явно иной механизм proof для целевых систем вне класса «канонический репозиторий автора», либо явный fallback-путь (ручное owner-status подтверждение) для этого класса целей — решение не входит в scope этой находки, фиксируется как структурный пробел.

## Тест обнаружения

«Механизм доказательства публикации проверен хотя бы на одном примере целевой системы вне класса "канонический/продуктовый репозиторий автора" (например, сторонний GitHub-репозиторий без привилегированного доступа)?» Нет → риск структурно нулевой, а не ослабленной, проверки для любого claim против такой цели.

## Связанные документы

- `DP.M.465` — сам набор из двух вариантов publish-proof (anchor / 3-way-merge), на предпосылках которого эта карточка находит пробел: оба варианта неявно требуют канонической цели.
- `DP.FM.510` — родственная хрупкость: единственный canonical close-proof без пути отказа/признания невозможности; здесь — не одна проверка без запасного пути, а весь набор проверок вне своего класса целей.
