# DP.FM.558 — Протокол origin расходится между приватным чекаутом автопубликации и каноном

## Симптом

Очередь публикации ledger не идёт для всех агентов, накопившись с вечера предыдущего дня. Нет явной ошибки в момент возникновения — просто тихий отказ.

## Причина

Автоматизация публикации работает не напрямую в каноническом репозитории, а через отдельный приватный чекаут того же репозитория (`~/.iwe-automation/DS-my-strategy`). Этот чекаут указывал на origin по SSH-адресу, тогда как канонический репозиторий настроен на HTTPS. Протокол и адрес origin именно рабочего чекаута — отдельная точка отказа, которую обычные проверки состояния канона не видят (они проверяют канон, не чекаут автоматизации).

## Антипаттерн → Паттерн

- **Антипаттерн:** диагностировать «публикация тихо не идёт», проверяя только `git remote -v` канона.
- **Паттерн:** когда автоматизация работает через отдельный чекаут того же репозитория — явно сверять `git remote -v` ВСЕХ вовлечённых чекаутов (канона И рабочих копий автоматизации), не только канона.

## Тест обнаружения

«У каждого чекаута, участвующего в pipeline публикации (канон + рабочие копии автоматизации), протокол и адрес origin совпадают?» Нет → риск тихого, накопительного отказа публикации без ошибки на месте возникновения.

Разные механизмы, общий класс «push/публикация из headless-окружения тихо не доходит».
