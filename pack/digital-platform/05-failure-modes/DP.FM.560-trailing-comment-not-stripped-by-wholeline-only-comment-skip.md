# DP.FM.560 — Валидатор с контрактом «комментарии не влияют» пропускал только whole-line комментарии

## Суть паттерна

Проверка документировала контракт «комментарии игнорируются, они не влияют на поведение», но реализация обрабатывала только строки, целиком являющиеся комментарием (`^\s*#`). Хвостовой комментарий на той же строке, что и проверяемый код (`код  # почему этот код ОК`), не исключался — литерал в хвостовом комментарии всё равно засчитывался как часть проверяемого содержимого.

## Механизм

1. Автор проверки документирует правило «комментарии не считаются» в общем виде.
2. Реализация покрывает только самый частый случай — строку, целиком являющуюся комментарием.
3. Код и комментарий на одной строке — отдельный случай, который контракт обещал, но реализация не покрыла.
4. Наивное решение «обрезать строку с первого `#`» здесь не подходит: `#` может легитимно находиться внутри строкового литерала в кавычках, и такая обрезка испортит проверку самого кода.

## Диагностика

«Валидатор документирует правило `comments are skipped`. Проверяемая строка содержит код и пояснительный комментарий с реальным литералом только в этом комментарии — помечает ли валидатор эту строку как нарушение?» Да → воспроизведён DP.FM.560.

## Профилактика / фикс

Двухчастная проверка вместо одной обрезки: (1) литерал должен реально исчезать после обрезки строки с первого `пробел+#`, И (2) остаток строки после этой обрезки должен содержать один из реальных маркеров комментария-пояснения — иначе это не легитимное исключение, а совпадение внутри кавычек. Любой валидатор/линтер с правилом «комментарии не считаются» обязан явно решить и протестировать случай «код и комментарий делят одну строку» — молчаливое покрытие только whole-line случая не реализует задокументированный контракт.
