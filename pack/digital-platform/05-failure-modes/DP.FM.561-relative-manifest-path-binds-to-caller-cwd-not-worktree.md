# DP.FM.561 — Относительный путь к манифесту привязался к cwd, не к worktree

## Суть паттерна

Скрипт охраны сессии (session-manifest-write.sh) сразу после commit-подтверждения заявлял созданный манифест в общем семафоре по относительному пути. Пока вызывающий процесс действительно стоял в нужном рабочем дереве (worktree), заявка резолвилась верно. Гонка проявлялась, когда это неявное предположение нарушалось: заявка не доходила до семафора, и закрытие сессии отказывало со ссылкой на «неполный охват коммита» — хотя содержимое уже было опубликовано.

## Механизм

1. Путь к файлу-манифесту передаётся в скрипт относительным.
2. Относительный путь неявно кодирует предположение «cwd вызывающего процесса = нужное рабочее дерево».
3. В средах с несколькими параллельными worktree одного репозитория это предположение не гарантировано.
4. При нарушении предположения заявка пишется не туда (или не резолвится), семафор не видит манифест, закрытие сессии ложно отказывает.

## Диагностика

«Скрипт, передающий путь к артефакту через границу процессов (семафор, IPC, несколько worktree одного репозитория), использует относительный путь, резолвящийся через cwd вызывающего?» Да → воспроизведён DP.FM.561.

## Профилактика / фикс

Заявлять путь к манифесту абсолютным. Общее правило: на границе процессов/worktree — всегда передавать абсолютный путь, никогда относительный, резолвящийся через cwd вызывающего, поскольку это предположение может незаметно перестать быть верным при параллельном запуске нескольких сессий на разных worktree одного репозитория.
