# DP.FM.563 — Top-level import платформо-специфичного модуля: падение на загрузке до диспетчеризации

## Симптом

Windows-ветка диспетчера (`is_windows_shell()` → `main_windows()`) была реализована и проверена (WP-7 Ф171), но на Windows никогда не выполнялась: модуль не загружался целиком. Сообщение об ошибке — ImportError на `fcntl` в блоке импортов, а не что-либо из логики диспетчера.

## Причина / механизм

1. `import fcntl` стоял на верхнем уровне модуля. Модуль `fcntl` существует только на POSIX; на Windows его нет — и установить его нельзя.
2. Использовался он только внутри POSIX-пути блокировки — ветки, до которой Windows-диспетчеризация по замыслу не доходит.
3. Импорт выполняется при загрузке модуля, **до** любого ветвления по платформе. Недостижимость кода по логике диспетчеризации не делает недостижимым его импорт.
4. Проверка ветки (тест `main_windows()`) запускалась в окружении, где модуль загружается, — она проверяла логику ветки, а не факт загрузки модуля на целевой платформе.

## Антипаттерн → Паттерн

- **Антипаттерн:** все импорты вверху файла «по конвенции», включая модули, существующие только на одной платформе, при том что файл обязан загружаться на нескольких.
- **Паттерн:** платформо-специфичный импорт либо под условием платформы на верхнем уровне (`if os.name != "nt": import fcntl`), либо внутри самой платформенной ветки, где он используется. Условие — по платформе, а не `try/except ImportError` с заглушкой (та скрывает отказ до момента использования — антипаттерн DP.M.304 §5).

## Тест обнаружения

«Импортируется ли модуль (а не только вызывается его ветка) на каждой платформе, которую он заявляет поддерживать?» Проверка — `python -c "import <module>"` на каждой целевой ОС (матрица ОС в CI, DP.M.033). Нет → проверенная ветка платформы может быть недостижима из-за загрузки, и это не видно ни одному тесту логики ветки.

## Границы

Любой язык/рантайм, где импорт выполняется при загрузке единицы кода, а не при первом использовании (Python, Node.js `require` на верхнем уровне и т.п.). Не о зависимостях, которые можно доустановить (ось DP.M.304), а о модулях, которых на платформе не существует принципиально.

## Отличие от смежных карточек

- **DP.M.304** (локальный импорт тяжёлой зависимости для optional backend) — метод для оси «зависимость не установлена в dev/test»; лечение — отложенный импорт. Здесь ось — платформа: модуль не установить, условие должно быть платформенным; добавлен симптом «проверенная ветка недостижима».
- **DP.FM.128** (ImportError на pytest collection) — тот же класс «ошибка на загрузке, а не в логике», симптом — тест не существует; здесь — ветка продакшн-диспетчера не существует на целевой ОС.
- **DP.FM.400** (платформенный примитив без проверки наличия → тихий no-op) — отказ в рантайме и тихий; здесь — отказ на загрузке, громкий, но в чужом месте (строка импорта, а не ветка).
