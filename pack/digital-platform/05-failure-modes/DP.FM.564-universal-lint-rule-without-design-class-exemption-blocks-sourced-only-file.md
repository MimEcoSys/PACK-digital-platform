# DP.FM.564 — Универсальное правило линтера без класса-исключения по дизайну

## Симптом

Smoke-тест проверял «у каждого shell-файла есть шебанг» и заблокировал легитимный коммит: в нём была библиотека, которая только `source`-ится из других скриптов — объявляет функции и никогда не исполняется напрямую. Шебанг у такого файла бессмыслен (он не точка входа), но правило об этом классе не знало.

## Причина / механизм

1. Правило сформулировано универсально: «у каждого X (shell-файл) должен быть Y (шебанг)».
2. Множество X содержит класс, для которого Y неприменим **по дизайну**, а не по недосмотру: sourced-only библиотеки.
3. Проверка не имеет способа узнать класс объекта — ни по имени, ни по содержимому, — и её отказ неотличим от настоящего нарушения.
4. Естественная реакция «ослабить правило» (не требовать шебанг вообще или пропускать по имени файла) теряет защиту для настоящих точек входа.

## Антипаттерн → Паттерн

- **Антипаттерн А:** правило без классов — каждый легитимный объект особого класса превращается в ложный красный и блокирует работу.
- **Антипаттерн Б:** ослабить правило для всех или вести внешний список исключений рядом с проверкой (DP.FM.238: список исключений в том же репо, что и аудитор, — self-referential).
- **Паттерн:** объект особого класса сам объявляет класс явным маркером в своём заголовке («Sourced, not executed»); проверка распознаёт маркер и применяет к классу его собственное правило (здесь — «шебанга быть не должно», а не «проверку пропустить»). Правило для основного класса остаётся строгим.

## Тест обнаружения

«Есть ли у правила «у каждого X должен быть Y» явно описанный класс X, для которого Y неприменим по дизайну, и способ объекта заявить принадлежность к этому классу?» Нет → первый же легитимный объект этого класса даст ложный красный, и чинить будут либо объект (добавят бессмысленный Y), либо правило (ослабят для всех).

## Границы

Структурные/стилевые проверки (lint, smoke-test, конвенции файлов), где самообъявление класса объектом допустимо. **Не для security-гейтов:** там статический маркер-исключение спуфится буквальным вводом (DP.FM.456) и может сам содержать шаблон секрета (DP.FM.379) — исключение должно опираться на непредсказуемый nonce или внешнюю верификацию, а не на текст в объекте.

## Отличие от смежных карточек

- **DP.FM.440** (fail-safe гейт верно отказывает легитимному нестандартному пути без спроектированного восстановления) — отказ по динамическому состоянию/пути; лечение — добавить случай или спроектировать восстановление. Здесь — статический класс объектов, лечение — маркер класса в объекте.
- **DP.FM.544** (переизбыточный glob guard) — проверка сверяется не с той идентичностью. Здесь идентичность верна, неверна область применимости правила.
- **DP.FM.103 / DP.FM.362** — false positive из-за отсутствия scope-фильтра / совпадения контент-паттерна; здесь scope верен, но правило не различает классы внутри scope.
