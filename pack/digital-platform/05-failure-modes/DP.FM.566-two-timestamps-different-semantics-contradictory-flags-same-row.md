# DP.FM.566 — Два поля времени с разной семантикой в одном подзапросе

## Симптом

Подзапрос табло наставника считал «последнюю активность» по `message_at` (момент написания сообщения), а окна давности 7/30 дней — по `sent_at` (момент отправки/видимости) — в одном и том же подзапросе на одной строке. Черновик может лежать днями до отправки, поэтому `message_at` и `sent_at` законно расходятся: одна и та же строка участника одновременно показывала «наставник писал на этой неделе» (по `sent_at` — свежо) и `staleArchiveActivity=true` (по `message_at` — старо), два взаимоисключающих утверждения разом.

## Причина / механизм

1. У сущности переписки два момента времени с разной легитимной семантикой: когда сообщение написано и когда оно отправлено/стало видимым; разница легитимна (черновики).
2. Новая функция сводила оба назначения (текущая активность и давность) из одного подзапроса, но каждое — по своему полю, без явного решения «какое поле — единственный источник давности для ВСЕХ сравнений модуля».
3. Соседняя функция в том же модуле это решение уже приняла правильно: там `message_at` — чисто информационное поле, никогда не участвует в сравнениях давности. Новая функция не переиспользовала это решение.

## Противодействие

Если у сущности несколько временных меток с разной легитимной семантикой, одна и только одна должна быть явно объявлена «временем давности» для ВСЕХ сравнений внутри модуля — не «то поле, что было под рукой» для каждого конкретного вычисления по отдельности. Фикс: все сравнения давности — по `sent_at`, как в соседней функции карточки участника. Регрессионный тест обязан допускать тестовый мир, где метки заданы раздельно и намеренно расходятся на недели — иначе тест не отличает «метки синхронны» от «поля не перепутаны».

## Тест обнаружения

«У сущности несколько временных меток с разной легитимной семантикой (написано vs отправлено, создано vs опубликовано)? Есть ли тест, где эти метки намеренно расходятся на недели?» Нет такого теста → смешение полей в разных частях одного вычисления не поймано, и одна строка может нести два взаимоисключающих флага давности.
