# DP.FM.579 — Перенос владения ломает SECURITY INVOKER-хелперы над RLS-таблицей

## Описание

SECURITY DEFINER-функция, которая работала потому, что её текущий владелец обходит RLS (роль с BYPASSRLS), вызывает SECURITY INVOKER-хелперы, читающие RLS-защищённую таблицу. После переноса владения на роль без BYPASSRLS хелперы начинают падать необработанным исключением при почти каждом вызове. Ошибка не локальна: каждый вызов для любого события, кроме одного частного случая, падает.

## Пример

`compute_effective_amount_v4` переносится на `rewards_points_engine_owner` (без BYPASSRLS, в отличие от `neondb_owner`). Два SECURITY INVOKER-хелпера читают `_foreign_indicators.calculated_profile` через политику `account_isolation` и начинают падать для всех событий, кроме `referral_attributed`. Найдено живой проверкой в отменённой транзакции.

## Признаки

- Перенос владения функцией на роль с меньшими привилегиями
- Цепочка DEFINER → INVOKER → RLS-таблица, где рабочий путь неявно зависит от BYPASSRLS текущего владельца
- Тесты не покрывают вызовы из цепочки либо проверяют только тот частный случай, который работает

## Митигация

Перед переносом владения пройти цепочку вызовов живой проверкой под целевой ролью. Варианты: отдельная RLS-политика-исключение (не широкий BYPASSRLS), перенос отложить, явный отказ вместо тихой деградации. Тихая деградация опаснее явного падения: она даёт систематически неверные числа вместо ошибки.
