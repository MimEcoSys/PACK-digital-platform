# DP.FM.580: Составная команда через `;` — guard видит только один блок текста

## Симптом
`destructive-guard.sh` пропускал вызов вида `rm -rf /important_data; rm -rf /tmp/scratch` — безопасная цель второго, отдельного вызова `rm` в той же строке «отбеливала» вердикт по первому, опасному вызову.

## Причина
Guard разбирает строку как единый блок текста и выносит по ней общий вердикт, не учитывая, что shell выполнит оба `rm`-вызова, разделённых `;`, как независимые команды. Проверка по факту применяется к конструкции целиком, а не к КАЖДОМУ сегменту до `;` по отдельности.

## Антипаттерн → Паттерн
- **Антипаттерн:** вердикт guard'а по составной строке выносится так, что присутствие безопасного сегмента снимает блокировку со всей строки.
- **Паттерн:** строка сначала разбивается на отдельные команды по всем shell-разделителям (`;`, `&&`, `||`, `|`, newline), затем КАЖДЫЙ сегмент проверяется независимо; опасно — если ХОТЬ ОДИН сегмент опасен.

## Переносимый принцип
Guard, анализирующий текст составной shell-команды, обязан явно перечислить ВСЕ независимо исполняемые сегменты (по всем разделителям shell, не только одному) и вынести вердикт по дизъюнкции их опасности («опасно, если опасен хоть один»), а не по тексту строки как единого целого — иначе безопасный сосед в той же строке маскирует опасную команду. Тот же класс дефекта на уровне целей одного вызова — см. `DP.FM.582`.

## Тест обнаружения
«Guard, получив `опасная_команда; безопасная_команда` в одной строке, разбирает её как один блок текста или как список независимых команд, каждая со своим вердиктом?» Первое — отбеливание возможно.

## Применимость
Любой текстовый guard/сканер bash-команд, работающий с составными (`;`/`&&`/`||`/pipe) конструкциями одной строки.
