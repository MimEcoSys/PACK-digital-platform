# DP.FM.581: skip-worktree скрывает путь от guard'ов, но HEAD продолжает двигаться

## Симптом
Переключение файлов-зеркал на `git update-index --skip-worktree` должно было избавить от хронически «грязного» канонического чекаута. Два раунда холодного ревью (независимый ревьюер + живой эксперимент) нашли: правка пилота на таком пути перезаписывается следующим тиком синк-скрипта без единого предупреждения и без следа в git-объектах (невосстановимо — хуже обычного unstaged-дрейфа), а существующие guard'ы (построенные на `git status`/`git diff`) не видят расхождение и докладывают «чисто».

## Причина
`skip-worktree` полностью выключает путь из сравнения worktree↔индекс — физическое содержимое скрытого пути отдельно не хешируется и не участвует в `git status --porcelain=v2`. Но это не останавливает продвижение HEAD: `canon-refresh.sh` (построенный на `git merge --ff-only`) продвигает весь HEAD, включая дерево скрытых путей, и доходит до `merge --ff-only`, не заметив, что рабочая копия скрытого пути расходится с новым содержимым дерева.

## Антипаттерн → Паттерн
- **Антипаттерн:** использовать `skip-worktree` как способ «заглушить» диагностику грязного чекаута для путей, которые реально меняются (вручную или процессом) — guard перестаёт видеть изменения, но git продолжает штатно продвигать историю поверх них.
- **Паттерн:** `skip-worktree` допустим только для путей, которые НИКОГДА не меняются в этом рабочем дереве после начальной настройки; для путей, которые реально редактируются (вручную или синк-скриптом), нужен другой механизм изоляции, явно учитывающий продвижение HEAD.

## Переносимый принцип
Любой флаг/механизм, выключающий путь из diff/status-наблюдения (`skip-worktree`, `assume-unchanged` и аналоги), не выключает механизмы, которые продвигают дерево репозитория независимо от observability (`merge --ff-only`, `checkout`, `reset`). Guard, полагающийся только на `git status`/`git diff` как на полную картину «что может измениться», не покрывает класс операций, двигающих HEAD напрямую.

## Тест обнаружения
«Есть ли в репозитории пути с `skip-worktree`/`assume-unchanged`, которые также целевые для `merge --ff-only`/`checkout`/`reset`-based синхронизации?» Да → потенциальная тихая, безвозвратная потеря правки на таком пути.

## Применимость
Любой репозиторий с git-механизмом автосинхронизации (`merge --ff-only` или аналог) поверх путей, частично выключенных из diff-наблюдения.
