# DP.FM.582: Allow-list для multi-target вызова — ANY вместо EACH

## Симптом
`rm -rf /protected /tmp/ok` проходил защитный хук: исключение по `/tmp` было устроено так, что ХОТЬ ОДНА цель вызова, попадающая в allow-list, снимала блокировку со всего вызова целиком — хотя `/protected` в allow-list не входит.

## Причина
Проверка multi-target вызова была написана как «есть ли среди целей хоть одна безопасная» (`ANY target safe → pass`) вместо «безопасны ли ВСЕ цели» (`ALL targets safe → pass`). Присутствие одной безопасной и одной опасной цели в одном вызове `rm -rf` было достаточно, чтобы пройти проверку целиком.

## Антипаттерн → Паттерн
- **Антипаттерн:** `any(target in allowlist for target in targets)` как критерий разрешения multi-target операции.
- **Паттерн:** `all(target in allowlist for target in targets)` — опасно, если хотя бы ОДНА цель не в allow-list; каждая цель (с поддержкой `--` как разделителя опций) проверяется отдельно.

## Переносимый принцип
Для любой проверки операции с несколькими целями/аргументами (multi-target команда) предикат допуска должен требовать «КАЖДАЯ цель безопасна», а не «ЕСТЬ хотя бы одна безопасная цель» — иначе один безопасный элемент отбеливает весь batch, включая опасные соседние элементы. Тот же принцип в другой форме — у составных shell-команд, разделённых `;` (см. `DP.FM.580`): там элементы — целые команды, здесь — цели одного вызова.

## Тест обнаружения
«Проверка multi-target/multi-argument операции построена как `any(...)` или как `all(...)` по отдельным элементам?» `any` → потенциальное отбеливание.

## Применимость
Любая проверка команды/вызова, принимающего более одного целевого аргумента (пути, идентификаторы, хосты).

## Источник
WP-529 Ф19, issue #1002, peer-session 2026-10-09-20-wp529-continue. Исправлено: каждая цель проверяется отдельно, с поддержкой `--`.
