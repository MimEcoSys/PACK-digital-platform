# DP.FM.592 — Проверка публикации через `git ls-remote` наследует `GIT_*` процесса

## Тезис и механизм ошибки

Проверка доказательства публикации (`verify_review_pr`) делала `git ls-remote origin` с копией окружения текущего процесса (`os.environ.copy()`). Если вызывающий процесс унаследовал `GIT_CONFIG_*`-переопределения (в источнике названы родительская сессия и тест), `ls-remote` мог тихо смотреть не на тот remote, и проверка отвечала про состояние другого репозитория, а не про то место, где должна быть публикация. Ошибки при этом нет: git отвечает успешно, но про другой remote.

## Диагностический принцип

Когда ответ git служит источником истины для проверки («опубликовано ли», «есть ли ветка на remote»), окружение этого вызова — часть входа проверки. Унаследованные `GIT_*`-переменные (в источнике — `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_<n>`, `GIT_CONFIG_VALUE_<n>`) могут переопределить, что такое `origin`; поэтому проверка выполняется в очищенном окружении: перед git-вызовом очищаются все `GIT_*`. Так сделан фикс в источнике (коммит «fix: ignore inherited Git overrides in remote PR proof»).

## Отличие от DP.FM.509

`DP.FM.509` описывает фикстуры и обёртки над git, которые зависят от конфигурации ХОСТА (`init.defaultBranch`, глобальная identity) и лечатся явным заданием параметров. Здесь проверочный код зависит от переопределений окружения ПРОЦЕССА-родителя и лечится сбросом унаследованного. Это другая ось внутри семьи «окружение автора ≠ окружение исполнения», с противоположным направлением фикса (задать явно ↔ очистить унаследованное).

## Границы

Применимо к коду, который использует ответ git (`ls-remote`, проверка предка, наличие ветки) как доказательство или источник истины. Не распространяется на код, который сознательно получает `GIT_*` от вызывающего: тесты и фикстуры, намеренно задающие `GIT_CONFIG_*` (см. «Противоядие» в `DP.FM.509`) — там переменные являются намеренным входом, а не унаследованным шумом. Не рассмотрено в источнике: очищаются все `GIT_*` без исключений; нужна ли проверке какая-то из них для самого доступа к remote, в источнике не обсуждалось.

## Проверка

«Проверка, которая спрашивает git о состоянии remote как об источнике истины, запускает git с копией окружения процесса (в источнике — `os.environ.copy()`)?» Да → унаследованные `GIT_*` могут её перенаправить.

Критерий приёмки (вывод экстрактора из описания теста и названия фикса в источнике; сам тест не читался): в окружении вызывающего процесса задан fake origin через `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_0` / `GIT_CONFIG_VALUE_0`; проверка обязана игнорировать эту подмену и обращаться к настоящему `origin`.
