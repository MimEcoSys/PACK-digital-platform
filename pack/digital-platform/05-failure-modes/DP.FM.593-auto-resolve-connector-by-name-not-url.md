# DP.FM.593 — Авторазрешение capability ищет коннектор по имени в аккаунте, не по URL

## Тезис и механизм ошибки

Авторазрешение capability на claude.ai использует точное имя коннектора в списке аккаунта как ключ поиска — не URL сервера. Одному и тому же серверу разные пользователи дают разные названия («Aisystant», «my-mcp», «iwe-local» и т.д.). Инструкция или конфигурация, жёстко называющая коннектор, работает только у того пользователя, у которого имя совпадает.

## Связи

- `DP.M.513` (сверка имени коннектора с местом регистрации перед публикацией Artifact) — смежный failure mode о том же классе риска «имя коннектора не константа»: там — автор перед публикацией не проверяет имя в месте регистрации (сценарий одного автора), здесь — авторазрешение резолвит коннектор по имени в АККАУНТЕ получателя инструкции (межпользовательский сценарий). Общая тема, разные механизмы — не дубликат.

## Симптом

Один пользователь передаёт другому инструкцию вида «авторазреши capability X». Инструкция не срабатывает: у второго пользователя коннектор с тем же сервером называется иначе.

## Инвариант

Имя коннектора — личный выбор, не константа платформы. Кросс-аккаунтные инструкции не могут надёжно ссылаться на имена коннекторов.

## Профилактика

Документировать коннектор по URL сервера + описанию роли; имя называть как «то, что пользователь сам присвоил при регистрации». Инструкция не должна содержать хардкодированное имя коннектора.
