# DP.FM.596 — Встроенные в SKILL.md shell-функции портятся подстановкой аргументов скилла

## Симптом

Около 130 строк shell-функций (проверка границы застейдженного, «застейдж и коммит либо стоп») были определены прямо в тексте SKILL.md. Платформа подставляет аргументы вызова скилла вместо `$1`/`$2` в тексте скилла до того, как его прочитает модель, поэтому позиционные параметры внутри тел функций искажались (issue #1176): функция получала не свои параметры, а аргументы, с которыми вызвали скилл.

## Причина

Два слоя шаблонизации делят один синтаксис `$N`: подстановка аргументов скилла на стороне платформы (до модели) и раскрытие позиционных параметров в bash (при исполнении). Текст SKILL.md проходит первый слой раньше, чем блок кода доходит до второго, и граница между слоями в тексте нигде не обозначена.

По документации платформы (12.10.2026): `$N` — сокращение для `$ARGUMENTS[N]` с индексацией с нуля, то есть платформенный `$1` — это ВТОРОЙ аргумент вызова, а не первый параметр функции; индексный плейсхолдер без соответствующего аргумента остаётся в тексте без изменений; для аргументов, объявленных в `arguments`, подставляется и `$имя`. Поэтому дефект плавающий: вызов скилла без аргументов оставляет функции целыми, вызов с аргументами молча подменяет `$1`/`$2`.

## Что отвергнуто

- **Экранирование `\$1` / `\$2`** (предложение рецензента Kimi). Документация предписывает обратную косую для буквального знака доллара, но прямо не говорит, снимается ли она из текста, который видит модель; рецензент Codex счёл ненадёжной саму границу между подстановкой аргументов скилла и bash.
- **Переменная-обёртка** вокруг позиционных параметров — по тому же мотиву.

## Антипаттерн → Паттерн

- **Антипаттерн:** определять в SKILL.md shell-функции с позиционными параметрами или с иным текстом, похожим на плейсхолдеры платформы (`$0`…`$9`, `$ARGUMENTS`, `$имя` объявленного аргумента), и полагаться на то, что до bash текст дойдёт неизменным.
- **Паттерн:** вынести функции с `$1`/`$2` из SKILL.md в поставляемый скрипт; SKILL.md подключает его через `source` по пути от корня рабочей области. Для ссылок на скрипты, поставляемые вместе со скиллом, документация платформы называет `${CLAUDE_SKILL_DIR}` — это альтернативный способ задать путь. Гард, который сканировал встроенный блок на опасные имена переменных, теперь сканирует файл-помощник: проверка переезжает вместе с кодом.

## Тест обнаружения

«В SKILL.md есть блок shell, внутри которого встречается `$0`…`$9`, `$ARGUMENTS` или имя объявленного аргумента? Скилл вызывают с аргументами?» Да на оба → тело функции искажается при вызове. Статически: поиск `\$[0-9]` и `\$ARGUMENTS` внутри блоков кода SKILL.md.

## Границы

Карточка про поведение платформы Claude Code. Документация не указывает версию, с которой появилось сокращение `$N`, и ничего не говорит о блоках кода внутри SKILL.md; поведение может меняться между версиями, поэтому проверять по актуальной документации. Механика искажения функций — из описания issue #1176 и ревью Codex; живой вызов скилла при составлении карточки не воспроизводился.
