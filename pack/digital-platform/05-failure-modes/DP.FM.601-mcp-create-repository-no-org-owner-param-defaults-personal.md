# DP.FM.601 — create_repository (MCP) не принимает владельца-организацию

## Тезис и механизм ошибки

MCP-инструмент create_repository не предоставляет параметр выбора владельца (организация vs личный аккаунт) — независимо от того, в какой организации у вызывающего токена есть права, репозиторий создаётся в ЛИЧНОМ аккаунте вызывающего. Это ограничение API-обёртки инструмента, не ошибка прав доступа и не проблема конфигурации токена: токен мог иметь полный доступ к целевой организации, а инструмент просто не даёт способа указать её в вызове.

## Диагностический принцип

При создании MimEcoSys/it-meetings агент вызвал create_repository, ожидая репозиторий в целевой организации по аналогии с gh repo create <org>/<name> (где владелец — часть позиционного аргумента). MCP-обёртка этого инструмента такого параметра не экспонирует вовсе — результат (личный аккаунт) неотличим по симптому от «токену не хватило прав на организацию», но причина другая: параметра для указания цели нет в самом контракте инструмента.

## Проверка

«Схема параметров MCP-инструмента для создания ресурса включает поле владельца/организации, или владелец выводится неявно (всегда из идентичности вызывающего токена)?» Нет явного параметра → инструмент структурно не может создать ресурс в чужом для вызывающего (но доступном по правам) неймспейсе; попытка обойти это через именование (owner/repo в поле имени) не сработает, если инструмент не парсит такую форму явно.

## Фикс и ограничение фикса

Для создания репозитория в целевой организации — обходить MCP-обёртку и использовать прямой API/CLI с явным параметром владельца (gh repo create <org>/<name>), пока сам MCP-инструмент не получит поле выбора владельца. Фикс не устраняет причину (ограничение инструмента остаётся) — он документирует обходной путь и предотвращает повторное ошибочное создание в личном аккаунте с последующим удалением.

## Границы

Применимо к конкретному MCP-инструменту create_repository в использованной интеграции; не характеризует MCP-протокол как класс (другие инструменты того же сервера могут параметр владельца иметь). Не о правах доступа токена — токен мог иметь права на организацию, инструмент просто не дал способа их использовать.
