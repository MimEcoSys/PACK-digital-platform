# DP.FM.605 — PreToolUse-хук по git-индексу слеп к `git add` в той же команде

## Симптом

`protocol-artifact-validate.sh` — хук PreToolUse на Bash — срабатывает по «артефакт DayPlan в индексе» (принцип WP-273: упоминание DayPlan в тексте коммита не должно давать ложных срабатываний). Хук читал `git diff --cached` ДО выполнения перехваченной команды. Если `git add` был частью ОДНОЙ составной команды с `git commit` (`git add X && git commit -m ...`), на момент проверки индекс ещё пуст — хук видел «ничего не застейджено» и пропускал коммит без валидации.

## Причина

PreToolUse-хук моделирует только состояние мира ДО команды, а не то, что сама перехватываемая команда успеет изменить до своего завершающего действия. Связка `add+commit` в одной строке меняет индекс ПОСЛЕ момента проверки хука, но ДО фактического коммита — хук, привязанный к состоянию, а не к тексту/эффекту команды, это не видит.

## Исправление

Дополнить фактический git-индекс путями из сегментов команды, начинающихся именно с `git add` (разделители составной команды: `&&`, `||`, `;`, `|`) — остальной текст команды по-прежнему не разбирается построчно. Массовый stage (`.`, `-A`, `-u`) резолвится через реальный `git status --porcelain -uall` (без `-uall` новый файл в неотслеживаемом каталоге схлопывается в имя каталога и не виден). Разбиение сегментов — через `awk`, не `sed 's/&&/\n/g'` (BSD `sed` на macOS вставил бы литеральную букву «n» вместо перевода строки).

## Тест обнаружения

«PreToolUse-хук читает git-состояние (индекс, diff --cached) ОДИН раз до выполнения перехваченной команды, и перехватываемая команда может быть составной (содержать `&&`/`;`/`|`), меняющей это же состояние до своего завершающего шага?» Да на оба → воспроизведена эта FM, если хук не домоделирует сегменты `git add` из текста самой команды.

## Зеркальный дефект

Тот же валидатор 06.09 давал противоположную ошибку — сканировал весь ОБЩИЙ индекс (не только сегменты текущей команды) и блокировал по чужим файлам других параллельных агентов. Здесь — обратная сторона: видит слишком мало (только состояние до команды), а не слишком много. Отдельная карточка под этот более ранний инцидент в проверенных снимках Pack не найдена этим циклом — не резервирую под него ID, только фиксирую соответствие в тексте, как указано в самом захвате.

## Переносимый принцип

Pre-execution гейт, привязанный к состоянию мира (а не к тексту/эффекту команды), обязан моделировать и то, что сама перехватываемая команда успеет изменить до целевого действия — иначе составная команда, меняющая проверяемое состояние на лету, обходит гейт без всякого умысла.
