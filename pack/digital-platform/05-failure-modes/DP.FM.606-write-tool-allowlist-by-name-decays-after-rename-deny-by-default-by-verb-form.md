# DP.FM.606 — Named-гейт по MCP-инструментам устарел после переименования сервера, стал fail-open

## Симптом

`dry-run-gate.sh` (хук PreToolUse) блокировал записывающие MCP-вызовы по точному списку имён инструментов под устаревшим префиксом `mcp__claude_ai_IWE__*`. Актуальный MCP-сервер знаний называется `iwe-knowledge` — ни один из его write-инструментов не совпадал ни с одной строкой списка. Гейт был fail-open ровно для того пространства имён, ради защиты которого создан, и это не давало никакой ошибки — защита просто тихо исчезла.

## Причина

Гейт «репетиции» блокировал по явному списку имён инструментов. Переименование сервера знаний (смена префикса) сделало список несовпадающим ни с чем, при этом отсутствие совпадений воспринималось гейтом как «нет write-вызовов для блокировки», а не как «список устарел» — drift между контрактом имени и списком-потребителем прошёл незамеченным.

## Исправление

Deny-by-default для любого MCP-инструмента сервера с «iwe»/«knowledge» в имени, кроме действий, чьё имя по ФОРМЕ читающее: `get_`/`list_`/`read_`/`describe_` в любом месте имени, суффиксы `_status`/`_stats`/`_search`/`_list` и т. п. Новый read-only инструмент вне распознанного паттерна даёт ложный BLOCK — безопасное направление ошибки (в отличие от ложного ALLOW). Регрессионный тест прогоняет настоящий хук (не его реимплементацию) на полном текущем списке read- и write-действий сервера.

Холодное ревью нашло, что паттерны, привязанные к НАЧАЛУ имени (`get_*`), ложно блокировали половину читающих инструментов, у которых глагол стоит ПОСЛЕ доменного префикса (`knowledge_list_documents`, `user_profile_get_tier`) — найдено живым прогоном, не предположением. Пограничный случай `agent_status_list` (чтение) vs `agent_status_update` (запись) различается формой имени, а не наличием подстроки «status».

## Тест обнаружения

«Security-гейт блокирует по явному списку ИМЁН инструментов конкретного внешнего сервера/модуля?» Да → спросить: «что произойдёт при переименовании сервера/инструмента — список продолжит матчить что-либо, или тихо опустеет относительно реального трафика?» Если тихо опустеет без сигнала — воспроизведён этот класс.

## Переносимый принцип

Allowlist/denylist, завязанный на буквальные ИМЕНА внешнего пространства (сервер, модуль, API), деградирует до fail-open при любом переименовании на стороне защищаемого — независимо от намерения автора списка. Устойчивая альтернатива — классификация по ФОРМЕ/семантике действия (verb-shape), которая переживает переименование сущности, плюс deny-by-default как направление ошибки по умолчанию.
