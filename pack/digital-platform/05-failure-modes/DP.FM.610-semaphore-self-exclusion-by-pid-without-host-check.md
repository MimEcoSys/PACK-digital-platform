# DP.FM.610 — Самоисключение семафора по pid без проверки host

## Тезис и механизм ошибки

Фикс самоисключения «это мой ещё не закрытый семафор, не чужой писатель» (добавлен ранее, commit ad18a4a) сравнивал только числовое значение pid с `CLAUDE_PID`/`OWNER_PID`. PID уникален только в рамках процессного пространства ОДНОГО хоста. Семафор, перенесённый с другого хоста (например, при восстановлении экзокортекса) и содержащий число, случайно совпавшее с текущим локальным pid, ошибочно проходил проверку «свой» и пропускался — хотя представлял живого чужого писателя. Это нарушает fail-closed контракт функции: при неопределённости семафор ошибочно считался безопасным.

## Фикс

Сравнение дополняется полем `host` (если оно присутствует в семафоре) с текущим `uname -n`, зеркаля уже существующий паттерн `session-guard.sh`. Самоисключение срабатывает только при совпадении И pid, И host.

## Диагностический принцип

Любая проверка «это я» по полю, уникальному лишь в границах одного масштаба (процессное пространство хоста), нуждается в дополнительном поле, фиксирующем этот масштаб (host) — иначе численное совпадение между разными экземплярами этого масштаба (разные хосты) ломает изоляцию, которую проверка должна обеспечивать.

## Границы

Отличается от `DP.D.298` (слабый lookup-ключ небезопасен при параллелизме) — там риск в выборе ПОЗИЦИОННОГО/эвристического ключа вместо точного; здесь ключ (pid) задуман как точный, но неявно предполагает область уникальности шире, чем он реально покрывает.

## Связи

- `DP.FM.603` — смежный, тот же домен (session-guard, семафор изолированного worktree) и тот же общий класс «проверка идентичности собственного семафора ошибается»: там self-identity ошибочно СЧИТАЕТ свой же семафор чужим (self-deadlock при reconcile-at-close), здесь, наоборот, self-identity ошибочно СЧИТАЕТ чужой семафор своим (self-exclusion проходит на чужом писателе из-за межхостовой коллизии pid) — противоположные направления одной и той же хрупкой проверки «это я/не я».

## Проверка

«Проверка self-identity сравнивает только числовое значение pid, без учёта host?» Да → риск ложного самоисключения при переносе состояния между хостами с численно совпавшим pid.
