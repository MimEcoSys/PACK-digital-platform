# DP.FM.624 — Гейт матчил опасную форму команды по глаголу, а не по полной грамматике

## Тезис и механизм ошибки

Новый гейт против `git reset --soft/--mixed` на нелинейную цель проверял факт вызова глагола `git reset` и трактовал единственный позиционный аргумент после `--` как ref-цель, запуская против него ancestry/tree-проверки. На самом деле форма `git reset [<ref>] [--] <pathspec>...` никогда не двигает HEAD, как только присутствует ЛЮБОЙ pathspec — это семантически unstage, а не перемещение указателя. Гейт протестирован только на опасных случаях (реальный `git reset <ref>`) и в таком виде развёрнут на два хоста; в следующей же сессии заблокировал штатный `git reset -- file`.

## Признаки

- Новый security/safety-гейт против опасной формы команды написан и протестирован только на позитивных (опасных) кейсах того же глагола.
- Матчинг строится на имени глагола/подкоманды, без разбора полной грамматики аргументов, которая определяет, какая именно форма вызова реально опасна.
- Гейт уже развёрнут и блокирует штатную, documented-безопасную операцию того же глагола.

## Диагностика

Для любого гейта, блокирующего «опасную форму глагола X» — перечислить ВСЕ грамматические формы X (с `--`, без `--`, с pathspec, с несколькими позиционными аргументами, bare) и явно проверить, какая из них реально производит опасный эффект. Матчинг по одному лишь имени глагола — недостаточный тест.

## Митигация

Проверять только ту форму, которая реально производит опасный эффект (для `git reset` — ровно один позиционный аргумент без `--`, разрешающийся в коммит); все остальные формы по умолчанию безопасны. Набор тестов нового гейта обязан включать безобидные формы того же глагола как негативные кейсы (bare/pathspec/multi-positional) — не только опасные позитивные.

## Тест обнаружения

«Набор тестов нового command-гейта содержит хотя бы один негативный кейс — безобидную форму ТОГО ЖЕ глагола, не только опасную?» Нет → потенциальный DP.FM.624.

## Отличие от смежного

- `DP.FM.417` (матчер пропускает служебные слова составных shell-операторов `do`/`while`/`done`) — другой механизм: там проблема в определении ГРАНИЦ исполняемого сегмента внутри составной конструкции; здесь гейт верно находит команду, но ошибается в разборе её АРГУМЕНТОВ.
- `DP.FM.423` (wrapper с опциями прячет настоящую команду от резолвера позиции) — другой механизм: маскировка command-идентичности оберткой, не неполнота грамматики аргументов уже найденной команды.
- `DP.FM.606` (allowlist MCP-инструментов по именам декэит до fail-open после переименования сервера) — смежный мета-класс «статическая классификация по поверхностной форме не переживает законный вариант», но субстрат другой: там имя сущности меняется во времени (rename), здесь гейт изначально не различал две сосуществующие формы одного и того же глагола.
- `DP.FM.440` (fail-safe гейт закрытия корректно отказывает легитимному пути, для которого нет recovery) — смежная ось «покрытие гейта × легитимные пути», но там дефект — отсутствие РАСПОЗНАВАНИЯ легитимного случая в принципе; здесь гейт в принципе способен различить формы, но матчил по неверному признаку (глагол вместо полной грамматики).
