# DP.FM.638 — Автозахват и ручной черновик одного метода расходятся без взаимной ссылки

## Описание

Один и тот же метод из одной пир-сессии (2026-09-28) оказался представлен двумя независимыми путями: автозахватом экстрактором (`DP.M.487`, зарегистрирован 2026-10-02) и отдельным ручным черновиком (временно `DP.M.486`→`DP.M.524`) — без взаимной ссылки между ними. Расхождение обнаружилось только 2026-10-15 холодным ревью, когда отдельная фаза WP-7 попыталась занести черновик в Pack под собственным новым id.

## Механизм

1. Пир-сессия производит знание, пригодное для Pack-карточки.
2. Экстрактор (DP.AISYS.013) автоматически захватывает и формализует его по своему pipeline (capture → extraction-report → apply) под одним id.
3. Параллельно (или позже) кто-то вручную драфтит ту же идею как отдельный черновик — без проверки, не захвачена ли она уже автозахватом по дате/id исходной пир-сессии.
4. Оба пути не содержат взаимной ссылки друг на друга — ни автозахват не знает о черновике, ни черновик не знает об автозахвате.
5. Расхождение остаётся незамеченным, пока кто-то не попытается зарегистрировать черновик как новую сущность — только тогда ревью находит дублирование.

## Почему опасен

Два пути захвата знания из одной и той же сессии (автоматический через Knowledge Extractor и ручной прямой черновик) — не редкость в системе с несколькими параллельными агентами и пилотом, пишущими в общий Pack. Без взаимной проверки по источнику (дате/id исходной пир-сессии) перед регистрацией нового id расхождение не создаёт явной ошибки — оно просто тихо живёт как два почти идентичных, не связанных файла/черновика, до случайного столкновения.

## Тест обнаружения

«Эта карточка/черновик формализует знание из пир-сессии с конкретной датой/id — проверено ли, что эта же сессия не была уже захвачена другим путём (автозахват экстрактором ИЛИ отдельный ручной черновик)?» Если проверки по source-дате/id пир-сессии не было — риск расхождения остаётся непроверенным.

## Противодействие

Перед регистрацией нового id для материала из пир-сессии — grep по id/дате исходной сессии среди уже существующих карточек Pack (не только по теме/ключевым словам). При обнаружении двух путей захвата — слить содержательные таблицы (например, Forces/Bias) в уже зарегистрированную авторитетную карточку, не создавать второй id для того же материала.

Два черновика сами по себе допустимы; отказ состоит в отсутствии сверки общего источника перед регистрацией.
