# DP.FM.646 — Поддержка нового участника расходится между списками допуска

## Отказ

Нового участника добавляют в один путь платформенного конвейера, но другой путь сохраняет прежний список разрешённых значений. Первый принимает участника, а второй отказывает либо неверно выбирает маршрут. В исходном случае поддержка Kimi требовала согласования shell resolver в `day-close-isolated.sh` и Python whitelist в `day-close-ledger-route.py`.

## Противодействие

Если пути реализуют общий контракт допуска, список и правила преобразования получают общий источник либо проверяемую согласованность. Намеренно разные наборы возможностей не объединяются только ради устранения дублирования: их различие документируется и тестируется как часть контракта.

## Проверка

Новый разрешённый участник проходит все пути, где заявлена его поддержка; неизвестное значение получает установленный отказ. Для намеренно различающихся возможностей проверяется ожидаемое различие, а не безусловное равенство списков.

## Область

Механика платформенного конвейера, а не правило поведения агента. DP.METHOD.153 посвящён согласованности семантического литерала производителя и потребителя; здесь рассинхронизируются списки допуска нескольких путей.
