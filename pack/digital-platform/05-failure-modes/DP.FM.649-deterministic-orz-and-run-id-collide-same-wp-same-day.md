# DP.FM.649 — Проверка уникальности RUN в одной рабочей копии пропускает общий журнал

## Исторический дефект

Ранняя запись 18.10 связывала коллизию ORZ/run_id с одинаковыми РП и днём. Позднее проверенный код уточнил механизм: `_generate_run_id` строил кандидат из process/slug и добавлял суффикс при занятости, но искал занятость только среди карточек своей рабочей копии. Общий журнал хоста видел идентификатор другой копии, который локальная проверка пропускала.

## Исправление и проверка

Исправление 20.10 проверяет наличие карточки ИЛИ записи общего журнала под общим `.start.lock`. Область проверки уникальности должна охватывать все хранилища, которые считают идентификатор занятым, а выбор и регистрация должны соблюдать общий протокол конкуренции.

Повтор собственной сессии разрешается до выделения нового идентификатора и сохраняет её идентичность. Случайный новый ID на каждом повторе не заменяет это требование. Проверка двух независимых рабочих копий должна показать разные идентификаторы новых запусков и стабильный идентификатор повтора.

## Датированное состояние и граница

Узкий фикс опубликован 20.10; живая приёмка двух сессий в источнике ещё открыта. Нельзя описывать исправленный код как по-прежнему неисправленный или объявлять весь инцидент закрытым. AS.FM.054 рассматривает другую гонку выделения номера по счётчику. Механизм имени ORZ требует отдельной проверки; ранний составной диагноз не доказывает тождественность всех причин.
