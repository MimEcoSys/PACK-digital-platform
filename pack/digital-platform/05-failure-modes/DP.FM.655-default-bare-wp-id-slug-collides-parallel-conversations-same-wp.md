# DP.FM.655 — Дефолтное имя журнала без идентичности разговора сталкивает разные сессии

## Механизм

Если имя журнала выводится только из рабочей единицы и даты, два разных разговора с одинаковыми этими значениями в одном пространстве хранения получают один путь. Устойчивость имени при повторе одного разговора не обеспечивает различимость разных разговоров. Коллизия зависит от совпадения всего ключа и области хранения, а не от параллельности как таковой.

## Проверенный прецедент и предел исправления

В iwe-local-config `e2f6a4c68405eea1f252208d0e37231dd3abcfb5` к дефолтному имени ORZ добавлены первые восемь символов нативного ID разговора. Ветка работает только при отсутствии явного slug и наличии нативного ID. Явный slug и случай без нативного ID этим изменением не защищены; короткий префикс сохраняет возможность коллизии. Поле slug в метаданных имеет отдельную семантику и может сохранять имя рабочей единицы.

## Проверка и предотвращение

Перечислить составляющие ключа и область хранения. Сравнить пути для двух разных разговоров с одной рабочей единицей и датой, а также для повтора одного разговора. Отдельно проверить явный slug, отсутствие нативного ID и совпавший короткий префикс. Выбирать схему различения согласно требуемой области уникальности; один короткий суффикс не доказывает глобальную уникальность.

## Отличие от соседей

DP.FM.649 описывает проверку уникальности RUN только в одной рабочей копии при общем журнале. Здесь неполон сам ключ имени. AS.FM.054 описывает гонку распределения номера через count; здесь одинаковый путь детерминированно вычисляется из одинаковых входов.
