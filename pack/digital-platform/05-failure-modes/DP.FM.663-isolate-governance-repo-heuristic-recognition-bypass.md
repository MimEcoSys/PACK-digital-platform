# DP.FM.663 — Проверка цели пропускается из-за эвристики структуры каталога

## Механизм

Защитный предикат вызывается только для цели, распознанной по знакомой структуре каталогов. Цель без ожидаемой папки выходит из области проверки, хотя правило относится к идентичности репозитория, а не к наличию этой папки.

## Проверенный случай

В iwe-local-config `a8350bb97d313788bad4cbfccf77833c449eb1f7` старая ветка проверяла целевой репозиторий при наличии WP и inbox/. Репозиторий без inbox/ пропускал именно эту проверку идентичности. Это не основание утверждать отсутствие всех защит операции.

Добавленный git_identity_matches сравнивает физический git-common-dir с разрешением симлинков; ошибка разрешения даёт несовпадение. Проверка стоит до старой ветки inbox/, но выполняется только без явного force. Поэтому слово «безусловная» неверно. Явное исключение отключает именно этот контроль и требует осознанного решения; карточка не рекомендует автоматически выставлять force.

## Контрмера и тест

Предикат области применения должен опираться на контракт операции. Проверить одинаковое правило на репозиториях с inbox/ и без него, на недоступном common-dir, симлинке и двух рабочих деревьях одного общего хранилища. Последние могут правомерно иметь одну физическую Git-идентичность; одинаковый remote у разных клонов её не доказывает.

Отдельно проверить предусмотренное исключение: его наличие должно быть видимым и ограниченным, а не приниматься за успешное прохождение отключённой проверки.
