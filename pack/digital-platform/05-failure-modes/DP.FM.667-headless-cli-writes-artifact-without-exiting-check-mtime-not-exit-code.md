# DP.FM.667 — CLI на базе headless-браузера пишет артефакт, но не завершает процесс

## Механизм

CLI-инструмент (marp-cli), использующий headless-браузер для рендера, корректно записывает/обновляет выходной файл (PDF), но сам процесс не завершается — зависает на закрытии браузера. Pipeline, ожидающий код завершения процесса как сигнал успеха, виснет или ошибочно считает шаг незавершённым, хотя нужный артефакт уже готов.

## Проверенный случай и ограничения

Сборка Marp-колоды (46 слайдов) для Марафона-4 на Mac: marp-cli генерирует корректный PDF, но процесс не завершается сам (зависает на закрытии headless-браузера). Это наблюдение на конкретной машине/версии; не доказано как универсальное свойство всех версий marp-cli на всех платформах.

## Контрмера и тест

Запускать сборку под `timeout`; успешность определять по mtime выходного файла (обновился ли после запуска), не по коду завершения процесса.

Тест обнаружения: «процесс CLI, использующего headless-браузер, завершается сам в разумное время после того, как выходной файл перестал изменяться?» Нет → применим этот FM, нужен `timeout` + проверка по mtime.

Здесь другой слой: сам CLI создаёт корректный результат, но код выхода/завершение процесса не является надёжным сигналом об этом результате — нужно отдельное средство обнаружения готовности (mtime), а не только таймаут.
