# DP.FM.685 — Алиас имени агента даёт вторую живую запись семафора одной сессии

## Симптом

Семафор сессии был открыт командой `session-guard.sh open --agent claude`. Хук ищет семафор по маске `claude-code-*.open`, не совпадающей с этим именем; агент открыл вторую копию командой `session-guard.sh open --agent claude-code`. Для одного slug оказалось два живых файла `.open`. Раннер закрытия отказал: «неоднозначная связь guard/harness/slug» — два `.open` с одним slug считаются неоднозначными. Выбрать каноничную запись нечем, штатного способа снять дубликат нет, ручная чистка служебных файлов неприемлема.

## Механизм

Имя агента входит в ключ семафора, а пишущая сторона (`open`) и ищущая (хук) трактуют это имя по-разному. Пока поиск не находит запись, созданную под другим именем, «не найдено» неотличимо от «такого семафора нет», и открытие повторяется. Ключевое пространство допускает две записи на одну логическую сессию, различающиеся только вторичным полем (имя агента). Автоматическое восстановление при такой неоднозначности невозможно: у процедуры нет признака, по которому выбрать каноничный замок. Это обратное направление к коллизии ключа: там два владельца получают один ключ (`DP.FM.215`, `DP.FM.655`), здесь один владелец получает два.

## Тест обнаружения

«Может ли один логический владелец (сессия, slug) создать в хранилище замков или семафоров две записи, различающиеся только вторичным полем (имя агента, формат идентификатора)? Что делает автоматическая процедура закрытия или восстановления, найдя обе?» Да, и выбор каноничной записи не определён → риск этого класса.

## Противодействие

Одна логическая сессия — одна запись: либо строгий ключ, при котором второе открытие для того же владельца отвергается в момент открытия, а не обнаруживается при закрытии; либо заранее определённая процедура разрешения дубликатов (какая запись каноничная, как снять лишнюю). Какое именно исправление внедрено в источнике, из него не следует.

## Границы

- Один инцидент (сессия 2026-10-27, WP-484 Ф261); описание дано по тексту записи источника.
- Связь «маска хука не совпала → агент открыл вторую копию» — вывод из соседства фактов, источник причинную цепочку прямо не утверждает.
- Нормализация имени агента как таковая — тема `DP.FM.385` (единый формат идентичности); здесь — последствие для закрытия и требование строгости ключевого пространства.

## Отличие от соседей

- `DP.FM.215` — ключ по agent-id слишком грубый: параллельные сессии одного агента делят указатель. Здесь ключ допускает две записи на одну сессию.
- `DP.FM.385` — writer и checker сравнивают разные форматы идентичности → ложное «чужой». Здесь — вторая живая запись и неразрешимая неоднозначность при закрытии.
- `DP.FM.603` — собственный открытый семафор засчитан «живым писателем» → самодедлок. Здесь — невозможность выбрать каноничную из двух записей.
