# DP.FM.689 — «Курсор остаётся для повтора» при монотонном курсоре

## Симптом

После нескольких подряд отказов воркер проекции открывает предохранитель и пишет, что остальные события пропускаются «до остывания, курсор остаётся для повтора». По тексту сообщения был сделан вывод «потерь нет, воркер сам доберёт события».

## Механизм

Курсор монотонен: он только растёт. Событие ниже курсора воркер больше не читает, поэтому пропущенное не повторяется само: сообщение описывает намерение, которого поведение кода не обеспечивает. Автоповтор очереди ошибок добавляет второй путь потери: он удаляет записи ниже курсора без начисления. Откат курсора назад недопустим, если правило обработки не идемпотентно.

## Тест обнаружения

«Утверждает ли лог или сообщение воркера, что пропущенное будет обработано повтором, и действительно ли код читает событие ниже текущего курсора? Что происходит с записью очереди ошибок, когда она ниже курсора?» Курсор монотонен, а в сообщении обещан повтор → вывод «потерь нет» не подтверждён.

## Противодействие

- Вывод «что будет с пропущенным событием» делать по коду и счётчикам (монотонность курсора, судьба записей очереди ошибок), а не по тексту сообщения воркера. Пока не проверено, «потерь нет» — гипотеза.
- Если курсор не может откатываться, пропуск должен попадать в явную очередь добора, а не только в лог.

## Границы

Один воркер проекции. Размеры очереди и объём добора в карточку не переносятся: механизм не зависит от них.
