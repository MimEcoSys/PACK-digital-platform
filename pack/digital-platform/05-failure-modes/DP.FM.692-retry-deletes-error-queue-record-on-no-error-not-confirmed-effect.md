# DP.FM.692 — Запись из очереди ошибок удаляют по отсутствию ошибки, а не по подтверждённому эффекту

## Симптом

Процедура повтора удаляет запись из очереди ошибок, когда `process_event` не сообщил об ошибке. Обработчик мог молча пропустить событие (ветка без действия), и запись потеряна вместе с необработанным событием.

## Механизм

«Нет ошибки» ≠ «эффект есть». Возврат без исключения говорит только о том, что обработчик не упал; сам результат (строка в целевой таблице) остаётся непроверенным. Молчаливый пропуск и успех для процедуры повтора выглядят одинаково.

## Тест обнаружения

«Удаляется ли запись по отсутствию ошибки, без перепроверки результата в целевой таблице?» Да → риск потери записи при молчаливом пропуске.

## Противодействие

Удалять запись только после подтверждённого эффекта: перепроверить результат в целевой таблице либо получить от обработчика явный признак применения, отличный от «не упал».

## Границы

Один процесс повтора очереди ошибок (РП-567). Вторая ошибка той же процедуры — разнесённые во времени проверка «начисления нет» и применение — описана как защита в `DP.M.329`.

## Отличие от соседей

- `DP.FM.101` — движок правил возвращает NOOP при отсутствии записи: событие отброшено молча. Здесь пропуск делает уже обработчик, а ошибку в удалении записи очереди создаёт процедура повтора.
- `DP.FM.462` — повтор на сетевую ошибку смешивает «запрос не дошёл» и «неизвестно, дошёл ли». Здесь вопрос о подтверждении эффекта после возврата без ошибки.
