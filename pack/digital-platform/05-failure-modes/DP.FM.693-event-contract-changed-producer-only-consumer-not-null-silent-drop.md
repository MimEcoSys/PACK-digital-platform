# DP.FM.693 — Поля убрали из события, а таблица-потребитель оставила их обязательными

## Симптом

Решение убрало поля из события, таблица-потребитель оставила их обязательными (NOT NULL); проекция трасс молча теряла записи три месяца. Починено без миграции: вместо NULL записываются пустые объекты.

## Механизм

Контракт события изменён только на стороне производителя; потребитель отклоняет запись, а пропуск не виден в журнале.

## Тест обнаружения

«Меняется ли схема события одновременно у производителя и потребителя? Есть ли счётчик молчаливых пропусков?» Нет на любой вопрос → отказ потребителя может остаться незамеченным.

## Противодействие

Менять обе стороны контракта сразу; молчаливый пропуск ловить счётчиком, а не журналом.

## Границы

Остаточный риск: новое поле, пропущенное хуком, остановит проекцию (KeyError не входит в постоянные ошибки). Один случай, одна проекция.

РП-567 и РП-500, закрытие сессии 2026-10-28.
