# DP.FM.696 — Очистка буфера по квитанции записи

## Симптом

Читатель объединяет опубликованный журнал событий с локальным буфером хоста. Квитанция подтверждает, что события есть на сервере. Буфер очищают по квитанции.

## Механизм

Квитанция подтверждает наличие событий на сервере, но не свежесть всех открытых рабочих копий. Изолированная копия может читать старую опубликованную версию и после удаления буфера потеряет видимость события вместе с его буферной копией.

Альтернатива «не чистить» тоже ломается: публикатор принимает не более 64 YAML-файлов и 16 МиБ за снимок, поэтому неудаляемый буфер со временем перестанет публиковаться.

## Защита

- Очистка по подтверждению записи безопасна, только если подтверждено и состояние читателей.
- Нужен либо порядок хранения подтверждённых событий, либо доказательство свежести всех читателей перед очисткой.
- Условия переключения источника записи (допубликовать старый хвост, настройка на каждом входе, права на обоих хостах, откат) — в DP.M.579; здесь не дублируются.

## Статус свидетельства

Оба отказа (потеря у отставшей копии и рост без предела) выведены пир-ревью проекта; схема с очисткой по квитанции в боевом режиме не включалась. Поэтому trust: medium, epistemic_stage: forming.
