# DP.FM.699 — Дескриптор замка в «служебном» диапазоне shell затирается перенаправлением

## Симптом

Замок локального освобождения сессии отпускается посреди работы владельца: параллельный писатель входит в критическую секцию, а владелец не получает ни ошибки, ни сигнала.

## Механизм

1. Владелец на Python берёт `flock` на дескрипторе с низким номером (так выдаёт ОС: первый свободный).
2. Дескриптор доходит до bash-скриптов: по наследованию или при явной передаче через exec.
3. Скрипты по своей конвенции используют номера 3 и 9 под собственные квитанции и замки (`exec 9>"$lock"`, `exec 3>&1`).
4. Перенаправление закрывает дескриптор в том процессе, который его выполняет. Замок теряется, когда этот процесс держит последнюю ссылку на open file description замка: владелец сам стал shell-скриптом через `exec` (exec-повтор) или скрипт-владелец переоткрыл свой номер. В форкнутом дочернем процессе закрывается только его копия, замок родителя сохраняется, но дочерний при этом может молча писать служебный вывод в файл замка.

Номер дескриптора — общий ресурс процесса без владельца. Конвенция «3 и 9 мои» в скриптах и выбор «первый свободный» в ОС не согласованы.

## Исправление (634b415c9)

- Копия дескриптора замка выше диапазона, который скрипты занимают явно: `fcntl(fd, F_DUPFD, 32)`, исходный дескриптор закрыт.
- Копия не наследуется (`os.set_inheritable(fd, False)`). Где замок действительно должен перейти в дочерний процесс, он передаётся явно (`pass_fds`).
- Проверка inode, порядок взятия замков и явная передача дескриптора не изменились.
- Тесты добавлены в `scripts/tests/test_session_local_release.py` (в том же коммите).

## Отличие от DP.FM.410

DP.FM.410 — унаследованный дескриптор живёт слишком долго: фоновый процесс держит замок и блокирует следующие тики. Здесь обратное: чужое перенаправление переиспользует номер, и замок отпускается слишком рано. В обоих случаях причина одна — неявное наследование. Исправление общее: дескриптор замка не наследуется по умолчанию.

## Тест обнаружения

«Может ли номер дескриптора замка совпасть с номером, который дочерний скрипт открывает перенаправлением?» Замок на 3–9 (или на любом номере, который скрипты используют явно) и наследуется → FM активен.
