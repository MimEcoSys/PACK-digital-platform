# DP.FM.700 — Повтор освобождения по завершённой квитанции переигрывает устаревший список маркеров

## Симптом

`process-runner.py release-local --agent claude-code` стабильно (дважды подряд) падает с `ERROR: residual/new marker; retry cannot report success`. Stop-хук блокирует завершение хода: «Локальное освобождение не завершено». Повтор не помогает: отказ детерминированный.

## Причина

1. Внутри одной harness-сессии последовательно открывались два изолята (`session-guard --isolate`): первый — 24.10, освобождён 25.10, квитанция `status: completed` зафиксировала один маркер; второй — 26.10, с другим `session_id`, создал новый маркер `/tmp/iwe-close-runner-started/<harness>.flag`.
2. Второй изолят закрылся с другим суффиксом (`.open.closed`, а не `.closed-local`), поэтому в выборку «retained» попала только старая квитанция.
3. При `len(retained) == 1` код пропускал сравнение кандидатов и брал единственного. Квитанция уже завершена, и `release()` повторно вызывал `finish_release()`.
4. `remove_owned_markers(card)` удалял маркеры по `card["markers"]`, зафиксированным два дня назад. Текущий набор маркеров с ним не пересекался, сегодняшний флаг оставался, финальная проверка «нет остаточных маркеров» падала.

**Класс.** Код предполагал, что ключ поиска («harness-сессия») однозначно указывает на одно актуальное поколение. На деле одна harness-сессия нормально порождает несколько поколений изолятов. Повторная операция над `completed`-записью переигрывала её исторический снимок вместо текущего состояния.

## Антипаттерн → Паттерн

- **Антипаттерн:** «запись уже завершена → повторить завершение по её сохранённым данным»; выбор «единственного кандидата» без проверки, что он относится к текущему поколению.
- **Паттерн:**
  1. Повторная операция над завершённой записью либо пересчитывает актуальное состояние (текущий набор маркеров), либо явно отказывается с диагностикой «запись относится к другому поколению». Молча переиграть снимок нельзя.
  2. Ключ поиска включает идентификатор поколения (`session_id` изолята), а не только долгоживущий ключ (harness-сессия). Выборка по долгоживущему ключу с одним результатом не доказывает актуальность.
  3. Суффиксы и статусы закрытия, равноправные по смыслу (`.closed-local`, `.open.closed`), попадают в одну выборку; иначе фильтр незаметно выбрасывает актуального кандидата.

## Переносимый принцип

Сохранённый в записи снимок («что я тогда создал») описывает момент записи, а не текущий мир. Если ключ записи может повториться во времени, идемпотентный повтор по снимку становится операцией над чужим поколением.

## Тест обнаружения

«Может ли ключ поиска записи повториться у нового экземпляра процесса (новый изолят, новый запуск той же сессии)?» и «Что делает повторная операция, если найденная запись уже завершена — пересчитывает или переигрывает?» Сценарий проверки: два изолята подряд в одной harness-сессии, закрытые разными путями. После второго `release-local` остаточных маркеров нет, или есть явный отказ с указанием поколения.
