# DP.FM.705 — timeout внутри подстановки команды не ограничивает время

## Симптом

Скрипт «с ограничением 45 секунд» может висеть дольше, если охраняемая команда оставляет дочерний процесс.

## Механизм

`timeout` завершает прямого потомка. Дочерний процесс, который тот успел запустить, продолжает держать открытым конец потока. Подстановка `$( … )` ждёт закрытия потока, а не завершения команды, поэтому вызывающий ждёт дольше срока. Смешение `2>&1` ещё и склеивает потоки: вывод и ошибки перестают различаться. Смежные, но другие механизмы: DP.FM.694 (ожидание убитого сторожевого процесса, код 143), DP.M.415 (захват кода возврата), DP.FM.464 (set -e и pipefail).

## Лечение

1. Писать поток ошибок во временный файл (`2>"$tmp"`), а не захватывать подстановкой.
2. Код возврата брать сразу после команды.
3. Хвост ошибки читать из файла и удалять файл после.

## Граница

Не воспроизведено как инцидент: найдено холодным ревью по механизму (в коде назван «stray child»). Смоук-тест проверяет исправление, а не зависание. Формулировка: риск шаблона, а не подтверждённый сбой.

## Тест обнаружения

«Результат команды со сроком захвачен через `$( … )` или читается из потока, который могут держать дочерние процессы?» Да → срок может не сработать.
