# DP.FM.707 — Предел глубины JSON жил в неявном поведении парсера

## Симптом

Ограничение «глубже N уровней — отказ» нигде не было записано в коде, и теста «слишком глубокий ввод отвергается» не было. Если неявный предел парсера сдвигается (смена версии интерпретатора или реализации парсера), глубокий файл проходит дальше по конвейеру без ошибки и без изменений в коде.

## Что известно, а что нет

- Из источника: в коде моста плана появился явный `MAX_PARSE_DEPTH = 100` для хранимых файлов (предел запроса остаётся 16), итеративная проверка глубины после `json.loads` и прогон на Python 3.12, 3.14 и 3.15 (по описанию коммита).
- Наблюдение автора кода (комментарий): на Python 3.14+ глубокий JSON разбирается без ошибки рекурсии (в оригинале: «Python 3.14+ parses deep JSON without RecursionError»). Это наблюдение, а не проверенный факт. Механизм (итеративный разбор или иной предел) не установлен, на 3.14 не проверялось.
- Проверка при разборе батча 2026-11-02 на Python 3.12.12: `json.loads` разбирает 5000 уровней вложенности, а ошибку рекурсии даёт на 100000. То есть неявный предел и прежде был намного выше 100 и не заменял явного.

## Механизм

1. Защита опирается на побочное поведение библиотеки (исключение при глубокой рекурсии), а не на проверку в коде.
2. Предел принадлежит реализации парсера, он не зафиксирован контрактом и тестом.
3. Смена версии или реализации может его сдвинуть или убрать; об этом ничто не сообщит.

Общий класс: страховка, которая держится на побочном поведении среды исполнения. Смежный случай на другом субстрате: DP.FM.386 (фоновый детач тихо теряет таймаут-подстраховку).

## Лечение

1. Явная константа предела для каждого входа (в источнике `MAX_PARSE_DEPTH = 100` для хранимых файлов; предел запроса 16 остаётся).
2. Итеративная проверка глубины после `json.loads`: обход явным стеком, чтобы сама проверка не зависела от предела рекурсии.
3. Тест «слишком глубокий ввод отвергается», прогон на нескольких версиях интерпретатора.

## Тест обнаружения

«Ограничение на размер, глубину или количество во входе обеспечивается не явной проверкой, а ожидаемым исключением библиотеки?» Да → предел принадлежит реализации и может исчезнуть при обновлении.

## Граница

Один прецедент (мост плана). Карточка о классе «неявная страховка», а не о поведении конкретной версии Python: версионное поведение — гипотеза до проверки `json.loads('[' * N + ']' * N)` на 3.14.
