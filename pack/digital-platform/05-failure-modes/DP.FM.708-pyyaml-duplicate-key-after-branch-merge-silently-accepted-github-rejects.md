# DP.FM.708 — Дубль ключа задания CI после слияния веток

## Симптом

Проверка «YAML парсится» зелёная, а GitHub отклоняет workflow.

## Механизм

1. Две ветки независимо добавили одно и то же задание CI.
2. Слияние оставило в файле два одинаковых ключа.
3. Разбор YAML в локальной проверке принимает дубль ключа и берёт последнее значение без ошибки (загрузчик в источнике не назван; так ведёт себя, например, PyYAML, проверено на 6.0.3); GitHub считает дубль ошибкой.
4. Локальная проверка «разбор прошёл» не видит того, что видит GitHub.

Формулировка «стандартные загрузчики берут последнее значение» подтверждена только для PyYAML; для других загрузчиков не проверялась, а какой загрузчик стоял в проверке случая, источник не сообщает.

## Лечение

Перед пушем файла workflow проверять уникальность ключей загрузчиком, который отказывается на дубле, а не только факт успешного разбора.

## Граница

Один случай (обзор инцидента в WP-388, одна строка в карточке, без команды воспроизведения). Вторая половина исходной заметки («расхождение веток по патчам не равно расхождению по содержимому») в эту карточку не входит: она уже описана в DP.M.430 и DP.M.439.

## Тест обнаружения

«Файл workflow получен слиянием веток, а проверка перед пушем — только успешный разбор YAML?» Да → дубль ключа не будет замечен.

## Отличие от соседей

DP.FM.349 — молчаливый выбор при нескольких значениях поля в поиске по YAML, другой контекст. Здесь дубль появляется в самом файле после слияния и расходится с поведением GitHub.
