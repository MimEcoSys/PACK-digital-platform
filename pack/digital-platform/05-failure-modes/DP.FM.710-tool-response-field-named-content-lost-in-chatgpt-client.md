# DP.FM.710 — Потеря успешного ответа в клиенте ChatGPT при ключе `content`

## Наблюдение

Участница читала личный документ через ChatGPT и получала пустой `{}`. Сервер при этом вернул успешный ответ с содержимым, ошибки нигде не было. Ответ содержал верхнеуровневый ключ `content`. Исправление — необязательный параметр `content_field:"body"`, который отдаёт содержимое под именем `body`; по умолчанию ответ не менялся. Проверено на ChatGPT пилота (не участницы). Запись — коммит fbfa7cdf5 в карточке WP-613; код — knowledge-mcp PR 82, gateway-mcp PR 127.

## Гипотеза о причине

Гипотеза: имя поля `content` совпадает со служебным ключом клиента, и клиент молча отбрасывает такой ответ. Механизм внутри клиента не проверялся, список зарезервированных имён у ChatGPT и у других клиентов не собран. Подтверждено только то, что без параметра ответ терялся, а с `content_field:"body"` доходил (на ChatGPT пилота).

## Что делать

- Считать имя верхнеуровневого поля ответа инструмента частью совместимости с клиентами. Для тех полей, чьё имя может совпасть со служебным (например, `content`), прогонять смоук через каждый поддерживаемый клиент, а не через один.
- По умолчанию для клиента ChatGPT указывать в инструкциях `content_field:"body"`.
- При появлении «пустого» ответа у одного клиента при успешном ответе сервера проверять имена полей ответа.

## Тест обнаружения

«У одного клиента ответ пуст, а сервер вернул успех? Есть ли в ответе верхнеуровневое поле с общим именем (`content`)?» Оба «да» → проверить гипотезу переименованием поля.

## Граница

Один случай, один клиент. Карточка не вводит правило о поведении ChatGPT и не обобщает за пределы наблюдения. Тихий отказ: ни сервер, ни клиент не сообщают об ошибке, поэтому ловят его по сигналу пользователя.
