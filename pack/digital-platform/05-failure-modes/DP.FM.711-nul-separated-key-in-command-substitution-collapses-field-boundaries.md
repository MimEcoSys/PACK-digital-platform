# DP.FM.711 — NUL-разделители ключа теряются в подстановке команды

## Статус наблюдения

Найдено холодным ревью до релиза. Случай коллизии ключей в работе не наблюдался: симптом ниже потенциальный. Механизм воспроизведён при разборе батча 2026-11-02 (GNU bash 5.2.37): `$(printf 'k\0%s\0%s' ab c)` и `$(printf 'k\0%s\0%s' a bc)` дают одну строку `kabc` с предупреждением `ignored null byte in input`; хэш, взятый прямо из канала, у этих двух вариантов различается.

## Потенциальный симптом

Две разные единицы работы получают один ключ идемпотентности. Вторая может быть принята за уже выполненную или ждать чужой блокировки, хотя её никто не запускал. В stderr стоит предупреждение bash, которое в фоновом запуске обычно уходит в лог и не читается.

## Механизм

1. Поля тождества соединяются NUL-байтом: NUL не встречается внутри строки shell, поэтому кажется надёжным разделителем.
2. Строка сохраняется в переменную через подстановку: `ident=$(printf 'tag\0%s\0%s' "$a" "$b")`.
3. Bash не хранит NUL в переменной и выбрасывает его из результата. Остаётся простая склейка полей.
4. Склейка неоднозначна: `('ab','c')` и `('a','bc')` дают `tagabc`, хэш и ключ совпадают.

## Почему трудно заметить

Скрипт не падает и не меняет код возврата. Проверка формата ключа (шестнадцатеричный хэш) проходит. Коллизия проявляется только на парах значений, где граница поля может сдвинуться, поэтому тесты с «типичными» значениями её не ловят.

## Лечение

- Не сохранять байты с NUL в переменной: отдавать их в хэш прямо из канала, `printf 'tag\0%s\0%s' "$a" "$b" | sha256sum`; шестнадцатеричную строку хэша затем можно присвоить переменной.
- Либо использовать разделитель, допустимый в переменной, с экранированием полей (например, длина поля перед значением).
- Регрессионный тест: две пары значений со сдвинутой границей полей обязаны дать разные ключи.

## Тест обнаружения

«В скрипте есть `$(...)`, внутри которого печатается `\0` (printf, find -print0, tr в `\0`), а результат сравнивается или хэшируется?» Да → границы полей потеряны. Строка `ignored null byte in input` в логах — прямой признак.
