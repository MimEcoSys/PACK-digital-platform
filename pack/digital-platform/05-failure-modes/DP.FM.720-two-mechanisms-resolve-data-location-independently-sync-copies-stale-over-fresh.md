# DP.FM.720 — Два механизма разрешают расположение одних данных независимо: синк копирует старое поверх нового

## Симптом

После закрытия дня в памяти агента оказываются устаревшие записи вместо только что сделанных («старое поверх нового»). Оба участника — бэкап памяти при закрытии дня и хук зеркала — по отдельности отрабатывают без ошибок; журналы обоих выглядят штатно.

## Механизм

1. Два механизма считают, что работают с одними данными (память агента).
2. Каждый получает расположение данных своим способом: один идёт по символической ссылке `memory/`, другой — по иному пути (реальная папка). Пока цели совпадают, расхождение невидимо.
3. После переноса или переустановки цели расходятся: ссылка и реальная папка указывают на разные каталоги с разным содержимым.
4. Синк между «источником» и «зеркалом» на самом деле идёт между двумя разными копиями; та, что старее, считается актуальной и затирает свежую.

Первопричина — не в логике синка и не в битой ссылке (ссылка цела, см. `AS.FM.073`), а в том, что расположение одних данных вычисляется в двух местах независимо.

## Почему опасен

Ни один из механизмов не ошибается в своих терминах, поэтому ни один не даёт сигнала. Потеря проявляется как содержательная регрессия памяти (пропавшие записи), которую замечает человек, а не проверка. Чем дольше цели расходились, тем больше свежих записей перетёрто.

## Тест обнаружения

«Сколько мест в коде вычисляют путь к этим данным?» Если больше одного (ссылка в одном скрипте, литеральный или вычисленный путь в другом) — расхождение целей возможно, синк между ними небезопасен. Прямая проверка: для каждого механизма напечатать `realpath` того, что он считает памятью, и сравнить; различие = воспроизведён этот отказ.

## Противодействие

Единый способ разрешения пути: одна функция (или одна ссылка), из которой расположение данных получают все механизмы — бэкап, зеркало, проверки. Исправление в источнике выполнено именно так: оба механизма переведены на один способ разрешения. Правило переносимо на любые данные с несколькими писателями или читателями: расположение — часть общего контракта, не локальное знание каждого скрипта.

## Границы

Карточка о расхождении **расположения** одних данных между механизмами. Не о битой ссылке (`AS.FM.073`), не о restore без слияния (`DP.FM.133`), не о протухшем canonical-указателе (`DP.FM.078`). Отдельный открытый вопрос из источника — сигнал при независимой правке обеих сторон синка (нужен проектный разбор) — карточкой не решается.
