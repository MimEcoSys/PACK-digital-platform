# DP.FM.721 — Негативный тест проверяет отсутствие общего с соседом текста

## Отказ

Один вывод (например, подсказка хука) собирают несколько механизмов. Негативный тест механизма X проверяет: «без условия X в выводе нет такого-то текста». Если этот текст выдаёт и соседний механизм Y, тест верен только до тех пор, пока Y молчит. Когда Y добавлен или сработал правильно, тест X падает, хотя X не изменился и работает верно.

## Наблюдённый случай

В хук внедрения стиля параллельно добавили две подсказки: «имена из кода» (WP-388) и «„в этом чате“ в строке „Дальше:“» (WP-605). Общий прогон: 21 тест прошёл, 2 упали. Оба упавших относились ко второй подсказке. Тест ждал, что без её детектора она не появится, а находил фрагмент, общий с выводом первой подсказки.

## Почему опасно

- Падение выглядит как регрессия X, и его чинят правкой X либо ослаблением теста.
- Тест X становится зависим от поведения всех соседей по выводу. Любая правильная доработка соседа ломает чужой тест.
- Если сосед временно молчит, тест X проходит, но это ничего не говорит об X.

## Как предотвратить

1. У каждого механизма общего вывода есть собственная метка (идентификатор подсказки, префикс, ключ в журнале).
2. Негативный тест проверяет отсутствие именно этой метки, а не фрагмента текста.
3. При добавлении механизма в общий вывод прогоняются негативные тесты всех соседей.

## Тест обнаружения

Включить в тестовом примере соседний механизм так, чтобы он сработал. Если негативный тест X падает, а X не менялся, тест проверяет общий текст, а не метку X.
