# DP.FM.723 — Одноимённый владелец аренды = продление: два процесса одного хоста под одной арендой

## Симптом

Два исполнителя одного хоста одновременно выполняют защищённый арендой цикл. Каждый считает, что аренда его. Ошибок захвата нет: оба вызова `acquire` возвращают успех.

## Механизм

1. Библиотека аренды поддерживает продление: повторный `acquire` тем же владельцем не отказывает, а сдвигает срок. Так долгий процесс может продлевать свою аренду.
2. Идентификатор владельца собран из того, что одинаково у разных процессов: имя хоста, роль, имя службы (`settler:<host>`).
3. Второй процесс того же хоста предъявляет тот же идентификатор. Библиотека видит «продление» и отвечает успехом.
4. Взаимное исключение внутри хоста исчезает молча: аренда защищает только от других хостов.

Прецедент: служба сведения запускается из открытия сессии и из открытия дня. Оба триггера на одном хосте брали аренду `settler:<host>` и работали параллельно.

## Противодействие

- Идентификатор владельца различает **процессы**, а не хосты или роли: `caller:pid` (при необходимости плюс хост и время старта процесса — см. DP.FM.686 о надёжности сравнения времени старта).
- Если продление нужно, оно выполняется тем же процессом, который захватил аренду, с тем же идентификатором. Чужой процесс не может «продлить» чужую аренду.
- Тест: два параллельных запуска на одном хосте; второй обязан получить отказ или ждать.

## Проверка

«Какая семантика у повторного захвата тем же владельцем? Может ли другой процесс собрать такой же идентификатор владельца?» Если повторный захват = продление и идентификатор не содержит ничего уникального для процесса, воспроизведён DP.FM.723.
