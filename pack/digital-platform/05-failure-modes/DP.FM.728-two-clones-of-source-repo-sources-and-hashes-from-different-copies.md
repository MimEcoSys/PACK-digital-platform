# DP.FM.728 — Два клона репозитория-источника: источники и хеши из разных копий

## Паттерн

На машине два клона одного репозитория-источника (например, `DS-ai-systems` и вложенный `DS-IT-systems/DS-ai-systems`). Скрипт синхронизации берёт **источники** по переменной окружения (`AI_SYSTEMS_DIR`, указывает на вложенный клон), а **хеши** (`.sync-hashes`) — из того клона, из которого сам вызван. Клоны выравнивают по очереди, один из них отстаёт. Синхронизатор показывает ложное расхождение (файл `dt-collect.sh` остаётся в списке) или скрывает настоящее. Класс расхождения зависит от того, какой клон запустил скрипт.

## Почему это ошибка

Скрипт тихо считает, что все входы читаются из одной копии. На деле у двух ролей (источник содержимого, эталон хешей) разные способы найти путь: переменная окружения и расположение самого скрипта. Пока клон один, разница не видна.

## Признаки

- Расхождение «не уходит» после выравнивания источника.
- Один и тот же запуск даёт разный результат в зависимости от каталога, из которого вызван скрипт.
- `find ~ -name <repo> -type d -maxdepth N` находит больше одного клона.

## Мера

1. Один клон на репозиторий на машине; лишний удалить или сделать ссылкой.
2. Если клонов несколько, скрипт перед работой проверяет, что источники и хеши берутся из одной копии (сравнить корень git обоих путей). При расхождении — громкая ошибка, а не продолжение.
3. Путь к источнику определять одним способом для всех ролей.

## Тест обнаружения

«Из какой копии скрипт берёт содержимое, а из какой — эталон для сравнения? Это один и тот же корень git?»
