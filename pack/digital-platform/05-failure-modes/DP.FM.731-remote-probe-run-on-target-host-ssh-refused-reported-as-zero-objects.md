# DP.FM.731 — Ошибка транспорта к самому себе трактуется как пустой результат

## Симптом

Сверка каталога процессов с живыми юнитами (`--check-live`) сообщает «0 объектов» вместо ошибки. Это легко принять за пустой каталог или за отсутствие живых юнитов.

## Механизм

1. Сверка всегда опрашивала сервер по ssh: единый удалённый транспорт без определения «я и есть цель».
2. Её запустили на самом сервере (tsekh-1). Ssh на собственное имя был отклонён.
3. Отказ соединения не был обработан как сбой: пустой вывод удалённой команды превратился в пустой список объектов.

## Антипаттерн → Паттерн

- **Антипаттерн:** один удалённый транспорт без проверки «хост совпадает с целью»; отказ соединения даёт пустой список.
- **Паттерн:**
  1. Определять, что хост совпадает с целью, и вызывать команду локально (`systemctl` без ssh).
  2. Ошибку транспорта превращать в сбой («неизвестно»), а не в пустой результат.
  3. Регрессионный тест покрывает оба транспорта: локальный и удалённый.

## Отличие от DP.FM.418

DP.FM.418 — сообщение об отказе защиты не различает «сама защита неисправна» и «команда отклонена по правилу»: сбой механизма выглядит как вердикт. Здесь тот же класс — сбой механизма проверки выдаётся за результат, — но с другим источником и другим видом ложного ответа: сбой транспорта к самому себе становится отрицательным результатом «объектов нет», а не блокировкой. Различение «неизвестно ≠ ложь» — DP.D.331.

## Тест обнаружения

«Проверка может быть запущена на целевом хосте и ходит к нему по сети, а пустой результат считается успехом?» Да → возможно ложное «0 объектов».

## Применимость

Любые проверки состояния и сверки, которые опрашивают хосты удалённо и могут быть запущены на одном из них.

## Связи

- DP.FM.418 — сбой защиты неотличим от её вердикта (см. «Отличие»).
- DP.D.331 — «неизвестно» (проверка не удалась) ≠ «ложь» (проверено, отсутствует).
- DP.FM.366 — проверка при нуле проверяемых объектов возвращает «всё хорошо».
