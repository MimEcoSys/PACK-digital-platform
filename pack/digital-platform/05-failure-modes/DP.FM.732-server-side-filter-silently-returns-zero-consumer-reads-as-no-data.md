# DP.FM.732 — Серверный фильтр молча возвращает ноль

## Описание

Регрессия в сервисе знаний: фильтр по источнику (`source`) перестал работать без ошибки. С 31.10 он возвращал 0 для любого значения: `docs-courses` и `PACK-digital-platform` оба пусты, тот же запрос без фильтра даёт результаты по `docs-courses`. Без фильтра и с фильтром по типу источника (`source_type`) результаты были. Ночной снимок с 31.10 четыре ночи получал пустой список, считал источник пустым и падал с «all programs empty».

## Симптом

Периодическая задача завершается с нулевым объёмом данных или падает с «пусто»; причину ищут в данных, а не в фильтре. Сбой обнаруживается через дни.

## Механизм

Сервер изменился, ошибки нет. Пустой список — штатная форма ответа, поэтому потребитель не отличает «фильтр сломан» от «по этому значению данных нет».

## Контрмера

1. Для потребителя, ожидающего ненулевой результат, ноль — тревога, а не норма.
2. Перед выводом «данных нет» — контрольные запросы: тот же запрос без фильтра и с двумя разными значениями фильтра. Без фильтра есть результаты, а оба значения дают ноль → сломан фильтр, а не данные.
3. Временный обход: сузить выборку по другому, работающему полю на сервере (здесь `source_type: guides`) и добрать точный отбор по сломанному полю на клиенте.

## Тест обнаружения

«Пустой результат фильтрованного запроса проверен контрольными запросами — без фильтра и с другим значением фильтра?» Нет → ноль от сломанного фильтра неотличим от отсутствия данных.
