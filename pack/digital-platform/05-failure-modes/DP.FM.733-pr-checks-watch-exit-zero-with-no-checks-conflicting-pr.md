# DP.FM.733 — «Нет проверок» читается как «всё прошло»

## Описание

Пока запрос №1421 висел, в основную ветку шаблона влили запрос №1418, менявший те же файлы (журнал изменений, манифест). Запрос №1421 стал конфликтным, CI не запустился, а `gh pr checks --watch` вышел с кодом 0 и сообщением «no checks reported on the branch».

## Механизм

Ожидание проверок завершается, когда незавершённых проверок не осталось. При нуле проверок это условие выполнено сразу, и код выхода 0 означает «ждать нечего», а не «всё зелёное». Конфликтный запрос CI не запускает, поэтому ноль проверок — штатная для него ситуация.

## Контрмера

Приёмка требует:
1. Ненулевое число завершённых проверок.
2. Состояние «можно слить» (`mergeable` / `mergeStateStatus`), а не только код выхода ожидания.

## Отличие от соседних случаев

- Застрявший запрос с красными проверками — проверки есть и красные; здесь их нет совсем, а ожидание показывает успех.
- DP.FM.366 и DP.FM.288 — тот же класс «пустое множество проверок даёт успех» (проверка трассы при нуле гейтов, цикл shell-гейта из нуля итераций); здесь пустое множество создаёт внешний CI из-за конфликта запроса.

## Тест обнаружения

«Приёмка запроса смотрит только на код выхода ожидания проверок?» Да → конфликтный запрос пройдёт без единой проверки.

## Связи

- DP.FM.366 — проверка трассы возвращает «ок» при нуле гейтов.
- DP.FM.288 — shell-гейт выполняет 0 итераций и выходит с кодом 0.
