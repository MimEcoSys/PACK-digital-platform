# DP.FM.738 — Якорь `/X/` в .gitignore не ловит ссылку на месте каталога

## Симптом

Корневой репозиторий рабочего пространства внезапно «грязный»: `git status` показывает один неотслеживаемый путь с именем бывшего вложенного репозитория. Перемотка корня по ff-only отказывает из-за грязного дерева. Слитая правка не доходит до хоста, явной ошибки в самой правке нет.

## Механизм

1. Вложенные репозитории в корне игнорировались якорями вида `/X/`.
2. В gitignore косая черта на конце означает «совпадать только с каталогом». Файл, символическая ссылка или другой не-каталог с тем же именем под шаблон не попадает.
3. Каталог `DS-ai-systems` перенесли в `DS-IT-systems`, а на старом месте оставили символическую ссылку для обратной совместимости.
4. Git хранит ссылку как отдельный объект и в каталог не переходит. Для git это неотслеживаемый файл, который якорь `/DS-ai-systems/` не покрывает.
5. Проверка «корень чистый» перед перемоткой (`canon-refresh.sh`, ff-only) видит неотслеживаемый файл и останавливается. Тихий дрейф: копия перестаёт обновляться, хотя никто ничего в ней не правил.

## Антипаттерн → Паттерн

- **Антипаттерн:** игнорировать «место» в дереве шаблоном с косой чертой на конце, когда на этом месте может оказаться не только каталог (ссылка после переноса, файл-заглушка, точка монтирования, отображённая как ссылка).
- **Паттерн:** якорь без косой черты на конце (`/X`): совпадает и с каталогом, и со ссылкой, и с файлом, но остаётся привязан к корню. Косую черту на конце оставлять только там, где одноимённый не-каталог действительно должен оставаться видимым.

## Тест обнаружения

«Если заменить каталог из списка игнора символической ссылкой с тем же именем, останется ли `git status --porcelain` пустым?» Смоук для всего набора якорей: для каждого якоря создать во временном репозитории сначала каталог, затем ссылку и проверить `git check-ignore`. Плюс статическая проверка: запрет косой черты на конце у якорей корня (если нет явного исключения).

## Противодействие

- Перевести якоря в форму `/X` (в исходном случае — 54 якоря).
- Добавить смоук «каталог и ссылка» и статический запрет `/X/` в корневом `.gitignore`.
- При переносе вложенного репозитория с оставлением ссылки проверить корень на `git status` до публикации переноса.

## Границы

Относится к любому репозиторию, который игнорирует вложенные репозитории, сборочные каталоги или монтирования по имени. Не о неполном наборе шаблонов для разных форм имени (это DP.FM.211, ось «имя файла») — здесь ось «тип объекта на том же пути». Не о собственных gitignore-артефактах конвейера, ошибочно принятых за грязь (DP.FM.448): здесь объект действительно не игнорируется.

## Связи

- DP.FM.211 — смежный класс «шаблон .gitignore не покрывает форму»: там вариант имени (`*.env` против `.env.*`), здесь тип объекта (каталог против ссылки).
- DP.FM.448 — гейт чистоты корня: тот же потребитель («дерево чистое?»), другая причина ложной грязи.
- DP.FM.152 — изменение .gitignore без учёта уже отслеживаемых путей: соседняя ошибка правки игнора.
