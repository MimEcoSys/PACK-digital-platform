# DP.FM.740 — Нормализация пути до проверки прячет символическую ссылку

## Случай

На одном хосте выходной файл генератора оказался символической ссылкой в чужой клон репозитория. Прогон по умолчанию писал туда и загрязнял чужую рабочую копию. Добавили защиту: генератор отказывает до любой записи (код 3), если путь проходит через ссылку; режим проверки только предупреждает. Первая версия защиты нормализовала путь, и ревью нашло в ней критическую дыру с `..`.

## Механизм

`normpath("out/link/../x")` даёт `out/x` чисто текстово, не заглядывая в файловую систему. Ссылка `link` из пути исчезает, и проверка «нет ли ссылки среди префиксов» её не видит. Операционная система при записи разрешает путь по компонентам: сначала идёт по `link`, потом поднимается на `..` уже **внутри цели ссылки**. Поэтому запись попадает не туда, куда показала проверка.

## Противодействие

1. Префиксы строить из **сырых компонентов** исходного пути, без `normpath`, и для каждого проверять `is_symlink()`. Компонент `..` после ссылки не должен её стирать.
2. Условие «путь лежит ниже HOME» (не трогать каталоги вне дома) проверять по `realpath` обеих сторон. Иначе псевдоним домашнего каталога (`/home` против `/Users`, ссылка на дом) или различие регистра на нечувствительной к регистру ФС macOS скрывает ссылку или ложно выводит путь за пределы дома.
3. Отказ — до любой записи и с отдельным кодом выхода. Обход — только явным аварийным флагом, не умолчанием.

## Отличие от соседей

Три карточки — три разных ошибки канонизации путей:
- AS.FM.155 — пути сравниваются строкой **без** канонизации, и ссылка обходит проверку.
- AS.FM.160 — `resolve()` сравнивается с литеральным путём того же объекта, и проверка ложно срабатывает под ссылкой-предком.
- Здесь — **текстовая** нормализация до проверки стирает ссылку из пути.

Общий вывод: какая канонизация уместна, зависит от вопроса. На «есть ли ссылка в пути» отвечают сырые компоненты, на «где цель на самом деле» — realpath. Текстовую нормализацию нельзя ставить ни на одно из этих мест.

## Тест (триггер распознавания)

Защита пути вызывает `normpath`, `os.path.abspath` или аналогичное текстовое схлопывание `..` до проверки на ссылки? Пропускает ли она путь `<каталог>/<ссылка>/../<файл>`? Если да, ссылку можно спрятать.

## Границы

Проверка префиксов не закрывает подмену каталога между проверкой и записью (TOCTOU, DP.FM.493) и жёсткие ссылки. Для них нужна запись с `O_NOFOLLOW` или проверка открытого дескриптора (AS.M.130).
