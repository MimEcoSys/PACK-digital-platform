# DP.FM.743 — `cd` в подстановке при CDPATH: две строки вместо пути

## Симптом

Идиома `checkout="$(cd -- "$checkout" && pwd -L)"` возвращает несколько строк вместо одного пути либо находит одноимённый каталог вне ожидаемого места. При неудачном переходе сообщение может потерять исходный аргумент.

## Механизм

Если относительная цель найдена через непустой элемент CDPATH, команда cd может вывести найденный каталог в stdout. Подстановка захватывает и этот вывод, и вывод pwd. Само наличие экспортированной переменной ещё не доказывает такой эффект: существенны её значение и способ разрешения аргумента.

В конструкции `checkout="$(...)" || ...` результат присваивается до обработки отказа. Если подстановка не дала пути, сообщение с `$checkout` уже не показывает прежнее запрошенное значение.

## Противодействие

```bash
requested="$checkout"
checkout="$(CDPATH= cd -- "$requested" 2>/dev/null && pwd -L)" \
  || { echo "audit: checkout not found: $requested" >&2; return 1; }
```

CDPATH отключается только для перехода, результат которого должен содержать один путь. Исходный аргумент хранится отдельно и используется в диагностике. Выбор логического или физического пути задаётся контрактом вызывающего кода; эта правка сама его не меняет.

## Проверка

Сравнить разрешение относительного пути с пустым CDPATH и с непустым каталогом поиска, содержащим одноимённую цель. Результат функции должен соответствовать её контракту и занимать одну строку. Для отсутствующего каталога ошибка должна назвать исходный аргумент.
