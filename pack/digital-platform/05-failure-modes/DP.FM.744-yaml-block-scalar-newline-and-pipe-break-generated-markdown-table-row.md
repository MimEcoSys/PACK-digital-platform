# DP.FM.744 — Значение из YAML вставлено в строку markdown-таблицы как есть: перевод строки рвёт строку, `|` делит ячейку

## Симптом

Значение из frontmatter вставлено в markdown-таблицу как готовый текст. Перевод строки обрывает строку таблицы, а неэкранированная вертикальная черта разделяет ячейки. Остальные строки могут оставаться корректными, и генератор не сообщает об ошибке.

## Механизм

Блочные YAML-скаляры `>` и `|` при обычном режиме обработки конца блока сохраняют завершающий перевод строки; буквальный блок сохраняет также внутренние переносы. Это не свойство всех YAML-значений и не безусловное свойство блоков: модификатор `-` меняет обработку конца. Кавычечное значение тоже может содержать перевод строки, например через escape-последовательность в двойных кавычках.

Поэтому проверять нужно фактическое значение после разбора YAML, а не только выбранную автором форму записи. Целевой синтаксис ячейки требует собственного преобразования.

## Противодействие

Каждое произвольное текстовое поле сериализуется по правилам целевой ячейки. Для краткого однострочного описания допустимо схлопнуть пробельные символы и экранировать разделители. Если переносы несут смысл, способ представления задаётся явно, вместо прямой вставки сырого перевода строки.

В источнике применён следующий узкий приём:

```python
def _cell(value):
    return " ".join(str(value).split()).replace("|", "\\|")
```

Он применяется к name и summary в карте и индексе. Это иллюстрация исправления конкретного генератора, не универсальный сериализатор произвольной разметки. Обратные слеши, уже экранированные разделители и встроенный markdown требуют отдельных проверок выбранного формата.

## Проверка

Фикстуры содержат свёрнутый и буквальный блоки, кавычечное значение с переводом строки, вертикальную черту и обратный слеш перед разделителем. Каждая запись даёт ожидаемое число строк и ячеек, а смысл содержимого сохраняется в пределах контракта колонки. Проверять все произвольные текстовые колонки, не только первоначально сломанную.

## Отличие от соседей

DP.FM.348 описывает интерпретацию текста в шаблоне замены регулярного выражения. DP.FM.362 — неверное распознавание структуры таблицы при чтении. DP.FM.551 — разбор окончаний строк. Здесь отказ возникает при сериализации значения в другой синтаксис.

DP.FM.018 описывает чтение оформленной markdown-ячейки как исходных данных: маркеры представления попадают в дальнейшую обработку. Здесь направление обратное — исходное значение записывается в ячейку без преобразования и меняет структуру таблицы. Удаление display-маркеров при чтении не заменяет экранирования разделителей и обработки переносов при записи.
