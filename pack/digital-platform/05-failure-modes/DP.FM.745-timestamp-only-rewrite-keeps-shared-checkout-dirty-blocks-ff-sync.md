# DP.FM.745 — Перезапись ради одной метки времени держит общую копию «грязной»

## Симптом

Генератор меняет отслеживаемый файл на каждом прогоне, хотя содержательная таблица не меняется. Отличается только служебное время генерации. Строгая синхронизация общей рабочей копии отказывает из-за этого незакоммиченного изменения.

## Механизм

Если время прогона включено в сравниваемый результат, байты результата различаются даже при стабильных входных данных. Генератор считает это основанием записи, а защита общей копии видит обычное изменение файла и не может проигнорировать его по происхождению.

Источник DS-my-strategy `a8ed64af08` описывает такой случай для `security-coverage-sync.sh`. Сообщение коммита сообщает об отставании на шесть коммитов; эта историческая величина заново не измерялась.

## Противодействие

1. Сравнить содержательное состояние старого и нового результата, исключая только определённое контрактом служебное поле времени.
2. Если содержимое не изменилось, не переписывать отслеживаемый файл. Результат прогона «проверено, изменений нет» сохранять отдельно.
3. Не исключать произвольные даты из данных: маска не должна скрывать настоящее изменение таблицы.

В прочитанном исправлении регулярное выражение маскирует все даты одного формата внутри генерируемого региона. Ограничение маски точно определённым полем — рекомендация этой карточки; её внедрение указанным коммитом не утверждается.

## Значение отметки времени

После пропуска неизменного результата время внутри файла может показывать последнее изменение содержимого, а не последний успешный обход. Эти вопросы требуют разных свидетельств. Проверку работоспособности генератора не следует связывать только с изменением отслеживаемого файла. См. DP.FM.725.

## Проверка

Дважды запустить генератор на неизменных данных: второй прогон не меняет отслеживаемые байты, но оставляет предусмотренное свидетельство проверки. Затем изменить содержательное поле, в том числе дату в данных, если такая колонка допустима: изменение должно быть видно.

## Отличие от соседей

DP.FM.585/DP.M.515 описывают накопление дописываемых данных и их публикацию. DP.FM.556 — неоднозначность чужой и автоматической правки. Здесь саму запись можно не выполнять, поскольку содержимое не изменилось. DP.FM.725 описывает обратный риск: после пропуска нельзя терять свидетельство проверки.
