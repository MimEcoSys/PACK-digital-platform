# DP.FM.750 — Классификатор по ключевым словам вырождается в класс по умолчанию без ошибок

## Симптом

Черновой автоматический разбор 718 строк учёта изменений (WP-611 Ф21) размечал «вид» изменения по ключевым словам. 689 строк ушли в класс по умолчанию «фича», класс «улучшение» не сработал ни разу. В ручной выборке пилота улучшения при этом были. Классификатор отработал без ошибок и выдал метку каждой строке, поэтому результат выглядел готовым к использованию.

## Механизм

1. Правило вида «есть слово из списка → класс X, иначе → класс по умолчанию» всегда возвращает метку. Отказа нет даже тогда, когда ни одно правило не сработало.
2. Если словарь правил не совпадает со словами реальных записей, почти все строки проваливаются в ветку «иначе».
3. Итог неотличим от правдоподобной разметки, пока не посмотреть на распределение: огромная доля одного класса и пустые классы.
4. Решение, построенное на таких числах (сколько фич, сколько улучшений), было бы основано на артефакте словаря, а не на данных.

## Диагностика

До использования результатов:

1. Построить распределение по классам. Насторожиться, если доля класса по умолчанию доминирует или хотя бы один класс пуст, хотя он заведомо встречается в данных.
2. Сверить автоматическую разметку с небольшой ручной выборкой (в источнике 9 строк пилота). Расхождение в классе, который ручная выборка точно содержит, означает вырождение классификатора.
3. Отдельно оценить каждое измерение разметки. В источнике разметка «компонента» по структурному полю «Где» выдержала сверку, а разметка «вида» по словам — нет.

## Лечение

- Не публиковать и не использовать числа вырожденной разметки. В источнике пилот остановил работу до решения о способе разметки.
- Предпочитать структурное поле (колонку, путь, тег), если оно есть, словам из свободного текста.
- Если нужна разметка по смыслу, выбрать ручную разметку, построчную разметку агентами со сверкой или уточнённые правила. Каждый из этих способов проверять той же диагностикой.

## Границы

- Наблюдение одно (WP-611 Ф21). Пороги «доминирующей» доли не установлены.
- Карточка не про качество отдельного правила: промах конкретной формы слова описан в DP.FM.562. Здесь речь о проверке выхода классификатора целиком.

- DP.FM.366 — смежный класс: проверка, которой нечего было проверять, возвращает «ок».
- DP.FM.413 — классификатор исходов смешивает разные исходы в один.
