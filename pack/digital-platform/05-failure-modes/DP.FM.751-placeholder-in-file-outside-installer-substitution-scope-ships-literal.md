# DP.FM.751 — Метка подстановки вне области установщика доходит до пользователя литералом

## Симптом

Новый навык `/onboarding` ссылался на свой основной текст путём `{{IWE_TEMPLATE}}/docs/...`. У автора в шаблоне путь выглядел корректно. У любого пользователя после установки путь остался бы как есть, `{{IWE_TEMPLATE}}/docs/...`, и навык не нашёл бы файл. Ошибки установки при этом нет. Та же неподставленная метка нашлась ещё в двух навыках шаблона (стратегическая сессия, закрытие недели).

## Механизм

1. Шаблон использует единый синтаксис меток `{{X}}` во многих файлах.
2. Установщик (`setup.sh`) подставляет значения только в явно перечисленные файлы: CLAUDE.md и AGENTS.md. Навыки копируются `cp -r` без обработки.
3. Множество «файлы, где стоят метки» шире множества «файлы, которые обрабатывает установщик». Метки в разнице доходят до пользователя литералами.
4. Автор не видит отказа: в шаблоне метка выглядит намеренной, а у него самого путь может разрешаться по другой причине.

Отличие от DP.FM.187: там сырой шаблон запускают без инстанциации. Здесь инстанциация выполнена, но её область не покрывает все файлы с метками. Guard на `{{` из DP.FM.187 к навыку не применим: SKILL.md читает модель, а не shell.

## Диагностика

Перечислить все файлы шаблона, содержащие метки (`grep -rl '{{[A-Z_]*}}'`), и сверить со списком файлов, которые обрабатывают установщик и механизм обновления. Любой файл из первого списка, отсутствующий во втором, — дефект.

## Лечение

- Не использовать метки в файлах, которые копируются без обработки. В навыке находить нужный файл самому: перебрать известные места или взять запасной путь через переменную окружения. Синтаксис запасного пути — см. DP.FM.752.
- Либо расширить область подстановки установщика и обновления на этот класс файлов, и только вместе с проверкой из «Диагностики».
- Проверку «метки ⊆ область подстановки» запускать до выпуска шаблона, а не после жалобы пользователя.

## Границы

- Источник один (FMT-exocortex-template, три навыка). При применении 12.11.2026 механизм подтверждён по `setup.sh`: подстановка вызывается для CLAUDE.md и AGENTS.md, а навыки копируются `cp -r`.
- Карточка про область подстановки, а не про выбор значения подстановки.

## Связи

- DP.FM.187 — сырой шаблон без инстанциации.
- DP.FM.596 — платформа подставляет аргументы в SKILL.md: обратный случай, подстановка там, где её не ждали.
- DP.FM.648 — исправление экземпляра не доходит до источника развёртываний.
- DP.FM.752 — правка этого дефекта через `${VAR:-{{X}}}` сама оказалась сломанной.
