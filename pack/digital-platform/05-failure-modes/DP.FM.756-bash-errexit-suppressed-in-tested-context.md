# DP.FM.756: set -e теряется в tested context

## Симптом
`( set -e; eval "$block" )` внутри `if ! …` — блок `false; echo survived` печатает survived и засчитывается как passed.

## Причина
Правило bash «errexit не действует на команду, чей статус проверяется» (if/while/&&/||/!) распространяется транзитивно на всё внутри — включая вложенную подоболочку с собственным `set -e` и включая через вызов функции (если сам вызов функции в tested-контексте, внутри функции errexit тоже мёртв).

## Антипаттерн → Паттерн
- **Антипаттерн:** `if ! ( set -e; eval "$block" ); then …`
- **Паттерн:** отдельный оператор: `cmd; status=$?` — затем ветвление по переменной. На каждом уровне вложенности; починка внутренней подоболочки недостаточна, если внешний вызов тоже в tested context.

## Тест обнаружения
Регресс-тест с падающей командой, за которой идёт успешная (не одна падающая команда — этот случай наивный тест пропускает).
