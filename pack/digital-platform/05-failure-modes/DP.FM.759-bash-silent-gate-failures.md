# DP.FM.759: гейт-пустышки — три bash-паттерна

Все найдены реальным запуском с трассировкой, НЕ статическим аудитом: исполнитель ~17 блокирующих проверок day-open не выполнял ни одной с момента создания, оба бага прошли ревью.

## Паттерн 1: awk `print "\x00"` не даёт NUL на macOS
BWK awk не разворачивает `\x00`; `read -r -d ''` не находит разделителей → цикл не итерируется ни разу, скрипт репортит успех.
- **Фикс:** `printf "%s%c", block, 0` внутри awk.
- **Защита:** считать реально обработанные записи и сверять с независимо посчитанным ожидаемым числом (`grep -c` по исходнику) — рассинхрон = падать громко. После любого `awk 'print "\x…"'` — проверять `xxd`.

## Паттерн 2: голое присваивание из пайпа под set -e молча убивает блок
`grep -c` при 0 совпадений печатает 0, но выходит с кодом 1 (не ошибка — «не нашёл»). Под `set -e`/`pipefail` присваивание `VAR=$(cmd)` наследует код — скрипт обрывается ДО следующей строки без сообщения. `VAR="${VAR:-0}"` следующей строкой НЕ помогает (обрыв выше). `|| echo 0` задваивает вывод (`"0\n0"`).
- **Единственный полный фикс:** `VAR=$(cmd_pipeline || true)`.
- **Охват:** grep по `=$(` в скриптах с set -e, где «ноль найдено» — штатный исход.

## Паттерн 3: (cmd >file) & wait; cat file — теряет exit-код
Код возврата функции — код `cat`, не обёрнутой команды: `if ! wrapper …` проверяет успех cat.
- **Фикс:** маркер в stdout: `OUT=$(run bash -c "real_cmd && echo ok"); [ "$OUT" = ok ] || …` — и таймаут, и провал дают пустой OUT одинаково.
