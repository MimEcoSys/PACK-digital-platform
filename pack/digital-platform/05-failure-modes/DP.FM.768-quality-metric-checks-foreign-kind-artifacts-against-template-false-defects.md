# DP.FM.768 — Проверка качества сверяет артефакты другого рода с чужим шаблоном

## Симптом

Метрика доли брака резко выше ожидаемой, при этом ручной разбор «дефектов» не находит. В случае-источнике счётчик качества закрытий в утренней сводке 06.11 показал 12 «дефектных» из 24, настоящих было 0.

## Механизм

1. Проверка выбирает объекты по признаку, который шире рода, для которого написан шаблон. В источнике это «папка сессии», а шаблон описывает закрывающую запись.
2. В множество попадают объекты другого рода (отчёты `report.md` пир-сессий). У них своё законное устройство, и шаблону закрывающей записи они не соответствуют.
3. Каждый такой объект засчитывается как брак. Доля брака отражает состав множества, а не качество.

## Почему опасен

Сплошной ложный брак обесценивает метрику: настоящий дефект теряется на фоне шума, а чинить начинают объекты, которые исправны.

## Лечение

1. Отбирать объекты по признаку рода, а не по месту хранения. В источнике папка пир-сессии засчитывается, только если для неё нет закрывающего файла.
2. Распознавать все законные формы объекта нужного рода. В источнике три формы имени закрывающей записи: Claude, Kimi, сторож.
3. После починки сверить метрику на реальных днях. В источнике получилось 0/56, 0/42 и 2/14.

## Тест обнаружения

«Все ли объекты, которые проверка сверяет с шаблоном, принадлежат роду, для которого шаблон написан?» Если нет, доля брака измеряет смесь родов. Быстрая проба: разобрать вручную несколько «дефектных» объектов и проверить, того ли они рода.
