# DP.FM.769 — Свой PR по одному имени ветки: PR из форка попадает в выборку

## Симптом

Бот по расписанию обновляет или закрывает «свой» открытый PR. Если в публичном репозитории есть PR из форка с тем же именем ветки, он попадает под выборку, и бот может перезаписать его заголовок или описание либо закрыть его как устаревший. Ошибок при этом нет: выборка вернула один PR, и бот считает его своим. Сбой не наблюдался: дефект нашла независимая проверка до того, как он проявился.

## Механизм

1. Бот открывает PR из ветки с постоянным именем (например, `bot/update-terms`) и при следующем запуске ищет его фильтром по головной ветке.
2. Фильтр по головной ветке сравнивает только имя ветки. Владелец головного репозитория в него не входит, и PR из форков с тем же именем ветки тоже подходят.
3. В публичном репозитории ветку с таким именем может создать любой форк: случайно (форк скопировал ветку бота) или намеренно.
4. Бот берёт первый найденный PR и выполняет над ним свои действия. Права бота в базовом репозитории позволяют закрыть и чужой PR.

Прецедент: ежедневный поставщик терминов перевода в FMT-exocortex-template. Нашла независимая проверка уже слитого кода (высокое замечание); ревью до слияния этого не заметило.

## Противодействие

- Свой PR отбирать по паре (владелец головного репозитория, ветка) и проверять владельца в ответе API, а не только в запросе: если среди результатов есть PR с другим `headRepositoryOwner`, отбросить его.
- Если найдено больше одного своего PR, не выбирать первый, а остановиться с понятной ошибкой.
- Тот же принцип для любой автоматики, которая ищет «своё» по имени: ветки, метки, комментарии бота. Ключ включает признак, который чужой участник не может повторить.
