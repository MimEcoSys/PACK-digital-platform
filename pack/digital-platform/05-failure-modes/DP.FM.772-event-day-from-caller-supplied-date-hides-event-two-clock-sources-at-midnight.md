# DP.FM.772 — Сутки события из переданной даты

## Симптом

1. Запись помечена чужой датой → событие (например, восстановление цикла) не попадает в вердикт нужных суток.
2. Честная запись около полуночи: два источника времени дают разные сутки → обнуляются двое суток.

## Механизм

Вердикт суток читает журнал по полю «сутки». Если это поле приходит параметром от вызывающего или вычисляется из двух независимых часов, сутки записи перестают зависеть от момента, когда запись реально сделана.

## Лечение

- Сутки определяются **одним** временем — временем записи по часам записывающего; время журнала — только запасное.
- Расхождение источников времени больше порога (в источнике 300 с) — запись считается испорченной.
- Период журнала при вердикте — ±1 сутки от суток записи.

## Отличие от соседей

- DP.FM.566 — два штампа времени с разной семантикой в одной строке.
- DP.FM.380 — журнал в UTC против локального времени у полуночи.
- DP.FM.673 — дата журнала дня бралась из имени файла сессии, и события ложились в чужой день: тот же класс «сутки записи из внешнего источника», но механизм — эвристика без границы, а не подстановка вызывающим.
- DP.METHOD.097 — граница, а не противоречие: генератор вывода за период принимает дату явно параметром; запись о событии «сейчас» получает сутки по часам записывающего.
- Здесь механизм иной: сутки задаёт тот, кто вызывает запись (подставленная дата), и это позволяет спрятать событие от вердикта.
