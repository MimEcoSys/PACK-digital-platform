# DP.FM.776 — Проверка по эквивалентности патча считает любой пустой коммит опубликованным

## Симптом

Уборщик рабочих копий снимает каталог, если все его коммиты уже на origin. Проверка (`unpublished_commits` в `scripts/ds-publish-gc.py`) сравнивает коммиты по эквивалентности патча. Среди 36 помеченных к снятию копий нашлись пять пустых маркеров начала закрытия месяца и недели. Два из них не достижимы ни из одной ветки: снятие копии убрало бы последнюю ссылку на них.

## Механизм

1. Эквивалентность патча проверяется по нормализованному диффу коммита. У пустого коммита диффа нет, и отличить один пустой коммит от другого такая проверка не может.
2. `git cherry` (и `--cherry-pick`, `--cherry-mark`) помечает локальный коммит «-» (эквивалент уже есть в апстриме), если в отрезке апстрима нашёлся эквивалентный коммит.
3. Наблюдаемое поведение: локальный пустой маркер получает «-», если в отрезке origin есть любой другой пустой коммит, и «+», только если пустых там нет. Воспроизведено на временном репозитории 09.11 и повторно 17.11 (при разборе кандидата).
4. Проверка отвечает на вопрос «есть ли такое же изменение», а для пустого коммита это совпадение «пусто = пусто». Сам маркер ценен своим SHA и сообщением, а не изменением, и такая проверка его не сравнивает.

## Диагностика

- В проверке «опубликован ли коммит» по эквивалентности патча выделить пустые коммиты (`git diff-tree --quiet <sha>` или пустой список файлов) и посмотреть, как они классифицируются.
- Перед уборкой перечислить коммиты копии, недостижимые ни из одной ветки, и сверить их с ответом проверки.

## Лечение

Варианты; выбор в исходном случае ждал слова пилота:

- исключать пустые коммиты из ответа «опубликован по эквивалентности патча» и проверять их по SHA (достижимость из origin);
- считать коммит опубликованным по эквивалентности патча только при непустом наборе файлов;
- до снятия копии закреплять недостижимые маркеры ссылкой. В исходном случае два маркера сохранены как `refs/rescue/…` по слову пилота.

Закреплять заранее особенно важно перед ручной чисткой хранилища: она удаляет недостижимые объекты сразу. В том же случае автоматическая чистка стояла с 30.09 из-за застрявшего `gc.pid.lock`, накопилось около 87 тыс. россыпных объектов.

## Границы

- В исходном случае срочности не было: маркер читается из локального HEAD, а итог закрытия публикуется отдельным коммитом (`--exact-commit`). Потеря маркера ломает историю и последующие проверки, а не текущую публикацию.
- Применимо к любому ответу «уже в апстриме?» по эквивалентности патча, не только к уборщику.
