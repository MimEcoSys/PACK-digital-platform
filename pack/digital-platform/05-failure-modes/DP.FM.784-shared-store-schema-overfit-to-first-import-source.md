# DP.FM.784 — Схема общего хранилища переобучена на первый источник

## Симптом

Общее хранилище для многих источников (библиотека методов любых авторов) принимает записи только одного источника. Запись другого автора не проходит проверку схемы.

## Механизм

1. Агенту поставили узкую задачу: перенести один свод.
2. Строгость, удобная для ловли ошибок этого импорта, легла в общую схему: автор — константа, префикс одного свода, одна лицензия, один вид записи, обязательная дословность и хеш источника, связи между записями запрещены.
3. Генератор, валидатор и программа чтения настроены так же. Правка одной схемы ничего не чинит: каждая программа отвергает чужие записи по-своему.

## Лечение

1. Развести виды записи: «выдержка из источника» (дословность, хеш, автор источника) и «карточка» (описание со своими автором и лицензией).
2. Атрибуты, зависящие от источника (автор, префикс, лицензия), — данные записи, а не константы схемы.
3. Строгие проверки импорта привязать к виду «выдержка», а не ко всей схеме.
4. При правке пройти всю цепочку: генератор, валидатор, чтение.

## Диагностика

Есть ли в схеме перечисление из одного значения для поля, которое по смыслу хранилища должно различаться между источниками? Пройдёт ли запись второго источника через генератор, валидатор и чтение?

## Границы

Один случай (PR #2 библиотеки методов, РП-581). Доверие низкое до второго случая.
