# DP.FM.789 — Неэкспортированная переменная теряется при переносе функции в дочерний процесс

## Симптом

После перевода отправки тревог на отдельную программу (`iwe-notify`) тревоги перестали приходить у тех, чей токен читался из `~/.config/aist/env`. Ошибки не было: дочерний процесс просто не видел учётных данных.

## Механизм

- `load_aist_credentials` присваивала `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` как обычные переменные shell, без `export`.
- Пока отправка была **функцией** в том же shell, она эти переменные видела.
- Когда отправку вынесли в **дочерний процесс**, переменные перестали до неё доходить. Работало только у тех, кто уже экспортировал переменную раньше.
- Смоук не поймал регрессию: он сам экспортировал переменную (пустую), то есть проверял не тот путь, по которому значение приходит в бою.

## Тест обнаружения

1. «Функцию, читающую переменные окружения, превращают в отдельный процесс?» Тогда нужно проверить, что каждая нужная переменная экспортирована или передаётся явно.
2. «Смоук задаёт ту же переменную, которую должен доставить проверяемый путь?» Если да, тест не проверяет доставку.

## Противодействие

- Передавать значения дочернему процессу **явно** (`VAR="$VAR" child …`) или экспортировать их в месте загрузки.
- В смоуке **снимать (`unset`) все альтернативные источники** значения: переменные учётных данных, шлюза и т. п. Остаётся только проверяемый источник (env-файл). Запускать проверяемую программу из копии, как в боевой раскладке.
- Проверка теста: со старой (сломанной) версией смоук должен быть красным.
