# DP.FM.792 — Отказ без ожидания на замке очереди морит периодического читателя

## Симптом

Доставка моста плана не запускалась 56 минут, хотя служба работала и записи принимались. Ошибок не было: каждый проход читателя завершался штатным «замок занят».

## Механизм

Очередь охраняет один замок. Писатели и читатель брали его без ожидания. Для писателя это верно: отказ означает «ничего не записано», и клиент повторяет. Периодический читатель (`deliver_once`, `--status`) приходит раз в проход. При ровном потоке записей замок почти всегда кем-то занят, и шанс читателя попасть в свободный момент мал. Каждый проход заканчивается отказом, и читатель не получает замок никогда — голодание.

Нашёл это нагрузочный стенд с двух хостов (отдельный пользователь systemd, своя очередь, локальный bare-origin; живая служба не затрагивалась).

## Почему опасно

Одна политика замка для всех ролей выглядит единообразной и безопасной. Писатели под нагрузкой здоровы, так что отказ виден только по отсутствию результата у читателя. Голодание не даёт ошибки и проявляется только при ровной нагрузке, а не на ручной проверке.

## Лечение

Из источника (коммит 054fa202aa; та же правка в установленной копии — 822d8fc в iwe-server-config):

- Писатели оставлены на отказе без ожидания.
- Периодический читатель ждёт замок ограниченно: до `READ_LOCK_WAIT_SECONDS = 10` с.
- Сервер ждёт замок записи с таймаутом короче таймаута производителя и отвечает `StreamBusy` («занято, ничего не записано»). Клиент получает определённый ответ, а не обрыв с вопросом «записалось ли».

Переносимое правило — политика ожидания по роли:

| Роль | Ожидание замка | Почему |
|---|---|---|
| Писатель с повтором | без ожидания | отказ = «ничего не записано», повтор дешёв |
| Периодический читатель | ограниченное | иначе при постоянной записи голодает |
| Сервер за клиентом с таймаутом | короче таймаута клиента | «занято» должно прийти раньше обрыва, иначе исход неизвестен |

## Тест обнаружения

«Для каждой роли у замка: что будет с ней при непрерывном потоке остальных ролей?» Роль без повтора и без ожидания — кандидат на голодание.

«Что дольше: ожидание замка на сервере или таймаут клиента?» Сервер дольше — клиент получает обрыв, а не «занято», и не знает, записано ли.
