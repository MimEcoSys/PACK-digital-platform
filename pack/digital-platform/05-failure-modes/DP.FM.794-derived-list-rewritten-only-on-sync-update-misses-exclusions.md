# DP.FM.794 — Производный список не узнаёт об исключениях

## Симптом

При исключении очередного файла (week-review.md) из доставки автор→шаблон нашёлся след прошлого исключения: strategy-session.md, снятый с доставки 03.11, до 09.11 оставался в CI-списке шаблона `.github/author-sourced-paths.txt`. По этому списку работает проверка CI (DP.M.599), то есть для файла, снятого с доставки, она продолжала бы требовать ссылку на авторский источник.

## Механизм

Список строит синхронизатор шаблона (`write_author_sourced_list` в DS-ai-systems `setup/scripts/template-sync.sh`). Вызов стоит внутри ветки коммита: только при `UPDATED > 0` и только если не задан `NO_COMMIT=1`. Исключение файла из доставки само не обновляет ни одного файла шаблона. Поэтому прогон, следующий за исключением, может не дойти до перезаписи списка, и производное расходится с источником.

Рядом нашлось второе расхождение того же рода: `sync-manifest.yaml` расходился с исполняемым перечнем; его привели в соответствие в DS-ai-systems #38.

## Состояние на 18.11.2026

Код синхронизатора прежний: в DS-ai-systems на origin/main `d779418` вызов `write_author_sourced_list` по-прежнему стоит только под `UPDATED > 0` и не при `NO_COMMIT=1`. Сам список исправили ручным PR в шаблон (FMT #1501). Следующее исключение снова потребует парного PR, пока код не изменён.

## Почему опасно

Производное выглядит самообновляемым («список строит синхронизатор»), поэтому его не сверяют. Расхождение не даёт ошибки: старый путь в списке молча продолжает влиять на проверку, а отсутствие нового — молча её ослабляет.

## Лечение

- Пересобирать производное из источника на каждом прогоне, независимо от того, обновил ли прогон файлы, или сверять производное с источником и падать при расхождении.
- Пока код не изменён: каждое исключение файла из доставки сопровождать парным PR в шаблон, который правит список.

## Тест обнаружения

«При каком условии переписывается это производное? Есть ли изменение источника, которое не выполняет это условие?» Исключение, переименование или удаление без обновления файлов — типичные кандидаты.

## Связи

- DP.M.599 — проверка CI, которая читает этот список; её шаг 1 («список строит синхронизатор») опирается на то, что список не отстаёт.
- DP.M.608 — сведение авторской копии с шаблоном; исключение файла из доставки меняет набор, по которому строится список.
