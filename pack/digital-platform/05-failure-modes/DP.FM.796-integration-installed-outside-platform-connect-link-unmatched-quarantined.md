# DP.FM.796 — Установка интеграции мимо ссылки подключения

## Описание

Бот прислал сигнал «новая установка GitHub» от живого пользователя. Человек поставил приложение прямо на GitHub, а не через «подключи GitHub» в клиенте платформы. Это было его первое подключение: аккаунта с его идентификатором GitHub в базе платформы не было, сопоставлять установку было не с чем.

## Причина

Платформа сопоставляет событие установки с аккаунтом автоматически, по идентификатору пользователя GitHub (`github_user_id`). Этот идентификатор платформа узнаёт и записывает в потоке подключения, который начат по её ссылке. Если человек впервые ставит приложение мимо ссылки, записи с его идентификатором нет:

1. сопоставление не находит аккаунта;
2. событие уходит в карантин установок-сирот (`orphaned_installation_events`) и дежурному приходит оповещение;
3. исправление для человека — переподключение по ссылке платформы.

Ручная корреляция конкретной записи из карантина (кто владелец установки, есть ли у него незавершённое подключение) — операция дежурного, а не автоматики и не агента. Автоматическое «усыновление» установки фоновой сверкой не реализовано: оно требует проверки безопасности до реализации.

## Почему не ручная привязка

Привязать установку к аккаунту правкой базы технически просто, но это путь в обход проверки, кто именно ставил приложение. Поэтому ручную привязку не делают, в том числе для организаций; для живого пользователя лечение — переподключение по ссылке, а не правка базы. Обсуждавшееся автоматическое усыновление допускалось только для личных аккаунтов при точном совпадении идентификатора GitHub; для организаций оно запрещено из-за риска угона установки по угаданному имени репозитория.

## Симптомы

- Оповещение «установка не сопоставилась ни с одним пользователем» и запись в карантине установок-сирот.
- Человек видит приложение установленным, а платформа его доступов не видит.

## Тест обнаружения

«Что делает платформа с событием установки, которое не сопоставилось ни с одним аккаунтом?» Нужен ответ из трёх частей: куда уходит событие (карантин), кто узнаёт (оповещение дежурному), как человек возвращается в штатный путь (переподключение по ссылке). Если события без пары молча отбрасываются или читаются только вручную по случайности, установки-сироты будут выглядеть как сбой.

## Противодействие

- Держать карантин установок-сирот и оповещение о каждой записи в нём.
- Человеку: удалить установку и подключиться заново по ссылке платформы.
- Не править привязку в базе вручную; для организаций это запрещено.
- Сигнал об установке-сироте — повод связаться с человеком, а не авария.
