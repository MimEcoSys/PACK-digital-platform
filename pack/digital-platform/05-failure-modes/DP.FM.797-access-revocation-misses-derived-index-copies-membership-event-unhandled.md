# DP.FM.797 — Отзыв доступа не гасит производные копии

## Описание

Доступ к командному репозиторию проверялся при выдаче ключа: ключ выдавался заново на каждую операцию с живой проверкой у GitHub, поэтому прямое чтение и запись после отзыва отказывали сразу. Поиск работал иначе: он сверял только флаги источника в базе (knowledge-mcp, слои личного и командного поиска). Перед закрытием фазы чтение кода показало, что при исключении участника из организации эти флаги никто не снимает. Бывший участник продолжал бы находить поиском уже проиндексированные тексты без срока.

Дыра найдена чтением кода, а не наблюдением: живая проба исключения не проводилась (второго аккаунта GitHub нет).

## Причина

Флаги, по которым поиск решает, показывать ли источник, снимали только события установки (удаление установки, снятие репозитория) и отключение аккаунта на платформе. Событие исключения из организации GitHub присылает (при подписке приложения на такие события), но обработчик событий нашего сервиса (github-integration-service) его не обрабатывал. Производная копия (индекс) живёт отдельно от выдачи ключа, и её погашение зависело от событий, часть которых сервис пропускал.

## Симптомы

По коду (не наблюдались живьём):

- прямое чтение уже отказывает, а поиск продолжает возвращать тексты источника;
- проба отзыва, проверившая один путь (с обработанным событием), создаёт уверенность для всех путей. Прошлая проба снимала репозиторий из установки приложения, а не исключала участника из организации.

## Тест обнаружения

«Какие копии данных источника существуют помимо живого чтения (индекс, кэш, выдержки)? Для каждого пути потери доступа: какое событие или проверка их погасит, обрабатывает ли наш сервис это событие и за какой срок?» Путь, событие которого не обрабатывается, и без периодической сверки — дыра.

## Противодействие

Исправление (github-integration-service PR #37, коммит `6eaa228`, выложено 10.11):

- сверка доступа раз в 5 минут и сразу по событиям исключения из организации и из соавторов: ключом самого пользователя проверяется видимость каждого командного источника у GitHub;
- после двух подряд однозначных отказов (или непригодного ключа) привязка снимается, источник выключается, его проиндексированные тексты удаляются; временные сбои ничего не меняют.

Переносимое требование: доступ, включая производные копии, гаснет в пределах срока и не зависит только от доставки события.

Урок записи: срок без замера не писать ни как «бессрочно», ни как «не меньше 30 минут». Отсутствие пути погашения в прочитанном коде — вывод из кода, а не наблюдение; в ограничения записывают то, что измерено, а если замера не было, то прямо говорят, что его не было.

## Ограничения

- Исправление PR #37 живьём не проверено: первый проход сверки — 9 источников, снятий 0, ошибок 0. Исключение из организации проверено тестами и чтением кода.
- Срок 5 минут — настройка, а не замер. Снятие после двух отказов подряд означает до двух интервалов сверки.
- Мгновенное снятие по событию требует права организации «Members» (чтение) и подписки на события исключения в настройках приложения. Включено ли это, не проверено.
- Исключение соавтора репозитория покрыто тем же кодом, живьём не проверено.
