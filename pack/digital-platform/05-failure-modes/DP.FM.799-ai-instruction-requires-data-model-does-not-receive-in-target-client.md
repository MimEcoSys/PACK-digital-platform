# DP.FM.799 — Инструкция для ИИ требует сведений, которых модель не получает в целевом клиенте

## Механизм отказа

Автор пишет для ИИ человека инструкцию и читает её, зная систему целиком. Модель же работает только с тем, что до неё дошло в конкретном клиенте MCP: с полями ответов операций и с текстами, которые клиент ей показывает. Если требуемого сведения нет ни в ответах, ни в доставленных текстах, модель либо выдумывает его (имя автора, адрес страницы), либо отвечает «не знаю». Инструкция при этом выглядит полной.

В случае-источнике сошлись три признака:

1. **Требование без источника в ответах.** ИИ велено называть авторов метода, а карточка метода их не отдаёт.
2. **Источник есть, но до модели не доходит.** Общая атрибуция Библиотеки лежала в общем тексте сервера; по отчёту проверки и документу РП-581, claude.ai этот текст модели не показывает, поэтому образец из него ИИ получить не мог.
3. **Заготовка без значения.** Метка `{CARD_PAGE}` не работала ни для образца адреса, ни для отдельной операции (отчёт проверки, п.2). По захвату, в инструкции не было указано, как её заполнять.

## Прецедент

РП-581 Ф30, инструкция Open для ИИ человека, редакция 2 (2026-11-10, черновик до выпуска, до исправлений). Независимая проверка, не видевшая работы, нашла расхождение до выпуска; исправление вошло в коммит cca06d15d (редакция 2: атрибуция ссылкой на страницу метода, имён не угадывать). Редакция 3 (10.11, по повторному ревью Coder PR #3) сняла и ссылку: страницы метода пока нет, образец адреса до модели в claude.ai не доходит, и на вопрос «кто автор?» инструкция велит ИИ говорить, что в тестовом каталоге этих сведений пока нет, имён не угадывать и непроверенных ссылок не давать; заготовка `{CARD_PAGE}` снята; доставка текстов до модели названа зависящей от клиента и проверяется в каждом клиенте (документ «Инструкция Open для ИИ человека», раздел «Что изменилось в редакции 3»). Вечером 10.11 (коммит 02533da; в документе РП-581 помечено 11.11) этот пункт редакции 3 заменён этапом 1 версии 4: по описанию договора чтение карточки метода отдаёт авторов и лицензию, ИИ называет их по вопросу (PR #3 aisystant/method-library, коммит 02533da; PR открыт, работа сервера не проверялась). Редакция 3 при этом заменила решение пилота «называть автора по вопросу» запасным «сведений пока нет» (смежный захват 2026-11: «Отпал способ исполнить решение пилота — сохранить само решение…»); версия 4 решение восстанавливает. Урок про источник сведений остаётся.

## Тест обнаружения

Для каждого требования инструкции («назови», «дай», «сообщи», «укажи») записать источник сведения: поле какого ответа какой операции или текст, который показывает модели клиент X. Источника нет, либо он не доходит до модели хотя бы в одном целевом клиенте, — риск DP.FM.799.

## Что делать

1. Рядом с каждым требованием инструкции записать источник сведения и клиенты, в которых оно доходит до модели.
2. Для сведения без источника сначала искать способ дать источник (например, поле в ответе операции). «Сведений пока нет, не угадывать» — только временная мера: она не заменяет принятое решение о том, что ИИ должен сообщать. Источник дать нельзя — спросить принявшего решение; значение по образцу не собирать.
3. Заготовке (метке подстановки) давать правило заполнения: откуда берётся значение. Иначе модель читает её как готовое.
4. Доставку текстов до модели проверять в каждом целевом клиенте отдельно от проверки того, что сервер их отправил.

## Граница

Один случай, один документ. Дефект был в черновике до выпуска и найден проверкой текста до выпуска; поведение модели в клиенте, то есть реальная выдумка имени или адреса, не наблюдалось. Описанное состояние карточки метода относится к 10.11; в версии 4 описание договора его меняет, но работа сервера не проверялась. Утверждение «claude.ai не показывает общий текст сервера модели» взято из отчёта проверки и документа РП-581 и в этой записи не перепроверялось; на другие клиенты не распространяется.

## Связи

- DP.M.505: границу доверия закрепляют в описании инструмента как в тексте, который модель читает. Здесь то же направление: требования инструкции опираются только на то, что модель получает. Что описания доходят до модели во всех клиентах, пока не проверено: в РП-581 для этого записан отдельный пункт приёмки (документ «Инструкция Open для ИИ человека», п.1).
- DP.FM.710: клиент молча теряет поле ответа. Другой механизм, но тот же вывод: «сервер отправил» не равно «модель получила», проверять в каждом клиенте.
- DP.FM.593: жёстко заданное в инструкции имя коннектора работает не у всех пользователей.
- AS.FM.047: данные пропали на выполнении, модель подменяет тему. Здесь сведения отсутствуют по самому договору ответов или по клиенту, а дефект сидит в тексте инструкции и находится до выпуска.
- DP.M.628 (Дополнение 20.11.2026): смежный дефект той же проверки (review-01, п. 4): сведение есть в ответе сервера, но инструкция не сказала брать идентификатор для запроса дословно, без перевода.
- DP.M.635: порядок составления инструкции для ИИ к MCP-серверу; противодействие этому сбою дают этапы 3–4.
