# DP.FM.801 — Проверка `-x` молча выключает барьер, запускаемый через интерпретатор

## Механизм отказа

Перед вызовом защиты стоит условие «есть ли защита». Это форма точки подключения необязательного расширения (`DP.METHOD.184`): нет исполняемого файла, значит ничего не делать. Если защиту запускают через интерпретатор (`python3 файл.py`), бит исполнения для вызова не нужен, и git его не гарантирует. Условие проверяет свойство, не относящееся к способу вызова: оно ложно, хотя файл на месте и запустился бы. Ветка «защиты нет» выглядит законным пропуском, поэтому отказ не отличить от штатного «расширение не установлено».

## Прецедент

**10.11.2026, закрытие дня (iwe-local-config, коммит 125ff74, WP-484 Ф298, дефект 3).** В `scripts/day-close-lock.sh` быстрый локальный барьер вызывался как `python3 "$GATEWAY_LOCK_PY" acquire …`, а перед вызовом стояло:

```bash
[ -x "$GATEWAY_LOCK_PY" ] || { log "gateway-lock.py не найден — пропускаю локальный барьер"; return 0; }
```

Файл `gateway-lock.py` хранится в DS-my-strategy с режимом 100644, поэтому проверка была ложной и барьер пропускался. Пропуск не был беззвучным: в журнал уходила запись, но с ложной причиной «не найден».

**Какой барьер выключился.** Комментарий в коде называет его необязательным: «Быстрый барьер для двух процессов на ОДНОЙ машине — необязательный, gateway недоступен → просто продолжаем и полагаемся на межмашинную аренду ниже (она единственная работает между машинами)». Решающей защитой закрытия дня остаётся межмашинная аренда. Выключенным оказался только быстрый слой на одной машине; отсутствие файла и после исправления означает пропуск (`return 0`).

**Исправление (тот же коммит):**
- проверка `-x` заменена на `-f`;
- код выхода барьера, кроме 0, 1 и 2, раньше не разбирался; теперь он пишется в журнал («локальный барьер вернул rc=… — пропускаю его, дальше решает межмашинная аренда»);
- `release` освобождает и локальный барьер: раз барьер действительно работает, прерванное закрытие не должно задерживать повтор из другой беседы на время жизни замка;
- выход с кодом 3 («день уже закрывается на этой машине») подсказывает, как восстановиться: `release` из той же беседы или ожидание истечения замка;
- раздел 6 смоук-теста кладёт заглушку `gateway-lock.py` с режимом 644, которая отвечает «занято», и ждёт, что захват остановится с кодом 3.

## Тест обнаружения

«Снять бит исполнения с файла защиты, которую запускают через интерпретатор (`chmod 644`), и выполнить действие, которое она должна задержать. Сработала ли защита?» Не сработала → условие перед вызовом проверяет не то свойство. В прецеденте это делает раздел 6 смоук-теста.

## Что делать

1. Условие перед вызовом проверяет то, что нужно фактическому вызову. `-x` годится только при прямом запуске (`./файл`); для `python3 файл` бит исполнения не нужен.
2. Одной проверки `-f` для защиты, запускаемой через интерпретатор, мало (возражение Кодекса при разборе пакета 32): вызову нужны ещё читаемый файл и доступный интерпретатор, а отказ должен быть заметен. Замена на `-f` закрывает механизм этого случая, но не общий класс.
3. Каждый код выхода защиты, которому нет отдельной ветки, писать в журнал, а не приравнивать к «защиты нет».
4. Включая выключенную защиту обратно, проверить последствия её настоящей работы. В прецеденте пришлось добавить освобождение барьера в `release`.

## Граница

Один случай, один скрипт. Выключенный барьер был необязательным слоем при межмашинной аренде; случаев, когда закрытие дня прошло дважды из-за пропуска барьера, источники не называют. Обязательной защиты, отключённой так же, в источниках нет.

## Отличие от соседей

- `DP.METHOD.184` — `[ -x ]` как точка подключения необязательного расширения: законно, когда отсутствие расширения означает «ничего не делать». Здесь тот же приём стоял перед файлом, который запускают через интерпретатор, и пропускал его, хотя файл был на месте.
- `DP.FM.412` (вариант 4) и `DP.FM.431` — защита ломается, когда нет интерпретатора или утилиты. Здесь всё на месте, ложно само условие.
- `DP.FM.387` — опциональный шаг без явного `else` задаёт итоговый код выхода: там видимый ложный провал, здесь пропуск с ложной причиной в журнале.
- `DP.FM.110` — тот же `gateway-lock.py`, но другая тема: рукопожатие по сокету.
