# DP.FM.804 — Проверка дублей через поиск платформы слепа при чужом корпусе индекса

## Механизм отказа

Проверка дублей опирается на поиск, индекс которого построен не по тому корпусу, куда пишется карточка. У ответвления авторского пака поиск платформы видит авторскую базу. Отсюда две ошибки:

1. **Пустая выдача принята за «дублей нет».** Карточки, которые есть только в паке пользователя, поиск не видит.
2. **Совпавший номер принят за дубль.** Номера в авторской базе и в ответвлении ведутся независимо; карточка с тем же номером в выдаче может иметь другое содержание. Это будущая коллизия нумерации при слиянии, а не дубль.

## Прецедент

**10.11.2026, навык разбора захватов (apply-captures), шаблон IWE, issue #1514.** Описание скрипта `pack-duplicate-check.py` (строки 4–6, коммит 375338a3; сообщение коммита говорит то же своими словами): «the platform search (knowledge_search) indexes the author's Pack, not the user's fork, so an empty result there is not "no duplicates", and a hit with the same ID may be a different card».

**Исправление (коммит 375338a3, слияние PR #1519):**
- скрипт `pack-duplicate-check.py` ищет файлы пака пользователя по ключевым словам кандидата, файлы с тем же номером и, если у пака есть удалённый репозиторий `upstream`, тот же номер на авторской ветке;
- исход сверки с авторской веткой назван явно: `ok`, `no-remote`, `no-ref`, `fetch-failed`, `not-a-git-repo`; `no-ref` или `fetch-failed` после повторной попытки означает «сверка не выполнена», об этом говорят пилоту;
- скрипт только перечисляет свидетельства; решение «дубль» остаётся за человеком-валидатором;
- в навыке: ссылка `github_url` в выдаче поиска показывает, чью базу видит поиск. Если ни одна находка не ведёт в хранилище пользователя и его источник не подключён к личному поиску (`personal_list_sources` пуст), в отчёте ставится `semantic_gate: skipped (индекс ≠ Pack пользователя)`.

Тест `test_issue_1514_pack_duplicates.sh` строит ответвление, где у автора под тем же номером лежит карточка с другим содержанием.

## Тест обнаружения

«Ведут ли находки поиска в то хранилище, куда пишется карточка?» Ни одна не ведёт → индекс покрывает другой корпус, пустая выдача ничего не доказывает.

## Что делать

1. Перед выводом «дублей нет» сверить, чью базу индексирует поиск (в прецеденте по `github_url` находок).
2. Основой проверки оставить файлы своего пака; для ответвления сверить номер с авторской веткой.
3. Совпадение номера не считать дублем, пока не сверено содержание.
4. Исход «не проверено» называть явно, чтобы он не выглядел как «чисто».

## Граница

Один случай, одна настройка поиска платформы. Карточка описывает конфигурацию, в которой индекс покрывает авторскую базу (замечание Кодекса при разборе пакета 32: условие ставится на проверку того, чью базу видит индекс, а не на поиск платформы вообще). Для пака, который индексируется сам, проверка через поиск остаётся рабочей.
