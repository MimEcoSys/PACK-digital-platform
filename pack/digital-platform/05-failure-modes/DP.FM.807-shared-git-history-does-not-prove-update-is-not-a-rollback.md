# DP.FM.807 — Общая история git не доказывает, что обновление не откатывает версию

## Симптом

Обновление на более старую версию проходит как обычное: файлы установленной версии переписываются файлами старой, предупреждения об откате (запроса ROLLBACK) нет, установка остаётся в смешанном состоянии.

Симптом найден чтением кода, не наблюдён на прогоне: независимая проверка конвейера выпуска (Fable, находка №3, 10.11.2026, РП-529) прочла `detect_release_rollback` в update.sh и показала, что у клона на метке v0.41.11 возврат с 0.42 на 0.41.11 откатом не распознаётся.

## Механизм

Решение «откат или нет» было отдано родству коммитов: по правилу #963 при общей истории git версии в манифестах не сравнивались (сравнение версий оставалось только для историй без общего коммита). Но положение рабочей копии в git не совпадает с установленным состоянием: update.sh переписывает файлы в папке шаблона и не двигает её HEAD. Поэтому клон, стоящий на метке v0.41.11, может нести файлы и манифест 0.42. Родство между HEAD папки и коммитом выпуска 0.41.11 читается как «выпуск = HEAD», отката не видно, и файлы переписываются на 0.41.11.

Родство отвечает на вопрос «связаны ли коммиты». Новее ли цель того, что установлено, оно не говорит.

**Второе проявление того же механизма (по комментарию в коде, b0fdf7b1, WP-529 Ф270, RT2-4 проверки rc.2).** После первого исправления сравнение версий работало только на канале release. С установки кандидата выпуска обновление каналом main (main до слияния выпуска оставался на 0.41.11) переписывало файлы на 0.41.11 без предупреждения об откате и оставляло смешанное состояние. Был ли это живой прогон или чтение кода — не проверено.

## Противодействие

Первой решает версия: версия установленного манифеста сравнивается с версией цели.

- Версия цели строго ниже установленной → откат, на любом канале (release, rc, main).
- Иначе (версии равны, цель новее, сравнение невозможно, манифеста нет) на канале release решает родство: выпуск — строгий предок HEAD (локальные коммиты впереди выпуска, #863) → откат. На каналах main и rc родство откат не проверяет: эти каналы по устройству уходят вперёд выпуска.

Состояние кода на 20.11.2026 (origin/main шаблона, функция `detect_release_rollback`):
- 6e5a0918 (10.11, РП-529 Ф261, PR #1520): сравнение версий поставлено перед родством; тест для общей истории (test-issue-1411-update-rollback-unrelated-history.sh) переписан под новое правило — «установленный манифест новее → откат (0)», хотя выпуск впереди HEAD.
- b0fdf7b1 (11.11, РП-529 Ф270): сравнение версий вынесено перед проверкой канала и работает на любом канале; подсказка при откате называет канал, соответствующий установленному, и предупреждает, что любой канал, который вернёт установку назад, тоже спросит ROLLBACK.

Замена правила #963 в карточке РП-529 на 10.11 помечена «ждёт подтверждения пилота»; запись о подтверждении в карточке не найдена.

## Тест обнаружения

Установка с файлами и манифестом версии N, рабочая копия папки шаблона на метке более старого выпуска, обновление на версию ниже N при общей истории git (и отдельно — каналом, отличным от release). Обновление проходит без запроса ROLLBACK → этот сбой.

## Границы

- Сравнение версий возможно только для простых версий вида X.Y.Z. Если версия цели или установленная пустая, кандидатская (rc) или нечисловая, сравнение даёт «несравнимо», и на канале release снова решает родство, которое не доказывает отсутствие отката; на каналах main и rc откат в этом случае не проверяется вовсе. Остаточный риск; отдельно не проверялся.
- Карточка не о доказательстве доставки: DP.FM.550, DP.FM.489 и DP.M.498 отвечают, попал ли коммит в ветку. Здесь вопрос — направление версии установленного состояния.
- Живой прогон отката 0.42 → 0.41.11 по старому правилу в источниках не описан; механизм установлен по коду и тексту находки.
