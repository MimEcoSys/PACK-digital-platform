# DP.SOTA.038 — Mem0 vs Hindsight: спайк внешней памяти

## 1. Контекст

Спайк «нужна ли внешняя память вместо текущей векторной индексации» (WP-579). Golden-набор расширен с 24 до 147 независимо подтверждённых событий (источник `decisions/`, реальный потолок 220 кандидатов, 147 помечены «Сверено»). Прогон обоих фреймворков по трём критериям: точность топ-1/топ-5, стоимость токенов на 1000 операций, развёртываемость без серверов РФ-периметра (оба укладываются в одну переменную окружения: `MEM0_TELEMETRY=False`, `HF_HUB_OFFLINE=1`).

## 2. Числа

Mem0: 46,6% / 70,3% точность топ-1/топ-5, 11,01М токенов на 1000 операций.

## 3. Находка 1 — Mem0 никогда не замещает устаревший факт

Mem0 работает по измеренным числам, но по дизайну фреймворка никогда не замещает устаревший факт новым при конфликте — это поведенческое ограничение архитектуры, не артефакт измерения golden-набора.

## 4. Находка 2 — спурические «узловые» сущности у Hindsight

После устранения бага неограниченного фонового объединения фактов Hindsight доходит до конца набора (ранее не доходил), но итоговое ранжирование искажено отдельным, независимым от первого фикса дефектом: часто упоминаемое в данных имя (тестового банка) стало спурически «узловым» фактом по частоте совместной встречаемости, а не по содержательной центральности — итоговая цифра точности признана ненадёжной.

## 5. Статус решения

Решение «внедрять/не внедрять» внешнюю память пилотом не принято — не было задачей этого раунда спайка.

## 6. Переносимость

Граф/эмбеддинг-ориентированная память, агрегирующая факты по совместной встречаемости, может производить спурические «узловые» сущности из часто повторяющихся, но не содержательно центральных имён — отдельный источник искажения ранжирования, не устраняемый одним фиксом «неограниченного объединения». Отдельно: архитектурное решение «никогда не замещать факт» (Mem0) — ограничение дизайна, которое нужно явно знать при выборе фреймворка для доменов с часто меняющимися фактами.
