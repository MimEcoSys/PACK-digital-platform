# DP.SOTA.039 — GitHub branch protection: DELETE снимает профиль защиты целиком

## Наблюдение (ограничение платформы)

GitHub REST API не предоставляет способа точечно «временно выключить одно правило защиты ветки и включить обратно». Единственный способ временно снять защиту — `DELETE /repos/{owner}/{repo}/branches/{branch}/protection`, который удаляет ВЕСЬ профиль защиты разом: обязательное ревью, обязательные статус-проверки, запрет force-push, запрет удаления ветки и т.д. После `DELETE` эти настройки нигде не хранятся на стороне GitHub — прочитать их у API после удаления уже не у кого.

## Контрмера

Аварийная процедура должна:
1. Хранить живой JSON-снимок текущего профиля защиты в репозитории (не только в документации или памяти участника).
2. Обновлять этот снимок ТЕМ ЖЕ коммитом, который меняет защиту — иначе процедура восстановит устаревший профиль.
3. Фиксироваться заранее, «на спокойную голову», а не в момент, когда защита уже блокирует нужное действие (например, откат при `enforce_admins`).

## Открытый хвост

Дедлок identity параллельных агентских сессий при обязательном одобрении PR (кто одобряет PR правящего агента, если ревью обязательно требует человека) — не решён этой записью, зафиксирован как известный открытый вопрос.

## Переносимость

Принцип не специфичен GitHub: любой механизм «снять защиту целиком» (без точечного управления) и без серверного хранения предыдущего состояния требует заранее сохранённого снимка для восстановления. Тест: «если снять это прямо сейчас, есть ли у МЕНЯ (не у сервиса) всё необходимое, чтобы восстановить точное состояние обратно?»
