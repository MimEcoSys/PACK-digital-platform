# [DP.MAP.005] Сценарии использования IWE и платформы

> **Назначение:** одно место, где видно, что человек делает с IWE и платформой, каким средством это обеспечено (инструмент MCP, скилл, хук или скрипт, бот, сайт), в каком состоянии средство, какая работа по нему идёт и где оно будет размещено при разделении MCP и обкатке в шаблон. Срез на 31.10.2026. Составлено по закрытым карточкам рабочих продуктов (РП) и по файлам IWE; истина по каждой работе остаётся в карточках.

## Что описывает таблица

Строка - сценарий использования: роль, действие и результат для человека. Сценарий - факт о человеке, он не принадлежит ни IWE, ни платформе: их обеспечивают средства. Поэтому «Средство» (чем обеспечено), «Состояние средства» (что оно делает сейчас), «Работа» (что делается по нему в карточках) и «Размещение» (где средство будет жить) - отдельные колонки.

## Как читать

Каждый сценарий записан один раз; в сводках внизу строка «Всего» равна числу сценариев.

- **№** - номер сценария. Прежние коды из старых каталогов хранятся в примечании как «Прежний код».
- **Сценарий использования** - кто и что делает, с указанием доступа и роли, если они важны. Роли: гость, участник, наставник, автор шаблона, оператор платформы, агент пользователя (ИИ).
- **Где** - в каком клиенте это происходит: claude.ai, веб-ChatGPT, Codex, Claude Code / VS Code, Kimi Code, LibreChat, Telegram-бот, браузерный кабинет, чат на сайте МИМ, терминал, фоновый запуск по расписанию, любой клиент.
- **Что получает** - результат для человека. Если при этом что-то фиксируется (запись, файл, журнал), это записано после слов «Платформа фиксирует» (для платформы) или «Фиксируется» (для IWE).
- **Средство** - чем сценарий обеспечен, с видом: `MCP: инструменты`, `скилл: имя`, `протокол: файл`, `хук/скрипт: имя`, `бот: команда`, `сайт/плагин: что`, `человек: роль`. Английские имена даны как в системе; если имени нет, написана суть текстом.
- **Состояние средства** - что средство делает сейчас, в скобках чем подтверждено (вид свидетельства, дата, где): «работает» (видели живьём или по коду), «работает частично», «есть, не проверено» (запуск ни разу не видели), «есть, не работает», «нет» (средства ещё нет).
- **Работа** - статус работы по карточке: «не ведётся» (по этому сценарию сейчас ничего не делается: либо всё готово, либо работа не заведена), «в плане: РП-N», «в работе: РП-N Ф-M».
- **Размещение** - где средство будет жить: для MCP - Open Aisystant, Open МИМ, Open (оба), Plus МИМ, Plus Aisystant, Plus (оба), сочетание через «+», «Вне платформы»; для скиллов, хуков и скриптов - «шаблон IWE» (папка есть в шаблоне), «Staging S-N» (на обкатке), «только у автора»; «Не выбрано» - решения нет. Заполнено только там, где решил пилот или это факт (файл лежит в шаблоне).
- **Примечание** - прежний код, предложения агента, какие РП делают сценарий и чего ждут.

### Слова, которые встречаются

- **MCP** - программа-сервер, через которую ИИ-клиент вызывает инструменты платформы; **инструмент (tool)** - одна её функция.
- **Скилл** - способность агента, описанная в файле `SKILL.md`; запускается ИИ командой вида `/имя`. **Протокол** - описание ритуала (шаги), которому следует агент. **Хук** - программа, которая срабатывает на событие (например, перед коммитом). **Скрипт** - программа, которую запускают вручную или она запускается по расписанию.
- **IWE** - персональная среда пользователя (агент, скиллы, протоколы, хуки, скрипты, память). **Платформа** - общая система (MCP, бот, сайты, базы).
- **Шаблон IWE** - заготовка `FMT-exocortex-template`, из которой создаётся IWE у других пользователей. **Staging** - очередь `STAGING.md`: правила, которые обкатываются у автора и переходят в шаблон.
- **Клиент** - программа, где человек общается с ИИ: claude.ai, веб-ChatGPT, Codex, Claude Code, LibreChat, Telegram-бот.
- **РП, Ф** - рабочий продукт (внутренняя единица работы) и его этап (фаза). Карточки РП закрыты.
- **Опись** - проверка списка и чисел нынешнего MCP от 29-30.10; повторно не снималась. **Живой запуск** - вызов или прогон с датой, который кто-то реально видел.
- **Охранное правило** - требование «ИИ не делает X»: описывает поведение агента, а не действие человека.
- **Онбординг, ступень, диагностика, чек-лист, табло, плагин, OAuth** - знакомство с платформой; уровень мастерства участника и проверка, которая его оценивает; перечень фактов о пути участника; страница наставника с состоянием группы; подключение MCP из каталога клиента; вход через аккаунт без передачи пароля клиенту.
