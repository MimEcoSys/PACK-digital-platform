# [DP.SC.049] Менеджер оргразвития

## 1. Правило (инвариант)

> Нарушение любого = провал SC.

- **Диагностика типа системы — обязательный Шаг 0.** Любой запрос на оргизменение проходит через MIM.M.030 (классификатор) до выбора метода. Без классификации — метод не выдаётся.
- **Оргцелостность не разрушена.** Проверяются 3 applicability-conditions перед выдачей метода:
  - **автономия** — субъект имеет полномочия на изменение себя/системы;
  - **согласие** — субъект согласен на изменение (для случая «другого» и «команды»);
  - **charter** — есть явный или implicit мандат на оргизменение.
- **Метод не выдаётся без проверки готовности.** Перед маршрутизацией к руководству — вызов Диагноста (DP.ROLE.042; готовность субъекта по cp-профилю).
- **Граница с Навигатором (MIM.R.007) — по программе.** Запросы программы ЛР («личностный рост / мировоззрение / зачем я») → Навигатор (MIM.R.007). Запросы программы РР («рабочий хаос / оргструктура / команда») → R31 Менеджер оргразвития. Пересечение на ст. 3-4 — обе роли применимы, программа определяет приоритет.

---

## 2. Обещание

**Кому:**
- **Пилоту** (как субъекту изменения себя/команды/организации) — «от запроса об оргхаосе до конкретного первого шага ≤30 мин из одного из канонических руководств программы РР»
- **Навигатор (MIM.R.007)** — «я не увожу пилота с траектории ЛР, если запрос в рамках РР; при ЛР-запросе перенаправляю обратно»

**Зачем:**
- `docs/docs/ru/professional/` содержит каноническое тело руководств программы РР, но нет проводника от «у меня бардак в команде» до «вот метод из СМ-руководства X, шаг 1»
- Без диагностики типа системы — риск FM.02: неверный выбор метода (ИЛ применён к организации → избыточная индивидуализация; СИ применён к личности → неприменимая абстракция)
- Без applicability-проверки — рекомендация субъекту, у которого нет полномочий/согласия → разрушение оргцелостности

**Что получит:**

```
{
  "system_type": "personality | team | organization",
  "method": "IL | SM | SI",
  "guide_reference": "см. MIM.M.031 routing-table — primary_guide (R8|R9|R10) + опционально foundation_guide (R1|R5|R7)",
  "first_step": "конкретное действие ≤30 мин (взять из MIM.M.031 first_step_pointer.action_template)",
  "applicability_check": {"autonomy": true, "consent": true, "charter": true},
  "r28_readiness": "ok | downshift | escalate_to_navigator"
}
```

> **Примечание (после WP-377 Ф2.1):** Маршрутная таблица для `guide_reference` зафиксирована в `MIM.M.031` (PACK-MIM). Таблица — `status: hypothesis` до 20 вызовов калибровки; revision-критерии в frontmatter MIM.M.031.

## 3. Время отклика

- Классификация типа системы (MIM.M.030) — 1-2 мин (7 вопросов).
- Applicability-check — < 1 мин (3 вопроса).
- Готовность субъекта (Диагност) — < 30 с (кэш или 1 уточняющий вопрос).
- Выбор метода + первый шаг — < 1 мин после диагностики.
- Полное сопровождение по руководству — часы/дни (не монолитно, между сессиями).

## 4. Основной flow

```
Запрос («Оргразвитие, в команде хаос с приоритетами»)
  │
  ├─ Шаг 0a: прочитать personal-guide/team-guide субъекта, если существуют
  │         (для не-противоречивости с прошлыми рекомендациями)
  │
  ├─ Шаг 0:  MIM.M.030 — классификация типа системы
  │   ├─ личность   → ИЛ (инженерия личности)
  │   ├─ команда    → СМ (системный менеджмент)
  │   └─ организация → СИ (системная инженерия)
  │   └─ margin < 3 → уточняющие вопросы (1-2), не выбирать метод вслепую
  │
  ├─ Шаг 1: проверка applicability (3 conditions)
  │   └─ не пройдено → отказ с объяснением границы, НЕ метод
  │
  ├─ Шаг 2: вызов Диагноста (готовность субъекта)
  │   ├─ cp ≥ 2 → продолжать
  │   ├─ cp < 2 → downshift: микро-шаги + CTA к Навигатору (MIM.R.007)
  │   └─ ЛР-запрос → перенаправление Навигатору (MIM.R.007)
  │
  ├─ Шаг 3: маршрутизация к руководству + конкретный первый шаг
  │   └─ MIM.M.031 (routing-table): system_type + cp.iwe → primary_guide
  │       (R8|R9|R10) + опционально foundation_guide (R1|R5|R7);
  │       first_step_pointer.action_template даёт шаг ≤30 мин.
  │
  └─ Шаг 4: фиксация рекомендации в personal-guide/team-guide субъекта
```

## 5. Сценарии использования

**Сценарий 1: «Я постоянно прокрастинирую, хочу измениться» — личность → ИЛ**
- MIM.M.030: система = personality (вопросы 1, 2, 3 дают вес personality).
- Applicability: автономия ✅, согласие ✅ (self), charter — implicit.
- Диагност: cp.iwe=3 → ok, продолжать.
- Метод: ИЛ — R9 «Инженерия личности», `docs/docs/ru/professional/personality-engineering/` (MIM.M.031 → primary_guide R9).
- Первый шаг: диагностика стиля (PD.FORM.098) — 15 мин.

**Сценарий 2: «В моей команде 5 человек, никто не понимает кто за что отвечает» — команда → СМ**
- MIM.M.030: система = team (вопросы 2, 3, 5 дают вес team).
- Applicability: автономия ✅ (тимлид), согласие — нужна проверка (команда уведомлена?), charter ✅.
- Диагност: cp.iwe=3 → ok.
- Метод: СМ — R10 «Системный менеджмент», `docs/docs/ru/professional/systems-management/` (MIM.M.031 → primary_guide R10, точка входа `management-practices-and-manager-roles`).
- Первый шаг: шаблон распределения ответственности — 30 мин.

**Сценарий 3: «Наша компания 50 человек, процессы разваливаются при масштабировании» — организация → СИ**
- MIM.M.030: система = organization (вопросы 2, 3, 7 дают вес organization).
- Applicability: автономия ✅ (CEO/owner), согласие — нужна проверка стейкхолдеров, charter ✅.
- Диагност: cp.iwe=4 → ok.
- Метод: СИ — R8 «Системная инженерия», `docs/docs/ru/professional/systems-engineering/` (MIM.M.031 → primary_guide R8, точка входа `engineering-process` / `evolutionary-architecture`).
- Первый шаг: карта текущих бизнес-процессов (AS-IS) — 1 час.

**Сценарий 4: «Помоги мне изменить моего сотрудника без его согласия»**
- applicability: consent = false.
- Результат: отказ + объяснение «оргцелостность требует согласия субъекта изменения» + предложение переформулировать как изменение собственного поведения по отношению к сотруднику.

## 6. Режимы отказа

| ID | Сценарий | Поведение |
|----|----------|-----------|
| **FM.01** | Рекомендации без проверки готовности | Диагност не вызван, cp неизвестен → пилот получает метод, который не может применить → фрустрация. Митигация: Диагност — обязательный Шаг 2 |
| **FM.02** | Неверный выбор метода | MIM.M.030 пропущен или проигнорирован → СИ для личности (избыточно) или ИЛ для организации (недостаточно). Митигация: Шаг 0 — обязательный gate перед выбором метода |
| FM.03 | MIM.M.030 даёт неоднозначный результат (margin < 3) | Запросить 1-2 уточняющих вопроса, не выбирать метод вслепую |
| FM.04 | Applicability не пройден | Отказ с объяснением границы, НЕ рекомендация |
| FM.05 | ЛР-запрос («зачем мне жить») | Перенаправление к Навигатору (MIM.R.007) |
| FM.06 | Конкретное руководство отсутствует в routing-table (MIM.M.031 FM.R4) | Откатиться на каталог `docs/docs/ru/professional/<guide>/` + интерактивный выбор подраздела с автором; залогировать в `learning.guide_routing_misses` |
