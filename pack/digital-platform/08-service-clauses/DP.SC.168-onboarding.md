# DP.SC.168 — Онбординг платформы: зонтичное обещание

> **Одной фразой:** онбординг — это два сценария шаблона IWE: **лёгкий** (открытая часть) и **полный** (подписочная часть). Точка входа одна, развилка одна — **вошёл ли человек аккаунтом МИМ**. Не вошёл или отказался — только лёгкий; вошёл — полный.
>
> Лёгкий доводит любого человека со своим ИИ-клиентом до маленького полезного результата на его задаче за один разговор. Полный ведёт участника МИМ с подпиской от первого входа до своей рабочей среды (DP.SC.170).

---

## §1. Лёгкий онбординг (открытая часть)

| | |
|---|---|
| **Кому** | Любому человеку со своим ИИ-клиентом (Claude, ChatGPT и др.), который подключил Open MCP или установил шаблон IWE. Аккаунта МИМ нет |
| **Обещание** | За один разговор — маленький полезный результат на своей задаче методом из библиотеки методов (FPF и паки). Итог разговора — квитанция «было → стало» |
| **Условия** | Без аккаунта, без подписки, без рекламы и оплаты |
| **Данные и память** | В лёгком без входа платформа МИМ не хранит о человеке ни прогресса, ни отметок, ни истории разговора. Память — только у агента человека (его ИИ-клиент, его IWE) |
| **Носитель** | Один канонический текст сценария (разговор, шаги, отказы, квитанция) и две тонкие привязки к среде: в Open MCP текст отдаётся инструкцией Open и опирается на библиотеку Open; в шаблоне IWE навык читает тот же текст и опирается на локальные FPF и паки. В самом тексте нет имён инструментов среды — только «найди метод в библиотеке». Вторая редакция текста запрещена |
| **Следующий шаг** | Задаёт канонический текст. Сервер МИМ лёгкий не вызывает |
| **Канал выпуска** | Шаблон IWE (открытая часть) → Open MCP |
| **Конечное состояние** | Квитанция «было → стало» на задаче человека |

---

## §2. Полный онбординг (подписочная часть)

| | |
|---|---|
| **Кому** | Участнику МИМ с подпиской МИМ (или оформляющему её), вошедшему аккаунтом МИМ |
| **Обещание** | От первого входа до своей рабочей среды: Интересант → Определяющийся → Первокурсник → P1–P9. Полный текст обещания — DP.SC.170 |
| **Условия** | Подписка МИМ (у вошедшего без подписки оформляется в ходе полного, DP.SC.170 §1); согласие на учёт активности |
| **Нулевой шаг** | Полный сам исполняет канонический текст лёгкого (§1). Пропуск — только если в этом же разговоре у агента человека уже есть квитанция «было → стало»; платформа МИМ гостевую квитанцию не видит |
| **Данные и память** | Платформа МИМ: учебный контекст, цифровой двойник, чек-лист оснащения |
| **Следующий шаг** | Инструменты шлюза за входом, в том числе `get_journey_state` (где человек сейчас) и `get_next_onboarding_step` (один следующий шаг); маршруты, диагностика, персональное руководство |
| **Маршруты** | «Новичок», «Опытный», «Команда» (классификация — §4) |
| **Канал выпуска** | Шаблон IWE (подписочная часть). В Open MCP не входит. В набор навыков установки без аккаунта не входит — включается только при подключённом аккаунте МИМ |
| **Конечные состояния** | (1) персональное руководство под ступень и узкое место; (2) работа по своим рабочим продуктам в своей среде; (3) стратегирование |

**Оснащённость внутри полного.** Ступени оснащённости подписчика (тиры) ведёт Владелец тира (DP.ROLE.078); модель тиров — DP.ARCH.002. Это не ось онбординга: лёгкий тиров не имеет, полный их использует как условие доступа к инструментам.

---

## §3. Граница между сценариями

1. **Лёгкий не рекламирует полный и подписку.** Варианты продолжения (аккаунт МИМ, подписка, своя IWE) появляются только по вопросу человека — ссылкой на сайт и переходом в установку IWE на стабильном выпуске.
2. **Оплатившего не отправляют в гостевой Open.** Память лёгкого живёт только у агента человека, поэтому новый чат, бот или другой клиент проходят нулевой шаг полного заново.
3. **Гостевые отметки лёгкого при входе не переносятся** на серверный чек-лист аккаунта.
4. **Одна истина — один текст, два места исполнения:** канонический текст лёгкого исполняется и в лёгком, и как нулевой шаг полного.

---

## §4. Классификация входа (единственное место правила)

| Кто пришёл | Сценарий | Маршрут |
|---|---|---|
| Совсем новый, без аккаунта МИМ | Лёгкий | — |
| Вошёл аккаунтом МИМ, подписка ещё не оформлена | Полный | «Новичок»; оформление подписки — шаг Онбордера (DP.SC.170 §1) |
| Подписчик МИМ без своей среды | Полный | «Новичок» |
| Подписчик МИМ с настроенной средой | Полный | «Опытный» |
| Команда | Полный | «Команда» |

DP.SC.119 и DP.SC.170 на эту таблицу ссылаются и своих классификаций не держат.

---

## §5. Два MCP без пересечений

- **Open MCP** — библиотека методов и лёгкий онбординг. Состояния полного не видит, гостевых отметок не хранит.
- **MCP с подпиской** (MIM MCP / Aisystant MCP) — только данные человека, включая полный онбординг.
- Подписчик подключает оба; Open не отключается. Целевое подключение по умолчанию — Open; MCP с подпиской — при входе аккаунтом МИМ.
- В установке шаблона без входа ни шагов, ни ошибок MCP с подпиской человек не видит.

---

## §6. Чек-лист участника: общий состав, разная запись

Состав чек-листа один для обоих сценариев (владелец — РП-522). Состав меняется сначала там, потом в сценариях.

| | Лёгкий | Полный |
|---|---|---|
| Что отмечается | Только бесплатные этапы без аккаунта: «Ценность» (ответ методом на своей задаче) и гостевой первый результат (квитанция «было → стало») | Этапы аккаунта: вход, согласие, диагностика, подписка, подключение, первый результат с вехами |
| Кто ставит отметки | Агент человека у себя, с указанием источника («слова человека» или «наблюдал агент») | Писатели экосистемы (платформенные процессы), не сам человек и не гостевой агент. Самоотчёт гостя их не заменяет |
| Где хранятся | Только у агента человека | Серверный чек-лист аккаунта |

| Канал | Обещание | Сценарий |

| Шаблон IWE без входа | §1 этого обещания | Лёгкий |
