# DP.SC.201 «Конвейер ОРЗ: открытие-закрытие сессии/дня/недели/месяца»

## Обещание

Восемь тактов ОРЗ (`{сессия, день, неделя, месяц} × {открытие, закрытие}`) — не разрозненные скрипты и протоколы, а единый конвейер с одним контрактом выхода. Пилот и любой агент могут положиться на то, что для каждого ожидаемого такта в едином журнале существует проверяемая запись о попытке — а не тишина, которую приходится трактовать как «наверное, всё в порядке».

## Триггеры

- Наступление любого из 8 тактов: открытие/закрытие сессии, дня, недели, месяца (по расписанию, по слову пилота или по автоматическому раннеру — источник триггера не сужает обещание).

## Входы

- Предыдущее состояние такта того же типа (если есть) — например, для «закрытия дня» это состояние, оставленное «открытием дня»
- Факты, накопленные с прошлого такта того же типа (коммиты, ledger-события, рефлексия пилота)

## Pipeline (детерминированный)

```
1. Определить тип такта и применимость к текущему пилоту (уровень оснащения T1-T4)
2. Собрать вход: предыдущее состояние + накопленные факты
3. Выполнить операции такта (специфичны для каждого из 8 — не часть этого обещания)
4. Записать валидную попытку в ledger (см. «Инвариант»)
5. Если такт — «закрытие дня» или «открытие дня»: произвести выход для персонального руководства и планов дня/недели (эталонный такт, WP-561 Ф3)
```

## Инвариант

**Инвариант 1 (наследован из черновика WP-484):** нет данных → явный маркер, никогда тихий пропуск.

**Инвариант 2:** такт не подтверждён, пока не произведена **валидная попытка** его выполнения, зафиксированная в ledger. Валидная попытка = одно из:
- (i) успешное выполнение с обязательными полями выхода — маркер `ok`;
- (ii) явный отказ выполнить — маркер `degraded`/`incomplete` с причиной;
- (iii) явное признание неприменимости к данному пилоту (уровень оснащения не покрывает такт) — маркер `not-applicable` с обоснованием.

Тихий пропуск без записи любого из трёх маркеров — единственное состояние, нарушающее инвариант.

**Инвариант 3 (счёт надёжности такта; день — WP-561 Ф36, неделя — WP-561 Ф39 / WP-484 Ф164):** для суточного и недельного такта ведётся серия «такт прошёл сам: да/нет, подряд N» и одна строка состояния последнего перехода (отчёт недели, вход стратсессии, сообщение в Telegram). Причину отказа нельзя переименовать после испытания ради сохранения серии: переклассификация — только новой записью через `ledger-append.sh`, исходная запись остаётся. Механической защиты от переписывания истории ledger нет — нарушение видно как правка уже опубликованной записи в истории git и ловится ревью.

**Граница с DP.SC контрактом сессий (WP-510, PIPE-14):** ledger этого обещания фиксирует **мета-запись о факте прохождения такта** (какой такт, когда, каким маркером), не содержимое такта. Содержимое сессии (сообщения, артефакты, handoff-и) остаётся собственностью контракта WP-510 — это обещание не поглощает и не дублирует его.

**Интерфейс чтения/записи:**
- Чтение — файлы `machine/ledger/{day,week,month}/...` (git-tracked YAML, доступны без специальных прав любому агенту с доступом к файловой системе репозитория) и их зеркало в Neon `domain_event` (для агентов с MCP/SQL-доступом)
- Запись — единая точка `ledger-append.sh <scope> <date> <event_type> <payload> <source>`; прямые записи в лог-файлы в обход неё не считаются валидной попыткой, т.к. обходят типизацию и concurrency-гарантии

## SLA

- Не определён на уровне обещания (специфичен для каждого из 8 тактов — фиксируется в реестре тактов, WP-561 Ф2)

## Fallback

| Ситуация | Поведение |
|----------|-----------|
| Инструмент такта недоступен (сеть, API, MCP) | Запись `degraded` с причиной — не молчание |
| Такт неприменим к пилоту (T1-T4) | Запись `not-applicable` с обоснованием — не пропуск |
| Такт выполнен частично | Запись `incomplete` с перечнем недостающих полей выхода |

## Свидетельства результата

- Для каждого ожидаемого такта существует ровно одна запись в ledger с маркером `ok`/`degraded`/`incomplete`/`not-applicable`
- Эталонный такт (день, открытие+закрытие, WP-561 Ф3): персональное руководство и план дня получают данные без ручного шага агента

## Smoke тест

```
1. Взять произвольный такт из реестра (WP-561 Ф2) за произвольную дату
2. Прочитать ledger (файл или Neon) — убедиться, что запись существует
3. Убедиться, что запись содержит один из 4 маркеров, не пустое поле статуса
4. Для такта «закрытие дня»/«открытие дня» — проверить, что руководство/план дня фактически используют эту запись, не отдельный ручной источник
```
